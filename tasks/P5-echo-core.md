出口条件分两步：

- **N2（排练版）：** P5-01 至 P5-05、P5-07、P5-08、P5-14 完成，核心链路可以每天使用。
- **N3（诞生）：** 其余各卡完成，Echo Core 通过施工总方案 M2 阶段门的全部验收项（清单见 `docs/echo-core/README.md` 第 3 节）：

- 事件能被合法接收；
- 快状态 x 确定性更新；

施工顺序按「分阶段启用」（ADR 0005、E13）：

3. 尚未接通的阶段走规格已有的降级路径，并在运行状态里如实显示。

这一阶段的每张卡都必须先读 `.agents/skills/echo-core-work/SKILL.md`，并在报告里附规格对照表。验收编号按规格原文执行，不得改名、合并或放宽。

### 交付物
- **存储：** 单个 SQLite 数据库，WAL、`synchronous=FULL`、`foreign_keys=ON`、有界忙等待，位于 `%LOCALAPPDATA%\Nemu\core\`；启动时校验所在卷是本机 NTFS（E3）。
- **表组：** 按总方案第 7 节建表。R 与 θ 的表在 v1.0 中只存 genesis 与空结构。
- **对象存储：** 内容寻址目录。写入顺序为：临时文件 → 校验摘要 → fsync 文件 → 原子改名 → fsync 父目录。垃圾回收与提交共享代际保留协议。
- **谱系（E14）：**
  - 一个存储目录只有一条谱系：排练谱系在 `%LOCALAPPDATA%\Nemu\core\rehearsal\`，正式谱系在 `%LOCALAPPDATA%\Nemu\core\life\`；
  - 存储头部写入谱系类型、创建时间，正式谱系另写 genesis 清单摘要；
  - 核心启动时没有任何谱系，就自动创建排练谱系；
  - 正式谱系只能经 genesis 创建接口建立（命令在 P5-15）；
  - 打开存储的接口按谱系类型区分（类型能力），正式谱系的任何读取路径都打不开排练存储。
- **提交协议：** branch head；staged → 原子发布；发布前核对 head 与 read set；接收先持久化 D 再回执。
- **故障注入点：** 可配置的崩溃注入（G 暂存后、owner 写入时、L 写入时、最终发布时），供 X03 使用。

### 验收

- X03（v1.0 存在的阶段）：只存在全旧或全新的权威状态。

- SYS22 的存储部分：磁盘满、容量满时有反压或明确拒绝，不半提交。

## P5-20 自主调度、机会规则与安静模式（W13 调度）

- **建议执行者：** Codex
- **难度：** 中
- **里程碑：** N3 诞生
- **依赖：** P5-14、P5-12
- **工期：** 4 天
- **分支：** `task/P5-20-scheduling`
- **目录：** `core/crates/core-runtime/src/scheduler/`
- **必读：** 总方案第 20、21 节；v0.6.4 第 11 节；《核心算子》第 17.3 节；CONTRACTS.md 第 8 节；ADR 0003（模式 B 的自主行动例外）

### 交付物
- 调度状态 Z。
- 强度 = 调度读出(m) × 运行门控，限制在 `[0, λ_sched,max]`。
- 有上界强度的 thinning：保存实际随机数、候选时刻、强度、门控和判定。
- 最小行动间隔；每小时上限。
- 机会规则引擎：读取 `config/opportunities.json`，触发谓词只引用已提交的有类型事件和 Q。
- 「安静模式」：你让她安静时，生成一个 T0 行动，在 Q 中设置带期限的门控；当天说话上限减半。
- 暂停条件：
  - m = 0 时暂停依赖核心的自主行动（排练谱系，或模式 A 载体失效进入 `CORE_UNMODULATED`）；
  - 模式 B 例外（ADR 0003，用户已批准）：`TEXT_PROJECTED` 下 m 由 J 正常编译，自主行动照常，回执标为非严格。

### 验收
- SYS10；v0.6.4 16.14：非爆炸条件；等待后生成行动使用对应时刻的投影。
- 结构夹具中，强度随 m 变化。固定倒计时、常数强度、或对 m 不敏感的实现，必须让这项测试失败。
- m = 0（排练谱系、载体失效）时 0 次自主行动；`TEXT_PROJECTED` 时照常调度。
- 模拟 8 小时工作日的事件流（含 2 次会议、1 次 PPT 放映、1 段全屏视频）：勿扰期间 0 次自主说话；说话次数不超过上限（完成标准第 18 项）。
