# P5 Echo Core（v2.0 核心，第 2–20 周）

下文的「v2.0」指 `docs/echo-core/echo-core-v2.0-first-principles.md`（ADR 0009）。v1.0 的范围、谱系与诞生按 ADR 0010：v1.0 包含 v2.0 的全部机制，成长从诞生起开启。

出口条件分两步：

- **N2（排练版）：** P5-01 至 P5-05、P5-07、P5-08、P5-14、P5-21 完成，核心链路可以每天使用。排练谱系的情绪在 P5-19 合并后接通，不卡 N2。
- **N3（诞生，ADR 0010 第 7 条）：** 其余各卡完成：
  - v2.0 的验收通过（AC2-01 至 AC2-25，加上 P5-18 判定保留的旧验收项）；

施工顺序按「分阶段启用」（ADR 0005、ADR 0010）：

1. 先搭好完整的事件顺序和核心链路：入口、存储、事实视图、编排、行动生命周期。排练版就跑在这条链路上。

3. 情境吻合 M、证据组装、规律 G、动力学 C 和重算接入（P5-29），正式谱系和实验谱系具备成长。
4. 尚未接通的阶段走降级路径，并在运行状态里如实显示。正式谱系要求全部阶段接通。

- **建议执行者：** Codex
- **难度：** 中
- **里程碑：** N2 她在了（排练版）
- **依赖：** P0-06、P0-02
- **工期：** 8 天
- **分支：** `task/P5-01-idl`
- **目录：** `core/contracts/`、`core/crates/core-types/`；生成到 `workers/*/generated/`、`packages/contracts/src/generated/`
- **必读：** 施工合同第一篇 3、6、7 节；《核心算子》2、16.1、19 节；总方案 5、6 节；v0.6.4 第 3.2、4 节；CONTRACTS.md 4.2–4.4、5

### 交付物
- **IDL：** 用 Protobuf 定义传输格式，覆盖以下全部消息：
  - 施工合同第一篇 6.2 的消息：EventEnvelope、FactProjection、SemanticCandidate、SemanticGraph（Ref、Claim、Act、Edge）、ConceptRef、ConceptProposal、FastStateSnapshot、FastDriveProposal、ProposalBinding、CoreTransaction、CoreCommitResult、DegradedStatus、FailureReason；
  - 总方案 19 节补齐的消息：EffectContract、QualificationCertificate、ConsolidationSlice、ThetaModule、ResponsibilityBinding、TrialResult、ModulationEnvelope、VersionedEnvironment；
  - 施工合同 0.4 的 R/G 对象：只定义类型与编码，v1.0 不接入运行路径；
  - 行动生命周期消息；
  - Nemu 终端消息（CONTRACTS.md 4.2–4.4），含 `user_retraction`、`query` 与 `query.result`；
  - 生成接口与说话模式（CONTRACTS.md 第 5 节）；
  - 谱系头部（ADR 0005）：谱系类型、创建时间、genesis 清单摘要。
- **CanonicalV1：**
  - 显式 schema 版本与类型标记、固定字段顺序、长度前缀、固定端序整数、严格 UTF-8；
  - 集合按规范键排序；SHA-256 加对象类型域分离；
  - Rust 为权威实现，Python、TypeScript 实现必须产出逐字节相同的结果。
- **数值与单位：** 有限 binary64，拒绝 NaN、Inf，规范化负零；时间为有界整数纳秒；拒绝未知 schema、未知枚举、重复单值字段、超限消息。
- **黄金向量：** `core/contracts/golden/`，每种消息至少 3 个合法向量和 3 个非法向量。
- **重建登记：** 字段在 v0.6.4 与 v1.0 文档中都找不到依据的，登记到差异登记，标为「重建，待用户确认」，并采用最小字段集。

### 验收
- 施工合同第一篇 10.8：Rust、Python、TypeScript 对同一黄金向量的编码、解码、必填字段、枚举与版本判定一致。
- SYS21：未知 schema、NaN、计数溢出被拒绝。
- 每条消息都能追溯到规格条款（规格对照表）。

> **2026-10-20 追加（v2.0）：** 这里的 R/G 类型（施工合同 0.4 的对象、总方案第 19 节的 EffectContract 等）已被 v2.0 取代，新的状态与记录类型在 P5-21。已用过的字段号、枚举值和类型标签都不复用。

## P5-02 单写事务与对象存储（W02）

> **高难度卡：** 由 Claude 与 Codex 协作完成。一方实现，另一方交叉审查；审查结论写在 PR 评论里，通过后才能合并（AGENTS.md 第 6 节）。

- **建议执行者：** Codex
- **难度：** 高
- **里程碑：** N2 她在了（排练版）
- **依赖：** P5-01
- **工期：** 8 天
- **分支：** `task/P5-02-store`
- **目录：** `core/crates/core-store/`
- **必读：** 总方案 7、8 节；《核心算子》16 节；v0.6.4 第 4、5 节；施工合同第一篇第 3 节；v2.0 第 2、13 节；ADR 0010

### 交付物
- **存储：** 单个 SQLite 数据库，WAL、`synchronous=FULL`、`foreign_keys=ON`、有界忙等待，位于 `%LOCALAPPDATA%\Nemu\core\`；启动时校验所在卷是本机 NTFS（E3）。
- **表组：** 按总方案第 7 节建表。R、θ、L 不建专用表：它们以 CanonicalV1 对象存进对象存储，表里只存对象引用、索引和快照指针。R 按倾向分成对象，快照是这些对象的索引，每次提交只写改变的部分。对象类型由 P5-21 定义，本卡不依赖其字段；P5-21 合并之前用占位对象类型测试。
- **对象存储：** 内容寻址目录。写入顺序为：临时文件 → 校验摘要 → fsync 文件 → 原子改名 → fsync 父目录。垃圾回收与提交共享代际保留协议。
- **谱系（ADR 0005、ADR 0010）：**
  - 三种谱系：排练（`REHEARSAL`）、正式（`LIFE`）、实验（`EXPERIMENT`）；
  - 一个存储目录只有一条谱系：排练谱系在 `%LOCALAPPDATA%\Nemu\core\rehearsal\`，正式谱系在 `%LOCALAPPDATA%\Nemu\core\life\`，实验谱系只能建在临时目录里（命令在 P5-15）；
  - 存储头部写入谱系类型、创建时间，正式谱系另写 genesis 清单摘要；
  - 核心启动时没有任何谱系，就自动创建排练谱系；
  - 正式谱系只能经 genesis 创建接口建立（命令在 P5-15）；
  - 打开存储的接口按谱系类型区分（类型能力）：三种谱系互不可读（I29），任何读取路径都不能把一种谱系的记录读进另一种。
- **提交协议：** branch head；staged → 原子发布；发布前核对 head 与 read set；接收先持久化 D 再回执。
- **故障注入点：** 可配置的崩溃注入（G、C 暂存后，L 写入时，最终发布时），供 X03 使用。

### 验收
- v0.6.4 16.1、16.13；施工合同第一篇 10.1、10.2。
- X03：只存在全旧或全新的权威状态。
- AT01–AT04（总方案第 30 节）。
- SYS22 的存储部分：磁盘满、容量满时有反压或明确拒绝，不半提交。
- 谱系测试：
  - 用排练存储启动正式谱系配置会被拒绝；
  - 正式谱系的事实视图读不到排练记录；
  - 三种谱系两两互不可读（I29、AC2-22 的存储部分）；
  - 全部测试只在临时目录里运行（AGENTS.md 黄金规则 14）。

- FactQuery 与 FactProjection：已提交前缀、类型、时间、来源过滤、查询版本、条数、字节、步骤上限、用途。

### 交付物

- **空间：** X = [−1, 1]^{4 + |R⁺|}。前四维是天性通道（联结、共情、好奇、成事），其后每个 k ∈ R⁺ 一维，按倾向 ID 的规范次序排列。
- **时间投影：** Φ_x(Δ; x) = x_rest + e^{−ΛΔ}(x − x_rest)，x_rest = (b, 0)，所有 λ ≥ λ_min > 0；λ_k 取参考式 Σ_i |d_{k,i}| λ_i / Σ_i |d_{k,i}|。
  - 写成 x + (−expm1(−λΔ)) · (x_rest − x)，使 Δ = 0 时在 binary64 下逐位不变；投影后再截断到 X（核验 D-2）。
- **F_in：** x̃ = Proj_X(x̄ + D(e))：
  - D_i = g_i · w_i(e) · (a_i(e) − b_i) + Σ_{k∈R⁺} f_{k,i}(e)，i = 1…4；
  - D_k = s_k · μ_k(e)，k ∈ R⁺；
  - f_k(e) 由 P5-27 的作用视图给出；
  - w_i：共情通道取事件所涉之人的亲近度，由关于此人的倾向得出（参考：(1 + π)/2，截断到 [w_min, 1]）；其余通道为 1；
  - D 不读 x̄（ADR 0008 §1）；a(e) 缺失（A 降级）时天性驱动为 0。
- **保守幅度检查：** ‖D(e)‖∞ ≤ max(1, 2g_max + r_max · max_i Σ_{k∈R⁺} |d_{k,i}|)，用绝对值之和计算。

- **参考形式（v2.0 第 5.2 节）：**
  - π_k = A_k/B_k，A_k = Σ ω·W·S，B_k = n₀ + κ_k + Σ ω·W·|S|；
  - 支持 S_{c,k} = μ_{c,k} · clip(2p_c/r̃_k − 1, −1, 1)，p_c = ⟨mean_{e∈c}(a(e) − b), d_k⟩，r̃_k = max(r_k, r_min)；
  - 权重 W = 强度 × 可信 × 可核实 × 份额；强度 = min(w_max, max(r̃_k, max_{e∈c} |⟨a(e) − b, d_k⟩|)/σ̂_k)，σ̂_k² = Σ_i d_{k,i}² σ̂_i²；教导的强度取 w_teach；
  - 份额：一致的一边、相反的一边各按 (1 + π_k)/2 分配，各自之和为 1，π_k 取组之前的值；
  - 新近权重：每来一组关于 k 的证据，k 的旧证据乘上当时的 ρ_k = 1 − ĥ_k；ĥ_k = (h₀n_h + F_k)/(n_h + N_k)；
  - κ_k = κ₁ × 情境谓词的条件数；r_k 为吻合组 p_c 的加权平均（权重 ω·μ），截断到 [0, r_max]；
  - s_k = max(0, 2π_k − 1)；π_k > ½ 时进入 R⁺，降到 ½ 及以下时离开 R⁺，仍留在 R 中。
- **计算次序是规范定义：** 按 H 的提交次序逐组处理，先乘 ρ，再加入新组；以递推为准，不用闭式（核验 LAW-7：闭式在末位有差异）。新候选提出时，按 EV5 收集到的旧组在全部吻合的倾向之间重新分摊，其他倾向已记入的份额相应调整，同样在 H 的次序中进行。
- **规范定义里还要写定、并登记差异登记的几处**（v2.0 没有写到，待用户确认，不阻塞）：组在 H 中的位置（取第一个成员，EV7）；后来加入组的成员怎样更新这一组（不算新的一组，不使旧证据再衰减一次）；份额在什么时刻取 π；补做的解释（M 降级后的补做、EV5 的回溯）在追加的位置按次序计入，使增量计算与整段重算仍然一致。
- **关于人的倾向**（v2.0 第 6、7、10 节）：
  - 亲近与信任是两种结构上的关系倾向，每个人至多各一个；第一次涉及此人时以 π = 0 建立，情境吻合由事件的参与者确定性给出（P5-24）；
  - u* 的亲近就是依恋，先验 A_att 不乘新近权重：π_att = (A_att + E − C)/(n₀ + κ_att + A_att + E + C)（推论 7）；u* 的信任按 v2.0 第 10 节由依恋先验给出很高的初值；
  - 亲近度 (1 + π)/2（截断到 [w_min, 1]）供 F 的共情加权（P5-10），信任 (1 + π)/2 供教导的权重；
  - 预言方向与证据的具体写法由本卡给出，在 P5-30 的实验 3、4 中检验，登记差异登记（待用户确认，不阻塞）。
- **保险丝**（v2.0 第 12 节）：R 的容量（满时证据量最小的候选先移出 R，平局按倾向 ID；证据仍在 H，重算得到相同结果）；单组强度不超过 w_max。
- 有限 binary64，固定的求和次序；NaN、Inf 与溢出是显式故障。

  - **EV9：** 可核实的取值来自 P5-06 的属性。
  - **EV10：** 只用 a(e)，从不读 x。

### 背景
- 现在 R 的变化率 ĥ 由「正反翻转的频率」估计。一种行为长期一致以后，ĥ 被估得很小，连续几次反例要很久才让旧倾向让位。人的直觉正相反：越稳定的习惯，一旦断了越显眼。
- Claude 的简化估算（单个倾向，P=0，c=4，h₀=0.1，n_h=10；不是参考实现）：你每晚都来 1 年、3 年后不再来，π 跌破 1/2 要 53、159 晚（旧形式），72、214 晚（ADR 0019 候选 B）。
- 换用贝叶斯在线变点检测（Bernoulli、Beta(1,1) 先验、风险率 1/1000），对「今晚会来」的预测在断的第 2、3 晚已降到约 0.5、0.4，与习惯长短几乎无关；断三晚后回来，预测回升到 0.50、0.57、0.63。

### 交付物
1. **写法：** 至少比较三种 h：现有的翻转频率；变点检测给出的「本组之前已经变化」的后验概率；ADR 0014 提到的模型混合。每种写法都写明状态有多大、怎样确定性地裁剪（I23）、binary64 的计算次序（ADR 0019 第 8 节）。
2. **性质：** 每种写法接入 ADR 0019 候选 B 后，LP1–LP8、I23、I25 的检查仍然通过；LP4（h 越大旧证据让位越快）照原判据检查；推论 1、2、3、5、7 逐条说明有没有变化。
3. **情景：** 用固定种子跑 P5-30 追加说明里的生活情景和 E2 的四种世界。报告：断了以后第几次察觉（预测跌破 0.5，以及 π 跌破 1/2）；回来以后多快恢复；稳定但有噪声的世界里误翻转多少次。只报告，不设门槛。
4. **缺席怎样成为事件（交给用户决定）：** 推论 5 规定没有事件就什么都不变。整理选项，各写清楚由哪个部件产生、对上面情景的影响：（a）主动调度在预期时刻检查，记一条「预期没有发生」的观察；（b）你回来时由解释记录从间隔推断；（c）缺席不算事件。
5. **结论：** 推荐一种写法或维持现状，附理由；推荐新写法时起草 ADR，按 v2.0 第 0 节第 4 条作为新规律版本。
