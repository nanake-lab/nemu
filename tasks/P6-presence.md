# P6 在场：任务层、终端、说话模式、助手、桌面与网络生活（第 10–24 周）

出口条件分三步：

- **N2 她在了（排练版，2027-01-17）：** P6-01、P6-02、P6-04、P6-10 完成，你在 P6-12 评审后开始每天使用。
- **N3 诞生（2027-03-07）：** 除网络生活以外的其余各卡完成，你在 P6-13 执行诞生。
- **N4 发布（2027-04-04）：** 网络生活（P6-14、P6-15）完成。它在诞生之后才打开，什么时候打开由你决定（ADR 0011）。

这一阶段把核心、身体、声音、助手接成一个整体。原则不变：

- 她说什么、做什么、什么时候主动，由 Echo Core 决定；
- 终端只上报发生了什么、执行核心的请求；
- 模型只能看到 o、p、c_task，以及 m 或它的投影；
- 她是谁不写成文字：协议 p 只含关于她的事实、你的边界、输出格式与语言规则（v2.0 第 2.3 节、I28）。

改动 `core/`、`workers/`、`executors/` 的卡，先读 `.agents/skills/echo-core-work/SKILL.md`。所有测试都用临时存储，不得打开你的排练存储或她的正式存储（AGENTS.md 黄金规则 14）。

## P6-01 任务层与协议 p v0（W21）

- **建议执行者：** Codex
- **难度：** 中
- **里程碑：** N2 她在了（排练版）
- **依赖：** P5-04、P5-05、P5-14、P2-01
- **工期：** 6 天
- **分支：** `task/P6-01-task-layer`
- **目录：** `core/crates/task-layer/`、`content/_candidates/core/protocol/`
- **必读：** 总方案第 11、12、20 节；《核心算子》第 3、12 节；v0.6.4 第 10 节；v2.0 第 2.3、9.4、10 节；ADR 0003、ADR 0005、ADR 0010；CONTRACTS.md 第 3、5 节

### 交付物
- **TaskInput 装配：**
  - o、p、c_task、快照 id、最大 token 数与最长时长；
  - 四个输入域分开（总方案第 11 节）：从历史里检索到的文字只是 c_task 里的数据，永远不会变成协议。
- **协议 p：**
  - 加载器：带版本，读 `content/nemu/core/protocol/`；定稿之前读 `content/_candidates/` 里的草稿，并在运行状态里标出「协议草稿」；
  - p 改变时更新 Q 中的运行绑定，使不兼容的计划失效，不直接改变 F、G、C、J；
  - **p v0 草稿：** 起草三种语言的 p v0，只包括：
    - 关于她的事实：名字、她是什么（运行在你电脑上的 AI）、你是谁、她能用的工具，取自设定集（`content/nemu/bible/`）；
    - 你的边界与诚实底线（v2.0 第 10 节）；
    - 表演提示语法（CONTRACTS.md 3.4）；
    - 语言规则：用你使用的语言回答。

    不写说话风格、自称、怎么称呼你、性格或喜好：这些由 m 表达，从她的经历中长出来（v2.0 第 2.3 节、I28）。
- **生成接口：** `generate(TaskInput, ModulationEnvelope) → PlanAndCarrierReceipt`（CONTRACTS.md 5.1）。
  - 生成器注册：本卡带一个脚本化测试生成器；模式 A、B、C 的生成器由 P6-03、P6-04、P6-05 注册；
  - m 提供者接口：本卡只实现 m = 0 提供者（原因码 `MODULATION_NOT_ENABLED`）。真实的 J 由 P6-03 接上；
  - 回执完整记录：模式、严格与否、模型版本、载体回执或投影版本、用量。
- **主动时机**（v2.0 第 9.4 节）：调度触发时（P5-20），任务层把「主动时机」作为 o 交给生成。模型在 m 下按当时的情境提出一个行动（限于主动边界表允许的种类），也可以什么都不做。
- **从计划到行动：**
  - 输出块随说话行动发出（P5-14）；
  - 可选的行动计划（身体动作、助手请求）转成行动请求，经权限门（P5-05）。
- **并发：** 生成过程中来了新观察时，旧计划失效，所有观察都保留，下一次生成使用实际生成时刻的投影（SYS08）。
- **只读查询：** 处理终端的 `query`（CONTRACTS.md 4.3）：`memory`、`actions`、`run_history`，用途 `user_view`，留审计。
- **运行状态：** 汇总 Q 的运行状态、谱系、说话模式、自主行动开关，变化时推送。

### 验收
- X01、SYS06：固定时间与事实，只改变 p 或 c_task，核心没有额外的直接变化。
- SYS08、SYS13：流式输出中断后保留已发出的块，不假装撤回，重放时不重发。
- SYS14（任务部分）：IRL 或模型不可用时，明确以 m = 0 响应，回执写明原因。
- 查询测试：三种查询各自返回正确内容；五种结果状态各有用例。
- `content/_candidates/core/protocol/` 下有三种语言的 p v0。
- I28：p v0 只有事实、边界、表演提示语法与语言规则四类内容（静态检查，加上你的阅读）。
- 主动时机：生成器提出「不做」时不产生行动；提出的行动不在允许的种类里时被拒绝。
- [ ] 你在 N2（P6-12）读 p v0，签字或写下修改（阻塞：p v0 定稿）。

## P6-02 终端客户端与身体接入

- **建议执行者：** Codex
- **难度：** 中
- **里程碑：** N2 她在了（排练版）
- **依赖：** P5-03、P4-06、P3-04、P6-01
- **工期：** 6 天
- **分支：** `task/P6-02-terminal`
- **目录：** `packages/terminal/`、`apps/desktop/src/terminal/`
- **必读：** CONTRACTS.md 第 2、4 节；v0.6.4 第 19.2 节；总方案第 9 节；ADR 0005

### 目标
主进程持有唯一的核心连接。它把应用内发生的事如实报告给核心，把核心的输出和请求交给声音和身体，并把执行结果报告回去。终端是所有观察事件的唯一入口：桌面感知（P6-08）、Codex 会话感知（P6-11）、面板（P6-10）都只在应用内总线上发事件，由本卡统一转换。

### 交付物
- **连接：**
  - 命名管道客户端，终端令牌认证（P5-03）；断线后带退避重连；
  - 核心不可用时进入「身体在场」：身体使用中性读出，只保留反射，面板显示原因；核心恢复后自动回到正常。
- **观察转换**（CONTRACTS.md 4.1 → 4.2）：

  | 应用内总线事件 | 观察事件 |
  | --- | --- |
  | `voice.recognized` | `user_utterance` |
  | `chat.send` | `user_text` |
  | `stage.hit`、`stage.drag` | `touch`：拍、甩的判定阈值固定并带版本 |
  | `desktop.observation` | `desktop`：`title` 只在 T1 授权后填写 |
  | `codex.session` | `codex_session` |
  | `memory.retract` | `user_retraction` |
  | 应用启动、退出、切换模式、时钟纪元 | `maintenance` |

- **发件箱：**
  - 只保存还没收到 `RECEIVED_DURABLE` 的事件，重发时复用原来的 `stable_source_key`；
  - 收到回执即删除；
  - 不保存任何其他内容（I18）。
- **入站：**
  - `output.chunk`、`output.end` → 语音输出管线（P4-06）；
  - `action.request` → 检查凭证没有过期 → `stage.action`；`stage.actionResult` → `body_action` 执行结果；
  - P4-06 的投递结果 → `speech_delivery` 执行结果；
  - `approval.request` ↔ 应用内总线 ↔ `approval.decision`；
  - `run_state` → `core.runState`；`readout` → `stage.readout`；
  - `core.query` ↔ `query` / `query.result`。
- **打断：** `voice.bargeIn` → 发送 `output.cancel`，随后补发实际投递结果。
- **延迟打点：** `received`、`committed`、`firstChunk`，汇总进 `metrics.latency`。

### 验收
- 端到端（临时排练存储 + 脚本化生成器）：说一句话 → 观察 → 提交 → 输出块 → 声音与口型 → `speech_delivery` 回写。重复 20 次，0 丢失。
- 断线：核心在提交前崩溃并重启，未确认的观察按原来的 key 重发，被 Γ 精确去重（SYS01 联测）。
- 打断：完成标准第 9 项的端到端测试。
- 核心不可用 → 3 秒内进入身体在场，恢复后自动重连。
- 结构检查：终端里没有以情绪、心情、好感命名的持久变量；发件箱里只有未确认的事件。

### 交付物
- **开关：** 只在正式谱系里存在，默认关闭，由你打开；打开即完全打开，不分阶段、不限平台（ADR 0011 第 1 条）。排练谱系没有网络生活；实验谱系只能连合成的社交世界，不连真实平台。
- **身份：** 她以 Nemu 的身份说话，从不冒充你。她自己的消息是 `social.message`（默认 T2，你可以设为信任）。发出前在 m = 0 下判定这条消息会不会让你承担什么（约定、付款、代表你表态）：会，或者判定不了，就按 `social.commit` 走 T3 审批（ADR 0011 第 3、10 条）。

  - 你的信息默认私密，你允许公开的类别除外；类别表由你设定；
  - 结构隔离：她对外交往时，任务层的 c_task 只含可公开的类别，你的秘密、密码和文件不在她的输入里；对外行动没有读取你的文件的能力；

- **保险丝：** 每天新认识的人数和发出的消息数有上限，由你设定；初值写进 genesis，之后每次调整作为事件记入 H（v2.0 第 16 节）。
