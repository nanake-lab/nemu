# P2 角色资产 V1（第 1–8 周，与 P1、P3 并行）

出口条件（N1 认得出是她，2026-12-13）：Nemu V1 在舞台上站着，有待机生命感；`asset-lint` 0 错误；「认得出是她」清单由你签字。

外观的标准是「认得出是她、动起来可信」，不追求和原画一模一样（ADR 0002）。美术判断全部由你做。代理只做三件事：生成候选、执行可重复的脚本、截图给你看。整个阶段不安排任何手绘或手工修图：贴图修整用 krita-ai-diffusion 局部重绘（框选、写提示、挑结果）或脚本完成。

时间安排：
- 设定集与人设种子在第 1 周；
- VRoid 塑形在第 2–4 周（每周约 4–6 小时）；
- 尾巴和表情的调校用 VRoid 的中期导出版本提前开始，不必等塑形全部完成；
- N1 评审在第 8 周。

## P2-01 设定集与人设种子（Nemu Bible）

- **负责：** 你主导；Antigravity 负责整理和一致性检查
- **依赖：** 无（第 1 周开始）
- **工期：** 3–5 天（你约 5 小时：约 3 小时在图像工具里生成候选并挑选，约 2 小时写人设种子；整理由代理完成）

### 目标
把你的原版彩色立绘扩展成一套够用的外观设定，并写下她是谁的「种子」。外观设定是 3D 工作的参照；人设种子是协议 p 和 genesis 校准（P5-17）的起点。

### 交付物（`content/nemu/bible/`）
- `00-original.png`：原版彩色立绘（不改动）。
- `01-turnaround-front.png`、`-side.png`、`-back.png`：三视图。用你常用的图像模型（例如你之前用的 image2.5），以原画为参考生成，A 字站姿，同一比例。每个视图生成 4–6 张候选，你选一张。
- `02-expressions.png`：12 种表情，与 CONTRACTS.md 的 `Emotion` 一一对应：平静（neutral）、开心（happy）、放松（relaxed）、生气（angry）、难过（sad）、惊讶（surprised）、得意（smug）、害羞（shy）、困倦（sleepy）、嘟嘴（pout）、兴奋（excited）、担心（worried）。这是她的表达词汇，不是她的情绪状态。
- `03-palette.json`：主要颜色的色号，至少包括发色（亮部、暗部）、瞳色、肤色、奶油色、薄荷绿、描边色。
- `04-proportions.md`：头身比、身高（设定值）、耳朵和尾巴相对头部与身高的比例。
- `05-outfit.md`：服装拆解（每件衣服的结构、材质感、装饰），配局部特写图。
- `06-persona-seed.md`（你来写，代理可以提问帮你整理）：
  - 用你自己的话写她是谁，几段即可；
  - 她和你的关系；
  - 中、英、日三种语言里她怎么说话：自称、怎么称呼你、语气、礼貌程度；
  - 喜欢和讨厌的东西；
  - 她绝对不会做的事。
- `07-genesis-notes.md`：代理根据人设种子提出 15–20 组「对照情境」，你为每组选一边或写下自己的版本，作为 P5-17 校准她初始倾向的材料。每组形如「被甩出去之后：会嘟囔一句 / 当作没发生」。
- `index.md`：Antigravity 把以上内容整理成一页，标出图与图之间不一致的地方（比如三视图之间裙长不同）。

### 验收（你签字）
- [ ] 三视图与原画的脸、发型、配色一致
- [ ] 三视图之间比例一致
- [ ] 表情表的 12 种表情都像 Nemu
- [ ] 色板颜色从原画取得，而不是生成图
- [ ] 人设种子和对照情境读起来就是你心目中的 Nemu

> **2026-10-20 追加（v2.0）：** 按 v2.0 第 2.3 节与 I28，她的性格、说话方式、喜好和初始倾向都从诞生后的经历中长出来，不写成文字。所以 `06-persona-seed.md` 与 `07-genesis-notes.md` 不再进入协议 p 和 genesis（P6-01、P5-17）。协议 p 只从设定集里取关于她的事实（名字、她是什么）；你的边界可以在 P6-12 读 p v0 时补充。外观部分照常是 3D 工作的参照，人设种子也照常是声音设计（P4-03）的参考：外观和声音属于她的身体，不属于她是谁。两份文件作为你的设计记录保留。

## P2-03 Blender 无头资产管线

- **建议执行者：** Codex
- **难度：** 中
- **里程碑：** N1 认得出是她
- **依赖：** P0-05 第二部分（Blender 已装好）、P2-04（校验器）
- **工期：** 5 天
- **分支：** `task/P2-03-asset-pipeline`
- **目录：** `tools/asset-pipeline`
- **必读：** `.agents/skills/blender-headless/SKILL.md`

### 目标
一条命令把 VRoid 导出的 VRM 加工成符合资产契约的 `nemu.vrm`，可重复执行，结果确定。

### 交付物
- `blender-version.txt`：锁定的 Blender 版本。
- `run.ps1` / `pnpm asset:build`：读取 `content/nemu/build.yaml`，依次执行以下步骤，每步之间保存中间 `.blend`（放在 `.cache/`，不提交）：
  1. `import_vrm.py`：导入，检查 VRM Add-on 版本。
  2. `validate_source.py`：检查源模型的骨骼、表情、材质，提前报出问题。
  3. `build_tail.py`：按 `build.yaml` 的尾巴参数（长度、粗细曲线、截面、颜色、尾尖形状）用曲线生成网格和 UV，生成 ≥ 8 节骨链，自动权重，材质沿用头发材质参数。
  4. `springs.py`：按 `build.yaml` 配置头发、耳朵、尾巴、裙摆的弹簧骨和碰撞体组。
  5. `expressions.py`：生成 Nemu 自定义表情（形态键组合、材质颜色绑定、贴图变换绑定）；设置预设表情的覆盖规则。
  6. `materials.py`：按 `build.yaml` 的 MToon 预设统一材质参数。
  7. `textures.py`：贴图缩放到 ≤ 2048，去除未使用的贴图。
  8. `export_vrm.py`：导出 VRM 1.0，写入 meta。
  9. `profile.py`：生成 `nemu.profile.json`——身高、头顶偏移、骨骼名从模型实测，其余字段（命中区域、机位、视线限制、耳朵与尾巴参数、`emotionMap`、`idleSet`、三种语言的口型档案路径）从 `build.yaml` 读取。按 CONTRACTS.md 1.6 的 v2 格式输出。
  10. 调用 `pnpm asset:lint`（含 profile 校验）。
- `build.yaml` 的 schema（JSON Schema）和一份带注释的样例。
- `tools/texture-fix/`：贴图的简单脚本处理（边缘透明扩展、按色板统一颜色、去除杂色），供 P2-02 使用，免去手工修图。
- `docs/SETUP.md` 中的「VRoid 导出设置」：列出 P2-02 导出时每个选项该怎么选，以满足资产契约的预算（例如材质合并到 12 个以内），并说明理由。
- 无 Blender 的单元测试：解析配置、计算骨链等纯 Python 逻辑。

### 验收
- 用 three-vrm 示例 VRM 跑通整条管线。产物的 `asset-lint` 结果中，除依赖角色本身的规则（猫耳弹簧链、头发链数等示例模型没有的部位）以外 0 错误；这些规则在 P2-05 用 Nemu 的中期导出版本验收。
- 幂等：连续运行两次，产物除时间戳外的 glTF JSON 部分完全相同（报告里附 diff 结果）。
- 每一步都有日志，失败时给出可读的原因和出问题的对象名。

### 禁止
- 不要在管线里做任何「审美」调整（比如自己决定颜色或形状）；所有可调参数都来自 `build.yaml`。
