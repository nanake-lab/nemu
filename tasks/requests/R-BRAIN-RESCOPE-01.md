# R-BRAIN-RESCOPE-01：按「核心管什么、模型管什么」重新定 R-BRAIN 的题

## 你要做什么
只做设计分析，不写代码，不训练。交一份报告，开 draft PR，标 needs-user，不合并。

## 为什么要重新定题
R-BRAIN-01（PR #210）的 A1 世界，让本地 4B 模型看对方的接触记录，从「联系 / 等待 / 询问 / 做自己的事」四个行动里选一个。试点跑了几轮，结果如下：

| 轮次 | 设置 | H0 翻转率（历史换成相反后，选择是否跟着翻） |
| --- | --- | --- |
| 第一轮 | 3 条历史，DPO，lr 5e-6，训 1 遍 | 训练前 0% → 训练后 41% |
| 第二轮 | 4 条历史，堵掉关键句捷径 | 训练前 0.8% → 训练后 1.6% |
| probe-v1 | 第一轮的 adapter 拿去做第二轮的题 | 3% |
| core 臂 | 只把与当前时刻相同的两条经历交给模型，不训练 | 18.8% |

从这些结果看：
- 第一轮学到的是「认关键句」，不是「对上时间」。
- 4B 不开思考时，学不会「拿当前时刻对历史时刻」这种两步推理。
- 就算由核心把相关经历挑好交给它，它也基本不会据此行动。

但真正的问题不在模型。按现有架构，A1 考的这两件事本来都该由核心做：
- **什么时候动手、动不动手**：自主调度管。行动强度是「乎」的固定读出，乘以权限、勿扰、预算、最小间隔这些闸门（ARCHITECTURE「自主调度」；v2.0 §9.4）。
- **找出与当前情境吻合的经历**：情境匹配 M、倾向 R、来由投影都在核心里（ADR 0042：核心挑真实经历，把原话交给模型）。

所以 A1 一直在训练模型去做核心本来就做的事。另外，只看 A1 这道题，它其实就是一个条件反射；一个很小的分类器，甚至核心自己的 R，就能做好，用不着 4B。

## 第 0 步：先调研，再设计（必做）
已有研究和社区结果能回答的问题，一律引用，不安排实验。先系统地查一遍论文、GitHub 和社区（LocalLLaMA、Hugging Face 模型卡与讨论区等），回答下面几个问题，每条结论都附链接和日期：
- 1B–9B 模型不经训练时，能不能按给定的上下文和证据做决策？在哪些情况下会忽略上下文、坚持自己的先验，或者被话语压力带偏？
- 小模型经过微调后，能在哪类代理子任务上可靠：工具调用、路由、分类、结构化抽取、行动选择？各需要多少数据？用的是 SFT 还是偏好训练？
- 社区普遍认为哪些事情小模型做不好？例如新情况、多步规划、开放式提出行动。混合路由（小模型做固定子任务，大模型做新情况）的实际效果如何？
- 主动性：什么时候该主动去找人，现有工作是怎么学的？（例如 ProactiveBench 用人的接受/拒绝训练奖励模型。注意这类以用户满意为奖励的做法，与 Nemu「好坏只从她自己的乎来」的原则冲突，引用时要写明这一点。）
- 「同一份材料，不同 LLM 抽出的事实不一样」这类解释漂移，有没有用固定的本地抽取模型来压低的先例，效果如何？

第 0 步的结论，决定 Q2 里哪些探针还有必要做。

## 要回答的问题

### Q1：行动链上，每一个决定归谁
把「她做一件事」从头到尾拆成步骤，例如：要不要动、什么时候动、关注什么、找哪些经历、提出哪些候选行动、在候选之间怎么选、具体说什么怎么做、执行、记录结果。逐步写清楚：
- 归核心还是归模型；
- 依据哪份文件的哪一节。

文件之间要是说法不一致、或者没写清，就单独列出来，写明各自的原文，不要自己替它们统一。例如 ARCHITECTURE 说「什么时候动手」由核心的自主调度决定，而 ADR 0042 的 U5 写的是「本地模型负责独处思考与行动选择」。

### Q2：模型那一侧的每项本事，4B 现在有没有
对 Q1 里归模型的每一项本事，先看第 0 步能不能直接给出答案。只有第 0 步答不了、而且是 Nemu 特有的问题，才设计一个**只评估、不训练**的最小探针：
- 输入要用核心实际会交给模型的格式（按 ADR 0042 挑过的经历原文，加上当前事实和允许的行动），不能是一堆没整理过的原始记录。
- 每个探针都要配一个防捷径的对照，比如历史互换、换说法、换名字。
- 写清楚预计的规模和耗时。原则是十几分钟能跑完，量够得出结论就行。

先测，再决定要不要练。已经有的本事，不练。

### Q3：要练的，题怎么出
对 Q2 中可能需要训练的本事，给出最小的世界设计。要求：
- **核心替代不了。** 题目必须依赖语言理解、开放的行动提出，或者把多条线索合在一起，确保核心的 R 和 M、或者一个小分类器做不到。逐题说明为什么替代不了。
- **标签不手写。** 脚本只产出事实 z，由核心按 #212 Q5 那种试点 A 算出 a，再按四乎严格帕累托生成偏好对。全部标明「试点用，不是她的天性定稿」。
- **自带防捷径的设计**，并写明每道题最可能被钻的空子。
- 只写所有 Nemu 都用得上的本事，不写任何关于特定的人的知识。

### Q3.5：本地模型的角色候选
根据第 0 步和 Q1 的结果，列出本地 4B 可能承担的角色，逐个评估。至少评估下面两个候选，你发现的其他候选也加进来：
- **候选甲：独处思考与行动选择**（ADR 0042 U5 现在的设定）。如果第 0 步显示小模型在新情况和开放式提出行动上普遍不可靠，就写明这个角色的风险。
- **候选乙：IRL 事实抽取**，即从材料里抽出事实 z。这是固定格式、反复出现、所有 Nemu 都用得上的抽取任务，正是社区认为小模型微调后最可靠的那一类；而且由一个固定的本地模型来做，可能压低 #212 Q4 里说的换模型漂移。评估它跟「LLM 不打分、只给事实」的分工是否一致，代价和风险分别是什么。
两个都标为候选，不替用户选。

### Q4：每项本事，用什么部件最省
对每项本事，比较这几种部件：核心规则或核心已有的学习、小型专用模型、本地 4B（不训练）、本地 4B 加 LoRA、云端 LLM。写清楚哪个是够用且最省的，理由是什么。

已有研究能回答的问题直接引用研究，不安排实验去重跑。例如：SFT 的信号比 DPO 强；小模型不思考时做不好多步推理；模型容易钻捷径。

## 约束
- 每个新增的量、规则、世界，都要过三问：能不能不加；一个人会怎样；加了以后什么改不掉。
- 不改核心的规律，不改规格或 ADR。分工上发现的冲突只列出来，由用户决定。
- 需要用户拍板的地方，写成「候选」，单列一节，每项写清选项和各自的后果。
- 结论用白话写，数字能说明的不加免责句。
