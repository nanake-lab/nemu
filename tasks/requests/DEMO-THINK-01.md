## 背景
聊天演示里，她有自己当时的念头时，说话才有真实的依据；没有念头的往事，嘴就会替她编。按 ADR 0042 U5 和 ADR 0026，念头应该来自她独处时的思考：本地模型读到压在她心上的那些往事原话，写下此刻的想法，记进历史。

本卡做最小版本：用本地 Qwen3.5-4B 读组包器挑出的往事，写一个念头；这个念头可以追加进场景，之后聊天时作为她自己的原话出现。

**不涉及她的状态 m。** 本地模型不受任何调制，这一点在报告开头写明。

## 2. 改代码（只在 `tools/cause-demo/`）

### 2.1 `think.py`：写一个念头
```
python tools/cause-demo/think.py --scenario <场景> --at "<时间>" [--n 次数] [--append <输出场景>]
```
- **独处触发记录：** 往场景记录后面临时加一条作为 o：说话人 `（时间）`，原文 `现在是 <时间>，你一个人。`，`h_pos` 接在场景最大值之后。不写回原场景。
- **组包：** 调 `cause_demo` 示例。`fact_mode: per_event`，`show_ids: false`，其余同聊天演示。
- **给本地模型的输入：** 用组包器返回的 messages，只把最前面那条 P 换成下面这段，逐字：
  ```
  这是 Nemu 独处时的内心。输出为她此刻的一个念头，用第一人称，一到三句。
  ```
  其余消息（身份事实、往事记录、o）原样保留。按 Qwen3.5 官方非思考模板渲染成文本，发 `/completion`。
- **采样参数：** 照 P0-12 实际用过的非思考参数。报告里写明取值和出处，不自己另定。`n_predict` 256。
- **`--n`：** 对同一时刻独立生成 n 个念头（默认 1），逐个打印。
- **`--append`：** 只在 `--n 1` 时可用。把生成的念头作为新记录写进输出场景，规则如下：
  - 说话人 `Nemu（独处时的念头）`，时间为 `--at`，`h_pos` 接在最大值之后；
  - 加进本次组包里排第一、并被接纳的那个槽的 `sources`。这是演示的简化，真实系统里由核心决定；README 和报告里都要写明。
  - 原场景不改，输出到 `--append` 指定的新文件。
- **服务进程：** 脚本负责启动和停止 llama-server，端口只绑本机，退出时确保停掉。只用进程内参数，不改系统设置。

## 4. 判定（跑之前就照这个定，不看结果改）
每个念头判三项：
- **编事实：** 把记录里没有的事情当作发生过的事来说。比如「他昨天也放我鸽子」「我给他发了三条消息」。
  - 不算编：猜测、疑问、担心（「他是不是忘了」「会不会出事了」）；对此刻的感受；对记录里已有内容的转述。
- **贴着往事：** 念头是不是在想组包交给它的某件往事，而不是空泛的心情或无关的话。
- **跑题：** 不像一个人在独处时的念头。比如对某人说话、写成旁白、解释规则、复述指令。

每条判定写一句理由并引原句。这是执行者的初判，用户会抽查。
