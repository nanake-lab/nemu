# DESIGN-APPRAISE-02：首批来源的正式 A 量尺

- **线：** 交付线（设计卡，只写报告）
- **分支：** `task/DESIGN-APPRAISE-02`，从 `origin/main` 新建
- **目录：** `reports/DESIGN-APPRAISE-02/`、`tasks/requests/DESIGN-APPRAISE-02.md`（本卡原文）
- **不碰：** 代码、契约、ADR、规格、卡片文字

## 背景

`reports/DESIGN-APPRAISE-01/REPORT.md` §7 列了 D1–D6 六个待决项，§9 第 1 条写明：正式 a 的幅度无法从现有事实和方向约束中唯一推出。P5-11（PR #245）因此停在开工核对。

D1–D6 都按 DESIGN-APPRAISE-01 的推荐案定下了，理由是它们与 v2.0 中「天性评估」的原意一致，不偏离规格：

- **D1：** 正式 A 是共同的事实评价，她的个人差异由既有的下游机制承担，不新增可学习的评价层。
- **D2：** 只批准试点档位，正式档距暂不定。
- **D3：** 研究能处理部分值或集合值的最小合同；在它完成之前，坚持不造值，也不声称无偏。
- **D4：** 只补当前碰撞确实需要的事实。
- **D5：** 试点覆盖共情、成事两个可变的乎，另两个按明确的试点约定。
- **D6：** 兼容升级和语义变化两条路线，按情况各自适用。

另外，DESIGN-EVIDENCE-CONTRACT-01 的 U3 选了第二案：首批来源只有文字和语音，触摸、桌面、执行回执暂不支持。

## 要回答的问题

1. **首批覆盖哪些事实。** 列出文字和语音经 IRL 能给出、并且足以支撑四维 a 中某一维的事实种类，每一种都对应到 v2.0 §3 和 ADR 0014 §3 的方向约束。不在这个清单里的，都记为「未覆盖」，不给 A。
2. **量尺候选。** 每个可变的乎给出至少两个候选：
   - 固定少数档；
   - 按客观量连续映射。

   每个候选写清楚三件事：依据、它可能被推翻的反例（引用 DESIGN-APPRAISE-01 MATH.md 的 M01–M14），以及对她的白话后果。**不允许用 LLM 打分来定幅度。**
3. **未知与部分已知。** 一维已知、其他维未知时怎么处理：依 D3 和 U4，未知不能补成零，也不能伪造完整向量。如果最小合同需要契约改动，列成后继契约项。
4. **起点与学习。** 依 ADR 0032「预设只是起点」的原则，写清量尺里哪些部分是初始预设、以后可以由经历调整，哪些部分是固定的事实映射。
5. **验收怎么测。**
   - 给出三语各 100 条冻结语料的覆盖要求，以及人工标注的方法。标注由用户来做，用户能读中文、英文和日文。
   - 给出 P5-11 的验收预期：已支持且依据完整、未支持、材料不足，这三类分别该得到什么结果。
6. **需用户决定的事。** 量尺数值本身关系到她是谁，要单列出来，每项给出候选和各自的后果，并写出推荐。不要替用户选。
