# P5-23：V2-80/105 容量输入与通知的后续接线请求

2026-10-29；对应 PR #49。请求原因：本卡仅可修改 `core/crates/core-kernel/src/law/`，而已发布的 `FuseConfig` 只有 `r_capacity`，没有 K；V3 R/q/V 也不携带候选提出次序。本卡不越界增添契约字段、运行时状态或终端事件。

## 本卡已提供的纯函数接口

- `LawContext.protected_candidates`：调用方显式传入当前 K。V2-80 的初始配置为 1；不把 K 写死在规律内，也不从 R 推断。
- `Step.proposal_order`：调用方从有效 H 提供规范倾向身份的提出次序（旧到新、身份唯一）；包含本事件。G 只在当前候选中取最后 K 个，缺项或重复时拒绝执行需要该次序的容量选择，不拿 ID 大小、N 或内存中的缓存猜新旧。
- `Output.capacity_notice`：暂存容量、保留数量、K 和暂缓进入 R 的规范候选身份，供外层事务成功后通知 u*。G 继续返回已有倾向按本事件证据更新的 R/L；无 `CapacityExhausted`、无成长暂停位、无持久的候选等候队列。
- 状态只使用 P5-34 生成的 `RSnapshotV3`、`TendencyV3`、`EvidenceGroupV3`、`EvidenceAllocationV3`。G 不访问存储。

## 请求所属卡接续

1. **边界配置/契约所属卡、P5-29**：按 V2-100 为 K 选择唯一的权威配置位置；容量/K 的初值来自 genesis，后续调整作为事件进入 H。需要 IDL 修改时按契约变更流程另行实施，不能给旧 `FuseConfig` 私加字段。本请求不替该卡决定消息格式。
2. **P5-24、P5-26、P5-29**：从同一有效 H 构造完整、确定的规范候选次序和 EV5 证据输入；包括容量调整、被拒收/移出后重新提出、结构关系与别名规范化。重放沿用已记录的提交/记录次序，不能读取当前时钟或把提出次序另存为影响行为的隐藏状态。别名不能制造新身份来占用保护名额；调用方遇到记录次序不足时应显式暴露接口缺口，不猜顺序。
3. **P5-29 及终端所属卡**：事务成功后处理容量通知，说明可调高容量或检查规律。不得把该通知映射为 `GROWTH_PAUSED`；被暂缓的候选仍留在 H，之后重新提出时收集全部有效历史证据。G 的通知本身不越过外层事务提交边界。
4. **P5-26**：真实有效 H 重放、V2→V3 迁移与失败回退/SYS17；不得默认 q=1 或 V=B−c。P5-23 的合成 H 与原生编码往返不替代该验收。

## 验收边界

以上属于卡上已分给证据组装、重算、编排和终端的接线工作，不是本卡纯 G 的实现阻塞。后续生产接入必须完成对应请求；本 PR 不宣称已实现通知 UI、完整 H 读取或数据迁移。本卡提供 K=1/K=2、容量调整、拒收/重提和两种 V3 编码后增量/整段逐位一致的合成回归供调用方对接。
