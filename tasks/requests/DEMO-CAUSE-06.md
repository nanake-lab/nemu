## 背景
DEMO-CAUSE-05 的两步法（列要点 → 代码核对 → 拼接）读着自然，但编造还会从两个口子漏出来：
- 标成 `now` 的要点其实在说过去，关键词检查漏了 15 条；
- `past_self` 引用对了，内容却加了记录里没有的举动（如「我就盯着时间」）。

代码查不了一句话的意思。本卡加一次模型核对，但只核对一句话对它引用的一两条记录，范围很窄。

**用户要求：** 有的话回答要快，有的话可以慢一些。所以只在说到她过去或现在的心情时才核对；纯事实、闲聊走快路，不核对。

## 1. 改代码（只改 `tools/cause-demo/`）

### 1.1 `plan_speak.py`：两步法加分路和意思核对
在 DEMO-CAUSE-05 的两步法（第一步列要点、代码核对，含 `now_refers_past` 和 `self_quote`）之后：

**分路（纯代码）：** 代码核对后保留的要点里：
- 没有 `past_self`，也没有 `now`：走**快路**，直接拼接成回答，不调模型；
- 否则走**慢路**，做下面的意思核对。

**意思核对（慢路才有，调 DeepSeek 一次）：**
- 只核对保留下来的 `past_self`、`now`、`past_event` 要点，`other` 不核对。
- 参数：`deepseek-flash`，思考关闭，`response_format: {"type":"json_object"}`，`max_tokens` 2048。
- 一次调用把所有要核对的要点一起发出。system 消息逐字如下：

```
你是核对员。下面每一条是 Nemu 要说的一句话，附有它引用的记录原文。逐条判断，只输出 JSON：
{"verdicts":[{"i":序号,"extra":true或false,"why":"一句理由"}]}
判断标准：
- 类型 past_event：这句话有没有说出所引记录里没有的事实？有，extra 为 true。
- 类型 past_self：这句话有没有说出所引记录里没有的过去举动或事件？只是给记录里的念头加情绪色彩、换说法，不算。有新的举动或事件，extra 为 true。
- 类型 now：这句话有没有断言过去某个时刻她的感受、想法或举动，而不只是说现在？有，extra 为 true。
```

- user 消息：每条一段，格式为 `[序号] 类型：<type>\n话：<text>\n引用记录：<被引记录的原文，多条换行；now 写「无」>`。
- 记录原文只给场景里的 `text` 字段，不给时间和说话人。
- `extra` 为 true 的要点删除，原因记为 `verifier_extra`，`why` 原样保存。
- 核对调用失败、JSON 解析失败或缺少某条的判定：这一轮按技术无效记下，不重试，不放行。
- 删光时最终回答为 `这件事我没有留下记录。`

**拼接：** 同 DEMO-CAUSE-05，另修一处：前一条已以句末标点或句末标点加右引号（`。」` `！」` `？」` `…」`）结尾时，不再补「。」。若以「」」结尾而前面不是句末标点，在「」」后补「。」。

`chat.py` 加 `--plan3` 走本卡流程。`/show` 显示走了哪条路、核对员的原始 JSON 和删除原因。

### 1.2 单测
补上：
- 快路、慢路分路各一个用例；
- 核对结果 `extra` 为 true 时删、为 false 时留，各一个用例；
- 核对 JSON 缺少某条时记为技术无效，一个用例；
- 拼接遇到右引号的两种情况，各一个用例。

核对调用用假的返回值，不调真 API。
