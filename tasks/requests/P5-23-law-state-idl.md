# P5-23 契约请求：G 需要的 R 存储字段

## 原因

P5-23 实现规律引擎 G。v2.0 第 5.2 节和本卡的规范定义（`docs/traceability/P5-23.md` 第 1 节）需要的两类状态，P5-21 的 IDL（`core/contracts/law.proto`，V2-34）里没有。本卡的「目录」只有 `core/crates/core-kernel/src/law/`，按 AGENTS.md 第 2 节与黄金规则 2，不能在 `core/contracts/` 之外另定义持久的类型，也不能改契约。

1. **典型幅度 r_k 的递推状态。** r_k 是 k 的全部吻合组中 p_c 的加权平均，权重 ω·μ（v2.0 第 5.2 节）。ω 每来一组关于 k 的证据就乘一次 ρ_k，所以逐组更新要存分子 Σω·μ·p_c 与分母 Σω·μ：

   ```
   M ← ρ·M + μ·p_c,  U ← ρ·U + μ,  r = clip(M/U, 0, r_max)
   ```

   `Tendency` 只存截断后的 `typical_magnitude`，截断丢掉了符号，也没有分母，所以无法继续递推。r̃_k 进入每一组的支持 S 与强度，最普通的一组证据也需要它。

2. **改写旧分配时的重放数据。** 三种情况要改已经记入的旧分配 (c, j)：
   - 新候选按 EV5 回溯收集到的旧组：v2.0 写明「其他倾向已记入的份额相应调整」（LP2、I25）；
   - 后来加入组的成员：组的均值变了，S、强度随之改变（V2-39）；
   - 容量移出一个倾向后，同一边的其他倾向收回份额，否则 I25「每一边之和为 1」不成立（V2-43）。

   改 (c, j) 的贡献需要它此刻的新近权重 ω_{c,j}，即 c 之后 j 的每一组的 ρ_j 之积。`EvidenceAllocation` 只有 support、intensity、share，证据组也没有次序，所以算不出 ω，也不能按次序重放 j 的递推。

## 期望接口（建议方案 a）

另开一张标注「契约变更」的卡和 ADR，PR 标 `needs-user`。按 ADR 0007 只增不改，以后继消息实现（V2-35 的做法）：

| 消息 | 新增字段 | 类型与约束 | 用途 |
| --- | --- | --- | --- |
| `Tendency` 的后继 | `magnitude_sum` | double，有限 | Σ ω·μ·p_c |
| | `magnitude_weight` | double，≥ 0 | Σ ω·μ；r_k = clip(sum/weight, 0, r_max)，weight = 0 时 r_k = 0 |
| `EvidenceAllocation` 的后继 | `ordinal` | uint64 | 这一组是该倾向的第几组（从 0 起）；建立后不变 |
| | `mu` | double，[0, 1] | μ_{c,k} |
| | `projection` | double，可缺省 | p_c = ⟨Δ_c, d_k⟩；教导组缺省（不进入 r_k） |

语义检查（`core-types/src/semantic.rs`）：一个倾向的分配序号正好是 0…N_k − 1；`magnitude_weight = 0` 时 `magnitude_sum = 0`。

有了这些字段，改旧分配时 G 从初值出发、按序号重放这个倾向的递推（`P5-23.md` D5）。值没变时重放与原值逐位相同，增量与整段重算一致（I23）。

## 备选

- **（b）每个分配存当前的 ω，每来一组就更新。** 字段少一些，但每来一组都要重写这个倾向的全部旧组对象。
- **（c）换一种不需要这些状态的参考写法。** 等于发布新规律版本（v2.0 第 0 节第 4 条），而且必须放弃回溯分摊或容量移出后的重新分摊，会违反 LP2、I25。

## 本卡的处理

在契约合并之前，本卡实现不依赖这两类状态的部分（单倾向的计数递推、支持与强度、份额、关系倾向的结构、保险丝的选择规则）和 LAW-1 至 LAW-10 的性质测试；被挡住的部分记在 `reports/P5-23/BLOCKED.md`。
