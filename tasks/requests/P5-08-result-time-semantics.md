# P5-08 请求：ADR 0032 D11 的时间语义

状态：**待后继设计**，不在本卡实现新的时间资格规则。

依据：ADR 0032 D11 已取代「结果超过 τ 就不再触动她」；D09/D10 已取消统一回落保证。旧 ADR 0026 / 旧算子中的对应读法不得作为运行时默认行为。

本卡保留 `EventEnvelope.event_time_ns`（事件发生时间）、`ingest_time_ns`（入口接收时间）与一次捕获的 `ProposalBindingV2.process_time_ns`，没有把 ingest_time 当作观察时间；commit completion 另取样但当前无权威持久化契约，见 runtime-publication 请求。队列延迟不会触发运行时的 τ 丢弃分支。

请后继设计明确：

- 发生、观察、接收、处理和提交各时间的含义、可信来源、缺失表示及可比范围；观察时间与发生时间的关联如何随事实保留。
- 结果迟到、停机期间发生、重放、补解释、修正事实分别如何进入她后来的体验；凭据/权限有效期与体验资格必须分别定义，不能凭借旧截止时间消除体验。
- 跨 boot/epoch 的映射、未知停机时长、重复与冲突观察的记录和恢复语义。
- 提供用户批准的可执行例子，再由契约与算子卡实现；不可把用户今晚未回复视为同意。

选项：沿用旧 τ 丢弃会违反 D11；立即另设窗口会代替用户决定。建议保留事实及时间、显式标记未知值，让后继设计定稿。本次采用这一保守边界；不增加任何定时强制平复规则。
