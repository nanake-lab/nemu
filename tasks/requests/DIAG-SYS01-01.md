# DIAG-SYS01-01：gateway SYS01 测试在 Windows 默认并发下超时

- **线：** 交付线（诊断，必要时修复）。
- **分支：** `task/DIAG-SYS01-01`，从 `origin/main` 新建。
- **目录：** `core/crates/gateway/src/tests/`；`reports/DIAG-SYS01-01/`；`tasks/requests/DIAG-SYS01-01.md`（本卡原文）。如果根因在测试目录之外，只诊断不修，把根因和建议的改动写进报告。
- **不碰：** 产品代码的行为、CI 配置、阈值和超时时长。

## 背景

在 Windows 上用 `cargo test -p gateway` 的默认并发跑时，SYS01 相关的测试（`src/tests/service/acceptance.rs`、`sys01_pipe`）会超时；单线程跑能过。main 上也能复现。

## 1. 复现

在本机 Windows 上执行：

- 默认并发跑 `cargo test -p gateway` 10 次；
- `--test-threads=1` 跑 10 次。

记下每次是哪个测试超时、耗时多少、最后一条输出是什么。没有复现，就把这个结果写进报告，然后停下。

## 2. 找根因

逐项排查，每一项都写结论和证据：

- 测试之间共享的资源：命名管道名、端口、临时目录、DPAPI 或用户级状态、全局单例；
- 测试夹具里的固定名字（例如 `setup(&root, "sys01", ...)` 的 name 参数），并发时会不会撞名；
- 等待逻辑有没有依赖墙钟时间，或者在高负载下才会出现的先后顺序；
- 会不会是 Windows 命名管道的实例数上限，或某个 ACL 引起的阻塞。

## 3. 修复（只在根因确实出在测试里时）

- 修法只能让测试彼此隔离，例如给每个测试用唯一的名字和目录。不能改超时时长，不能把测试改成串行，也不能跳过测试。
- 修好后，默认并发跑 20 次，全部通过才算完成。

## 4. 交付

- `reports/DIAG-SYS01-01/REPORT.md` 写：根因、证据、改了什么、前后各跑了多少次、通过了几次。
- 开 PR，标题 `test(DIAG-SYS01-01): 修复 SYS01 并发超时`；只诊断没修的，标题用 `docs(DIAG-SYS01-01): SYS01 并发超时诊断`。
- 写「请审查」后停下。
