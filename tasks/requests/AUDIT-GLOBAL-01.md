# AUDIT-GLOBAL-01：独立全局审计

## 用户原始提示词（照抄）

请对 GitHub 仓库 nanake-lab/nemu 做一次独立的全局审计。只读，不修改仓库。先记下你读取的 main 提交号。

背景：这是一个 AI 角色「她」的核心系统 Echo Core。她的状态由历史 H 按固定规律算出，要求增量计算与全量重算逐位一致。设计原则见 docs/adr/0039-echo-core-principles.md（10 条原则加 1 条前提），规格见 docs/echo-core/echo-core-v2.0-first-principles.md，规律定义见 docs/adr/ 下各 ADR（重点 0026、0032、0035、0037），实现在 core/crates/core-kernel/src/。

我们的审查一直是逐个 PR 的局部审查。请找出局部审查最可能漏掉的问题：
1. ADR 之间、ADR 与原则之间、ADR 与规格之间的矛盾或悄悄收窄；
2. Rust 实现与 ADR 0035 的规律文字不一致之处（A1 依据替换的分支、D07-A 共同折扣、D11-A 理解时作用与消费键、Φ 推进）；
3. 会让她在长期运行中走偏的漏洞：被重复计数、被自己的念头改变、被时间或重启改变学到的东西。

已知问题不用重复报告：P5-71（PR #154）审查列出的四项测试缺口；ADR 0035 §4.6 的 U1–U3；PRINCIPLES-01 报告中挂不上原则的三条（模式 B、π>½ 门槛、σ₀/τ₀ 出生份额）；开放的 PR #171、#176 中的草案。

要求：
- 每个发现给出文件路径和行号作为证据，标明严重程度（会改变她的行为 / 会让验证失效 / 文字问题）和把握程度（确定 / 很可能 / 怀疑）。
- 能举反例的就举具体反例；有疑问的地方直说，不要硬下结论。
- 不提新增设计。如果确实认为需要新增，先回答三问（能不能不加？一个人会怎样？加了以后，有什么从此改不掉？）。
- 按严重程度排序，最后用白话写一段总结：这个系统最让你担心的是什么。

## 用户补充交付方式（照抄）

补充交付方式：先完整读 AGENTS.md 并遵守。只新增两个文件：tasks/requests/AUDIT-GLOBAL-01.md（任务说明，照抄本提示词）和 reports/AUDIT-GLOBAL-01/REPORT.md（审计报告，结论写在最前面）；不改任何其他文件。从最新 main 新建分支，开 draft PR，加 needs-user 标签，在 PR 里写「请审查」，然后停下。不合并，不在其他 PR 上评论。
