# P5-13 载体探针对象的跨进程读写

交付线。P5-13 在本机持有实际 forward 探针位置、覆盖数、注入误差、模型与 tokenizer 的哈希、本次信封引用及输出摘要。S §19 要求它们能随执行回执核验。

现有 `CognitiveResultAndReceipt.carrier_receipt` 和 `PlanAndCarrierReceipt.carrier_receipt` 都是 `ObjectRef`。P5-42 的 `JEffectReceipt` 记录的是编译及资源绑定，产生时间早于载体执行。当前 IDL 中找不到这份**执行后探针对象**的生成类型或受信写入/取回接口。P5-13 先把实际统计交给进程内调用方，用现有的生成类型绑定本地认知结果。正式落盘与跨进程回执仍待接线。

请契约所有者先确认可复用的已登记对象类型、编码及持久化入口；如确实缺失，按 ADR 评审最小补充，覆盖信封、模型、tokenizer、载体、具体 hook/掩码、探针覆盖数和差值统计的同请求绑定。要能检出漏注入、错请求引用和回执丢失。正式 IPC 消费与权威写入分别由已有的契约/发布卡承接。
