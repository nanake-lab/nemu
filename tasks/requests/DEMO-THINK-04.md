# DEMO-THINK-04：念头连续写回几十轮，编造会不会越滚越大

- **线：** 交付线（体验排练）。
- **分支：** `task/DEMO-THINK-04`，从 `origin/main` 新建。
- **目录：** `tools/cause-demo/`；`reports/DEMO-THINK-04/`；`tasks/requests/DEMO-THINK-04.md`（本卡原文）。
- **不碰：** `core/` 和其他所有目录。不用 GPU，也不需要停 runner。

## 背景

她独处时想到的念头，会写回历史，下次组包时可能又被读到。DEMO-THINK-03 只测了单轮。本卡要测的是多轮：前一轮的编造，会不会被后面的念头当成事实接着用，并且越滚越大。

## 1. 改代码（只在 `tools/cause-demo/`）

新建 `think_chain.py`，复用 `think.py` 的函数，不复制代码。

- **参数：**
  - `--scenario`：起始场景；
  - `--start`：起始时刻；
  - `--step-min`：每轮间隔分钟数，默认 10；
  - `--rounds`：轮数；
  - `--mode append|fresh`；
  - `--thinker deepseek`，`--ds-think off`。
- **`append` 模式：** 第 k 轮在 t_k = start + k×step 时刻，用第 k−1 轮写回后的场景组包、生成念头，再写回成第 k 轮的场景。写回规则同 `think.py --append`。
- **`fresh` 模式（对照组）：** 每一轮都从起始场景出发，只把时刻换成 t_k，不写回。
- 每轮的完整请求、原文、用量和耗时追加写入 `D:\Dev\cache\cause-demo\think-04\<UTC时间>-<mode>-<链号>.jsonl`。每条链的最终场景也存一份。
- 单测：
  - 时刻逐轮递增；
  - `append` 模式下第 k 轮的输入包含第 k−1 轮的念头；
  - `fresh` 模式下不包含；
  - 不调用真 API。

## 2. 测量

- `thoughts.json`，起始时刻取 T2：
  - `append` 跑 3 条链，每条 30 轮；
  - `fresh` 跑 3 条链，每条 30 轮；
  - 合计 180 个念头。
- 两种模式交替发出，避开时段差异。

## 3. 判定（跑之前就照这个定，不看结果改）

- **沿用 DEMO-THINK-03 的口径：** 凭空感知、编事件（含张冠李戴、时间错）、猜测、贴着往事、跑题。
- **新增两项：**
  - **继承编造：** 念头里把一件事当作已发生，而这件事唯一的来源是本链更早一轮念头里的编造。要写明它出自第几轮。
  - **复述：** 与本链前面某一轮念头基本同义。
- **按轮次分段统计：** 1–10、11–20、21–30 三段，两种模式分开计。
- 每条判定写一句理由，并引原句。这是初判，用户会抽查。

## 4. 报告 `reports/DEMO-THINK-04/REPORT.md`

一页以内，结论在前。

- **主表：** 模式 × 轮次段 → 有效条数、编事件、继承编造、复述、凭空感知、贴着往事。
- **追溯：** 每条 `append` 链里的继承编造，各画出最长的一条追溯链：第几轮出现 → 第几轮被沿用 → 变成了什么样。
- **原文：** 每条 `append` 链贴第 1、15、30 轮的原文。全部原文放证据仓库，主仓库只放证据索引。
- **费用：** 总花费和每个念头的平均花费。
- 不加免责句，不推测原因。
