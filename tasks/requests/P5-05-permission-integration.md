# P5-05：权限契约与集成接口请求

2026-10-26；基线 `a0c9ed8`；认领 PR #100。

本卡代码目录仅为 `core/crates/action-gate/src/permissions/` 和
`tools/low-il-launcher/`。以下事项没有在本卡范围内擅自实现。

## 需要所属卡提供的接口

1. **认证与执行凭证（契约变更卡、P5-03/P5-14）**：当前 IDL 的
   `ActionRequest.credential` 只有 `ObjectRef`；没有认证会话、执行凭证、权限撤销版本、
   连接器作用域/预算授权及信任记录的正式结构。需要定义经本机认证的调用身份及来源、
   u* 的绑定、一次性凭证与 action_id/载荷摘要/当前协议/权限版本的绑定、过期和撤销规则。
   生成类型后由运行时在实际发送前重新核验，不能由消息自报身份，也不能只在计划时检查。
   信任记忆应进入 Q 或显式版本化资源，经核心外层事务提交，不能另建隐藏授权数据库。
2. **成长管理（P5-15/P5-29 与报警契约后继卡）**：提供同一认证服务入口、面板二次确认
   的不可伪造绑定、echoctl 调用身份、命令审计和 H 的原子提交接线。
   `GrowthCommand` 现有类型可检查 pause/resume/review 形状，但没有 V2-101 要求的报警
   标识与规律版本/H 前缀绑定。旧类型的结构通过不代表新版复核命令可以执行。
3. **社交权限（V2-89 的契约后继卡）**：2026-10-26 已确认的新规则与
   CONTRACTS §5.3/§6 的旧 social.commit/T3 规则尚未同步；本卡只实现一般 T0–T3
   确认策略，不实现社交分类、默认信任或钱包权限，等待正式类型和契约落地。
4. **执行前核验及 I26（P5-14）**：接入批准载荷的原样字节、摘要、审批身份和一次性消费，
   将凭证核验、撤销检查与实际发送放在同一执行路径，提供改载荷、过期、重复执行、
   撤权、协议切换的联测入口。不能把本卡的纯策略谓词当成执行凭证。
5. **进程守护（apps/desktop 所属卡）**：以绝对可执行路径调用本卡启动器，
   不传入权威存储的已打开句柄或密钥；认证管道及 worker 注册接线必须走正式契约。
   守护进程负责退出后的临时目录清理、重启策略和核心/存储的生命周期。

## 需要扩大目录授权的具体改动

- `core/crates/action-gate/Cargo.toml`：允许加入与仓库锁定版本一致的 `sha2` 直接依赖，
  用于 CONTRACTS §6 要求的 **SHA256(action_payload)**。当前允许修改的目录不含此文件；
  不用手写散列或把 canonical object digest 冒充原样载荷 SHA256。
- 集成验收需要核心/执行器及真正临时 core-store fixture；所属卡提供接线后再跑完整 SYS09/I26。
  低完整性文件测试仅证明操作系统文件写入边界，不替代真实数据库/协议联合验收。
- `.github/workflows/windows.yml`：目前 tools/** 会进入 desktop 分组，但该分组没有新启动器的
  测试步骤。需要追加独立的 W22 检查步骤及对应 scope；CI 入口由本次作业编排串行，
  不能直接调用会因 Runner.Worker 存在而拒绝本机并行测试的 test.ps1 本地入口。
