## 为什么做

下一个里程碑原本是「第一次真的聊上」：嘴、心和理解都走 DeepSeek API，由 Echo 从外面框住模型。框法有两层：来由投影按 Echo 的权重挑出最重的几件往事交给模型；模型先交带引用编号的 JSON 要点，代码逐条核对后机械拼接。

用户 11 月 23 日重新想了 LLM 和 Echo 的关系，做了三个决定（原话见下一节）：
- 她的脑子要用改造过的开源模型，不直接用现成的模型；
- 权重只练每个 Nemu 都需要的本事，她这个人只在 Echo 里；
- 接受「模型管聪明，Echo 管真实」这条分工的两个代价。

本卡做两件事：
1. 把这三个决定登记成 ADR（PR 1）；
2. 把「她的脑子」怎么做设计清楚，写成后继研究的路线（PR 2）。

## 用户原话（逐字登记，带珀斯时间）

- 11-23 13:01：「我还是不太想赶进度走文字路线 我又想起了LLM和echocore的关系 觉得更应该发挥LLM的能力」
- 11-23 14:11：「你希望哪一种 两个代价是必然 所以我们得对模型进行调整 不能直接用开源了的模型 得适配为自己的」
- 11-23 17:06：Claude 问「『权重只练每个 Nemu 都需要的本事，她这个人只在 Echo 里』，这条线你还认不认？」，用户答「认！」

14:11 那句里的「两个代价」，指 Claude 13:01 之后提出的分工「模型管聪明，Echo 管真实」所带来的两个代价：
1. 换模型以后，同一件事她会判断得不一样；
2. 模型自带的腔调会透出来，比如助手人格、DeepSeek 的口气、默认的温和。

这条分工本身由 Claude 提出，用户的回答把这两个代价当作必然，并决定用改造模型来应对。分工具体落到哪些既有决定上，本卡不替用户定，写成候选。

## PR 1：ADR

**编号：** 按 AGENTS §7 取下一个未用号。目前 main 上最后是 0048；#260 占了 0049；差异登记 main 上到 V2-190，#260 占了 V2-191。所以预计是 ADR 0050、V2-192。开 PR 前和交付前各核对一次。

**标题：** 「她的脑子是改造过的开源模型」。

**内容：**
1. **背景。** 写清楚四件事：
   - 文字路线怎样从外面框住模型（上面那两层框法），引用 ADR 0042、0045 和 P6-01 卡面的两步说话；
   - 11 月 18 日第一次来由投影聊天演示后，用户觉得回复太长、有 AI 味、不自然；
   - 用户 11-13、11-14 提过：厂商模型自带很强的说话风格，Nemu 没有一个真正属于自己的模型；
   - 用户关心的「她是谁不放在任何一家的模型里」：厂商可以下线或替换模型。
2. **决定。**
   - D1：她的脑子用改造过的开源模型，不直接用现成的模型。
   - D2：权重只练每个 Nemu 都需要的本事；她这个人（性格、经历、关系、她认识的人）只在 Echo 里。
   - D3：接受「模型管聪明，Echo 管真实」的两个代价；靠改造模型和 Echo 的记录来应对。
   每条附上面的原话。
3. **由 D2 直接推出的两点。** 写成推论，单列「请用户确认」：
   - 训练数据里不含她的任何真实记录。所以按现有安全规矩，训练可以租云 GPU，云上只放合成场景和 DeepSeek 写的念头。
   - 换底座以后，同一个改造配方和数据要能在新底座上重跑。她过去的每一次判断都已经作为事件记在 H 里，不会随底座改变。
4. **与以前说法的关系。** 逐条对照，标「不变」「被取代」「待定」：
   - 用户 11-14 说过三种方式都要用：上下文、激活、权重，权重最慢，像经历慢慢改变人的性格。按 D2，「她个人的性格进权重」这部分被取代；「权重最慢、只改本事」不冲突。
   - 用户 11-16 说过「用她自己的真实结果训练本地模型」。按 D2，训练数据不含真实记录，这部分被取代。
   原话出处去 ADR 0043、R-BRAIN 系列请求和差异登记里找，找不到的写「出处未找到」，不要编。
5. **与既有决定的关系表。** 至少列这些，每行写受不受影响、为什么，不改它们的正文：ADR 0002、0003（模式 A/B/C）、0012 §3、0026、0031、0034、0042（来由投影和两步说话）、0043（两线分工）、0045 D1/D2/D8/D10、v2.0 §§2.3、9.5、I28，以及 R-THINK-LOCAL-01 已定的路线和门槛 B。
6. **三问**（AGENTS 黄金规则 17）。
7. 差异登记追加一条，指向本 ADR。

## PR 2：设计报告 `reports/DESIGN-BRAIN-01/REPORT.md`

开头三行白话结论。然后按下面各节写。每个事实附出处和日期，并分清论文、项目自测、模型卡和社区帖子。凡是 Claude 的想法，都标「候选」。

### 1. 已有证据

只摆事实，每条写清它能说明什么、不能说明什么：
- DEMO-THINK-01～05：本地 4B 不训练时凭空感知 18/60、编事件 34/60；DeepSeek off 分别是 5/60、18/60。
- R-STEER-SURVEY-01、R-STEER-PAIR-01/02：正方向 5/22，质量异常 16/22，用户评语「编造性太强了」。
- R-BRAIN-01 的几轮试点和 R-BRAIN-RESCOPE-01 的结论：捷径问题；先测再练。
- R-THINK-LOCAL-01 已定的路线：先零训练对照，再试只在想事时挂载的适配器；切换门槛定为 B。
- P0-12、ADR 0034 的载体事实。
- #242（P5-13）的 GPU 窗口结果：已经测了就用；还没测就标「待测」，并列出本卡需要从中拿到哪些数。
- 11 月 18 日演示的用户反馈。

### 2. 本事清单

起点是下面 10 项。调研中发现每个 Nemu 都需要、清单里又没有的，可以加，加的那几项标「新增」。

| 编号 | 本事 |
| --- | --- |
| S1 | 不当助手：不出现「我是 AI 助手」、厂商自称、客服腔 |
| S2 | 不编造：说到自己的过去和感受，只说 H 里有出处的；猜测要明说是猜测，口径按 ADR 0045 D8 |
| S3 | 说话自然：长短随场合，不列点、不总结、不讨好 |
| S4 | 读得懂 Echo 给的状态（见第 3 节） |
| S5 | 听懂：IRL 抽取，边界按 ADR 0040、0048 |
| S6 | 独处想事：并入 R-THINK-LOCAL-01 已定的计划，不另起一套 |
| S7 | 自己查记忆：决定要想起哪段往事，向核心只读地查询 H。这和 ADR 0042「核心挑往事」有冲突，列出来 |
| S8 | 求助更强的模型：知道什么时候问、怎么把问题交出去；答案回来时当作信息，不当成她自己说的话 |
| S9 | 看图：清楚地看，不为省显存降分辨率（用户 11-02 的要求） |
| S10 | 三种语言：模型侧只用中文练，英文、日文只做小探针（用户 11-13 的决定） |

每一项写清楚：
1. 可以测量的定义。
2. 为什么每个 Nemu 都需要；里面不能含任何关于特定一个人的知识。
3. 归模型还是归 Echo，对照现行 ADR。有冲突的写原文，不替用户统一。
4. 现在的底座有没有这项本事：
   - 有证据的，引用证据；
   - 没有证据的，写「未测」，再给一个零训练探针的设计：十几分钟能跑完；输入用核心实际会给的格式；带防捷径对照，比如历史互换、换说法、换名字；预计规模和耗时写清楚。
5. 要练的话：
   - 数据只用合成场景加 DeepSeek 老师，经独立核对，不含她的真实记录；
   - 训练方式写候选，比如 SFT、偏好训练，并写明 R-BRAIN 的捷径教训怎么防；
   - 规模按学习曲线预算。
6. 怎么算练好了：
   - 自动指标和判据先写定；
   - 风格和自然度用用户的盲测两两比较（用户 11-13 定的「至少我还是个人」）；
   - 写清楚每一项最可能被钻的空子。

### 3. 状态怎么进模型

逐个评估下面这些候选：
- **T：** 把状态写成文字。按 ADR 0003 属于非严格；还要对照 I28。
- **J：** 现行的低秩激活加法 h′ = h + U·a，证据见 R-STEER 系列。
- **P（Claude 提的候选）：** 状态投影器。Qwen3.5-4B 看图时，用 mmproj 把图片变成模型能读的向量；同样可以练一个小投影器，把 x、R、θ 或 m 变成模型能读的软输入。
- **A：** 按状态挂载或混合的适配器。
- 调研中发现的其他做法。

对每一个候选写清楚：
- 已有证据；
- 要训练什么，需要多少数据；
- 换底座时怎么迁移：重练、重提方向，还是别的办法；
- 怎么验证「表达随状态变，却不说出状态词」；
- 和 v2.0 §§2.3、9、13 以及 ADR 0003 严格性的关系；
- 推理时的显存和延迟代价。

本节不下结论。最后列出需要做数学证明或计算的问题清单，每个问题写清已知量、要证明或计算什么、为什么重要。Claude 会据此给 GPT Pro 写提示词。

### 4. 底座怎么选

调研截至本卡执行日仍可获得的开源权重模型。筛选条件：
- 许可证允许 Nemu 分发和使用，原文要摘录；应用代码不引入 GPL/AGPL；
- 能看图，而且分辨率够用；
- 中文好；
- 有 llama.cpp / GGUF 支持（ADR 0031）；
- 思考模式可以关掉；
- 微调工具链成熟。

分两个显存预算列：
- 现在的 RTX 3080 10 GB；
- 计划要买的 16 GB 卡（RTX 5070 Ti 或 5080）。

每个预算都做一张显存表，同驻项包括：
- 脑子：按量化和上下文长度分别算 KV 缓存；
- 看图的投影器；
- 声音：过渡的 GPT-SoVITS V5，约 3.5 GB；目标的 Breeze TTS 2，至少 8 GB。按 ADR 0027 核对实际数字；
- 舞台渲染。

用到 #242 的同驻实测就引用；没有实测的标「估计」。还要写清楚：用 Breeze 时 16 GB 卡上还能给脑子留多少，用 GPT-SoVITS 时又能留多少。底座的推荐写成候选，不替用户选。
