# 任务书总览

共 8 个阶段、70 张任务卡。其中 8 张由你完成：P0-05、P0-09、P2-01、P2-02、P2-07、P6-12、P6-13、P7-05。另有几张卡需要你参与挑选或评审：P0-00、P2-05、P2-06、P3-05、P4-03、P5-17。

每张卡都写明了负责方、依赖、工期、目录、交付物、验收标准，有的还写了禁止事项。

## 0. 开工前

先完成 `P0-foundation.md` 里 **P0-05 的第一部分**：建仓库，放入任务书包，装基础工具链（Rust、VS Build Tools、Codex CLI 等），约 1 小时。代理要在你的机器上运行 Node、pnpm、Python、Rust 和 .NET，这一步不做，第一张卡就开不了工。

## 1. 怎么派任务

把下面这段提示词粘贴给 Codex 或 Antigravity，替换 `<任务号>` 和 `<阶段文件>`：

```text
先完整阅读 AGENTS.md、docs/ARCHITECTURE.md、docs/CONTRACTS.md、docs/echo-core/README.md。
然后执行 tasks/<阶段文件> 中的 <任务号>。
在分支 task/<任务号>-<短名> 上工作，只修改任务卡「目录」一栏列出的范围。
完成后运行任务卡里的全部验收命令，把报告和证据放进 reports/<任务号>/，
按 AGENTS.md 第 6 节的模板写 REPORT.md，然后提交 PR。
PR 满足 AGENTS.md 第 6 节的合并条件就自己合并，再按 tasks/README.md 第 2 节的规则接着取下一张卡。
遇到阻塞时写 BLOCKED.md 并继续做其余部分，不要停下来等我。
```

派出第一张卡以后，一般不用再逐张派：代理合并一张，就接着取下一张。线程停下来时（会话结束了，或者下一张卡在等你），先看报告末尾写的「在等什么」，处理完后发这一句让它续上：

```text
先完整阅读 AGENTS.md、docs/ARCHITECTURE.md、docs/CONTRACTS.md、docs/echo-core/README.md，然后按 tasks/README.md 第 2 节的规则取下一张卡，按第 1 节的要求执行。
```

两类卡需要额外加一句：

- Echo Core 相关的卡（改动 `core/`、`workers/`、`executors/` 的卡）：
  ```text
  开始前先阅读 .agents/skills/echo-core-work/SKILL.md，报告里附规格对照表。
  ```
- Antigravity 做渲染、动画、界面类任务时：
  ```text
  做视觉验证时先阅读 .agents/skills/stage-visual-check/SKILL.md，用 /browser 打开 pnpm dev:stage 的页面截图核对。
  ```

## 7. 每周节奏

- **周一：** 花 10 分钟看上周合并的 PR 摘要；哪个线程停了，就按第 1 节让它续上。
- **周中：** 代理执行、自己合并、接着取卡。卡住时会写 BLOCKED.md；需要你批准的 PR 会打上 `needs-user` 标签。
- **周末：** 30 分钟处理带 `needs-user` 标签的 PR，再看 `reports/` 下的新报告，勾选「待用户确认」的项目。

## 8. Codex 额度

- 三个开发线程同时运行，消耗明显。建议使用 Pro 计划：没有 5 小时上限。用 Plus 时，线程会因额度暂停，日期相应后移。
- 从 N2 开始，排练版本身也在用 Codex：模式 B 的说话用「日常」档，助手任务用「工作」档。面板会显示各档位的用量。
- 升级 Codex CLI 必须走一张任务卡，并重跑 codex-bridge 的录制回放测试（ADR 0004）。
