这一节写给你。第 1 节以后是派活和排期的细节，代理也读。

**每天看一眼看板：** 在仓库目录（`D:\Dev\nemu`）的 PowerShell 里运行 `pnpm board`，浏览器会打开本地看板 http://127.0.0.1:8765 。

- 最上面的「等你处理」列出所有在等你的事，处理完就会消失。
- 下面依次是里程碑进度、进行中的卡、可以开工的卡、全部任务卡。
- 每次打开、每次点「刷新」，看板都直接从 GitHub 读最新状态，大约两秒。页面开着时每分钟自动刷新一次，右上角可以关掉。
- 卡的状态没人手改：`tools/status/build_status.py` 根据 GitHub 上的 PR、分支和审查结论推算。
- 第一次用之前，先装 GitHub CLI 并登录：`winget install --id GitHub.cli`，然后 `gh auth login`。看板只在你这台电脑上运行，不经过任何云端服务。

## 1. 怎么派任务

**派一张卡**：第一次开线程，或者点名让某个执行者做一张卡时用。替换 `<任务号>` 和 `<阶段文件>`：

```text
先完整阅读 AGENTS.md、docs/ARCHITECTURE.md、docs/CONTRACTS.md、docs/echo-core/README.md。
然后执行 tasks/<阶段文件> 中的 <任务号>。
开工时先在分支 task/<任务号>-<短名> 上开草稿 PR 认领，只修改任务卡「目录」一栏列出的范围。
完成后运行任务卡里的全部验收命令，把报告和证据放进 reports/<任务号>/，
按 AGENTS.md 第 6 节的模板写 REPORT.md，再把草稿 PR 转为可审查。
按任务卡的难度走 AGENTS.md 第 6 节的审查与合并流程，合并后按 tasks/README.md 第 2 节接着取下一张卡。
遇到阻塞时写 BLOCKED.md 并继续做其余部分，不要停下来等我。
```

**续上**：线程停下来时（会话结束了，或者下一张卡在等你），先看报告末尾写的「在等什么」，处理完后发：

```text
先完整阅读 AGENTS.md、docs/ARCHITECTURE.md、docs/CONTRACTS.md、docs/echo-core/README.md，然后按 tasks/README.md 第 2 节的规则取下一张卡，按第 1 节「派一张卡」的要求执行。
```

**请 Codex 审查**：看板提示「请转给 Codex 审查」时用。在 Codex 里选 GPT-6 Astra、最高推理强度，替换 `<编号>` 和难度：

```text
先完整阅读 AGENTS.md 和 tasks/README.md。你是 PR #<编号> 的审查方，这张卡的难度是<中/高>。
对照任务卡的交付物、验收和「目录」，以及 Echo Core 规格原文（如果相关），审查实现、测试和报告。
只审查，不改代码、不推送、不合并。
把结论写成一条 PR 评论：第一行写「审查结论：通过」或「审查结论：有阻塞问题」，下面逐条写问题（文件和行、原因、建议）。
```

两类卡需要额外加一句：

- Echo Core 相关的卡（改动 `core/`、`workers/`、`executors/` 的卡）：
  ```text
  开始前先阅读 .agents/skills/echo-core-work/SKILL.md，报告里附规格对照表。
  ```
- Antigravity 做渲染、动画、界面类任务时：
  ```text
  做视觉验证时先阅读 .agents/skills/stage-visual-check/SKILL.md，用 /browser 打开 pnpm dev:stage 的页面截图核对。
  ```

## 7. 每周节奏

- **周一：** 花 10 分钟看看板和上周合并的 PR；哪个线程停了，就按第 1 节让它续上。
- **周中：** 代理执行、互相审查、合并、接着取卡。卡住时会写 BLOCKED.md；需要你的事会出现在看板的「等你处理」里。
- **周末：** 30 分钟处理「等你处理」里的事，再看 `reports/` 下的新报告，勾选「待用户确认」的项目。

## 8. Codex 额度

- 三个开发线程同时运行，消耗明显。建议使用 Pro 计划：没有 5 小时上限。用 Plus 时，线程会因额度暂停，日期相应后移。
