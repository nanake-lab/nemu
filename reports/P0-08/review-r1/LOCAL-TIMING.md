有约束的解析器构建 P50/P90 = 13.12/24.68 ms；约束回调累计 wall 时间 P50/P90 = 4762.44/8976.85 ms。逐对回调占整次请求比例的 P50/P90 = 31.15%/33.91%，包含可能的设备等待，不是纯算法 CPU 时间。

逐对「有约束完成时间 / 无约束完成时间」P50/P90 为 1.54/1.63；逐对「无约束 / 有约束」生成速率比 P50/P90 为 1.56/1.64。控制共同 token 前缀长度后的速率比 P50/P90 = 1.56/1.64。输出内容仍可不同，不称为每毫秒的纯因果分解。

## 诊断结论及边界

- 约束路径确有明显开销：相同输入、固定配置及相同观测器下，无约束生成约快 1.56 倍；回调 wall 占比约31%。本卡没有换解码库或改变 Schema。
- 模型生成与输出规模也构成瓶颈：无约束完成 P50 仍约9.9秒，首token约397ms，不能仅靠移除约束达到整次400ms目标。prefill约394ms，之后主要时间仍在逐token生成。这里的“模型路径”包含被固定的框架、内核和同步开销，不是纯GPU计算时间。
- 两臂都加相同 forward observer/streamer，同步有开销；本批不替换原200条规则总体。有约束50条的输出哈希与原200条前50输出 **50/50相同**。
- 两臂原始 Schema 均49/50合格，来源检查均43/50合格；有约束第30条仍为JSON解析失败，未修写输出。原200条的8条日文失败与169/200来源合格仍保留。
