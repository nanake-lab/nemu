# P0-09 决策方向（P0-08 本卡不实施）

现有后端/P90 只能按卡片公式产出规则结果，不能当作可用部署默认或回复等待策略。操作配置中的 backend/deadline 均保持 null，正式配置不改。low 组完成后按同一阈值另算规则结果；max 为用户指定对照，不删除或混入 low。

| 可选方向 | 可能改善的部分 | 需要决定/验证的代价 |
| --- | --- | --- |
| 缩小 SemanticCandidate 输出 | 降低生成 token 数及序列化/约束工作 | 保留哪些来源、类型和边界；若影响正式契约，走契约/ADR流程。当前中位 token 数只作诊断，不能承诺新延迟 |

| IRL 移出回复关键路径 | 回复不等当前事件完整 IRL | 当前事件评估晚一轮，改变时序和语义；必须由 P0-09/架构决定，不能绕过核心权威事务或丢来源 |
| IRL 与 A、M 合为一次调用 | 减少调用与重复处理 | ARCHITECTURE 第5节已有候选；需明确复合输出、失败/超时和预算，仍只提出 Proposal，不直接写权威存储 |
