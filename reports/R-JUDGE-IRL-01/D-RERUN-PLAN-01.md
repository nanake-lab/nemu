# R-JUDGE-IRL-01：采用 ADR 0040 重标与重跑 D 的计划

拟重新标注全部 12 根、36 个三语视图，包括原来双方一致的字段，再以新版指南运行 36 次代理制标。正式运行前做中英日各一次独立冒烟，最多共 39 次模型调用。本阶段只用 gpt-6.1-terra API，不需要本机 GPU 或独占窗口；新增费用的保守计算上界为 **US$6.4896**，拟设阶段硬上限 **US$6.50**。第一版 D 的标签、失败和结果保留，新版单独建包、记账和分析。**本计划待用户批准，当前不重标、不生成执行包、不运行模型；B 冻结和 GPU 窗口仍暂停。**

## 1. 依据、问题与范围

2026-11-13 Perth 核对：[PR #176](https://github.com/nanake-lab/nemu/pull/176)已合并，合并提交为 `5403d40dd56e14af6d9d3f30112512383b6cab8b`；最终增量[审查通过](https://github.com/nanake-lab/nemu/pull/176#issuecomment-6842401382)。采用该提交的 [ADR 0040](../../docs/adr/0040-irl-fact-annotation-boundaries.md)、[标注指南 Z01–Z12](../DESIGN-IRL-Z-01/ANNOTATION-GUIDE-DRAFT.md)与[模式值表](../DESIGN-IRL-Z-01/PATTERN-VALUES.md)，对应 V2-161–164。文件名和正文中的历史“草案/待审查”措辞不改变此次已合并状态；ADR §5 明确合并设计不自动授权重标或模型运行。

研究问题是：将已采纳的定义落实到可复现提示和完整作者标注后，旧 D 中哪些解释分歧消失、哪些仍是材料不足、规则缺口或执行偏差？不预设一致率提升，也不设“4B合格”的门槛。本轮要批准的是**新版 D 作者/代理制标及诊断**，不包含 B 冻结后的三系统四路径正式评估、4B、DeepSeek 或 H。

减法三问：能否不加——无需增加字段、模型、样本、投票轮次或新量尺，只把已批准定义用于原材料；一个人会怎样——按同语原文逐项记事实、来源与未知，不拿旧答案补证；有什么从此改不掉——不新增永久行为规则，新解释以独立版本保存，旧记录可追溯。

## 3. 新执行包与控制变量

- 三语提示分别完整落实 Z01–Z12 的操作性定义和共同操作；保留无唯一焦点、动作/状态未决、获取路径、持续片段、N目标范围及 μ 三值规则。旧提示“中间可自选或null”等冲突句删除。新提示不附模式答案表，不为某根添加专用规则。执行前逐条核对三语语义，不用别种语言补材料条件。
- 保持 `gpt-6.1-terra`、`reasoning_effort=high`、`max_completion_tokens=16384`、`service_tier=default`、`store=false`、JSON object、m=0、无人格/历史、相同端点；未设种子的旧配置不擅加种子。正式顺序仍 D01→D12、每根 zh→en→ja；最大并发2。
- 保持原 JSON 字段、枚举、严格类型、长度及引用检查；字符串 `"None"`/`"null"` 不转义成 null。工作纸放旁侧证据，不新增模型响应字段。schema 合法的 μ 中间值若违反新版 Z12，记语义不符，不修改原 schema 的数值范围以把它事后变为技术 invalid。
- 新版材料/概念不变，指南、提示与作者解释版本改变；并非只换模型或纯单变量因果试验。旧 D 参与了指南设计，只能作同材料描述性对照，不称独立验证或未见样本泛化。

批准后的离线检查先核对全部36份材料/概念与A-03一致、全部字段覆盖、三语规则、严格 schema、计费预留、停止门、旧文件摘要与新路径隔离。用保存响应和合成边界输入验证检查器，不调用模型；旧记录即使按新语义不同也不改旧终态。沿用现有 Python 工具环境，检查修改过的执行器类型与静态错误，不跑全仓编译或产品测试。
