# P5-43：G01–G05 字段、编码与兼容提案

这些记录解决的是「她到底从哪里知道、知道了哪一部分」，不替她规定该喜欢谁或相信什么。已有文档批准的是所需语义；下列类型、必填性与编码选择是 **U1–U4、U9 待批准提案**。不写 `.proto`，不抢占类型标签或字段号，不让设计助记成为第二份契约。

## 1. 共用编码与兼容提案

**三问先用于共用做法。** 能不能不加：不新增一套编码，复用 ADR0007、ObjectRef、ConceptRef、ProposalBindingV2；新增的只有现有对象表达不了的权威语义。一个人会怎样：能分清原话、记忆里的解释与后来修正。加了什么改不掉：已发生的原始字节、当时的解释和资源版本不可覆写；未来理解可追加，编码与规律可经显式升级改变。

| 项 | 拟采用的具体表示 | 批准依据与本次增量 |
| --- | --- | --- |
| 引用 | 对象用既有ObjectRef：32字节摘要、object_type、resource_version、byte_length；事件/概念用原正式ID并绑定H前缀/注册表版本；引用到节点必须同时带图对象引用与节点ID | ADR0007、旧架构§3、base.proto；**新增**各ObjectRef允许指向的正式对象类型与跨对象约束，不改ObjectRef |
| 字符串/整数 | 严格UTF-8，无隐式Unicode归一；身份非空；索引/长度采用u64，小端固定宽度；集合/嵌套长度仍用CanonicalV1的u32；不把u64位置误写为JS number | ADR0007决策4–9；**新增**跨度/局部序位使用u64的选择；溢出是表示错误，不截断 |
| 判断未知 | 语义三值以显式枚举表示；数值μ用「已知有限binary64值 / 未知及理由」的必选分支，不能用NaN；未评由阶段结果/覆盖范围表示，与已评未知分开 | ADR0040 U3、旧架构§3.3；**新增**正式编码形式；0仍是已知不吻合 |
| 必填与可选 | 每项依赖其类型必须具备；可选只用于确实可无的前任、理由等，缺省与显式空不同；集合为空只能表示「已检查且没有」，不能表示未查 | ADR0007决策5；下表逐项定义必填性 |
| 排序 | 无序引用集按规范键字节排序、重复拒绝；实际顺序用有序向量，不能排序抹平时间；同一字段不能兼任两者 | ADR0007决策6；具体键见各节 |
| 版本 | 推荐与现有后继消息一致：新语义用新冻结type tag，各新消息schema_version起始为1；沿用字段保留原号、被取代字段reserved、增量字段使用前任最大号之后的新号；不改旧枚举判别值 | ADR0007及CONTRACTS的P5-22追加；标签/号由43在#164交接后提交正式审查，不在本报告假造已发布值 |
| 版本层次 | 编码版本、IRL/A/M及适配/属性规则资源版本、规律版本分别记录；对象引用完整绑定摘要；只改资源字符串而不绑定实际字节不充分 | v2.0§§1/2.2/5.4、ADR0007、0035§2；规则语义变化不可冒充纯序列化更新 |
| 兼容 | 旧消息只按旧语义读取；新输入不降级为旧布尔值/旧Teaching；旧客户端遇新标签明确不支持；不靠Protobuf忽略未知字段 | ADR0007决策2/8/11；新表示保持CanonicalV1封装，不改NCV1 |

迁移共同路线：旧记录原样保留 → 核对源载荷及当时资源 → 信息足够时由确定性适配生成有出处的后继记录；需语义重解释时走获准的新解释流程 → 从有效H按指定规律重算 → 同事务发布及记H/L。信息不足保留未知，不把旧 `verifiable=true` 推成三项皆真。回退恢复旧应用和备份，禁止把新快照作为旧消息解码；SYS17由存储/重算所属卡执行，43/44提供路由和契约向量。

## G01 来源与跨度

**三问。** 能不能不加：ObjectRef能定位对象，却不能说明哪段字节、谁取得、是否可用；必须补其正式内容，不能另存一份正文。一个人会怎样：分得清亲耳听到、转述、自己推测，也知道所引原句。加了什么改不掉：当时实际收到的载荷及其出处不能重写；来源归属、使用资格和解释可以经更正改变；「收到」不会因内容说错变成「没收到」。

| 字段组（必填，除另标） | 类型、约束与编码 | 追溯；哪些是本次提案 |
| --- | --- | --- |
| 原载荷绑定 | event_id、payload:ObjectRef；解析时核对EventEnvelope.payload_ref/payload_digest、实际规范字节；derived对象另给原对象引用集及转换资源ObjectRef | 旧架构§§3/3.2/4、G01请求；具体绑定对象为新增，不复制原正文 |
| 定位分支 | 必选 `整对象` / `文本字节区间` / `正式字段路径`；文本为start、end u64，0≤start<end≤字节长度，边界须落在UTF-8码点边界，半开[start,end)；字段路径为已知消息type tag下的字段号及重复元素索引有序向量 | G01要求跨度单位与范围；**本次选择**字节而非UTF-16/字符偏移，整对象另有明确分支，不用0长度冒充全文 |
| 多段出处 | 一条节点可有多处定位，按对象摘要与定位规范字节排序；每处都回到原载荷或记录过的转换链；显示转义、换行或规范化不改变原定位 | 旧架构§3.2 source_refs/source_span；**新增**多段的明确关联；字幕/OCR文本须绑定生成对象与原媒体，不能假装是原图字节中的文本 |
| 来源链 | 既有derivation、epistemic_type；直接来源记录集合、最初可追溯来源引用、观察者/生产者身份引用、实际对话身份可选（非对话明确不适用） | 旧架构§§3.2/3.5、v2.0 EV1/2/3、P5-24请求；根引用只表示来路，G独立根另经治理，不把每条引用当独立证据 |
| 有效性依据 | 来源认证记录引用、来源有效性版本、权限/撤回决定引用与适用前缀；不能携带真实凭证；认证失败/资料不足不得构造可用视图 | G01请求、旧架构§3.3、I14；**新增**引用边界，不自造P5-40的认证政策 |
| 可读边界 | 持久记录绑定base_commit/前缀；本事务事件由核心提供仅在本事务有效的staged只读能力，含事务身份及对象集合；提交后由正式提交记录解析 | G01请求、v2.0§2.4；**新增**进程内能力接口，不序列化为worker可伪造的`committed=true`证明 |

版本与兼容：新增来源/定位对象及必要的SourceMetadata后继，旧 `source_span:ObjectRef` 不按新格式猜读；若旧对象原本具有可证明的相同内容，适配也须绑定其旧类型与版本。缺跨度可以保留原事件，但引用不到的语义部分不能ACCEPTED；来源认证不代表断言属实，三项核实交G05。

时间只引用P5-52/72的正式事实/证明对象；本节不创造另一套epoch、长时长或时间可信度格式。缺这些对象是接口缺口，不能把ingest/process时间写进语义发生时间。

## G02 概念注册表与别名

**三问。** 能不能不加：现有ConceptRef可引用身份，不能装载签名、grounding及生命周期；补注册表内容，不建第二套语义数据库。一个人会怎样：新词可以先不懂，也可以后来知道两个称呼指同一个东西。加了什么改不掉：旧ID及当时含义留在历史；标签和认识可变，不能靠改名或新别名获得新证据、先验或保护次序。

| 字段组 | 类型与规则 | 追溯；本次增量 |
| --- | --- | --- |
| 身份与修订 | concept_id、registry资源引用、revision对象引用；previous_revision可选，仅首版为空；创建/修订来源引用集必填 | 旧架构§3.4；正式注册项为新增。ID由核心在原子暂存内分配，worker只提mention/provisional请求，不接受worker自授正式ID |
| 显示与定义 | 三语label/definition/正反例，复用TrilingualText；定义性约束与来源引用；缺可用grounding时仍可provisional，不用编造三语事实填满 | v2.0§7、旧架构§3.4；存显示文字不授予身份；所需字段的空/未知规则由正式类型区分 |
| 签名 | 允许的角色标识、各角色node种类/概念域、值分支、必要性；角色按规范角色标识唯一排序 | 旧架构§3.4 signature；**新增**可校验签名字段，角色不是任意模型字符串 |
| 生命周期 | stable / provisional / deprecated；每次转移含来源、前任和采纳记录；禁止复用旧ID给另一概念 | 旧架构§3.4已列三态；**新增**转移记录的正式表示。deprecated仍能重放历史；新解析须显式选择保留、替代或未解，不暗改旧引用 |
| 关系 | 已批准类别broader/narrower/near_synonym/incompatible等按版本资源登记；每条两端ConceptRef、关系种类、依据 | 旧架构§3.4；相近不等价，不由embedding决定合并 |
| alias/equivalent/canonical | 版本化映射：from、to、依据；equivalent须经治理转成唯一规范代表，有向canonical映射无环、无冲突、无跨版本悬空目标 | 旧架构§3.4、ADR0014§4；**新增选择**显式唯一代表，不以最小字符串ID猜代表；旧事件不改写 |
| 暂存输出 | registry_before、拟新增/修订条目引用、registry_after；依赖本事务采纳结果，失败整体不发布 | G02/G04请求、v2.0§2.4；复用事务不增独立注册表写入通道 |

版本与兼容：旧ConceptRef保持原ID和registry_version；新registry对象有新标签。升级后查询显式选择注册表版本和映射，不能总查「最新」；别名语义更正可能影响G重算，但不能刷新真实提出时间。同义概念与「同一人多个账号」是不同映射，后者要来源治理，不拿语言别名当身份认证。

## G03 Claim 值与确定性适配

**三问分别审两项结构。**

| 新增结构 | 能不能不加？ | 一个人会怎样？ | 加了什么改不掉？ |
| --- | --- | --- | --- |
| 有型operand、模态及时间引用 | 裸ObjectRef不足以检查值域；保留Claim三槽，只补正式内容，不扩成任意JSON | 知道数字、引语、愿望和已发生事实不是同一种答案 | 值类型和未知的含义成为本版边界；将来扩域须新版本，旧解释不重标 |
| 确定性适配资源 | 结构化输入无需再让模型猜；但没有版本映射无法重放；一份资源足够 | 看到明确的按钮回执不会每次重新猜它是否按下 | 本版字段→语义映射固定，改映射是修订，不随心情改变 |

| 字段组 | 拟议表示与约束 | 追溯 |
| --- | --- | --- |
| value | 必选：无值适用、未知、布尔、有符号64位整数、有限binary64实数、原文字符串、Ref/Claim节点引用；整数沿ADR0007固定宽度，非有限数拒绝；量的单位用注册概念限定，不用自由单位字符串；只有当前predicate签名允许的分支可用 | 旧架构§3.2/3.4、G03；**本次最小取值域**。无值与未知不同；集合/复杂对象需求出现时再做后继，不建任意递归容器 |
| modality | 必选：未限定的陈述、可能、条件、愿望、报告或未知；条件/报告等限定引用同图节点与来源，不把reported转成asserted | 旧架构§3.2列模态；**本次封闭首版表示**，额外模态需正式扩版，不从词面放行 |
| time | 必选不适用、未知或正式时间事实对象引用；Claim表述范围与实际发生/观察、持续片段的关系分别可查 | ADR0035§5.1、0040 Z11；不设计52/72拥有的时间证明，不以研究t0/t1/t2值代替真实时间 |
| polarity与角色/边 | 保留逻辑肯定/否定；角色须符合注册签名；interaction_kind、edge关系改为由版本表约束的标识；ref节点不能引用不存在的图/节点 | 旧架构§3.2–3.4；**新增**字符串表的正式资源引用。负命题不等于负情绪或负S |
| 映射资源头 | 资源版本/摘要、输入type tag与schema、输出registry版本、产生的predicate与角色约束 | G03请求、旧架构§3.3；不能只写函数名或依赖运行时当前注册表 |
| 映射条目 | 正式字段路径→predicate/role/value/span；适用条件、未覆盖分支的未知/拒绝结果；顺序按已声明条目键，重叠冲突拒绝 | G03请求；**新增**可审查映射表，不允许运行任意脚本改语义；只适配已认证载荷 |

首版映射覆盖清单：触摸及接触阶段（保留contact_id及部位/时长出处）、桌面观察（不由IDLE推缺席）、执行结果（action_id、执行实例与已知/未知结果）、会话身份（不把应用session当对话）、维护事件（不进入F/G/C）。表项的predicate必须来自注册表；本报告不凭空分配概念ID。新来源类型未登记时显式不支持，不退回自然语言猜测来冒充确定性适配。

main新增ADR0042§1.3的关系交接：对话接续、原文来源/正文引用、必要更正须由正式关系种类及冻结映射区分；不把普通reply/parents统一解释为正文依赖或因果证明。该映射复用本节资源，投影器仍由其后继卡实现；按h选出的表达材料不能回流IRL/A/M或G/C选材（0042§5.1）。

兼容：Claim原value/modality/time对象不原位更换解码器；选择新图/Claim后继与operand类型，旧图可读。旧interaction_kind/role字符串经已批准映射且无歧义才能转换；其它保留未解。多Claim可共用一个事件ID，不能自动转成多条A、多个G根或多个F消费（ADR0040 U1）。这里只补表示力；分句事实核实及因果归属仍受ADR0033升级B前提限制。

## G04 解释联结与采纳阶段

**三问。** 能不能不加：现有binding说明提议用了什么，不能证明谁真正采纳了它；须记录核心的阶段结果，不能只加accepted布尔值。一个人会怎样：区分听到一句解释、理解了一部分和后来纠正。加了什么改不掉：当时用过的输入、输出与采纳次序留痕；后续可补解释，但不能伪装当时已经知道。

| 字段组 | 拟议表示与约束 | 追溯 |
| --- | --- | --- |
| 目标与生产 | 解释record_id、被解释event_id/对象类型、IRL/A/M阶段、producer/资源引用、实际输出ObjectRef、candidate引用；继承ProposalBindingV2 | G04请求、v2.0§2.4/EV6；目标事件可早于本次binding.event_id，不能强制二者相同 |
| 实际读取 | read_set、实际c_core对象/摘要、允许的概念定义资源、生成隔离记录引用；核心核对实际调度路径m=0及输入白名单 | G04请求、EV6/I14；自报m=0或摘要相等不是证明；worker不能读完整binding里的状态值当判断上下文 |
| 阶段结果 | 有效、部分有效、失败；有效子图/结果引用、覆盖的目标/字段范围、有依据的未知及原因；A必须给有效完整四维向量或相应失败，不能拼缺值成零；M区分已知0、已知正数、已评未知、未覆盖 | 旧架构§3.3、ADR0035§3.1/5.2、0040 U3；**新增**明确阶段输出和覆盖表示 |
| 治理与注册表 | source/type/schema检查资源引用、registry前后引用、有效子图、失败部分理由及依赖引用；正式采纳记录由核心产生 | G01–G04请求；部分有效不意味着非法节点仍可被其它有效节点引用 |
| 重解释关系 | new_record与prior_records的正式类型/阶段、同一被解释目标、原因（首次补足/解释错误修订）、新旧生产资源；引用链无环，不得跨A/M类型冒名替换 | G04请求、EV5/6、ADR0035§4.7/5.2；更新某个M目标时须明确覆盖范围，不默认替换该事件全部结果 |
| 发布边界 | base_commit、事务身份、拟采纳解释/注册表对象集合；提交记录绑定最终对象集合；staged到committed由外层原子发布 | v2.0§2.4、G04请求；阶段结果不是独立提交入口，不在持久对象里自引用其尚未生成的commit摘要 |

版本与兼容：新增正式阶段结果/采纳对象；旧ReinterpretationLink和SemanticCandidateV2可以作为被引用的历史提议，**不自动升级为已采纳**。本次设计不复制P5-72消费表：F消费键仍是记录身份＋接纳/A/M阶段，补解释只按ADR0035既定条件更新，解释器修订不新发消费键。纯重放读已采纳记录；只有批准的修订流程才重新调用模型。

main新增ADR0042§§1.1/3.1的消费方约束：回复侧等本轮及有序前置的有效解释/必要状态提交；合法无作用可以完成，失败或缺失占位不能当完成。本节提供可判别的阶段结果，不新增等待期限；晚到补解释不自动复活失败回复任务。

## G05 属性规则完整生产

**三问分别审两项结构。**

| 新增结构 | 能不能不加？ | 一个人会怎样？ | 加了什么改不掉？ |
| --- | --- | --- | --- |
| 属性规则资源 | 分类必须可重放；补一份规则表，不另设可靠度打分器 | 分清别人回复、自己操作的程序结果和电脑维护 | 本版来源分类固定，经历不能把工具返回变成外源；规则错误可显式修订 |
