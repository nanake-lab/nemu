# R-WECHAT-01「她的微信：接入路线调研」

## 白话总览（首页）

她将有自己的账号。**用户主号永远不接入**，也不把主号的聊天、联系人、登录态交给她。这是本次用户决定；注册人仍须是真实的人或合适的组织，不能把“她有账号”理解为平台承认 AI 是独立责任主体。[微信协议 §§7.1.2–7.1.3][s1]、[企微协议 §§1.1、7.1][s2]是平台侧的限制。

**两条路线目前都不能直接认定为“已经适合她自由使用的微信”。** 企业微信能和个人微信用户成为联系人、聊天，但普通客户联系接口不等于任意好友聊天接口。核实到的官方自动收发入口是企业微信体系里的**微信客服**：对方不用加好友，使用客服会话；通常须对方先发消息，随后 48 小时内最多连续回复 5 条，对方再发才恢复额度。它适合有来有回的回复，不能保证她随时主动找朋友。[官网][s3]、[客服官网][s4]、[发送接口][s5]

电脑版微信的界面自动化，更接近普通好友体验，但既有误读、串会话和抢键鼠的工程风险，也有明确的条款风险：微信协议限制未经授权的第三方自动化读取、控制界面；**不注入并不等于获得平台许可**。没有公开、可核实的封号概率，也没有“低于某个发送频率就安全”的保证。[微信协议 §8.2.1.6、§8.5][s1]

**建议（由用户决定）：** 如果能接受客服身份与回复窗口，优先验证官方微信客服 API；如果必须是普通微信好友、可以自由主动联系，建议先保留需求、向腾讯确认可用能力与授权，暂不把电脑版自动化投入她的生活。这不是替用户选路线，也不改变她正常交往不设人数、消息数行为上限的决定；平台限制必须如实呈现。[V2-89/V2-104](../../docs/traceability/diff-register.md)、[ADR 0032 §3](../../docs/adr/0032-presets-as-starting-points.md)

无论哪条路线，**电脑睡眠、关机，或核心没有运行时，她都无法回复**。平台暂存消息或未来设置只收件的转发器，都不是另一个在云端继续思考的她。醒来后也可能错过客服回复窗口或消息拉取窗口。[ADR 0028 D4](../../docs/adr/0028-lifecycle-single-instance.md)、[接收接口][s6]

用户下一步只需决定：是否接受客服身份和窗口；若不接受，是否先询问平台授权、保留电脑版路线作后续研究。账号、设备、费用与真机实验都另行批准。**本卡没有登录、注册、读取真实人的数据、发送微信消息、安装工具或改变设置；全部实验均为 `not_run`。**

### 三种经常被混淆的能力

1. **客户联系：有好友关系，不等于任意收发 API。** 官网确认成员可加个人微信好友并单聊/群聊。开发接口主要提供成员/客户管理、客户变化事件与打开相关页面等；联系人新增回调不是聊天正文。`externalcontact/add_msg_template` 创建群发任务，需成员确认才发送，不能当自动私聊回复。内部自建应用向成员发消息、群机器人，也不能据名字推成向任意个人微信好友发送。[S3][s3]、[S7][s7]、[S8][s8]
2. **会话内容存档：获取记录，不是发送许可。** 官方有获取会话内容及 SDK 解密能力，但不能由此推出可代成员自动回复。适用资质、许可、开通范围、对方同意/拒绝机制与保存窗口须按当时租户正式文档核对；本卡未开通、未获取 SDK 或聊天记录。[S9][s9]。因此不推荐为解决收件而先购买存档，更不能把“能存档”写成自由双向接口已经成立。
3. **微信客服：核实到可自动双向通信的官方子路线。** 通过客服链接进入，对方无需成为好友；API 可管理客服账号、分配会话、收发消息。它是路线一内部的服务能力，不能悄悄替换“普通好友”的需求。[S4][s4]、[S10][s10]

客服收件链路是收到平台通知后调用 `kf/sync_msg`。应跟进游标与 `has_more`；回调里的拉取 token 有效期为 10 分钟，无 token 拉取另有严格频率限制，具体额度未核实。接口可获取最近 3 天消息/事件，**不支持用此接口读取自己通过发送接口发出的消息**，自己的原样输出与结果必须另由核心行动记录保留。[S6][s6]

客服发送使用 `kf/send_msg`，受可调用应用、指定客服账号、接待状态和回复窗口限制。它支持文字、图片、语音、视频、文件等；这些类型支持不代表本项目已经允许读取或发送附件。调用成功只证明接口受理，须处理失败事件；没有最终送达或已读证明时，不把它记成“对方已看见”。客户端看到消息、平台受理、最终送达、对方阅读应分开。[S5][s5]、[S6][s6]

| 指定窗口截图 + 本地 OCR | Windows 提供窗口捕获及 OCR；识别结果是图像文字与位置，没有天然可信的消息 ID、发送人或投递回执。[M5][m5]、[M6][m6] | OCR 原文、识别派生文本要区分；误读、遮挡、缩放和滚动会产生缺口（工程推断）。不得默认截取整个用户桌面或上传云端 |
| Power Automate 等通用桌面 RPA | 官方支持控件定位、鼠标/键盘和数据提取，部分操作会把窗口带到前台。[M7][m7] | 可作后续实验工具选项，**本卡未选型、下载或安装**；微软提供工具不等于腾讯许可自动操作微信 |

消息列表若使用虚拟化，屏幕外项目未必有可读元素；滚动后才出现也会影响顺序和去重。微信是否采用、采用到何种程度须真机检查；不能把微软对虚拟控件的说明当成已观察到微信的证据。[M3][m3]

**可靠性与延迟结论：未核实。** UIA 事件可以提示变化，但不保证微信每条新消息都有完整事件；轮询/OCR 会增加等待和处理成本（推断）。后续应分别测平台收件→可见、可见→读取、读取→核心提交、核心派发→界面发出，并报告丢失、重复、错序、文本错误及未知投递。没有实测，不填写毫秒数、成功率，也不承诺“实时、稳定、后台可用”。

### 同时用电脑的冲突与隔离

真实键鼠是共享资源：用户切窗、输入法组合键、拖动窗口、弹窗、通知或剪贴板变化，都可能使步骤失效（依据输入模型的工程推断）。整体阻止用户输入、关闭安全机制、强制抢回焦点、修改电源/注册表，不是本卡可采用的解决方法。[M4][m4]及用户禁令

未来可供用户选择的做法：只在明确让出桌面的一段时间运行；限定支持直接 UIA 模式的操作；使用单独的 Windows 会话或专用设备。后两种的可用性、成本、登录限制和锁屏行为都**未核实**，另行批准，不预设为默认。换到专用设备若同时运行核心，须迁移并封存旧实例，不能复制两个她。[ADR 0028 D4](../../docs/adr/0028-lifecycle-single-instance.md)

P5-05 的 Low IL 隔离不能直接拿来保证 UI 自动化可用：低完整性进程的输入控制可能被 UIPI 拒绝；Low IL 主要是写入完整性边界，不提供完整保密/网络隔离。后继应设计只能操作她的目标窗口的执行器能力，不能为了操作微信提升所有 worker 权限或关闭系统防护。[P5-05 报告](../P5-05/REPORT.md)、[M4][m4]

### 微信条款与公开封号信息

- **官方已核实：** 微信协议 §8.2.1.6 限制未经授权的第三方注册、登录、使用、自动化操作，以及访问/读取/控制界面和数据；§8.2.1 的例外是法律允许或腾讯书面许可。使用官方微信客户端和模拟点击，不能自行推出已经满足例外。[S1][s1]
- **处罚依据已核实：** §8.5 包括警告、功能限制、封禁直至注销/回收；注册人承担相关账号行为责任。不把“低频”“自用”“不赚钱”写成豁免。[S1][s1]
- **公开报道已核实，官方原帖未独立取得：** 2026-01-29 的微信安全中心公告被媒体转载，点名模拟按键/自动化脚本自动回复等风险；2026-10-24 的企微安全团队公告转载称，某外挂服务遭攻破后出现异常发送，并说明会处罚外挂使用。报道分别涉及微信与企微，不能把两者处罚数据混用。[N1][n1]、[N2][n2]
- **未核实：** 本用途得到许可的先例、普通个人专用号的具体风控阈值、可比较封号率、解封保证，以及同实名其他账号是否受牵连。报告的风险判断是条款与工程推断，不是账号实验结果。

**第三方协议、逆向登录、注入/Hook 工具排除出候选。** 未授权协议/改造路线与上述条款冲突，并增加不可审计代码、凭据和聊天数据被取走、绕过 P5-05 隔离的风险；按本卡用户要求列为最高风险、予以排除。这里的“最高”是方案风险排序，**未核实到统计封号率**；本卡未下载、安装或运行此类工具。[S1][s1]、[N2][n2]、[P5-05 设计](../../tasks/requests/P5-05-permission-integration.md)

## 两条路线怎样接入她，而不是另造一个聊天机器人

以下是依据现有设计提出的接线要求，不是新增 IDL，也不表示这些接口已支持微信载荷。[ADR 0024](../../docs/adr/0024-terminal-ingress.md)、[P5-35 接入契约](../../core/contracts/terminal_ingress.proto)、[P5-05 设计](../../tasks/requests/P5-05-permission-integration.md)是依据。

### 共用的收件和发送边界

1. **收件进入 H 的唯一入口仍是核心。** 适配器获得外部消息，保留来源、账号/会话范围及稳定去重标识；通过 Electron 主进程持有的本机命名管道终端连接认证、上传业务对象，再提交 `TerminalEvent`。对象上传完成、`RECEIVED_DURABLE` 和 `CORE_COMMITTED` 是不同阶段，前两个不证明已写入 H。服务端分配接收位置、接收时间；终端不伪造这些字段。
2. **重连和去重不能丢。** 新连接重新认证、新 session；事件重投复用来源键、事件 ID 与相同内容。容量背压按类型化拒绝处理；I/O 结果未知不换 ID 当新消息。游标/已接收但未入 H 的暂存如影响未来处理，必须有显式版本化/恢复合同，不能在桥接程序私藏权威“记忆”。
3. **别人不是 u*。** 当前 `UserText` 只有文本，没有微信账号、第三方说话人和会话绑定；不能把微信来信直接套成用户管理命令，也不能在自由字符串/bytes 中塞未登记私有协议。第三方消息的内容不授予查询全部历史、成长管理、授权或执行能力。确切消息、来源、时间与联系人身份映射交后继契约卡设计。
4. **回复在核心决定后才发送。** 计划→权限闸门→Q/outbox→绑定凭证的执行器→真实结果入 H。发送目标、她的账号、原样正文/附件、操作种类必须与获准载荷绑定；需要审批时遵守 I26，显示并消费同一载荷。一般 T3 与管理权限不因她的社交默认信任一并放开。P5-05 的纯谓词与载荷快照不是完整认证/跨重启一次性凭证；P5-40/P5-41、P5-14 的后继接线仍须完成。
5. **采用最新网络生活决定。** 她以自己身份的消息和约定默认信任；涉及 u* 的事项按 V2-89 事后通知；不恢复旧 `social.commit` 一律逐次 T3 的读法。诚实底线、用户秘密结构隔离、外部人不能改变权限仍保留。消息数/联系人数只设 V2-104 的防程序循环或被操纵刷屏保险丝，不重新规定正常社交额度。外部平台的窗口/限流是客观能力限制，要记录，不冒充她的偏好或内部保险丝。
6. **发送不明就保持 UNKNOWN，不盲目重发。** 过期凭证不能因醒来/恢复联网重新有效；结构重放不重复发送。微信撤回作为后来发生的事件，不抹去已发生的历史。[CONTRACTS §§4.4、6](../../docs/CONTRACTS.md)、[ADR 0032 §§6–7](../../docs/adr/0032-presets-as-starting-points.md)

### 各路线的具体差别

| 接线点 | 官方客服 API | 电脑版界面 |
| --- | --- | --- |
| 入站来源 | 校验官方回调签名/加密与租户、客服账号范围，再拉取消息；以平台消息 ID 等构成去重依据（具体格式待契约）。不是把公网 webhook 直接暴露成核心管理入口。[S6][s6] | 限定她的进程/窗口与会话；UIA/OCR 观察和原始消息分开。没有稳定 ID 时不能靠“相同文本只留一条”去重，因为人可能真的重复说同一句（设计推断） |
| 外源性 | 确认来自别人的回复可按现行外源分工进入核心；她自己发的消息、发送失败/平台错误不是“别人回应”的替身 | 屏幕读到本人发言或复制的引用不能再当新外源；发送人/方向无法确认时留待核对，不伪造归属 |
| 出站核验 | 绑定客服账号、接收人和确切载荷，发送前复核会话窗口/权限，平台受理与最终投递分开。`sync_msg` 不能补读 API 自发消息，故 Q/outbox 必须保留原样输出。[S5][s5]、[S6][s6] | 发送前再次核对账号、收件会话、编辑框全文；用户改动、焦点变化或弹窗使核验失效时不继续。点击/按下发送不是已送达，界面证据不足就 UNKNOWN |
| 对外隔离 | 令牌/Secret 由可信凭据边界保管，核心安装令牌和平台密钥分开；中继不持有核心写权限或她的状态 | 执行器只能操作她的专用窗口，不能因为看见别的窗口就读用户主号/剪贴板/文件；能力不足写入后继阻塞，不以提权或注入补齐 |

上述外源分工依据 [v2.0 §§1、2.4、8](../../docs/echo-core/echo-core-v2.0-first-principles.md)、[ADR 0032 §3](../../docs/adr/0032-presets-as-starting-points.md)。她的发送、平台结果和人的回复都可是真实记录，但是否成为成长证据仍由核心规则判定，适配器不算关系分数、不保存人格提示、不补自动问候脚本。

## 单实例、睡眠和关机：影响及待选做法

[ADR 0028 D4](../../docs/adr/0028-lifecycle-single-instance.md)要求同一时刻只有一个她；以下均是选项，**没有替用户选择，也没有修改电源/登录设置**。

| 选项 | 体验与限制 |
| --- | --- |
| 接受她只在电脑运行时回复 | 最直接。恢复后读取能取回的消息；遗漏与时间差如实记录，不补写停机期间的思考。客服可能已过 48 小时回复窗口，超过最近 3 天拉取范围的内容也不能承诺取回。[S5][s5]、[S6][s6] |
| 用户自行安排较长在线时段 | 仍只有本机核心；增加用电、维护和占用。是否改变休眠设置只能由用户决定并操作；锁屏、网络、微信登录态仍可能使 UI 路线不可用。[M4][m4] |
| 官方路线增加只接收的中继/暂存 | 只收平台通知或获准范围内的原始数据，不运行模型、不替她回复、不产生她的历史/状态。可降低漏通知风险，但增加公网端点、数据副本和费用；暂存范围、寿命、密钥和持久确认语义均须另批。中继离线/保留期满仍可能丢消息（设计选项） |
| 使用平台非接待时间提示 | 仅作为可识别的平台状态提示候选；不能伪装成她在停机时写的话或记成她已说出。官方客服转 API 管理后原生接待规则可能不生效，兼容性**未核实**。[S10][s10] |
| 以后迁移到专用设备/移动端 | 是搬迁同一个她，旧实例须停用/封存；不是 PC、手机、云端各开一个核心。设备可用性、微信登录支持及成本另行研究。ADR 0028；不承诺 v1 已支持 |

离线消息的“平台发生时间、适配器观察时间、核心接收/提交时间”必须区分。不能把恢复时读取到的消息说成停机时已经经历；也不能因处理晚就自动取消真实结果的资格，时间合同按 ADR 0032 §7 交后继卡明确。

## 登记人责任、封号后果与隐私

### 账号责任分别由谁承担

- **企业微信：** 注册主体、管理员和最终用户按企微协议各自承担相应责任，资料须真实且妥善保管凭据；她的昵称不替代企业/登记人的责任。若借用现有单位租户，还涉及其他管理员、企业数据管理与许可问题，本卡不默认用户拥有这样的授权。[S2][s2]
- **个人微信：** 协议把使用权限于初始注册人并禁止转让等，账号行为由登记人负责。用专用号避免主号接入，不等于“交给 AI 使用”已经得到许可；该用途需平台确认。[S1][s1]
- **共同后果（推断）：** 功能受限/封禁会中断联系、可能失去平台端联系人及聊天访问，申诉需登记人处理；本机 H 能保留的只是此前真实提交过的记录，不能恢复平台账号。实名/手机号关联的其他账号影响未核实，不承诺主号绝对免于平台连带影响。不要自动换号绕处罚，或把未送出的旧行动换新账号盲发。

### 对方是真实的人，消息不是可以随意留存的数据

以下是对两条路线的隐私设计要求与待决项，依据 [ADR 0011 §§4、6、后果](../../docs/adr/0011-network-life-boundaries.md)、[ADR 0032 §§3、6](../../docs/adr/0032-presets-as-starting-points.md)与[个人信息保护法][l1]：

| 环节 | 拟遵守的边界或必须先解决的问题 |
| --- | --- |
| 读取范围 | 只读她自己的获准会话和必要的来源资料；不导入主号通讯录、其他窗口、整份联系人画像或无关群成员。头像、微信标识、手机号、位置、附件均可能涉及真人信息，不能因它们在界面上可见就任意扩收 |
| 核心与日志 | 必要的对话及来源经核心进入 H；调试日志不保存正文、头像、截图、平台凭据或完整联系人表。缓存/游标不得变成独立关系数据库；真正会影响行为的持久信息须有权威归属。截图/OCR 原件是否需要保留、保留多久、怎样做最小化，须后继契约设计，不能默认为永久截屏 |
| 远程模型/中继 | 本地处理和调用云端是不同决定。向外部模型发送 o、c_task 或把原始消息交给中继，会增加接收方；须明确范围、地点、用途、保存期与权限，不把用户允许开微信视为第三方对云端处理的同意。跨境等义务是否适用未核实 |
| 记录可见性 | u* 在现行设计里能看她的全部记录，不能向对方承诺“只有她能看”。别人问还有谁能看时怎样回答仍是规格未决项；不在本卡偷偷补一条自动话术。进入真实交往前须决定符合适用义务的告知安排；这与“是否主动说自己是 AI”应分开处理 |
| 忘记与删除 | 她可以承诺不再提起，不等于 H 已物理删除。对方撤回消息也不自动抹去历史。个人信息保护法如适用，其 §47 等删除/停止处理要求不能靠本地只追加设计直接免除；适用范围及真正抹除机制须先解决，不能骗对方说已删除 |
| 收到敏感资料/拒绝存档 | 不为实验收集身份证、病史、支付、未成年人等真实资料。未来对方拒绝存档、撤回同意或要求删除时的处理，以及对会话存档的提示/同意流程，先设计再对接真人 |

法律核查的范围有限：个人信息保护法 §§6、13、17、47 涉及必要性、处理依据、告知和删除；§72 对自然人的个人/家庭事务有例外。**本项目是否落入该例外、适用哪些地区法律、云端处理的具体义务未核实**，不根据用户时区推定管辖，也不以“私人账号”直接认定免责。该缺口不阻塞研究文档交付，但不能据此启动对真实人的数据处理。[L1][l1]
