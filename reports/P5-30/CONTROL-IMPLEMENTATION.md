# L0-control-1 实现与运行前绑定

档位：重档；核心纯函数适配、条件性重算导出及预注册执行。

本版只使用合成输入，在已有 G、旧 C、旧 F 上进行对照。无模型、API 或 GPU，不打开 LIFE/REHEARSAL。v0.2 的世界和主判据保持；未就绪机制在运行前记 not_run。执行包与源码推送后才允许启动生活轨迹。

## 输入与参数

- G/C/容量/保护候选数/空 R/零 x/零 attachment 起点来自 `core-kernel/src/recompute/tests/fixture.rs` 与 `tests/legacy.rs` 的 old-v1 合成资源。C 实际参数以导出的 ThetaEstimatorParameters 为准；G LawParameters 中未被 G 消费的旧 C 字段不替代 C 参数。
- F 的 g_max 绑定 C 的实际上界 3，r_max/w_min 绑定 G 资源；kappa=0.5 来自 `profiles/structural_fixture/fast/fixture.json`，外源事件权重恒为 1，kappa 在本输入域不参与驱动。不是生活校准。
- 合成资源对象使用完整绑定字节的 SHA-256 和长度；没有借用正式 genesis 或黄金向量的对象摘要。
- 候选在首个机会对称提出；人物和情境分别作为两个谓词。主要模板对应正负坐标单位方向；玩对应联结、成事两个方向。反馈竞争解释是正方向的“U 出现”和“U 有时间”，用 G 的 LP2 分摊，不指定份额。反馈之外该两候选无吻合。
- xorshift64* + Fisher–Yates 固定 12 机会块内部顺序。种子 53001/53002；两配对共享外生顺序。W6/W7 严格保留 +1/4、−1/4 顺序并交换领域。
- 每日机会均匀位于运行区间内部；停机列表仅去除每日运行区间以外的时间。日检查点是只读投影，不提交额外心跳。
- O5 采用已登记 c=±1/8、k=0/1/4/1/2，坐标选联结；其他坐标沿 W0 基础模板。环境读取上一步已提交 x，输入表中冻结环境函数，运行时记录实际生成的 a。无扰动、181–210 日冷遇后恢复、181 日起永久冷遇三支；各 1095 日、每日 4 机会、8 小时、两种子。

## 清单与证据预算

180 个可运行生活单元：126 个 W0–4/W6–7，6 个 W5，12 个 W9，36 个 O5。20 个按种子登记的缺口单元为 not_run：W8 各支的缺席资格适配、O16/O17 的新机制、完整自主行动反馈。

主轨迹总计 435810 个事件，单条最多 4380；完整运行域共 91980 个日检查点（另有各条 genesis）。Q2 候选来自固定 7 世界 × 4 检查点，在同种子/密度/运行时长内穷举；无匹配不补样本。每个合格前态的 ±共同新事与无新事分支复用，同一前态不为不同配对重复计算。

原始事件状态/解释/参数/检查点保留；事件与日探针以 gzip level 1 流式无损保存，避免积累未压缩轨迹。准备表和全部结果 create-new，不覆盖已有文件。剩余磁盘运行前约 16.8 GB；未压缩预算以每事件 128 KiB、每日 512 KiB、每检查点 16 MiB 作为工程上界估计，压缩比未知，不能当已实测容量保证。磁盘故障保留既有输出并报告，不能删旧证据或缩矩阵继续。

## 顺序与检查

运行器只调用已有 Φ/F_in/G/C/F_out，逐事件暂存完成后更新内存快照。事件表即 oracle 解释和原因来源；独立机会各有唯一原因；本域不包含重复报告冒充独立证据。真实 P5-24 来源认证/缺席适配未接入，不对它们签验收。

P5-26 仅在 synthetic-recompute feature 下导出纯接口；evidence 不必导出。三条机械记录实际消费 start/step/replay，比较完整 R、分配、θ 估计器和 x；生活主轨迹另从 genesis 以同一 Kernel::advance 整段重算。后者不是独立第二实现，完整第二实现 unavailable；没有使用逐前缀保留全部审计的 replay 来冒充低成本运行。

长跑仅 release 优化构建；debug 二进制拒绝 run/continue。预计最慢为 G 对历史分配的逐事件校验与重算，其次为同实现完整重放和 Q2 分支。没有以试跑成长轨迹估计耗时。运行后报告实际阶段耗时。

原始失败：编译适配错误、资源类型绑定错误、把 CanonicalV1 二进制当 JSON 读取导致的机械测试失败均保留日志。修正限本卡适配，未改算子、阈值或断言。

## 限制

结果是第一版对照 / 非正式结论。空 R、零依恋的合成测试起点不是诞生起点。无独立第二实现、生产来源治理、H/L 原子持久化、迁移、载体、真实生活或完整 P5-30 验收声明。正式校准和新规律保持各自后继义务。

磁盘保护：启动每个单元前须至少有 2 GiB 可用空间（大于按上述单条上界估计的约 1.3 GiB）。不足时写 resource-stop，保留已完成与未运行清单；不清理用户文件、不替换失败单元。此为工程资源边界，不是成长早停判据。

## 冻结前验证记录补充

完整工作区首轮为 debug，内核与存储等已通过；在既有 fact-view 长测试消耗超过 500 CPU 秒后主动中止（退出 0xffffffff），原日志与中止说明保留。不是断言失败，不作为完整通过。随后完整工作区改用 --release 重跑，已通过（包括原先中止的 fact-view）；长生活运行同样拒绝 debug 构建。

系统 Python 没有 mypy；未安装新工具，改用 D 盘既有 P5-42 验证环境的 mypy，四个 Python 文件 strict 检查通过。此处只复用检查工具，不读取旧实验数据。`cargo metadata --offline` 查询全平台依赖因未缓存 errno 失败，不影响已锁定 Windows 构建；未下载或改依赖。

最终冻结前：工作区 clippy -D warnings 通过；新增重命名阴性对照机械验证通过，Q2 每个共同序列用双份相同完整状态逐步比较。分析按单条/成对流式读取，Q2 只保留四个候选检查点，避免全矩阵轨迹同时驻内存。
