## 改动与核查范围

- `windows-snapshot.ps1` 在序列化前投影：全机仅进程数、working-set 字节总和、private-memory 字节总和、累计 CPU 秒数及监听 TCP 数量。内存求和不是去重后的物理内存占用，CPU 秒数不是瞬时占用率；不声称测量 GPU/显存。
- 项目进程必须同时命中固定名称和本次 checkout 的路径边界；路径只在内存中判断、不导出。同名外部 Node/Electron、相似目录前缀、不可读路径均不导出。外部安装的项目工具也保守省略，避免将其误归属项目。
- 移除全机端口归属、地址与端口明细、可能带用户名的会话列表。保留交互状态、当前 session ID、会话事件时间/ID 与未知锁屏状态；采集失败仅写固定 `unavailable`，不写原始异常文字。
- `windows-evidence-text.ps1` 对 P0-01、P5-02、P5-03 日志中的 checkout、用户目录、临时目录和工具链环境路径前缀作脱敏。保留测试输出、源码相对位置、退出状态与原有工作流失败分支。
- 核查 P5-02 的 rustup/clippy/core-store 日志、P5-03 的 clippy/gateway 日志及 Rust 测试输出代码，未发现全机进程或网络归属枚举。P0-01 截图来源为 Playwright 页面/Electron webContents，不采集整个桌面。
- 新增合成夹具验证：后台进程仍计入资源总量；外部同名进程、名称/路径/标题/命令行、端口归属和异常文字不能进入公开快照；日志脱敏不吞掉失败文字与原生命令非零退出码。

## 产物核对方法

下载本次手动 run 的三类产物；检查 P0-01 所有快照的字段和进程投影、文本日志及 manifest SHA-256，检查 P5-02/P5-03 文本中是否含进程清单、端口归属或其他程序路径。历史清单按分页 API 的 `expired=false` 筛选，再逐个检查内容，不仅凭产物名称推断。公开报告只保存元数据和统计，不复制泄露的程序名、路径或窗口标题。

P0-01 已核查 28 个下载文件：9 个快照，只有窗口等待时快照含 13 个 checkout 内 Electron 进程；其余快照的进程明细为空。所有快照字段符合投影，没有路径/标题/命令行/端口归属；当前主机非项目进程名称只在内存中用于检索，文本内精确带引号名称或 `.exe` 名命中为 0，未保存该名称清单。两张图片仅含应用自身画面。Playwright 原有 `e2e-results.json` 中保留本次作业的 checkout、证据目录与 Node 工具位置，共 13 种路径，均在 runner `_work` 下；不含其他程序路径。

已下载的 27 个 manifest 条目 SHA-256 全部一致。另有原有边界：manifest 列出了 `test-results/electron/.last-run.json`，但 upload-artifact 默认排除隐藏文件，产物不含它；因此不声称全部 manifest 条目都已下载验证。本次不改变上传逻辑；这不是隐私检测失败，也不将缺失条目记作通过。

三类新产物合计 45 个文件，37 个文本/JSON 文件；P5-02 的 3 个文件和 P5-03 的 14 个文件未检出绝对本机路径或全机进程/端口归属字段。对全部文本重复做当前非项目进程名称的内存检索，精确带引号名称/`.exe` 名命中为 0。W02：51 个单元测试和 3 个文档测试通过（单元测试 722.34 秒）；W18：42 个测试通过（103.75 秒）。
