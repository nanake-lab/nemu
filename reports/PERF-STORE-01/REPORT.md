# PERF-STORE-01 测量准备

Ubuntu 手动计时工作流已写好。两个平台均缺改前样本，目前无法确定最慢测试、函数热点或提速幅度。WSL 问题已由托管机方案解除。下一步需要 Windows 空闲测量窗口，并由维护者安排 Ubuntu 工作流进入默认分支。

## 测量口径

[工作流](../../.github/workflows/perf-store.yml)仅由 `workflow_dispatch` 触发，在 `ubuntu-latest` 用 Rust 1.99.0 运行 core-store。基线固定为 `6734adc2bfe8b145e8062a2fc669dd2024dd2ba6`，已包含 #238。留空 `candidate` 可先测基线，提供改后完整提交号则在同一台托管机上依次测两版。每个修订记录实际 SHA、平台镜像版本、架构及工具链。

先以 `cargo test -p core-store --locked --no-run` 预编译，再用 `-- --list` 核对整包、库测试和文档测试清单。每轮运行一次完整包，然后逐个按名称用 `--exact --test-threads=1` 运行。每次校验退出码、成功测试的名称及通过数，并检查计时段内是否重新编译包。三轮均成功才生成该修订的中位数及最慢 15 项。

| 字段 | 计量范围 |
| --- | --- |
| `harness_s` | Rust 测试框架输出的耗时，保留框架精度。整包数据为各测试框架报告值之和，最慢 15 项按此字段的中位数排序。编译失败类文档测试包含验证编译失败所需的工作。 |
| `process_s` | 从启动 Cargo 到进程返回的实际时间，含 Cargo、测试进程及 rustdoc 启停开销。预编译和枚举在计时前完成。 |

Actions 产物按修订保存测试清单、逐轮原始计时、进程输出和中位数，失败时保留已生成的数据。正式运行后须将证据归档到私有证据库并登记提交号与 SHA-256。
