# DESIGN-CLOCK-01：时钟、可信恢复与长期时间域方案

建议把“外面过了多久”和“她确实运行了多久”分开记：前者让心情按真实经过时间平复，后者只由可核验的运行区间累加。关机一周后正常恢复、开着但长时间没人输入，都不该只因间隔长而报错；不能证明的部分如实记为未知。迟到结果仍按既定角色和一次消费规则处理，不能因发生时间未知或排队太久而失去感受资格。104.25 天是现有 C 数值版本对一个完成段的限制，建议保留旧版本，并另行批准长段转换的新数值版本，绝不截断或拆成多次学习。下面给出可批准的推荐方案、备选及七项白话问题；未获批准的部分均为候选。

## 3. 为什么选这条路线

### 3.1 先比较不同路线

| 路线 | 能解决什么 | 排除或保留的理由 |
| --- | --- | --- |
| 一只墙钟管全部时间 | 记录简单，日历易懂 | 排除：可调日期、离线与运行混在一起，不能证明存在年龄。 |
| 只用进程单调钟 | 同一次连续运行可求间隔 | 单独使用排除：跨进程/boot 不能直接相减，停机的客观时间丢失，Φ 会冻结。 |
| 用心跳次数、消息数或 CPU 忙时计年龄 | 容易实现 | 排除：重复报告会加速年龄，正常等待被漏计；两次心跳也不能排除中间挂起。 |
| 每次启动必须联系外部授时方 | 可提供跨重启客观时间证据 | 留作部署备选：失网不等于核心没运行；外部授时也证明不了核心运行区间，且不能只信远端自报。 |
| 保存全部纳秒为128位或任意精度整数 | 扩大或取消固定宽度上限 | 备选而非推荐：增加编码、大小与资源边界；104天问题在浮点转换，现有64位整数已经能记下长段。 |
| 整数时间事实＋可信映射＋运行区间证明 | 同时保留客观时间、存在时间与未知 | **推荐**：复用 H、Q、单写事务和资源版本，不再造一份权威年龄数据库；增加的只是现有语义缺少的证据。 |

## 4. P5-52 的基础时间语义候选

### 4.1 域、身份与精确整数

“域”回答这个数在哪把尺上，“epoch”回答这把尺从哪次连续解释开始；单有一个整数不构成可信时间。

| 概念 | 推荐含义与比较范围 |
| --- | --- |
| boot | 经可信本机启动证据识别的一次系统启动；不能用 PID、墙钟日期或一个随意字符串冒充。无法确认是否同一启动就记身份未知，不跨启动减单调值。 |
| 核心运行实例 | 一次核心服务的实际连续生命周期；同一 boot 下核心退出重启也产生新实例，与 OS boot 分开。它证明“哪个核心”，不是第三只时间钟。 |
| clock epoch | 某来源、某域的标尺连续性区间；重启、计数器重置、不可连续解释的校正或来源切换需明确边界。正常挂起是否改变 epoch 由来源语义决定，不能只换编号来抹掉异常。 |
| 单调区间域 | 用于同一可比区间内的客观经过时间；资源说明它是否包含系统挂起、分辨率、频率换算与误差。没有这些说明不能拿它与墙钟直接核对。 |
| 日历域 | 说明发生、观察和提交在日历上的位置；推荐按 UTC 标识记录、另保留来源的时间尺度/闰秒或平滑策略及版本，展示时区不是计算输入。日历到连续经过时间须有明确映射，不能默认每种“UTC”实现都一样。 |
| process 时间 | 从已提交锚点延续的客观经过时间坐标；每事务一次捕获，供 Φ 和 ProposalBinding 使用，包含可证明的离线经过时间，不是核心运行累计值。 |
| 存在时间 T、目标年龄 d | 由同一 H 前缀里的运行证明求出的派生量；不是可由模型设定的钟，也不是用日历校准出的运行时间。 |
| 提交顺序 | H 的提交身份/顺序决定 F 次序；时钟同刻或不可比都不改变该顺序，不以给时间加1制造严格先后。 |

推荐复用现有**无符号64位整数纳秒**表示非负时长/本地偏移，日历读数保留现有有符号64位整数纳秒语义，并明确其时间原点。前者最大 `2^64−1 ns`，约584.55年；后者从原点沿单方向约292.27年，不能与总运行时长的范围混用。P5-52补齐域与版本语义，不因104天限制再引入一种大整数。TypeScript使用可精确承载既有整数的路径，不经 `Number` 中转；边界加减、区间求和和映射的中间值必须精确并检查溢出，绝不回绕。表示溢出是编码/计算边界，不能冒充时间异常的第四种业务原因；本版不承诺无限寿命，若以后确需超出此范围再发布扩位和迁移方案，不能暗改单位。

映射允许不同来源的分辨率不同：以整数边界包住量化误差，不声称记录纳秒就测准到纳秒。若存储内部按块保存，拼接必须先恢复同一个精确总整数；块边界不得成为 F/C 事件或符号段边界。

### 4.2 时间事实怎么表达未知与可信

以下是供 P5-52/72 落字段的语义清单，**不是新消息定义**：事实身份及它指向的内容/事件/执行实例、观察者和来源证据、域/boot/epoch、时间值或边界、证据生效的 H 前缀、版本与纠错关系。可信性由核心核验证据得出，不接受发送者自带 `trusted=true`。

| 表示状态 | 含义 |
| --- | --- |
| 已定位的点 | 在指定域及分辨率下有单个整数读数；它仍可能有测量不确定度，不能自动等于精确物理时刻。 |
| 有界区间 | 下界、上界及其包含关系都有依据；上下界相等才退化为同域的点。 |
| 单侧界或未知 | 只知道至少/至多某时，或全不知道；记录缺失理由与已有证据，不用0、最大整数、当前时间、NaN或假 epoch 代替。单侧界不足以界定恢复 Δ。 |
| 不可比 | 两个事实各自已知，但域间没有可信映射；是这对事实的关系，不要把两条原事实抹成未知。 |
| 冲突 | 保留互相矛盾的来源/映射，不挑对年龄、感受或执行许可更有利的一份。外部事实冲突不自动变成本机时钟故障。 |

映射须说明原域/目标域、有效区间、偏移/速率关系、误差边界、证据和版本。只能在覆盖范围内使用；串接映射要传播全部误差，缺一段即不可比；多条映射不能暗选有利路径，互相不相容的有效证明进入冲突治理。映射正确只证明日历位置，**不证明核心在运行**。

对区间语义关系按 ADR 0035 §5.1：所有可行赋值都满足才判真，全部不满足才判假，其余未知；共同来源带来的相关约束也保留，不能任意把误差消掉。比如发生在[10,20]、观察在[15,25]，不能断言发生严格早于观察；发生在[10,12]、观察在[15,18]则可断言。数字仅为区间示例，不是容差配置。

### 4.3 什么足以成为可信来源

推荐复用 Trusted Core 的本机采样边界与版本化资源，建立两类互不替代的证明：

1. **经过时间证明：** 同 epoch 的连续区间读数；跨 epoch 则是覆盖两端的可信日历/授时映射及误差证据。只看到两种钟一致不证明它们独立或正确，仍须明确来源、校正记录和有效范围。
2. **运行证明：** 受信采集边界关联同一核心实例，证明区间内服务连续有效、系统没有未处理的挂起/实例替换/采集缺口，并记录其完整性依据；并非只证明机器开机或进程尚在列表中。正常无输入、等待锁或 worker 不占 CPU，不因此扣除运行时间。

Windows 适配器的具体 API、启动身份来源、挂起通知覆盖与误差参数必须由 P5-53 做原生核验后绑定资源；本卡不以一个 API 名称代替上述证明。误差边界应由分辨率、成对采样的时间跨度、两端不确定度及来源保证的漂移界组成；会随经过时间增长的误差不能拿固定短时样本替代。所有数值须有供应方保证或预登记测量依据，当前**待测、未填值**；有限样本最大误差本身不是未来所有时长的硬保证，超出来源保证范围需换有证据的映射。

网络断开只影响需要联网的来源，不自动否定已有本机证据；墙钟差能被可靠界定的一周离线应正常恢复。没有任何可靠来源能界定跨重启间隔时，如实故障；不能保证“随便坏成什么样都恢复”。

## 5. checkpoint、恢复和原子发布

### 5.1 checkpoint 要绑定什么

推荐在已有权威事务/检查点机制内绑定：谱系、分支与父提交；对应 H/D/L 前缀和 x/R/θ/Q/U 根；已提交 process 锚点与采样证据；boot、epoch、核心实例；有效映射/运行证明的前缀与资源版本；未闭合运行/停止/未知边界；尚未完成的提交观察与行动。缺初始时间证据时可记未知，不能制造“genesis 前一直在运行”。

checkpoint 是对**某个已提交状态**的恢复依据，不是另一份可先于状态落盘的墙钟文件；恢复先核验它是否属于可继续的提交链、当前单写者及最新可恢复前缀。恢复旧备份不能使消费键、行动或已用权限归零；尾部无法恢复走已有有损恢复/分支规则，不在此伪造单调延续。[系统方案 §22](../../docs/echo-core/echo-core-system-plan-v1.0.md)的检查点与行动核对要求保留。

### 5.2 一次处理与一次提交，不能多算两遍

推荐按下列顺序落地：

1. 从已提交基线读取时间证明。Γ 过滤的重复入口不触发 F、不推进原状态锚点；它自身的接收事实可以按既有入口路径保存。
2. 获准处理时只捕获一次 process 时间及证据，冻结其投影、read set、解释与资源绑定；所有 worker 沿用。事务失败时这些 staged 结果不成为新锚点。
3. H 的作用记录、x/槽、必要的 R/θ/L、Q/U、消费标记、process 锚点及其证据**一起原子发布**。时间不可信时不能只提交新年龄或消费标记，让状态另一半留在旧前缀。
4. 提交成功之后才能观察“持久化已经完成”。保留原事务的提交身份，另将完成观察追加为系统记录；该记录自身提交后才是权威证据，不回填或改写原事务。
5. J/行动从已提交状态投影到实际使用时点，检查新输入 frontier 和当前许可；计算等待时间不消失，也不在提交处对原事务重算一次 drive。重放只读记录，不取今日时钟或重新调用模型。

这里有一个真实限制：**事后取得的完成时间不能先存入已完成的同一个事务**。推荐原事务原子保存作用/提交身份与已知下界；完成观察给出其上界，或由可验证的存储完成证据提供更窄区间。外部看到的 `commit_wall_time` 是完成观察，不冒充精确落盘瞬间。若崩溃发生在成功落盘后、完成观察持久化前，恢复认定该提交已存在，但完成时刻保留未知或较宽区间，后续证据可以补齐；不为补一条完成观察无限递归生成“观察的完成观察”。

**年龄仍以真实作用提交身份为起点，不偷换成 process 时点。** 对某提交的真实落盘时刻若只能证明落在 `[L,U]`，存在年龄只能使用确定在源提交之后、确定在当前提交之前的运行部分（§6.2）。当前事务的那次 process 采样在因果上早于其提交，可作当前提交的已证下界；它不等于提交时刻。此前提交缺上界时，年龄标为未完全确认，不能从它的 process 时点开始假计运行。后续收窄边界只影响新 H 前缀的计算，保留既有结果。

此候选保留[核心算子 §17.2](../../docs/echo-core/ada-core-operators-spec-v1.0.md)一次 process 捕获和数学生效时点，也保留 ADR 0038 的提交锚点；它不承诺精确知道存储引擎内部的瞬时落盘时间。U3 批准的正是这种区分和补证方式。

### 5.3 恢复判定表

| 情形 | 客观时间/Φ | 运行时间/年龄 |
| --- | --- | --- |
| 同 boot、同 epoch、连续来源 | 用符合来源语义的单调差；墙钟用于交叉核验，长间隔本身无罪 | 只累加对应核心实例的有效运行覆盖；不能用单调钟前进自动证明核心运行。 |
| 同 boot 核心重启 | 有可比采样时可恢复经过时间；新实例另记 | 旧实例结束后到新实例开始之间不补运行；不因 boot 没变而合成连续实例。 |
| 系统休眠/挂起再恢复 | 用包含该间隔的来源或可信映射恢复；若所用单调钟排除挂起，先加入有证据的挂起经过时间，再与墙钟比较 | 已知未运行部分扣除；边界没记全的部分未知，不能猜满。 |
| 一周关机后重启 | 在误差已界定的可信恢复下，完整推进一周的客观经过时间；无 `max_interval` 拒绝 | 关机区间不增加 T、d；恢复后的实际运行再计，原累计不归零。 |
| 核心开着、长时间无输入 | 下次处理/读取按真实 Δ 投影；没有新证据时 R、θ 逐位不变 | 有连续运行证据则正常增加 T、d；没有 F 事件不等于停止。 |
| 崩溃后重启 | 可恢复客观 Δ 时不因崩溃就丢掉它 | 只到最后有证据的运行边界；最后证明至确知退出之间保留未知，已知退出至重启为停止。 |
| 远端发生时间未知或跨 epoch 不可比 | 仅语义时间关系未知；本机经过时间仍可信则正常处理 | 不改变本机运行证明；也不取消该记录的 F 资格。 |
| 所需跨重启间隔无法给出可靠有限界 | 时钟结构故障：保留可恢复状态、m=0、不主动、只回应，走既有恢复路径 | 不补0、不补一整段运行；已确认部分及未知范围分开显示。 |

对客观时间，推荐同 epoch 使用可信单调采样的名义差；跨 epoch 使用可信来源记录的名义恢复差，并记录其有限误差区间及映射版本。名义值必须由来源测量/映射给出，且落在有效证明允许的范围内，不由模型选取。若可信来源只给出完整、非负、有限的经过时间区间 `[L,U]`，U1 推荐显式采用整数 `L + floor((U−L)/2)` 作为该次计算代表值，连同原上下界与求值版本一起持久化；这是**待批准的有界测量处理规则**，不是已知的真实精确时长，不适用于只有一侧界、未知来源或互相矛盾的证据。多个来源由冻结资源指定取用次序并交叉核验，不临时挑选对状态有利的一份。

这项候选不改变Φ按客观经过时间的规律；它补的是测量存在有限误差时标量输入如何确定。选择中点的理由是在没有额外信息时兼顾两端，减小最坏绝对误差；中点在两个整数之间时固定向下取整是显式的版本约定。误差和采用来源须可见，恢复报告不得超出来源精度声称轨迹精确；相同绑定重放使用同一代表值，不重测或重选。**存在年龄不使用此中点**，仍只计§6的已证明运行部分。日历时间后来被更正时，不能将新偏移悄悄加到旧 process 锚点；走 §6.4。

## 6. 存在时间与目标年龄

### 6.1 只从已证明的区间得到

在同一已提交 H 前缀 P 下，先解析有效运行证明、停止证明、映射及纠错，再形成三类不重叠的覆盖：**已知运行、已知停止、未知**。采用半开区间 `[起,止)` 计长度，同刻边界按 H 的提交/生命周期因果关系处理，零长度不增加时间。重叠的运行证明先求并集；它们重复、拆分、迟到或换了报告身份都不加倍。

运行证明之间要能辨认同一物理区间；跨 epoch 未证明可比、或无法排除是同一段时，不把两段直接相加。已知运行与已知停止实质冲突时，不靠优先级随便选一方，走纠错；只收窄端点不确定区间不等于否定旧证明。

T(P) 是有效运行区间并集的整数长度。可以缓存这个派生值，但缓存须绑定 P 和证明解释版本，可从 H 重建；缓存丢失不改变结果。时间事实、心跳或系统维护记录不是外源经历，不因计龄而进入 C，也不把停机自动解释为 u* 缺席。

### 6.2 年龄按提交锚点截取，再求并集

固定现行目标来源提交 `c_source`，当前作用提交为 `c_now`。从**同一 P** 的证明取得两个提交锚点和运行覆盖，把确定处于两次提交之间的运行部分截出来，再取并集求长度，得到 d。不能用“当前累计T”减去“目标当时冻结的T”。

如果源提交只定位到 `[Ls,Us]`，当前提交只定位到 `[Ln,Un]`，确定在两者之间的部分最多为 `[Us,Ln)`；再与确定运行覆盖求交，且只用存在可信对应的坐标。`Us ≥ Ln` 时没有已确认正长度，不造负年龄，也不将“已确认0”说成“真实年龄确实0”；若锚点只有一侧已知，使用可证明的部分，其余仍未知。若证明相互矛盾则不适用这条保守计量规则，必须进入 §6.4，不能用空集把矛盾吃掉。

这是一种对已证明区间的解释候选：端点不确定时只累计保证发生在锚点内的部分。它不要求猜一个精确提交时刻。真实提交身份、原目标和起点速度始终不变；真实目标更新才换来源起点，反思不重起。

以下用同一可比域的整数秒简写演示截取，**实际保存仍是纳秒**：当前提交在100；目标A源提交在40，目标B源提交在80；先有运行证明 `[40,60) ∪ [80,100)`，A年龄40、B年龄20。后来补证 `[20,90)`，有效并集为 `[20,100)`，A年龄变60、B仍20。起点前的 `[20,40)` 不给A加龄，B起点前的补证也不加龄；同一补证不能对两个目标都简单加50。旧前缀仍重放出40和20。

### 6.3 挂起、她的睡眠与崩溃

- **系统休眠、核心停止、核心实际被挂起：** 未运行部分不计。暂停/恢复的操作事实和实际完成边界分开；发出暂停意图不证明已经停止。
- **她为 GPU 研究进入睡眠：** 明确记录暂停思考/睡眠与恢复；若核心仍实际运行，按运行证明计时；若核心停止或挂起，不计那部分。睡眠标签本身不能强制年龄停止，也不能强制年龄继续。CPU忙时、模型是否正在产 token 都不是计量尺。
- **仅断网、排队、等锁、等模型、无人输入：** 只要核心连续运行且能证明，就计时；不能将一次等待当成停机。
- **崩溃：** 两个心跳之间可能有运行、停止和未知，不能由重启时的墙钟差把尾部全部补满。后续取得可靠退出/运行证据可以补证，日历映射单独不足以补运行。

最低实现需要在启动、停止/挂起/恢复和已有权威事务边界收集可持久的运行证据；正常空闲仍须有能够覆盖连续性的来源。是否增加定期 checkpoint 仅决定崩溃时可能丢失多少证明和写盘成本，频率待工程测量，不作为年龄规律或行为计时器。

### 6.4 迟到证明与否定旧证明是两条路径

**补证：** 新证明确认此前未知的运行，从该证明生效的 H 前缀起计算；只增加与源提交之后、当前提交之前相交且未计过的部分。重放旧前缀仍用旧证据。补日历映射不把已确认停止变成运行，不刷新目标来源、速度或消费键。

**纠错候选：** 否定旧运行/映射证明时，先追加冲突及其影响范围，撤销依赖该证明的“正常可用”状态，按既有时钟结构故障边界处理受影响路径，不保留虚假大年龄继续驱动。以固定 H 前缀、有效证据和明确纠错/规律版本在隔离的暂存结果中重建；核验通过后，把恢复依据、年龄派生版本、x/槽、相关 θ/估计器和 Q 屏障一次发布。重建期间若有新事实进入，发布前必须核对 read set/前缀并接续，不能覆盖新 Q。

需分别核对三种影响：

1. 只增加此前未知的运行证明：按 ADR 0038 的前向补证规则，不重写过去重访。
2. 已用的运行证明被否定：重建受影响的淡化、目标/槽作用；若 C 的时长也依赖该证明，按 P5-25 请求从 genesis 重算 θ，不能把修订时间接在旧估计器后面。
3. 客观经过时间证明被否定：既往 Φ 及其下游状态也受影响，不能只改 d 或只修时间字段；恢复须覆盖受影响的结构重放与派生计算。

旧提交、旧作用、旧时间判断和实际对外行动永久留在 H；“纠错后当前派生状态”不等于“过去真的如此”。外部行动不重发，消费键不归零，不能靠重新给旧记录取ID再感受一次。证据不足以完成上述重建时维持受限恢复，不以用户点击“继续”代替时间证明。完整纠错资源和回退由后继卡落地，U5 批准前不声称可自动恢复。

**C 的时长统计不能把年龄下界当完整观测。** ADR0038的d只计已证部分，并不授权C把未知时段当停止。推荐：需要完整运行时长的C候选若跨过未解决的未知区间，则保留旧θ及整个估计器，不推进其学习游标、不跳过该经历；事实留在H，补证后从有效历史重算接续。这是输入证明未齐的计算等待，不把已可信的客观Δ另判成时钟故障，也不取消F资格。若未知只关乎某目标的提交端点、而C所需的运行区间已经完整，则不阻塞C。后继快照须能表达待补算前缀；不能沿用 `elapsed−stopped` 自动把剩余全部算成运行。

## 7. 长时间与104.25天怎样共存

### 7.1 三种不同的边界

| 边界 | 当前事实 | 本方案 |
| --- | --- | --- |
| clock 的 `max_interval_ns` | `interval()` 对长间隔报 Jump，`restore()` 对跨 boot/epoch 的长墙钟差也报 Jump | 去掉“时长大所以故障”的业务判断，按 §8 检查真实异常；不把上限调大冒充解决。 |
| 整数表示范围 | 现行 process/running 多为 u64，墙钟为 i64；它们与 binary64 精确整数界不同 | 推荐保留，公开§4.1的有限范围；范围内精确记录长段，超界不回绕，单位不变。 |
| C 完成段数值域 | `duration.rs:6` 在 `T_ns >= 2^53` 返回 `TimePrecision`，调用点为一个非零符号段闭合时 | 旧数值版本保持原行为；新版本审批后才扩展，不把错误转叫 clock Jump。 |

`2^53 = 9,007,199,254,740,992 ns`，约104.249991天。限制的是**单个已完成符号段的运行时长**，不是谱系年龄、两次消息间隔、整个实验世界长度或离线墙钟时长。离线一周不会仅凭离线使运行符号段长一周；连续运行120天后才闭合的同号段则会触发旧版限制。未闭合段仍按 V2-95 不作为完成观测，不能在到104天时伪造反号来闭合。

### 7.2 长段路线与推荐转换

| 路线 | 判断 |
| --- | --- |
| 将时长截到 `2^53−1` | 排除：丢真实时间，隐藏改变 τ。 |
| 自动换成毫秒/微秒再塞进旧字段 | 排除：偷换单位、改变舍入与快照解释。 |
| 每隔若干天切成一个“完成段” | 排除：多次加入 log 和质量，改变一段经历的学习权重；检查点不是反号事件。 |
| 只用 `log(T_ns)−log(10^9)` 绕过秒转换 | 留作其他数值版本备选：运算次序与旧版不同，短段也可能不逐位相同，不能无登记替换。 |
| 完整整数保留至数学入口，一次显式转换为秒 | **推荐**：保持一段只计一次，秒仍是算子单位；允许长段的有限 binary64 近似，但不伪称所有纳秒仍可由浮点精确区分。 |

**推荐的新 C 数值入口：** 完成段保持精确整数 N；仅在需要 `ln(T秒)` 时，以舍入到最近、偶数优先，将精确有理量 `N / 1,000,000,000` **一次正确舍入**为 binary64 秒，然后使用版本绑定的 log 和原递推次序。不能先把大整数 N 舍入成 float 再除，声称等同一次有理数舍入。N小于`2^53`时须与旧版逐位一致；N达到/超过边界时新版本有明确结果，旧版本仍 `TimePrecision`。零时长单独计数，未结束段不入完成统计，对数平均及事件权重均不变。

这不是精度无损的浮点延长：长期纳秒记录精确，算子输入按已声明的数值版本舍入；相邻纳秒可能落到同一秒值。后继用独立高精度参照检查转换的相邻浮点边界、中点偶舍入、单调性、极值和后续 log/τ/λ 合法界，不以同一函数自测代替参照。不能仅删掉 `TimePrecision` 检查。

**Φ 的边界单独保留：** 现有 [fast/space.rs](../../core/crates/core-kernel/src/fast/space.rs) 用 `delta_ns as f64 / 1e9`，槽在 [fast/contribution/mod.rs](../../core/crates/core-kernel/src/fast/contribution/mod.rs)用同样 Δ。修合法长间隔只需让真实 Δ 进入既有 Φ，不需要换这条路径；尤其不能把上述 C 的新转换顺便用于 Φ。x/槽用同一 Δ、同一 pull，仍按 ADR 0035 §4.4，不分块反复推进；既有乘积有限性和数值故障边界不放宽。本次推荐的整数域没有扩张，Φ的公式、单位和数值次序都保持；若将来另选扩位，超出u64的适配须单列数值合同和独立参照，不能以“数学上等价”过关。

### 7.3 版本与迁移

后继记录同时绑定时间表示/映射版本、规律版本和数值资源版本。现有整数值及其单位保持；改变 C 数值入口时发布新版本，从 H 的有效运行证明、外源事件、记录的解释与同序递推重算，重建开放段起点及完整估计器。旧快照缺所需证据时不可猜造，旧版只读重放仍可用；切换必须有前后快照、重算差异、恢复/回退记录和 SYS17 验收，不能将修订后的运行坐标接到旧累计状态后直接续算。三态证明仍需后继快照表达，不能因整数宽度未改就跳过迁移检查。

**没有新外源学习事件就不改变 θ。** 时间表示、心跳、checkpoint 或完成观察都不产生新的 C 观测。旧版真正遇到长完成段时是 C 计算域不支持：保留旧 θ/估计器、记录故障并待合法修复补算，沿 V2-97；不能误判成时钟结构故障冻结全部体验，也不能签发该长期 C 已通过。

## 8. 怎样消除合法长间隔的 Jump

当前 [clock.rs](../../core/crates/core-runtime/src/clock.rs) `interval()` 第155行把两件事合在一起：`elapsed > max_interval_ns` **或** 两钟差超误差，都返回 Jump；`restore()` 第83行只因墙钟间隔长就拒绝。`start()` 第59行还要求该上限非零。已有测试把一致的 `sample(100_000)` 当 Jump，这个用例应改成合法长间隔正例，并保留真正两钟不一致的负例，不能只删断言。

推荐后继判定顺序：

1. 先核验身份/版本/证据与可比范围；boot/epoch 改变走恢复映射流程，不自动意味着时间倒退。
2. 同域时检查受比较时钟是否倒退；跨域时先恢复映射，绝不直接减两个 boot 的单调读数。已经确认的倒退不能用 epoch 重命名或 `anchor+1` 修掉。
3. 两钟先换到**同一时间尺度、同一挂起计入语义**，再比较差是否超过已界定的误差总界；包括端点误差、采样跨度和相应时长的漂移界。差等于界以内接受，严格超出才拒绝。缺来源依据不能拿一个大常数包住一切。
4. 跨重启的停机经过时间须有可信有限界；有合法长区间就完整恢复，无可靠界才走未知停机故障。时间格式坏、整数溢出等仍由输入/计算边界拒绝，不扩张业务故障定义。
5. 恢复候选的 process 锚点、证据与状态原子发布，失败不部分前进；消费与重放沿提交前缀保持一致。

时钟业务故障只保留用户指定的三类：**时间倒退；两种时钟的差超出已界定误差；停机时长无法界定**。现有 `Untrusted`/`EpochChanged` 等内部返回值要由后继区分“需补证/进入恢复”与真正不可恢复的上述原因，不能换个错误名字继续拒绝合法长离线。调度预算、处理延迟预算、权限到期和数值范围属于各自边界，不能重新引入最大心理时长。

交付前新增的 [ADR 0042 §§1.1、3.1](../../docs/adr/0042-cause-projection.md)进一步规定本模式B回复等待本轮有效理解完成，**不设理解等待截止**，解释失败只显示故障、不生成她的回复。本报告所说的既有结构故障“只回应”是能力上界，不保证每轮都生成角色回复；旧算子处理延迟预算不能借来覆盖此新决定，也不能据等待长就触发clock Jump。该追加不改变本方案的Φ/存在时间区别。

## 9. P5-72 的各个时间事实与一次作用

| 事实 | 记录什么 | 明确不能推出什么 |
| --- | --- | --- |
| 发生 | 某内容/行动结果发生的时间及来源，可能只有远端声称的点、区间或未知 | 远端自报不能证明准时，不能变成本机 process 时间。 |
| 可信观察 | 哪个观察者实际取得哪份内容、何时取得，含观察证据；多个观察分别保留 | 本地入口时间不替代所有观察，也不证明她当时已经理解。 |
| 接收 | 本入口持久接纳哪条记录的时间与身份；重复投递可有多个接收事实但仍是同一稳定记录 | 不回推首次发生/观察，不拿队列等待判断事情已经过时。 |
| 处理 | 本事务唯一一次捕获的时点、基线与 ProposalBinding | 不是 F 资格截止，不允许重试刷新事件年龄或偷偷重绑旧提议。 |
| 理解/作用提交 | 哪次提交使接纳/A/M 的合法作用生效；绑定相应阶段、来源前态与时间证明 | 不假称发生时就理解；精确落盘时间未知不抹去已提交作用。 |
| 完成观察 | 哪个可信观察确认上述提交已持久化，其日历时间/区间，按 §5.2 后续发布 | 不二次推进原事务，不当成新的心理刺激。 |
| 凭证期限 | 某凭证、行动、载荷及权限的有效区间和所属时钟证明，执行前重核 | 不决定已执行结果是否值得感受，不刷新旧 Q，也不因回执迟到重新准许执行。 |

时间事实复用 P5-52 的域、epoch、来源与映射，不另造一套 clock。发生/观察的可信关系进入 z，判断在 m=0 下记录；接收/处理/排队/落盘耗时不混入 z 当成外部事实。区间跨过许可边界、或执行时刻不可比时，不能证明许可仍有效就拒绝新执行；已经发生的结果仍按下表处理。

消费键严格沿 ADR 0035 §5.2，为“**稳定记录身份＋阶段（接纳、A、M）**”，不含时间戳、boot/epoch或依据身份。时间更正、重新接收、换进程都不能给同一阶段换一把键。每次都由单写者检查已提交消费状态，标记与 H 作用记录、状态和 Q 一起提交；恒等作用也按已消费处理，不能等以后衰减再重发。

| 边界 | 处理 |
| --- | --- |
| 传输重发/同一阶段重发 | 复用原键，已消费不再 F；冲突载荷保留冲突，不能凭较新的时间戳取胜。 |
| 首次接纳 | 消费接纳及当时有效的 A/M，各部分只一次；缺失部分不伪称已驱动。 |
| 首次有效补解释 | 只用尚未消费的 A 或 M；原记录角色使用自身目标、且现行目标仍来自它时才补足目标更新；重访记录的补解释或已被新目标替代的旧结果只记 H，不回退目标。 |
| 合法重访 | 新记录用自己的键，引用原依据；不因共享依据而被当重发。 |
| 解释器修订/时间纠错 | 不凭修订创造消费键；按既有更正重建路径，不作为再次接触发脉冲。 |
| 旧结果与新 Q 交错 | 结果可记录、可按角色作用；旧执行计划不能覆盖新 Q，UNKNOWN 不盲目重发。 |

一次作用的崩溃边界：提交前失败时，作用和消费都不可见；提交已成功但回执丢失时，两者都在，重发只返回已有结果。时间补证不是再消费一次。F 资格完全不读时间事实；发生/观察未知或跨 epoch 不可比不取消资格。这里只是时间语义未知且本机时钟正常时照常处理；真实本机时钟结构故障仍按 v2.0 §12 降级，两者不可混同。
