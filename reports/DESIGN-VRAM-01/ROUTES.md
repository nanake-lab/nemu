# 候选路线：先发散，再收敛

所有路线均为候选。下表的“保留/排除”是本报告的建议，不是用户决定，也不是组件已经实现的声明。未给出的图像尺寸、内存、时长、质量与并发预算一律 **待实测**；源码支持一个参数，不表示该配置已通过本机验证。

## 一、彼此不同的实现路线

| 编号 | 路线 | 为什么值得考虑 | 代价、排除理由或保留条件 |
| --- | --- | --- | --- |
| V01 | 原图高分辨率直接送当前视觉模型，所有组件常驻 GPU | 数据流最直接，保留整图关系；若优化后可行，优先简单做法 | 当前约 9.36 GB 尚不含声音与舞台，不能作可行默认；模型仍有图像 token/resize 上限，不等于任意原图都能直读 |
| V02 | 限制图片尺寸；过大明确拒绝，或告知后只看缩小概览 | 最容易限制工作量，失败可解释 | 单独不能满足大图小字目标；拒绝不是看清。静默缩图排除，明确概览可作为其他路线的一部分 |
| V03 | 原始像素分块，按已请求范围逐块覆盖，保留位置与必要重叠 | 避免小字因整图缩小而消失；可提供全图读取能力 | 跨块关系、接缝、上下文与总等待增加；不能只返回摘要就声称全部细节已保留；需真正约束工作区 |
| V04 | 先概览，再由她选择区域凑近看；也允许直接指定区域 | 她能按当前目的选择关注，可能省去无关区域的计算 | 未选区域可能有重要小字；不能单独保证全覆盖，也不能强制每图都遵循此顺序；与 V03 同等进入比较 |
| V05 | 保持同一模型，将视觉编码器放 CPU，decoder 保留 GPU | 直接把视觉权重/工作区移出 GPU；不必减少图像细节 | CPU/RAM、传输与线程竞争待测；decoder 的图像 prefill 仍用显存，CPU 不解除模型输入上限，超限仍需分块 |
| V06 | 视觉编码器只部分放 CPU，或按层传输、分段计算 | 可以在完全 CPU 与完全 GPU 之间权衡 | 固定版本是否支持、传输成本与精度均未核验；自有逐层装卸复杂，先比较现成完整 CPU 路线 |
| V07 | 对视觉图建立较小、明确的 token/工作区上限，并相应调整初始化预留 | 针对 4628.88 MiB 的重要候选；有界块配有界工作区才可能降低峰值 | 仅限制输入或改 batch 不保证原预留消失；若触发 resize 会损失细节。必须保持请求像素覆盖并测实际预热、分配与释放 |
| V08 | 视觉编码器按需初始化与销毁，主脑保持加载 | 看图不频繁时不长期占视觉显存；底层有独立 context 生命周期可研究 | 加载和预热延迟待测，峰值看图时仍存在；现有 server 不因此自动获得热装卸能力，不能靠重启整脑冒充局部释放 |
| V09 | 视觉与 TTS 分时，真正释放非活动组件的 GPU 权重/工作区 | 可把部分同时占用变为不同阶段占用，保留主脑 | 只是排队不够；需释放证据与冷启动测量。说话、近看可能互等，不能改她的文本、语气选择或投递事实 |
| V10 | 保持同一 TTS，把合成放 CPU或部分 CPU | 给视觉让出 GPU，声音身份原则上可保留 | 此版本支持性、整句等待和 CPU 竞争待测；不能宣称在 CPU 上也满足语音要求 |
| V11 | 主脑部分层放 CPU，或在 CPU/GPU 混合推理 | 能腾出 GPU 且不必关闭认知 | 主脑每轮、IRL 与回应都受传输影响；属于载体执行配置变化，需绑定并验证，不以“模型未换”免除连续性/能力检查 |
| V12 | 看图或合成时卸载主脑，再重新加载 | 短时能借走更多 GPU 容量 | 不推荐主路线：清醒持续认知发生实际中断；若用户另选这种降级，必须显示中断并按合同恢复，不能声称四项正常共存 |
| V13 | 优化视觉 attention/工作区，例如可支持的 Flash Attention、精确分块计算或分配生命周期 | 可能保持相同图像信息，减少中间计算占用；优于先损失细节 | 固定版本具体视觉路径、GPU算子支持和数值差异须核验；主干开关不等于视觉已启用，不把“关闭预热”当峰值解决方案 |
| V14 | 降低 mmproj 权重量化或改变视觉计算精度 | 可减少部分权重或中间量；值得与工作区优化分开测 | 权重文件仅是占用的一部分，不能解决所有工作区；小字与图像理解可能退化。属于显式版本变更，不可 OOM 后暗换低精度 |
| V15 | 主脑更低比特、KV 精度调整、缩小上下文/并发/batch | 可能减少主脑缓存和工作区，为视觉腾空间 | 三者作用不同；循环状态另算。缩上下文会改变能用的材料，须明确截断；量化/内核变化需载体验证，不能吞掉她的输入 |
| V16 | CPU OCR 提取文字与位置，再给同一主脑；视觉保留作核对 | 截图密集小字值得单独比较，文字无需一直以图像 token 留在工作材料 | OCR 会错、会漏版式和照片信息；只能作带来源的工具输出，不能将 OCR 猜测升为原图事实；组件待选型，不在此指定模型 |
| V17 | 对屏幕优先使用已授权的 UIA、COM、文档文本等结构化读取，截图补足外观 | 与架构既定结构化优先一致，直接拿到可访问的文字 | 不能覆盖照片、画布、不可访问控件；结构树也可能过期或缺失，不等于她已经视觉看过；原授权边界照旧 |
| V18 | 换更省显存的视觉模型，或以独立视觉模型给文本主脑提供材料 | 能独立比较识字能力和视觉成本，摆脱当前编码器工作区 | 不是既定选择。ADR 0034 的 Qwen3-VL 回退仍须原条件与复测；独立解释模型还涉及 ADR 0012 判断一致性和额外同驻，不能直接换 |
| V19 | 换更小或更便于按需运行的声音组件 | 若声音才是最后缺口，可以把资源问题放在次要组件比较 | ADR 0027 已定过渡/目标路线，重新选型要用户决定与后继 ADR；声音身份、情绪能力和许可不能只看体积 |
| V20 | 云端或局域网远端视觉，仅把结果作为材料交回本地 | 能把视觉负载移出本卡 GPU；较强视觉能力值得另评 | 不满足完全本机的主路线，另有网络、权限、成本、来源与等待；不能让远端替本地 m 决定关注或行动，失败不静默上传 |
| V21 | 增加第二张卡或独立机器，按组件分工 | 减少视觉/声音争用，有利于更高质量组件 | 超出当前“单张 3080”目标，不作为本卡解决成功；多卡不是自动共享显存，兼容性、电源、机箱、传输及成本另核 |
| V22 | 换更大显存的一张卡 | 直接扩大同驻空间，仍可保持本机路径 | 不再是现有 3080 上解决目标；容量也不自动解决小字准确率。没有本机证据前不推荐具体购买型号或预算 |
| V23 | 若已有可用核显，将显示/舞台工作放在核显 | 可能减少 3080 的显示与渲染占用 | 本卡未盘点硬件；跨适配器复制、窗口/驱动兼容与视觉表现待测，不能假设“免费多出渲染空间” |
| V24 | 缓存同源图像的纯编码产物，重复查看时复用 | 可减少重复编码与装卸次数 | 不能降低首次峰值；缓存自身占 RAM/显存。只能在图像、裁切、编码与预处理绑定相同且产物与 m 无关时考虑，不能缓存主观判断充当事实 |
| V25 | 依赖 WDDM 共享显存、系统换页或“让显存溢出到内存” | 有时能暂缓分配失败 | 不作为主方案：不等于新增 GPU 本地显存，尾延迟与卡顿不可据此保证；共享使用仍纳入既定观测，不能把它隐去 |
| V26 | 先超分辨率/生成增强小字，再识别 | 可作明确标注的辅助对照 | 排除为原始证据替代：可能生成不存在的笔画；不能以增强结果证明看清，原图不可读仍须报告 |
| V27 | 看图时降低舞台质量或停止渲染 | 可以调查渲染是否真是最后的资源缺口 | 不替代“四项都能用”的目标；既有全屏/隐藏暂停按原规则，额外关身体或改视觉基准须用户决定，不能偷偷应用 |

## 二、收敛为同等口径的比较

资源安排与取图方式是两条轴，可以组合；不能把“分块”本身当成显存调度器。以下先并列比较，再提出推荐。所有绝对显存和延迟预测均未实测。

| 候选组合 | 能否看清 | 显存 | 延迟 | 她的体验 | 复杂度与主要风险 |
| --- | --- | --- | --- | --- | --- |
| A：V03 + V07；原图全范围分块、GPU 小工作区，主脑/声音/舞台常驻 | 保留原图局部细节，可核对覆盖；接缝及全局关系仍需测 | 编码峰值有机会受块限制；真实预留、decoder 与声音相加后仍未知 | 多块串行与多轮材料处理；不能按块数乘旧 TTFT 得出总时长 | 可读完整图；长图会等待，进度真实，期间可使用其他材料 | 中；覆盖、接缝、材料接续。若工作区仍大则不解决同驻 |
| B：V04 + V07；全貌后她选区域近看，GPU 小工作区 | 被选区域可以读细；未选区域不保证，须保留全范围能力 | 每块峰值与 A 可相近；选少几块只减少工作量，不保证降低驻留峰值 | 至少包括概览、提出区域与后续处理；也可能减少总工作 | 她能控制关注、停止或改变主意；可能因未发现细节而漏看 | 中偏高；比 A 多来源绑定和行动接续，不能把概览当完整解释 |
| C：V05，必要时 V03；同模型 CPU 编码，decoder/声音/舞台留 GPU | 不以缩图换容量；CPU 也须经过相同清晰度验证，超模型上限仍分块 | 移走视觉 GPU 工作；RAM 与 decoder 图像工作区仍需测 | CPU 编码、传输及与 ASR/核心竞争，尾延迟未知 | 声音有望保持可用；看图等待可能更长，不自动暂停其他认知 | 低至中，若现成接口适配可行；CPU/RAM 瓶颈和数值差异是风险 |
| D：V08 + V09，配 A 或 B 的取图；非主脑视觉/TTS 分时释放 | 与同取图方式相同，不要求降低图像细节 | 只有证明两套非活动分配已释放，才有机会避免同时占用 | 装载、预热、等待与切换均计入；不能只报热路径 | 看图与开口可能互等；已生成音频仍可播放，认知不冒充连续可算 | 中至高；GPU 释放、在途合成/播放、取消及崩溃恢复 |
| E：V01 + V13；相同高分辨率、优化视觉工作区后直接读 | 保留整图关系；原有模型/resize 上限仍在，小字能力需测 | 若工作区优化足够可最简单；节省量未知 | 或可少一次多块接续，实际 prefill/取消粒度未知 | 更像一次看图，避免额外显式近看；不保证所有大图可直读 | 配置可支持时实现较简单，验证负担较高；算子回退和数值变化需显露 |
| F：V16 + V17，再配 A/B/C 的视觉；结构化与 OCR 补充 | 截图文字有额外读取路径；照片、布局和图像语义仍靠视觉 | 可减少某些任务的图像负载；额外 OCR 自身成本未知 | 文字获取可能省后续视觉工作，也可能多一步；待测 | 能知道文字来自接口、OCR还是视觉；不会假装所有来源都等于看见 | 中；冲突结果、来源追溯、过期页面和 OCR 错误 |

这些组合没有一个可以在本卡被判为“已满足单卡目标”。A/B 的显存上限取决于 V07/V13 或释放机制；C 也不免除全系统同驻与持续认知验证；D 解决的是同时占用，是否接受等待由用户定。

## 三、怎样判断资源方案真的成立

常驻组合应测：主脑权重、KV/循环状态及计算工作区，加视觉、声音、舞台和进程开销，并与桌面可用预算核对。各项不能取不同模型、不同 context 的旧峰值拼成“实测总和”。

分时组合只有在视觉和声音的相关 GPU 分配真正互斥时，才能用“固定占用 + 二者较大阶段”安排预算；若只是串行调用、两套分配仍保留，预算仍须包括两者。共享显存和装卸瞬时副本都不能漏计。

降低图像 token、上下文、精度和声学能力都可能改变她实际能得到的材料；这些不是资源不足时可随意替换的等价开关。后继必须固定并报告配置，失败明确返回，由已批准的路线处理。

## 四、推荐的收敛方向

推荐保留 A 的原图与全范围读取能力，先测其受限 GPU 工作区，并以 C 做同信息量对照；E 若以更简单方式满足相同清晰度和总预算，应优先。B 作为可选感知行动，不能强制或取代完整读取。D 在常驻无法达成时交用户选择，F 可补强截图文字。

V11/V14/V15/V18/V19 涉及主脑、视觉或声音能力/数值配置，留作前述路线失败后的待选研究，不提前实施。V20–V23 属用户另选的外部资源/硬件方向；V25/V26 不能作为本目标的通过依据。没有提出更换引擎、3D 框架、核心或角色资产管线的实施决定。
