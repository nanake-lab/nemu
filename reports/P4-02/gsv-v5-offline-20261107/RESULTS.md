## 范围与数据

测量发生于 2026-11-06（下表时间均 Perth / UTC+08）。独立 TTS，v5turbo、CUDA float16、G2PW CPU、4 个 torch CPU 线程、seed=42、speed_factor=1.0、固定合成参考音频。没有载体、ASR 或舞台同驻。非流式整句合成；首声从调用 model.run 前到第一段 24 kHz little-endian float32 PCM bytes 可播放，含前处理/合成/重采样，不含 WebSocket 与声卡启动。每条只返回一段 PCM，语音听感/语义正确性未验收。

## 混合句最大首声的归因

最大首声 5.484369 秒，原句「你好，hello world。」；case_id=1（0 起），混合组第 1 句、latency 阶段第 2 次、含冷请求的全程第 3 次请求。请求总耗时 5.707243 秒，音频 2.04 秒。没有从混合 20 句中剔除这条。

固定上游提交 04a44eb977586645f33594b72af13a035a2056c6：TTS.py:1641 的四段打印为 t1−t0、t2−t1、语义生成、音频合成；stdout 第 60–61 行该次为 0.002 / 3.973 / 0.664 / 0.837 秒。t2−t1（TTS.py:1270–1325）覆盖文本前处理、BERT/音素提取及组 batch。cleaner.py:37 动态导入 text.english；english.py:360 顶层构造 en_G2p，构造时调用 g2p_en 初始化、wordsegment.load() 和词表加载（248–257）。这些源码与首次遇英文时前处理显著变慢相符。

**归因仍待查**：本次没有模块导入、词表读取、NLTK/英文前端各子阶段的独立时戳，也没记录首次调用时的 sys.modules。3.973 秒不能全部归给英文前端加载，5.484 秒还包含语义/音频合成等。现有证据支持“首次英文前处理可能是主要因素”，不支持确定因果。保留待查，不重跑。

## Private bytes 约 9.7 GiB 的含义

全程 PrivateMemorySize64 峰值 10393067520 B = 9.679298 GiB；RSS 峰值 5378334720 B = 5.008965 GiB。private 是进程私有提交量，不是当前物理 RAM 驻留量，也不是纯 GPU 显存。[Microsoft 的计数器映射](https://learn.microsoft.com/en-us/windows/win32/memory/memory-performance-information)将 Private Bytes 对应 PrivateUsage/Commit Size；[结构定义](https://learn.microsoft.com/en-us/windows/win32/api/psapi/ns-psapi-process_memory_counters_ex)说明其为进程私有 commit charge。RSS/WorkingSet64 是当时驻留的工作集，包含可共享页面；不能将 RSS 与 private 相加。

是否、多少 CUDA 映射/驱动主机侧分配计入本次 private：**待查**。当前只有进程总数、WDDM 与 torch allocator，没有地址空间区域分类、驱动分配追踪、系统 commit/pagefile/可用物理内存/硬缺页采样；不能把 private−RSS 归为 CUDA，也不能把所有 GPU 地址映射视为同量 RAM。对用户内存，它意味着私有提交预算负担；约 5.01 GiB 的 RSS 才是本进程观测到的工作集峰值，仍不能推算整个 32 GB 主机还有多少物理余量或是否换页。

## 错误、加速状态和 PCM

记录到 failure 事件 0、Traceback 0、ERROR/CRITICAL 日志行 0、外部重负载触发观测 0，进程 exit 0。日志另有 FlashAttention 未安装 INFO 1 条、rich 未安装导致 AR acceleration 不可用 WARNING 2057 条；本次测的是 ordinary inference 路径，不是加速路径。该可选路径回退不能隐藏成“无警告”。错误数不代表音频听感或语义已验收。

连续 2016 次中，每个 case 重复 50 或 51 次，**40/40 case 内 PCM SHA-256 一致**。包含各 20 句与冷请求的全程则 38/40 一致：case 0 中文冷请求与随后同句不同；case 1 首次混合请求与随后同句不同。两者的音频时长分别仍固定 2.92 秒、2.04 秒；字节不同的原因和听感差异待查，不能说全程确定性一致。逐 case、各哈希出现次数和覆盖时间见 [CASE-HASHES](CASE-HASHES.md) 与 case-hashes.json。
