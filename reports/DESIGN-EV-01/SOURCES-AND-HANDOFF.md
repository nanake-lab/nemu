## 2. 当前 G 和 P5-24 确实提供了什么

以下为只读源码核对，定位到当前 main；不是本卡改动。

- [law/input.rs](../../core/crates/core-kernel/src/law/input.rs)：`GroupContent` 区分 Experience 与 Teaching；Experience 共用组内 appraisals，再有按目标的 matches；`GroupItem` 只有一个 `verifiable: bool`。因此“同一组对不同命题有不同合格成员/真假依据”不能无损塞入现接口。
- [law/plan.rs](../../core/crates/core-kernel/src/law/plan.rs) 与 [support.rs](../../core/crates/core-kernel/src/law/support.rs)：现有 teaching_plan 仍用固定 w_teach、supports 正反与 trust 权重；experience_plan 仍把布尔 verifiable 映成 1 或 v_u。仅改组装器名称不能完成 D12/D13。
- [law/relation.rs](../../core/crates/core-kernel/src/law/relation.rs)：结构关系只有亲近与能力型信任；信任方向固定为好奇/成事；u* 的亲近使用固定有限先验，信任使用会让位的初始证据。D04 不能给新“诚实”候选打上旧 TRUST 后指望其不被合并，也不能把旧先验复制到每个新维度。
- [#117 模块](https://github.com/nanake-lab/nemu/tree/8992eed030f70c2837cdae2f9ea59cd45b5093e5/core/crates/core-kernel/src/evidence)：现已随 #117 合入 main，代码与 `c6f3065d` 相同。仍是旧规律的受治理合成投影，未注册到生产 crate；同组 μ/verifiable/合格目标不一致时拒绝；缺 Claim 级引用、正式属性和 H/重算/C 接线。其结构关系再入现已要求显式意图/次序，并完整回溯。

新设计须同时改变上游记录语义、P5-24 组装和 G 输入适配；现有数学递推尽量保留，但不能以“纯函数测试过”代替新语义验收。#117 的原失败、修复证据和旧规则测试保留在原版本；本卡不搬走、不覆盖。

## 4. 版本、重放与更正设计

用户选择后，先以一个明确后继规律版本绑定：建议语义、核对/出处解释器、三项核实、目标成员选择、归组/分摊、关系输入和排序。用户只批准选项，不等于参数、IDL 或部署已批准；后继卡再冻结精确合同并交叉审查。

| 变化 | 历史处理 | 重放检查 |
| --- | --- | --- |
| 普通新观察 / 补做 M | H 追加真实观察或新的解释；保留原始首次提交。结果晚到不伪装早已知 | 同一个提交前缀下增量与全量位一致；同组更新不额外增加 N/q |
| 旧份额或匹配的正常修订 | 按 ADR 0019 两阶段修改分配，保存首次 q 与 ordinal | 对照固定分摊计划的反事实；不能重新估旧 q 来制造单调性 |
| 新观察与旧陈述相反，但两次观察都真实 | 保留相反经历与原陈述；这是关系学习所需反例，不按“内容不实”删掉旧根 | 普通新证据路径；不能因建议失效、预测未中而撤掉负面结果 |
| 某目标把已被查明失效的事实前提当真 | 仅撤回依赖该前提的资格，追加更正及依赖范围；原话、真实相处与查明过程保留 | 对该目标按“未使用失效前提”的有效视图重建；**不是**“这个人从未说过这句话”的假历史；不能连带删除陈述可靠性的反例 |
| 来源/事件本身伪造或篡改 | 失效来源的派生支持移出有效输入，原 H 字节保留 | AC2-19：对应失效证据从未计入的结果，重建受影响 q；不让伪造节点残留为分组桥 |
| 说话人改口 / 改约 / 修复 | 新经历，非来源失效；可影响今后预期 | 不能删掉此前真实承诺、失约或后果 |
| 解释器确有错误 | 新解释追加，带更正理由、版本与受影响范围 | 只在批准的重解释流程调用判断者；通常重放只读固定记录 |
| 切换新规律 | 从同一 H 与有效解释生成新 R/θ，旧快照/版本保留；差异与原因进入 H/L | 新版本各前缀自洽，旧版本仍可精确复现；不保证两版本结果相同 |

这里“新反证”“目标前提失效”和“来源失效”的更正范围是待选择设计必须闭合的语义，不能拿既有全事件删除入口勉强实现。特别是 D13-B 的依赖图只追踪受影响目标：纠正天气预报不抹掉真实的安慰，也不删掉预报失准的反例；发现回执造假则不能继续把假回执用于兑现。资格撤回及其下游 q 重建必须有受治理的失效依据，不能只因结果不符合期待就重解释旧输入。

新旧类型只增不改：旧 Teaching/单布尔解释沿旧版本解码；新版本不把缺字段默认成“已核实”。旧记录信息不足时显式列缺口，需要受治理的追加解释或按目标保持未知；不得仅凭旧 verifiable 自动拆出三项。无跨版本缓存可改变权威结果，索引全可重建。

若需要存储变更，由后继契约/存储卡提供后继类型、CanonicalV1/黄金向量、迁移与回退及 SYS17。部署前备份由既有流程执行；失败保留旧系统。不能仅换标识就沿用旧规律的验证。本文没有创建存储、迁移或新编码。
