# Nemu 架构说明 v2.0

本文件是《Nemu 3D 桌面伙伴 · 总体工程设计 v2.0》中代理需要的部分。

- 接口细节以 `docs/CONTRACTS.md` 为准。
- Echo Core 的一切以 `docs/echo-core/` 中的规格为准，优先级见 `docs/echo-core/README.md` 第 1 节。
- 本文件与上述文件冲突时，以它们为准，并在报告里指出冲突。

## 1. 目标

Nemu 是一个常驻 Windows 桌面的原创二次元 3D 伙伴。她最重要的是**存在本身**：

- 持续在场；
- 有连续的历史和状态；
- 会因经历而改变；
- 知道什么时候该安静；
- 需要时能帮你做事。

外观以「认得出是她、动起来可信」为准，不追求和原画一模一样。

四条硬性要求：

1. **只属于用户。** 默认私有，想分享时可以随时公开，也可以一直自己留着。代码仓、Nemu 内容包、Echo Core 规格三者分开管理，可以单独公开其中任何一部分。
2. **不写死她。** 她的变化只存在于 Echo Core 的状态里（x、R、θ，经 J 作用于模型），不写进代码，也不写进提示词。代码里只允许固定、带版本的机制，例如身体反射和读出函数。
3. **模型可替换。** 执行任务的助手模型随时可换；承载她状态的载体按 Echo Core 的迁移合同更换；她的身份（H、x、R、θ、L）不依赖任何一个模型。
4. **三种语言。** 中文、英文、日文，她用你使用的语言回答，同一个声音，同一个人。

## 3. 设计原则

1. **存在先于外观。** 可信度来自时机和行为：什么时候看你、什么时候安静、记得什么、怎样改变。身体的标准是可信，不是精确复刻。
2. **Echo Core 是唯一权威。** 她的历史、状态、成长和行动只由 Echo Core 提交；终端、模型、worker、界面都只能提出。
3. **反射在身体，决定在核心。** 物理、呼吸、眨眼、视线跟随、被拖拽、下落这类反射在终端本地完成，参数固定并带版本。说什么、做什么、什么时候主动，由 Echo Core 决定。
4. **常驻要省。** 待机 30 fps、睡眠 12 fps、全屏程序在前台时暂停渲染；模型只在需要时运行。
5. **用结构化接口拿上下文。** COM、UI Automation、MCP 优先，截图只作为可选的最后手段。
6. **四条稳定边界：**
   - 资产契约：模型可换；
   - 舞台协议：渲染器可换；
   - 终端协议（Echo Core IDL）：身体可换，以后也可以有手机终端；
   - 生成接口：载体和助手可换。
7. **一切可验证。** 每个任务都有可执行的验收；人工只做审美和感受判断。

## 4. 进程模型

| 进程 | 技术 | 职责 |
| --- | --- | --- |
| `nemu-core.exe` | Rust（tokio、rusqlite、prost） | Echo Core Trusted Core：入口与 Γ、事实视图、IRL 与解释记录的治理、Concept Registry、Φ 与 F、证据组装、规律 G 与动力学 C、重算与复核、授权作用与 J 编译、事务与对象存储、任务层、行动闸门与 Q、自主调度、结构重放 |
| `irl-worker` | Python | 提出 SemanticCandidate，以及情境吻合 M 的 μ、候选倾向与证据标注，都在 m = 0 下。IRL 后端二选一：本地（与载体共用模型）或远程（Codex「日常」档）；M 默认只用本地后端（6.9） |
| `drive-worker` | Python | 天性评估 A：在 m = 0 下提出 a(e) |
| `model-adapter` | Python + PyTorch（CUDA） | 模式 A、C 的载体：冻结 decoder + 显式残差注入；方向提取与验证；同时承担 IRL、A、M 的本地后端 |
| `voice-sidecar` | Python + TTS 模型（ADR 0027：目标 Breeze TTS 2，过渡 Ming-3.0-tts 0.5B） | 流式合成 |
| `codex-bridge` | TypeScript + `codex app-server` | 模式 B 生成、模式 C 起草、IRL 远程后端、助手任务 |
| `office-connector` | .NET 10 + COM | Word、Excel、PowerPoint 操作，是行动闸门下的连接器 |
| Electron 主进程 | Electron + koffi | 守护以上所有进程、窗口与托盘、桌面感知、终端客户端、应用内总线 |
| 舞台渲染进程 | three.js（WebGL2）+ @pixiv/three-vrm v3 | 透明叠加窗口、渲染、动画分层、口型、命中判定、气泡字幕、麦克风采集、音频播放 |
| 面板渲染进程 | React 19 | 对话、审批卡、运行状态（谱系、说话模式、是否严格）、「她记得什么」与行动记录、设置 |
| 语音工具进程 | Electron utilityProcess + sherpa-onnx | VAD、ASR（含语言识别）、打断判定、语音输出管线（分句、调用 TTS、投递回执） |

通信：

- **终端 ↔ 核心：** Windows 命名管道，长度前缀 + Protobuf 传输；权威内容的哈希用 CanonicalV1（总方案第 6 节）。只有 Electron 主进程持有终端连接，应用内其他进程经主进程转发。
- **worker ↔ 核心：** 命名管道；每个 Proposal 带 ProposalBinding。worker 以低完整性级别启动，无法写入权威存储（`docs/echo-core/README.md` E2）。
- **执行器 ↔ 核心：** 带执行凭证的行动请求与执行结果。结果作为新事件进入 H。
- **应用内：** 控制通道、音频通道、麦克风通道沿用舞台协议；应用内总线只承载界面层事件，不承载她的状态（CONTRACTS.md 第 4 节）。

Electron 主进程负责启动、健康检查、崩溃后退避重启和退出清理，但从不读写 Echo Core 的存储。

## 5. 一句话的数据流

以模式 A 为例：

1. 舞台采集麦克风 → AudioWorklet → 16 kHz PCM → 麦克风通道 → 语音进程。VAD 判定说完时，舞台立即做非语言回应（看向你、轻点头），这是身体反射，不经过核心。
2. 语音进程用 SenseVoice 识别出文字和语言，主进程把它作为 `observation.user_utterance` 事件发给核心，收到 `RECEIVED_DURABLE` 回执。
3. 核心按 v2.0 第 2.4 节的唯一事件顺序处理：
   - 入口 Γ 与时间投影 Φ（只有 x 随时间投影）；
   - H ⊕ r、事实视图 c_core；
   - IRL：worker 提出候选，核心确定性治理，有截止时间；
   - 天性评估 A 与情境吻合 M：在 m = 0 下得出并记录，有截止时间；
   - F_in：核心按 a(e) 和 R⁺ 的情境作用装配驱动；
   - G、C：按规律更新 R、θ（排练谱系和暂停时不变）；
   - F_out、L 追加；
   - 原子提交，返回 `CORE_COMMITTED`。
4. 核心从已提交快照（投影到当前时刻）编译 m，任务层调用 `generate(o, p, c_task, m)`。模式 A 下由 model-adapter 带调制生成，输出带表演提示的流式文本。
5. 核心把输出块和行动请求发给终端。行动请求包括身体动作，以及经行动闸门批准的工具调用。
6. 语音进程按三语分句规则切句 → 按语气和语言选参考音频 → TTS → 音频通道 → 舞台播放；口型与表演提示同步。每块的实际投递结果回报核心，记录为已发生的输出。
7. 她说话时你开口：舞台 300 ms 内停止，终端回报已投递范围和取消，新的话作为新事件处理。

延迟预算（暂定，P0-07、P0-08 实测后修订）：

| 环节 | 模式 A | 模式 B | 模式 C |
| --- | --- | --- | --- |
| VAD 判定说完 | 300 ms | 300 ms | 300 ms |
| ASR | 200 ms | 200 ms | 200 ms |
| 入口 + IRL、A、M（截止时间）+ 核心 + 提交 + J | 500 ms | 500 ms | 500 ms |
| 首句生成 | 600 ms（本地） | 700 ms（远程首个文本增量） | 1,500 ms（远程起草 + 本地改写首句） |
| TTS 首包 + 播放缓冲 | 400 ms | 400 ms | 400 ms |
| 合计 | 约 2.0 s | 约 2.1 s | 约 2.9 s |

> **2026-10-22 追加（ADR 0017）：** 「VAD 判定说完」三种模式都改为 350 ms（中位）。打断从开口到 `voice.bargeIn` 的中位目标为 300 ms；完成标准第 9 项的 300 ms 从 `voice.bargeIn` 算起。其余各行仍待 P0-09 冻结。

IRL 超过截止时间时，按规格以「语义失败」提交（该事件不产生语义驱动），回复照常生成；A、M 超时分别记 `A_DEGRADED`、`M_DEGRADED`；M 之后在后台补做，追加的解释按次序计入（P5-23、P5-29）。超时比例由 W15 指标记录，目标 ≤ 10%。成长接通后 P5-29 复测这一行；达不到时，把 A、M 并进 IRL 的同一次调用是候选方案，需要用户批准。

## 6. 子系统

### 6.1 舞台与渲染

- **窗口策略：** Nemu 所在显示器上，用一个覆盖工作区的透明叠加窗口，窗口内一块与角色等大的画布用 CSS transform 移动。P0-03 基准测试后如有兼容问题，回退为「角色等大窗口跟随移动」。
- **点击穿透：** 默认 `setIgnoreMouseEvents(true, { forward: true })`。光标移动时（最多 30 Hz）用 WebGL2 异步读回（像素缓冲对象 + fence）读取光标处 1 像素的 alpha，> 0.1 时关闭穿透。不要每帧同步调用 `readPixels`。
- **透明正确性：** `premultipliedAlpha: true`；抗锯齿在默认帧缓冲 MSAA 和 4× 多重采样渲染目标中二选一，以透明边缘检查为准；不做破坏 alpha 的后处理。
- **画面：** 透视相机约 20° 视角；三点光；MToon 描边宽度随画面大小自适应。
- **帧率：** 活动 60、待机 30、睡眠 12 fps；全屏程序在前台或角色隐藏时暂停。
- **确定性模式：** `?deterministic=1` 冻结时间、固定随机种子、关闭弹簧骨随机扰动，用于视觉回归。

### 6.2 角色管线

VRoid Studio（用户）→ VRM 1.0 → Blender 无头脚本：导入、校验、生成尾巴、配置弹簧骨、生成自定义表情、套用 MToon 预设、压缩贴图、导出、生成 `nemu.profile.json` → `asset-lint` → 评审台评审。所有可调参数集中在 `content/nemu/build.yaml`。不安排任何手绘或手工修图：贴图修整用 krita-ai-diffusion 局部重绘或脚本完成。

### 6.3 身体与动画

| 层 | 内容 | 驱动 |
| --- | --- | --- |
| L0 基础姿态 | 待机、走、坐、睡、被拖拽等循环片段，交叉淡化 | 物理状态机 |
| L1 手势叠加 | 上半身遮罩片段 | 表演提示 `act`、核心的身体动作请求 |
| L2 程序化身体 | 呼吸、重心摆动、视线跟随（头、颈、眼分级，带延迟）、坐窗沿 IK | 反射；节奏受身体读出影响 |
| L3 面部 | 表情混合、眨眼、口型；说话时表情权重上限 0.6 | 表演提示 `emo` 给出说话时的表情，没有按情绪的表情基线（v2.0 第 9.3 节）；wLipSync 给出口型 |
| L4 次级运动 | 头发、耳朵、尾巴、裙摆弹簧骨；耳朵与尾巴的姿态偏移在弹簧骨之前叠加 | 物理 + 身体读出 + 表演提示 |

- **身体不保存会影响行为的情绪状态。**
  - 整体姿态的基线来自身体读出：朝向你、放松或紧绷、精力三项，是天性通道的固定、带版本的线性组合，m = 0 时为中性（v2.0 第 9.3 节，CONTRACTS.md 第 7 节）。
  - 读出由核心推送：每次提交后一次，空闲时按时间投影每 10 秒最多一次。
  - 表演提示带来的表情在所在句子结束后按固定曲线回到基线。这是动画过渡，不是情绪状态。
- **物理状态机：** idle、listening、speaking、sitting、walking、dragged、falling、sleeping、peeking、hidden。任意切换的过渡 ≥ 150 ms。
  - 状态转换由反射规则和核心的身体动作请求触发，比如核心决定小睡就会请求 `sleep`，主动性本身不在身体里。
  - 核心不可用时，身体只保留呼吸、眨眼、视线和物理。
- **待机小动作：** 从 `profile.idleSet` 按权重随机抽取，带冷却；节奏系数来自身体读出。
- **动作来源：** 全部转为 VRMA，登记在 `content/nemu/motions/manifest.json`，带许可字段；动作库 v1 共 30 个槽位。

### 6.4 声音

- **收音：** 默认按键说话，可选常开监听，可选唤醒词。
- **识别：** SenseVoice，自动识别中、英、日（也支持粤语、韩语，不在验收范围内），把语言代码随文字上报。
- **打断：** 回声消除后的 VAD 检测到开口，300 ms 内淡出停止。
- **合成：** 见 ADR 0027：目标 Breeze TTS 2，过渡 Ming-3.0-tts 0.5B（2026-10-25 取代 Qwen3-TTS）。
  - 用 VoiceDesign 设计一个原创声音；运行时用 Base 模型按参考音频克隆。
  - 每种语言、每种语气各准备一段参考音频，经说话人相似度检查后定稿。
  - Base 模型不接受文字指令，语气从参考音频带出。支持文字指令的云端 TTS 则使用 `voice.json` 的指令表。
- **分句：** 三种语言的规则见 CONTRACTS.md 3.2。
- **非语言回应：** 说完后立即由身体反射完成。不预先合成固定的语音填充语，因为她说出的每一句都应来自核心的生成。

### 6.5 Echo Core（v1.0 范围）

- **实现范围：** v2.0 的全部机制（ADR 0010）：H、x、R、θ、L；天性评估、情境吻合、证据规律、θ 的动力学、重算与复核、保险丝。成长从诞生起开启。规格以 `docs/echo-core/echo-core-v2.0-first-principles.md` 为准。
- **genesis 清单（她的出生）：** v2.0 第 13 节：
  - 规律版本及其参数；天性结构与初始增益，b₀、σ₀、τ₀；
  - 依恋先验 A_att 与你的身份；
  - 载体、提取的方向与验证记录；
  - 读出函数；保险丝与边界；
  - 协议 p 的版本。

  不含任何性格或风格文本。由 P5-17 汇总、你签字，放在内容包的 `core/genesis/`，有版本、有摘要。
- **IRL、A、M：** 结构化事件（工具结果、执行结果、桌面事件）走确定性适配器和规则表；自然语言经 worker 在 m = 0 下解释，结果记录进 H，重算只用这些记录。IRL 的后端由 P0-08 实测决定；M 要读 R 的概念定义，默认只用本地后端。离线时只能用本地后端。
- **快状态：** x ∈ [−1, 1]^{4+|R⁺|}，四个天性通道加上已成为性格的倾向各一维，静息点 (b, 0)；驱动 D_i = g_i·w_i·(a_i − b_i) + Σ f_{k,i}，不读 x̄（ADR 0008）。
- **运行状态：**

  | 状态 | 含义 |
  | --- | --- |
  | 正常 | 核心状态经严格 J 作用于模型 |
  | `NO-GROWTH` | 不产生成长：只在排练谱系，原因码 `GROWTH_OFF_REHEARSAL` |
  | `GROWTH_PAUSED` | 你暂停了成长；事件照常进入 H，恢复时按 H 补算 |
  | `GROWTH_REVIEW_PENDING` | 变化过大，暂缓应用，复核规律本身；你会收到通知 |
  | `TEXT_PROJECTED` | 模式 B 的代理实验，标为非严格 |
  | `CORE_UNMODULATED` | 载体失效，m 未被应用 |
  | `A_DEGRADED`、`M_DEGRADED`、IRL 降级 | 对应的判断失败：该事件不产生相应的驱动或证据；M 可以之后在后台补做 |
  | `MODULATION_NOT_ENABLED` | 只出现在排练谱系、F 尚未实现时：m = 0，依赖核心的自主行动暂停（E13） |

  多个状态同时存在时取最严格的能力交集；面板始终显示。
- **谱系与诞生（ADR 0005、ADR 0010）：**
  - 排练谱系：开发期间和排练版（N2）使用；情绪接通（F 实现之前 m = 0），不成长。
  - 正式谱系：由签字的 genesis 清单在诞生时创建（`echoctl birth`）；她的名字是 H 的第一条事实；从诞生起成长。正式谱系要求全部阶段接通，包括成长。
  - 实验谱系：在合成世界里验证与校准规律，不含你的数据。
  - 三种谱系互不可读。诞生后排练谱系转为只读存档，她读不到；你可以选择把排练对话作为导入文档交给她，它不算她的经历。
- **自主调度：**
  - 行动强度是天性的固定读出，乘以运行门控（权限、勿扰、预算、最小间隔），并限制在 `λ_sched,max` 以内（总方案第 20 节、v2.0 第 9.4 节）。
  - 做什么由模型在 m 下按当时的情境提出，限于你允许的行动种类。主动边界表（CONTRACTS.md 第 8 节）只写边界，不写「什么情况做什么」。
- **行动与权限：**
  - 所有对外行动走行动生命周期：计划、请求、授权、派发、结果；包括说话、身体动作、工具和助手。
  - 权限分级 T0–T3 在行动闸门实现（CONTRACTS.md 第 6 节）；审批显示的就是将要执行的行动，原样（I26）。
  - 结果未知时进入 UNKNOWN，不盲目重发。
- **记忆：**
  - 她记得的就是 H，经事实视图 c_task 进入回答。
  - 你让她忘掉某件事时，生成一条纠错事件，使相关内容不再进入 c_task，原始记录仍在 H 中，那段经历仍是证据。真正抹除需要另立数据生命周期合同（E10）。
  - 面板提供只读的「她记得什么」「她的变化」视图和撤回入口，不提供直接编辑。
- **她是谁：** 协议 p 是任务层输入，只含关于她的事实、你的边界、表演提示语法和三种语言的规则，不含性格或风格（v2.0 第 2.3 节、I28）。p 放在内容包 `core/protocol/` 并带版本，变化不直接改变 F、G、C、J（X01、SYS06）。她的性格、喜好、说话方式和与每个人的关系只在核心状态里，经 m 作用于模型。
- **网络生活（ADR 0011）：** 诞生之后由你打开。与你共用账号；她以 Nemu 的身份说话，从不冒充你，让你承担的事要你审批；你的秘密在结构上不进入她对外交往的输入；诚实底线不变。

### 6.6 说话模式与显存

三种模式见 ADR 0003。显存估算如下，以 P0-07 实测为准：

| 配置 | 渲染 | TTS | 载体（含缓存） | Windows 与其他 | 合计 |
| --- | --- | --- | --- | --- | --- |
| 3080 10 GB，模式 A | 约 1 GB | 0.6B，约 3 GB | 4B 级 4 bit，约 3.5 GB | 约 1 GB | 约 8.5 GB |
| 3080 10 GB，模式 B | 约 1 GB | 1.7B，约 5–6 GB | 无 | 约 1 GB | 约 7–8 GB |
| 3080 + 第二块 16 GB 卡，模式 A | 3080 上：约 1 GB | 3080 上：1.7B，约 5–6 GB | 第二块卡上：8B 级 8 bit 或 14B 级 4 bit，约 10 GB | 约 1 GB | 两块卡各自不超限 |

显卡建议见设计文档：先在 3080 上完成 P0-07 的载体探针，确认 J 可行后再决定是否购买。

### 6.7 助手与办公

- 助手经 `codex-bridge` 接入 Codex app-server，按「日常、工作、困难」三个档位配置模型（ADR 0004）。她可以把问题或任务交给助手，结果回来后用自己的话告诉你。
- Office 连接器（.NET COM）是行动闸门下的执行器：
  - Word 的修改用 `UndoRecord` 包成一步，可以撤销；
  - Excel 写入前备份到隐藏工作表；
  - PowerPoint 备注写入前保存原文并提供还原。
- 用户自己的 Codex 会话（可选，默认关闭）：钩子把开始、需要审批、结束三类事件发给 Nemu，作为观察事件。

### 6.8 桌面场景交互

- **感知（koffi）：** EnumWindows、IsWindowVisible、IsIconic、DwmGetWindowAttribute（EXTENDED_FRAME_BOUNDS、CLOAKED）、GetWindowThreadProcessId + QueryFullProcessImageNameW、SetWinEventHook、EnumDisplayMonitors + GetDpiForMonitor、SHAppBarMessage、SHQueryUserNotificationState、GetLastInputInfo、GetGUIThreadInfo。
- **两条去向：**
  - 高频的几何信息（窗口矩形、可站立平台、光标插入点）只给身体，用于坐窗沿、跟随、下落、让开光标，不进入核心；
  - 低频的语义事件（前台应用切换、开始或结束空闲、勿扰状态变化、会议开始或结束、锁屏）作为观察事件发给核心。
- **坐标：** 每显示器 DPI 感知 v2；一律物理像素；换算只在 `packages/desktop-sense` 与 `apps/desktop` 中出现。

### 6.9 安全与隐私

- 本地优先；默认无遥测；密钥用 Electron `safeStorage` 加密保存。
- 权威存储在 `%LOCALAPPDATA%\Nemu\core\`；命名管道 ACL 只允许当前用户；worker 低完整性运行。
- 发给远程模型的只有 o、p、c_task 和必要的投影样例；IRL 与天性评估的远程后端另外收到当前事件与 c_core（P0-08）。核心状态本身不出本机：R 的概念定义也是核心状态，所以情境吻合 M 默认只用本地后端，用远程后端要你允许。窗口标题、文档内容等个人上下文需要 T1 授权。
- 截屏与视觉理解默认关闭，开启时有常驻提示。
- 所有行动（包括被拒绝的）都在 H 与 Q 中有完整记录，面板可按日期查看。
- 网络生活中，你的秘密、密码和文件靠结构隔离，不在她对外交往的输入里（ADR 0011）。
