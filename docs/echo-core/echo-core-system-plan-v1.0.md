# Echo Core Ada 全系统施工总方案 v1.0

版本 1.0 日期 2026 年 9 月 23 日 对应核心算子与整体动力学规格 v1.0

本方案覆盖整个 Echo Core / Ada：从终端和事件接收，到 H 历史证据权威、IRL 与 Concept Registry、事实检索、x/R/θ、F/G/C/J、基础模型、任务协议、自主调度、权限与行动，再到事务存储、重放、身份延续、多端接入、容灾、部署和验收。四算子作为其中的核心机制子系统，不能代替其他系统层的施工合同。

工程团队可以据此拆分工作、实现接口、安排集成并提交验收。参考部署采用单机单写者 Trusted Core、独立 Proposal worker、单一事务存储和可测量的内部激活调制载体。先证明模型接入可行，再建立从接收、记录、语义、状态、行为到真实反馈的完整产品路径。

本文件交付的是实施设计、接口和验收安排。本轮没有实施这些业务模块，没有运行模型实验，也没有把待执行测试写成已通过。θ 直接沿用已交付方案，不重新当作缺失机制。工程默认值、实验待标定项和需要另行修改冻结边界的扩展，在文中分别标明。

# 1 基线和交付边界

总架构基线为 Echo_Core_v0.6.4_Frozen_Architecture_Review_and_Remediation.docx；工程基线为 Echo_Core_v0.6.4_Integrated_Implementation_Review_and_Remediation.docx；核心闭合基线为 《Echo Core Ada 核心算子与整体动力学规格》v1.0（仓库规范文件：Echo_Core_Ada_Core_Operators_Closure_Spec_v1.0.docx）。三者共同覆盖总系统，最新算子规格补齐此前保留的 θ 与四算子接口。施工不得从早期正文抽取一句旧接口，覆盖后来已明确的责任、权限和失效合同。W00 要固化三份交付文档的版本与摘要，并建立差异登记。

优先级为：用户已冻结的本体和约束，随后是本轮核心算子规格的明确闭合合同，最后是本方案的工程选择。若发现真实冲突，应登记、定位并修订对应合同；不得在代码中静默改变算子写权限或证据标准。工程选型可替换，但必须保持输入、输出、权限、时间和重放语义。

首版完成条件是：一个实例能合法接收事件，确定性更新 x，形成并验证非零 χ/K，完成至少一次真实合法的 R→θ 接管，经 J 对实际模型产生可重复的预期作用，并在重复输入、失效、崩溃、重放和缓存变更下保持不变量。仅接通 API 或只跑通模拟器不能算完整核心交付。

首版明确不包含：分布式多主写入、在线改变基础模型权重、J 私有在线优化器、运行时 residual 扩维、未经 R 时间功能资格的新 b/Λ 凝固，以及无需合法 C 就局部关闭 θ 的 C.REVOKE 路线。严格 θ 失效仍可导致全核心长期隔离。这些限制是施工边界，不以占位实现冒充已完成。

# 2 首版技术路线

| **层次**        | **首版工程选择**                                  | **选择理由与替换约束**                                                |
|-----------------|---------------------------------------------------|-----------------------------------------------------------------------|
| Trusted Core    | Rust 库和独立 core-daemon 进程                    | 用类型和模块可见性限制写权限；算子本体不访问网络、数据库或实时时钟    |
| Proposal 与实验 | 独立 Python worker 进程                           | 学习和推理工具易接入；只得到有类型输入和不可变资源，无权威存储写权限  |
| 事务存储        | 本地 SQLite，单数据库，WAL，FULL 同步             | 单实例便于原子发布与故障注入；不把状态拆到多个独立事务库 \[E2\]\[E3\] |
| 大对象          | 本地不可变内容寻址目录                            | 保存完整模型输出、试验原始结果和资源；先持久化再提交引用              |
| 进程协议        | Protobuf 消息，Unix domain socket，长度和时限约束 | 传输与权威内容编码分离；不把 Protobuf 字节序列当规范哈希 \[E1\]       |
| 模型载体        | PyTorch 显式 residual 注入包装，冻结 decoder      | 第一版一个 hook、固定掩码和低秩 U；禁止只有文本提示的替代实现         |
| 自动化验收      | Rust 核测试、Python 实验执行器、独立只读核验器    | 结构判据与行为判据分离，所有结果关联规格编号                          |

这些是工程默认选择，不是新的本体公理。若现有实现语言不同，先保留可复用代码并做合同适配；只有能够提供相同隔离和确定性保证，才替换参考模块。不能因为采用 Rust 就宣称安全，也不能因为采用事务数据库就省略提交协议。

W00 冻结实际工具链、依赖锁文件、操作系统、CPU 指令配置、数据库构建和模型运行环境。选择当时已核验的依赖版本，不在计划中编造未来部署版本。数据库构建必须包含已知相关 WAL 修复，并通过本方案的持久化测试；数据库文件放本机可靠文件系统，禁止以网络文件系统共享 WAL。\[E2\]

首个可行性实验提前执行 W12 的载体探针：加载候选模型、固定真实注入位置、验证零调制与注入差值、重算缓存。它不提前开放 G/C，也不改变规格给出的核心施工依赖。若只能使用文本 API，后续仍可开发结构核，但不得签发完整 J 交付。

# 5 数据类型和权限合同

保留 S=(H,x,R,θ,L) 与运行 Q、入口 D/U 的既有职责。H 是 Γ 接受的规范事件、观察、声明、行动结果、来源与纠错关系的只追加历史证据权威；它保证“记录过什么及其来源/纠错关系”，不保证记录中的命题天然为真。x 是近期历史对声明短时窗口内未来核心转移的有限维近似因果充分状态。R 保存固定 x、θ 与合法事实访问后仍不能被消去的、尚未凝固的最小历史区别 χ 及其条件耦合 K、资格和作用控制。θ 是长期核心动力学状态，概念上采用 θ=(D_θ,G_θ)：D_θ 表示当前生效的长期动力学，G_θ 表示使这些动力学可寻址、门控、组合、接管、失效、隔离和修复所必需的当前责任结构。L 仍是只追加的凝固/贡献账本。后文的 receipt、证书、slice、barrier 和索引均是这些对象的字段、派生消息或运行资源，不成为第五算子或新的因果状态。

状态完备性作为 W01/W16 的硬合同：固定 S/Q/U、当前规范事件 r、处理时刻 Δ、全部已记录实际结果以及显式版本化环境 Ω（Registry、scope/解释器、carrier、model、tokenizer、配置等）后，不允许任何未声明的持久变量改变下一次权威核心转移。worker 私有内存、缓存命中、索引内部状态或临时优化器可以影响性能，但不得改变权威语义结果；若某持久信息确实能改变未来核心转移，必须归入既有状态、Q/D/U，或成为显式版本化且受迁移/资格合同治理的 Ω 资源。

来源与 provenance 默认只用于形成解释、预算、失效传播、资格和审计，不是运行时触发器。只有来源类别本身被显式写入合法 scope、具有端点输入权限并通过资格验证时，才可参与 F/G/J 的求值；Registry/worker/cache 不得凭来源指针或历史文本暗中形成长期行为作用。

所有 ID 的合法身份由 Core 注册：worker 可以提出临时字符串，但不能自行签发 root、Concept、责任或证书。source_id 表示来源，root_id 表示独立性分组的身份记录，responsibility_id 表示稳定作用责任，causal_revision 表示机制版本；不得用一个 UUID 混充四种语义。不同 root_id 不自动等于因果独立：由同一上游行动、exposure 选择、模型生成副本、复制来源或共同未控制原因产生的记录，在资格与 θ 信用中必须按同一或相关 root 处理，除非预注册设计能够识别所需的独立外生变异。

R 的 evidence revision、active causal revision、责任绑定分别存储。θ disposition 是 suppression 权威，R binding cache 可重建。更改证据、归档 R、禁用或补偿 module，都不能凭名称变化恢复已经接管的 R 作用。

Trusted Core 通过能力类型限制写入：F 返回 StagedX；G 返回 StagedR；C 返回 StagedThetaAndL；J 只返回信封。只有 runtime 持有 CommitCapability 和 Q 写能力。C 的隔离请求是结果字段，runtime 依据固定规则原子生成 Q 故障状态。测试必须尝试让 worker 直接写库，并观察操作系统和协议两层拒绝。

# 6 编码 数值和配置

Protobuf 只承担跨进程传输。权威哈希使用本项目的 CanonicalV1 编码：显式 schema 版本与类型标记、固定字段顺序、长度前缀、固定端序整数、严格 UTF-8；集合按规范键排序，向量保留语义顺序。哈希函数采用固定版本 SHA-256，摘要加入对象类型域分离。哈希用于寻址和绑定，真正的语义等价仍由规范字段判定。\[E1\]

不接受未知权威 schema、未知枚举、重复单值字段或超限消息。RPC 解码层要拒绝这些情况，不能让解析器静默丢弃后继续提交。可扩展审计字段单独版本化，不参与未声明的因果计算。新增字段用新的规范编码版本和显式迁移，不靠编译器升级重新解释旧摘要。

权威核首版采用有限 binary64 数值；拒绝 NaN/Inf，规范化负零，固定舍入、矩阵求和次序和超越函数实现版本，不启用改变结果的 fast-math。单位在类型中区分：时间为有界整数纳秒，λ/γ 为每秒，向量和预算各有明确量纲。模型可用另一 dtype，但信封必须记录转换与误差容限。

结构重放要求同一核构建和支持数值目标得到相同规范结果。跨 CPU、编译器或数学库不自动承诺逐位相同；先运行黄金向量和全日志核验，通过后登记兼容迁移。浮点误差不得使边界判据时过时不过；预算计算使用保守上界，统计边界不确定则 continue_shadow 或拒绝。Φ 的半群性按预注册容差验证，正式时间投影始终从锚点一次求值。

必须提供两个不同用途的 profile。structural_fixture 仅用于逻辑测试，可设 d=4、b=0、λ_i=1/s、γ=0.05/s、固定非心理语义矩阵与明确预算；它不能用于声称真实行为有效。deployment profile 的 d、η_x、λ 区间、ρ、N_candidate、α、δ、驻留、长期窗口、d_Θ 权重、root 配额、n_min\>1、因果 root 独立性合同、θ ValidityContract、hook/rank/U/W/β、延迟和动作上限必须由 W17 逐项冻结。未填写或未经所需验证的字段阻止相应能力启用。

初始 θ 的合法 b/Λ、基础事件敏感性 B_0、初始 x、基础模型和载体形成可追溯 genesis 清单。预置内容不是由本系统经历形成的成长，不发行虚构 root。新 θ module 只能走 C；B(θ) 的可成长部分必须以具稳定 responsibility_id 的 F_event 责任从已合格 R slice 接管，不允许 C、A_x 或 worker 直接改写全局 B。修改 genesis、维数或载体属于显式版本迁移。

# 7 存储模式和权威边界

首版使用一个 SQLite 数据库保存所有必须原子发布的小对象和引用。以下表名是物理分解；每行必须能归属于既有 H/x/R/θ/L/Q/D/U、显式版本化 Ω 资源或可重建派生索引，不能因建表、缓存、Registry 或后台 worker 额外制造状态权威。stored R/θ 与它们的有效作用视图分离：纯读取和时间投影不得写回 R/θ。

root 总配额登记后分为 b_R 与 b_Θ，且二者之和不超过总量。G 读取 R 配额及消费投影，C 读取 θ 配额及 L，不通过通用库访问绕开合同。固定配置变化不为旧 root 重新充值。跨分支继续使用同一来源时不能复制额度；首版禁止两个可写生产分支同时消费一份权威 root 账本。

数据库连接初始化并验证 journal_mode=WAL、synchronous=FULL、foreign_keys=ON，设置有界忙等待。真正提交失败不返回成功。FULL 有助于提交持久性，但仍依赖底层存储实现正确，必须在目标环境验证故障恢复。\[E2\]\[E3\]

大对象写入步骤为临时文件、写完、校验摘要、fsync 文件、原子改名、fsync 父目录，再允许权威事务引用。对象读取再次校验摘要。数据库与对象目录之间不假装存在跨介质事务：提交前残留可作为孤儿回收；提交后的引用丢失是恢复故障。垃圾回收必须与提交共享对象锁或代际保留协议，不能在“已准备但未引用”的窗口删除对象。

# 9 接入 事件和历史证据权威

W18 提供文本、结构化工具结果、系统维护、执行回执和未来传感器的统一接入。第一版实际交付文本与结构化结果连接器；其他模态必须遵守同一 EventEnvelope，不能因增加音频或图像建立另一条成长路径。身份验证属于运行时来源认证，内容是否真实仍由认识论类型和证据机制处理。

事件字段至少为 id、kind、event_time、ingest_time、parents、payload_ref、provenance；补充 device/session、stable_source_key、payload_digest、action_id/trial_id、correction_of、derivation。支持 startup、observation、action_request、execution_result、consequence、cancel、correction、maintenance。因果父引用必须已有或是本事务合法 staged 引用；缺失父项的反馈可以记录并标记 unresolved，不能编造来源。

接收回执区分 RECEIVED_DURABLE 与 CORE_COMMITTED。前者仅表示 D 已持久化，不能让终端误以为 x/R/θ 已处理。D 有明确字节和队列限额；超限在接收成功之前拒绝并返回可重试状态，不先确认再丢数据。终端重连带稳定源 ID，不通过内容相似度猜测两个真实观察是同一事件。

Γ 的确定规则为：同源稳定 ID 且同载荷重复，过滤；同 ID 异载荷，记录冲突并拒绝覆盖；合法新记录，进入核心事件序列；来源认证失败或格式非法，留入口审计但不成长。源系统没有稳定 ID 时，由接入层分配并把可能重复明确标为不确定，不声称能从相同文字识别独立经历。

H 保存“谁在何时以何种方式提供了什么”，不保证每项陈述都是世界真相。纠错是新事件，保留被纠错内容、修正关系与生效解释版本。检索默认返回当前有效解释及原始引用；审计可查看旧版本。自身输出、摘要和叙事必须沿来源链继承派生标记，不能重新输入后升级为外部独立根。

交付验收包括 D=(e1,e2,e2) 的精确去重、冲突 ID、乱序延迟回执、未提交时断电、过滤不采样不推锚点、多终端同时输入，以及所有接收回执的可恢复性。接入层不解释“这件事应使 Ada 改变多少”。

# 10 IRL 和 Concept Registry

W20 完整实现 Raw→Adapter→SemanticCandidate→Validated→Resolved→Canonicalized→Accepted。SemanticCandidate 与 SemanticGraph 是两个不同类型。只有治理通过的有限子图能成为 z，未通过部分留下错误原因；不得通过强迫模型重试把不确定性洗成确定事实。

SemanticGraph 保留 Ref、Claim、Act 三类原子。Claim 的 predicate 必须是 ConceptRef，并包含 roles、value、polarity、modality、time。每个原子具有 source_refs、source_span、derivation、epistemic_type、resolution_state 和 representation_version。否定不是负面情绪，用户自报不是外部验证，quotation 内的指令也没有协议权限。

确定性 adapter 优先处理可信结构的工具与系统结果；自然语言 worker 仅见当前事件、c_core 和注册表查询投影，不见 x/R/θ。治理按 schema、容量、类型、来源、span、引用闭包、认识论合法性、Concept 身份与规范排序逐项校验。来源合法只证明引用存在，不证明语义理解一定正确；语义准确率另由冻结语料、人工标注或可核验任务验收。

Registry 记录不可变 Concept ID、signature、grounding、关系、状态和修订来源。Resolve 可返回 existing、provisional proposal 或 unresolved；无法解析不必新建概念。新身份由 Core 暂存为 provisional，随事件一次提交。stable 升级与 alias/equivalent 关系需要明确来源和治理记录，embedding 近邻只能召回候选。旧 ConceptRef 和旧解析资源保留，不因词表更新批量改历史。 Registry 只治理概念身份、规范化与解释资源；Registry 更新本身不得直接产生新的 F_event、G_meta、J_direct 或 θ 长期行为作用。任何经验形成的行为倾向仍必须经 x/R/C/θ 的合法路径。

对 alias 图执行循环检查并计算确定性 canonical representative；有冲突返回 unresolved/拒绝该变更。canonical 映射变化可能改变 scope 和旧证书的解释，因此不自动重解释 active R/θ；先做依赖分析与兼容证明，否则继续旧资源或进入 review。Registry 废弃一个 label 不等于撤销其全部历史身份。

最低测试集包括同义改写、否定、条件、愿望、引语、用户自报、模型推断、纠正、歧义指代、工具结果与新造词。恶意候选包括伪造 source ID、把 model_inference 改成 user_self_report、越界 span、超深图、未知 Concept、隐藏指令和环状 alias。黑箱评分器可提议错误，但不能自行宣布自己的解释是真值。

# 11 事实检索 任务协议和只读叙事

W19 为 H 提供显式 FactQuery 和 FactProjection。请求包含已提交历史前缀、类型/时间/来源过滤、查询版本、最多条数/字节/步骤和用途；响应包含内容、source ID、可用性、纠正链、索引版本及截断标记。不存在命中、索引落后、权限不允许、对象缺失和预算耗尽必须是不同结果，不能统一变成空集。

c_core=V(H_k,current_event) 供 IRL 使用，其查询计划不得由 p、当前人格或 shadow 文本任意改变。c_task 供任务层按当前任务和权限检索，可以具有不同预算；二者不能混用。C 使用声明的支持与反证查询计划，完整性不足则 EVIDENCE_INCOMPLETE。全文/向量索引是派生加速器，返回的片段仍须核对原始 H，索引分数不是证据资格。

第一版优先实现可界定成本的精确条件查询和有限候选召回。允许语义召回，但记录实际查询与返回；不能把不可重放的“最新 embedding 服务”当隐式输入。IRL/R witness 的事实替代对照必须使用相同获准预算和同样能用的查询族，不能故意给对照更差的检索器以证明 R 必要。

W21 将 p、当前输入 o、c_task、m 分为独立输入域。协议配置身份和权限由运行时绑定，历史中的文字不因被检索到而成为系统协议。p 的变化更新 Q 中的运行绑定、使不兼容计划失效；固定时间和经历下，不直接改变 F/G/C/J。任务目标与待办在 Q.P，不在 x 中藏提醒，不在 θ 中写待办完成标记。

任务模型只输出 ResponsePlan/ActionPlan：计划 ID、绑定快照、任务/协议版本、输出或工具参数、预计作用域、依赖、截止时间。模型不能填一个“已授权=true”替代权限决定。普通对话文本也是对外输出，保留实际发布回执和原始文本引用；中途取消不会删除已经发布的部分。

自我叙事 N(S) 只读展示经允许的来源和解释，不形成独立核心副本。叙事删除不清空 R/θ/L，导出后再导入仍标自身派生。管理界面显示当前工作模式、来源链、待办和复核状态，不提供“直接调高信任值”等不存在的本体编辑器。需要纠错时创建来源锚定事件，不能用 UI 绕过 Commit。

第一版界面交付对话、输入接收/处理状态、待执行动作与取消、连接器授权、当前降级模式和只读审计查询。详细数学参数留在管理与实验界面，不要求终端用户理解内部矩阵才能使用系统。

# 12 授权作用解析与共享接口

# 13 快速状态和 F 施工

W05 实现 FastStateSpace 的 validate、project_time、validate_drive、apply_drive、distance、serialize/deserialize；首版插件是固定 d 的盒空间。x 的施工语义是“近期历史对声明 T_x 内未来核心端点的有限维近似因果充分状态”：在固定 R/θ、合法事实视图和 Ω 后，压缩到同一 x 的近期历史应在该合同内近似不可区分。保留抽象接口但不同时建设多个未经验证的状态表示。坐标无预置心理名称；runtime 也不能增加隐藏文本缓冲帮助 x 通过测试。

# 15 试验 资格和统计结算

沿用核心规格的因果独立 root block 有界差异检验：为每个全局检验机会 j 分配 alpha_j，再为累计 n 分配 alpha_jn；一项正式比较在该累计 n 只结算一次。不同 root_id、不同时间点或不同记录并不自动形成独立 n；同一上游行动、exposure 选择、模型生成副本、复制来源或共同未控制原因产生的 block 必须合并/相关处理，除非预注册设计能够识别独立外生变异。机会分配属于固定治理，G_meta 无权改变。scorer、主指标、等价检验和停止规则均纳入预注册机会；换名字、split 或更换 worker 不重置试验族。

改进需要置信下界超过最小效果量；等价需要整个置信区间进入容差，不能用不显著代替等价。样本量由 W17 根据目标效果量、保守方差界和总机会预算事先计算；没有达到功效只报告证据不足。出现选择性缺失、root 因果不独立或行动策略混杂时，返回 non_identifiable，不能凭插补得到正式因果资格。统一执行“机制不得仅凭由自身作用因果产生的后果获得自身资格信用”：若 K/θ→行动或 exposure→结果 Y，Y 只有在随机化、合法对照或独立外生信息足以识别目标反事实时才可贡献资格。

证书绑定语义依赖和测试域，Proposal 绑定当前精确快照。无关 x 数值变化不使长期证书每次作废；相关 baseline、scope、解释器或模型变更则暂停试验或重新取证。过期的 Proposal 不能静默 rebase，已有结果能否在新候选使用必须有预注册兼容规则和新的机会处理。

# 20 自主调度 任务与行动闭环

W13 实现 Q 中既有 P 待办、A 行动生命周期和 Z 调度状态。随机等待只决定何时尝试行动，不创造目标。候选行动来自明确任务、已授权机会规则或模型计划；执行权限、费用、并发容量和目标合法性由运行时门控。任务即时回复与自主发起使用不同队列策略，不用一个随机等待拖慢必须响应的任务。

首版自主强度使用固定、可校准的读出函数，以合法 J 调制向量为核心输入，乘运行门控，并限制在零与 λ_sched,max 之间。这样 x/R/θ 的作用经既有授权 m 进入时机，不另开读取全量 R 的旁路。固定读出参数属于运行实现配置，不在线自学习。相同 m 同一门控产生相同条件强度，shadow 文本和候选数量不参与。

参考实现可用有上界强度的 thinning：保存抽样资源版本、实际随机数/结果、候选时刻、强度、门控和判定；只有在已绑定投影与门控下接受候选。新观察、协议/权限或运行模式改变使旧调度条件失效，按固定规则重评估。轮询仅是唤醒手段；固定倒计时、常数强度或不响应状态消融的实现不能通过自主时机功能验收。

调度记账通过有类型内部维护记录和外层发布进入 Q。它不发行证据根、不自动生成 drive、不因重试消耗新的资格机会。纯时间部分遵守 Φ；被 Γ 过滤的重复接收项不重新抽样。恢复读取已有抽样结果，不能换一组随机数把坏结果重新抽掉。CPU 唤醒延迟、触发时间、计划时间和实际执行时间分别记录；不能把排队后的实际行动当成理想抽样时刻。

实际自主行动设最小开始间隔和有限并发，另限制计划生成、维护及失败重试次数，保证非爆炸与无忙循环。允许永久等待的模式明确记录；需要最终执行的任务由任务期限和运行协议处理，不在门控长期关闭时虚称必将自主行动。

行动状态至少包括 PLANNED、REQUESTED、AUTHORIZED、DISPATCHING、SUCCEEDED、FAILED、CANCELLED、UNKNOWN。outbox 与 action-request 原子登记；执行器只接受当前有效执行凭证和 action_id。真正发送前再次核对 branch、snapshot continuation、protocol、permission、ingress frontier 和资源。授权只约束运行行为，不成为 θ 的直接输入。

执行与结果记录之间没有通用跨系统事务。对支持幂等键和结果查询的连接器，按 action_id 去重/核对；对不支持者，发送后崩溃进入 UNKNOWN，不能盲目重发。新事件取消的是尚未发生的步骤，已发生行动的延迟结果仍接收并保留原关联。取消、失败、反馈、后果是不同记录，不因 UI 关闭而删除。

首版流式回复采用有编号的输出块与已发送记录；无法确认对端是否收到时保留 UNKNOWN_DELIVERY。结构重放不再次发送任何块。整段响应完成不能冒充所有块一次原子发布。请求登记属于明确合法 continuation 时不递归生成新请求，避免自失效和无限请求链。

# 21 运行治理与失败处理

W22 的权限管理采用独立协议版本、身份认证、连接器作用域、资源限额和执行凭证。UI/worker 不能直接操作数据库；管理员命令也走类型化接口和审计。暂停核心输出是运行时门控，不能借暂停接口偷偷编辑 θ。学习 worker 与试验 worker 运行在独立进程，无权威目录写权限，无生产连接器执行凭证。

| **故障**             | **当次处置**                             | **恢复条件**                           |
|----------------------|------------------------------------------|----------------------------------------|
| IRL 语义失败         | H 与合法时间路径继续，失败语义 NO-GROWTH | 合法新表示或后续明确修正；不补造旧结果 |
| A_x 超时或非法       | 使用合法 Φ 结果，无猜测 drive            | 当前绑定合法重试或未来新事件           |
| G/C 非关键候选超时   | 延后成长，提交事实和必要快状态           | 未来 typed result 与当前绑定重新校验   |
| 硬失效或污染后代     | 同事务安装屏障；必要时全核心隔离         | 合法修复、复核和 x 清洁处理            |
| J/carrier 失效       | 明确 m=0 任务模式，停核心自主动作        | 版本、注入、缓存和固定探针全部通过     |
| 对象缺失或提交链损坏 | 停止权威发布和相关行动                   | 完整恢复与结构核验；不能由模型猜补     |
| 外部执行状态未知     | action 留 UNKNOWN，不盲目重发            | 外部查询/独立确认或明确人工处理记录    |
| 时钟跨重启不可信     | 停止时间资格与核心自动执行               | 恢复合法时间映射或显式受限恢复合同     |

系统至少区分正常、NO-GROWTH、CORE_UNMODULATED、CORE_QUARANTINED 与存储恢复故障。它们是 Q 的运行状态和能力标志，不是新的情绪维度。多故障共存时按最严格能力交集执行，恢复某个 worker 不自动清除其他屏障。

核心隔离时可以记录事实和执行固定治理的独立证据结算，任务层可 m=0 响应。不能因不读取 θ 就使用仍含污染的 x；不能因禁用 J 就让受失效 meta 影响的候选继续成长。恢复应逐项证明 barrier 原因已解决，再原子改变运行模式。

若 θ 的时间参数或数值资源本身已无效，不能继续使用它们并把 Φ 标为正常。保留最后可恢复状态和故障记录，关闭正式 F/G/J 路径；后续经合法时间资源处置和显式快状态恢复事件重新锚定。事实维护仍可进行，失效期间的快状态轨迹不得伪称已连续恢复。

clock provider 使用单调区间时钟并记录 boot/clock epoch；跨重启通过可信墙钟或已界定误差的时间来源恢复真实经过时间。时间倒退、过大跳变和不可界定停机时长是显式故障，不能用“最后时刻加一”伪造驻留，也不能默认离线时间为零后声称动力学连续。确切时间不可得时需报告恢复不确定性，禁止利用它获得长期资格。

# 22 Replay 检查点和工程身份

W14 的结构重放只读取已提交原始事实、accepted candidates/results、时间、规则版本、资源和确定性核。它重建 H/x/R/θ/L/Q、U、Registry、owner、预算、trial 使用和行动状态，不调用模型、不取新时钟、不重发行动。种子、prompt 和输出摘要都不能替代实际非确定性返回。

提供两种核验：从日志重算得到相同规范状态；用独立只读检查器检查追加前缀、余额、唯一 owner、失效屏障和依赖闭包。不能仅比较被同一错误实现一起算出的两个哈希。核验器采用独立推导的断言和攻击夹具，避免复制实现逻辑作为测试预期。

Checkpoint manifest 绑定 origin、branch、parent、commit 与 D/H/L 位置、状态与 Q、资源摘要、数值构建、时间锚点、未完成行动、迁移记录和对象清单。SameLineage 和 ValidContinuation 分别返回 TRUE、FALSE、UNKNOWN；记录缺失返回未知，不能因快照哈希相似推断是合法延续。

备份恢复必须恢复到完整一致的提交点，并核对备份之后可能已执行的行动。恢复较旧点不能使试验机会、root 消费或外部发送记录归零继续运行。尾部无法恢复时登记有损恢复/新分支，隔离可能重复执行的动作，不能宣称无损延续。首版不支持生产分支自动合并。

迁移分为存储格式、语义资源、状态表示和模型载体。每种迁移记录前后版本、映射、范围和回退点；语义保持需独立证明或测试，不能统一叫“升级”。更换 tokenizer、U/W、hook 或模型必须通过 J 迁移实验；更换 Registry 解释需复核相关证书。迁移不发新 root，不退款、不借升级提高额度。

结构重放和行为重放分开报告。模型环境并不一般保证跨版本、平台逐次结果相同；锁定环境、确定性选项与随机条件仍需实测。\[E4\] 无法逐次一致时保留真实历史输出，并以预注册统计检验衡量新环境行为；不通过再次生成覆盖过去。

# 23 部署 多端与容灾

W23 的第一版拓扑是一个权威 core-daemon、同机事务库/对象目录、受限 worker 与模型适配器、多个可重连终端。手机和桌面只是入口和显示，不持有可独立成长的生产核心。终端离线可暂存待发送观察，带原 event_time 重连上传；不得倒插已提交顺序或用迟到时间回退状态时钟。

多端使用同一 branch 的单一领导者。请求认证绑定实例、终端和权限，传输加密，写入由服务端序列化；终端的本地缓存和聊天窗口可丢弃，持续性来自完整权威状态。首版禁止自动双主和跨主自动合并。需要高可用自动切换时，必须另有可验证 fencing/共识合同，不能用两个同时运行的 SQLite 副本代替。

备份包含数据库一致性快照、不可变对象、版本资源、manifest、未完成 outbox/行动和恢复所需密钥引用。使用一致备份接口或停写检查点流程，不在数据库运行时只复制主文件、丢掉未合并 WAL。\[E2\] 加密增量副本与周期完整副本放独立故障域；备份成功以恢复演练和对象闭包核验判定，不仅是文件上传成功。

发布采用停收核心新工作、排空或持久化在途阶段、停止发出动作、生成检查点、校验新构建、只读重放、启动受限模式、探针通过、再开放。数据库格式升级失败恢复整个一致检查点，不能将新数据库配旧对象目录。对已经发生的外部动作只做核对和补偿，不倒退世界。

主机故障后的切换先证明旧主失去执行和提交能力，再恢复新主。无法证明时保持只读或停止行动，避免两个执行器持同一身份发出动作。RPO、RTO、复制确认语义和允许丢失窗口在部署 profile 中填写；异步备份不能声称零数据丢失。

初期本地/单机交付已包含完整总系统的运行能力；跨机多主、自动故障转移和生产分支合并属于后续扩展包，有明确前置合同，不作为已经实现的能力宣传。

# 24 性能 容量和可观测性

W15 为入口、IRL、纯核、C 准备、提交、J、模型生成、执行和端到端响应分别测 P50/P95/P99、吞吐与队列年龄。先在目标模型和硬件上测量，再冻结 SLO。无法从架构文档推导真实 GPU 吞吐或用户可接受等待，因此这些数值是部署前待标定项，不用编造时延承诺填表。

普通路径采用确定性 adapter、本地验证、一次轻量 A_x 和 ready-only G/C；深度候选和行为 probe 出队为试验任务。状态已提交且满足降级条件时，任务层可以明确 NO-GROWTH/m=0 响应。性能优化不得跳过 H、来源、幂等、绑定和原子发布，也不在后台私自追写 θ。

每个 profile 明确 D 队列、z 节点/边/深度、c 字节、R active/shadow、θ slot/tombstone、依赖图、候选数、试验并发、对象容量、action 并发、tokens 和重试上限。容量打满采取反压、延后成长、零作用归档或明确拒绝；不能删除责任 tombstone 让 R 复活。

H/L 是追加权威，可分段归档到仍可读取的不可变介质；归档只改变存放位置。需要的历史或证据暂不可用，查询返回 unavailable，相应资格停止。若产品要求永久删除某些内容，必须另立数据生命周期及其对重放和证据有效性的合同；本方案不假装“删除后仍完整可重放”。

日志使用 event/commit/proposal/trial/action ID 串联，记录原因码和耗时，避免将日志文字反向输入核心。监控必须看到：重复过滤、语义降级、非法 Proposal、stale 拒绝、窗口剩余额、owner 冲突、依赖屏障、x 污染、carrier 未应用、KV 失效、UNKNOWN 动作、对象缺失、WAL 大小和备份年龄。报警不直接修改成长参数。

只读审计接口支持 explain_commit、trace_responsibility、trace_root_spend、explain_rejection、list_barriers、verify_checkpoint。权限最小化且支持分页，不把完整隐私历史无界返回到模型或普通 UI。原始敏感内容和模型实验材料按访问域隔离，密钥不进入 prompt 或持久化调试明文。

# 25 全链路样板与测试夹具

先构造确定性外部过程夹具：至少两个可证明因果独立的观测 root、可核验目标、受限同预算事实检索、近期效应和更长历史条件效应；另构造“不同 root_id 但同一上游原因”的负例。冻结合法替代族、candidate-free baseline 和参考指标，不允许测试在看到结果后修改环境。正例只证明该有限域中的机制可工作，不证明存在唯一或普遍正确的心理表示。

完整样板从 genesis 启动，接收观察并形成 H/z/x；在 candidate-free 且因果独立 witness 下生成 χ/K shadow；运行真实或可明确标识的外部过程试验；合格后 G 激活并完成 canary；经过实际驻留、≥n_min 个因果独立 roots 和长期证书，由 C 接管当前作用并安装 ValidityContract；J 将提交后有效作用视图送入真实模型；模型产生计划，权限门决定执行，结果作为新事件返回。每一步都有可定位的提交和拒绝替代路径。

样板再注入硬反证，检查责任关闭、后代屏障、x 污染与严格 θ 隔离；在 G stage、θ owner、L 消费、事务提交和发送后记结果前分别崩溃；恢复后比较完整权威状态和外部动作，最后更换载体执行迁移拒绝或合法迁移。一个成功样板和一个污染/失败样板共同构成集成演示。

夹具分四类：纯核黄金向量；含重投、乱序、缺资源和时钟异常的故障轨迹；可重复外部控制过程；真实模型与真实行动实验。模拟器可用于数学/事务测试，不能替代最终模型行为和外部因果辨识。任何 fixture-only 资格标记在生产配置中不可接受。

CI 将待实现/未执行/通过/失败/不可辨识分开。mock 证书只在封闭结构测试中有效，不能导入生产数据库。拒绝路径覆盖充分仍需正向实例：恒等 G/C、常量 J、忽略 m 的模型都必须被验收杀死；正常 F_out 恒等则是允许实现。

每个 gate 只有在证据包齐全后标通过。工程 gate 与实验 gate 分开：M5 的结构模拟可先完成，但长期 T_promote/驻留尚未经历时，实验部分保持未通过，不用压缩时间代替真实驻留。没有行为验证的系统可作为开发原型交付，不能命名为完整已验收 Echo Core。

# 27 分工 排期与第一批任务

建议按责任而非算子名称分配人员：核心与事务负责人负责 W01—W05/W10；语义与事实负责人负责 W18—W20；塑形与实验负责人负责 W06—W09/W17；模型与运行负责人负责 W11—W13/W21；基础设施与验证负责人负责 W14—W16/W22/W23。小团队可兼任，但提出候选与正式结果核验必须是不同代码路径，关键结论安排独立复核。

排期先按 M0—M7 的依赖和证据安排，不从文档长度推算可信完工日期。M0 完成后用实际 IRL 延迟、模型内存/吞吐、外部试验速度和目标效果量估算人力与历时；M3/M5 的样本及驻留时间单列，不能混入“开发已完成”的百分比。工程任务可并行，单 branch 权威提交仍串行。

| I19      | R 新自由度必须来自 candidate-free 历史非等价 | 候选自身造成的差异不得作为其必要性 witness；W06/W07                              |
| I20      | 长期 θ 更新要求 n_min\>1 个因果独立 roots    | root ancestry/exposure 图与独立性合同；重复 ID/split 不增加独立支持；W07/W09/W10 |
| I21      | stored state 与有效作用视图分离              | Phi_R/CompileAuthorizedEffects 为纯投影；读取、衰减、到期不写 R/θ；W03/W04       |
| I22      | θ 长期作用不得超出 ValidityContract          | 有限有效期到期或持续条件失效时严格隔离，不能静默无限延长；W04/W09/W10/W13        |

对施工方案进一步构造如下反例，并把修复写成必须实施的合同。这里完成的是设计审查，表中修复仍需由相应代码和测试兑现。

AT09 的实现细则：授权缓存键含投影时刻域/最近到期点。过期属于已知确定条件，即使后台维护队列延迟，正式作用也不能继续；R 证书按 R_eff 失效，θ 则按 ValidityContract 通过 Q 整体门控处理，不通过到期读取偷偷写 enabled。AT11 的隔离不禁止被明确授权的审计问答，但其内容重新进入成长时保留自身派生身份。

# 31 尚未定值的事项及阻断规则

当前不存在必须为了继续写代码而新设心理坐标或新增核心算子的必要。下列事项需要真实工程/实验数据，不能靠完整文档声称已经获得答案。它们有明确确定方式与启用前置条件。

上述多为经验定值或产品能力扩展，不是需要用户在两套核心哲学之间二选一的分岔。若以后要求“θ 没有合法更新额度也能立即局部撤权，同时其余核心继续运行”，则与当前严格模式构成真实设计分岔，必须修改冻结条款后另发版本。当前选择已明确：维持冻结边界，必要时全核心隔离。

冻结施工前必须具备可执行 IDL、版本化配置 schema、规范编码、权限矩阵、数据模式、错误与降级合同、全系统阶段门和验收编号。功能部署前进一步要求实际 profile 定值及其证据。两种冻结程度不能混称；本总方案足以组织施工，不是对未来实验结果的保证。

# 32 最终交付包与引用
