**R / G 可塑机制实现规格**

基于 v0.6.4 Frozen Architecture 的实现层深化 · Final Audit Draft

规格地位：本文件是 v0.6.4 冻结架构的实现层伴随规格。它深化 R、χ、K、G、shadow 验证、作用释放以及 C/θ 交界，但不增加第五个核心状态，不改变 H/x/R/θ/L 的顶层职责划分。

版本：Implementation Spec v1.0（最终审查稿）

审查目标：在进入编码前，尽可能暴露并修复循环论证、隐式自证、状态爆炸、行为漂移、统计假阳性、R/θ 双重计数、metaplasticity 自增强以及恢复/重放不一致等结构性问题。

术语约定：数学层保留 χ、K、G；工程层优先使用完整名称 distinction、coupling、plastic_update，避免继续占用单字母命名空间。

# 0 最终审查结论

本轮审查不是对前五步文字做润色，而是把它们当作将由第三方挑错的机制规格进行攻击式复核。审查后，原设计的主方向保留，但若干先前表述必须收紧或改写。以下修订已直接吸收进本规格正文。

| **审查发现**                                | **风险**                                                                                      | **本稿修正**                                                                                                                    |
|---------------------------------------------|-----------------------------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------|
| 单个 trace 只有一个 K                       | 与“同一 χ 同时存在多个候选 K”矛盾，无法真正做候选竞争。                                       | distinction 与 coupling hypothesis 分离；一个 trace 可挂多个 K 候选，每个候选独立版本化。                                       |
| F/J 直接读取完整 R                          | evidence、shadow、候选说明等非正式内容可能旁路验证而影响行为。                                | 新增确定性的 effective causal projection；F/J 只消费 active 且未被 θ 接管的因果视图。                                           |
| shadow 可用未来真实结果直接验证所有 K       | 若 K 的作用需要改变行动，shadow 本身未实施该行动，外部结果无法验证该 action-mediated effect。 | 拆分观察验证、固定输入内部路径探针、受控真实干预三种证据模式；内部模拟不得充当独立现实证据。                                    |
| counterfactual simulation 可作为 probe 证据 | 模型用自己的模型证明自己，形成自证。                                                          | 模拟仅用于挑选鉴别条件/候选，不计入独立支持。                                                                                   |
| “历史标签置乱”作为通用检验                  | 时间序列和根来源通常不满足可交换性，盲目置乱会给出伪 p 值。                                   | 仅在预先声明的 block/exchangeability 条件成立时使用受限 permutation；否则不用。                                                 |
| 验证通过即视作“真的”                        | 有限场景不能证明全状态空间或唯一参数真值。                                                    | 统一改为 scope-qualified：只声明在给定 scope、版本和容差下通过。不可辨识允许长期保留。                                          |
| 最小描述原则未限定编码                      | 不同编码规则可改变“最简单”的结论。                                                            | 复杂度比较只在冻结、版本化 representation code 下作为 architecture-relative tie-break。                                         |
| R 的 provisional 结构缺乏容量合同           | 持续运行会无限增长，最终无法算、无法审。                                                      | 引入 active/provisional 资源预算、确定性淘汰/归档规则；明确有限系统不保证保留所有未来相关区别。                                 |
| metaplastic K 可影响 G                      | K 可能让 G 更容易强化自己，形成自增强回路。                                                   | metaplastic coupling 不得修改自身/同 lineage 的验证、预算、激活规则；至少跨一次已提交事件后才能生效，并记录 mechanism context。 |
| R→θ 使用“减去已吸收部分”                    | 非线性系统中“部分”通常没有唯一分解，简单 subtraction 不成立。                                 | 改为原子 responsibility handoff：θ 模块接管一个明确 slice，同时在同 scope 抑制源 R slice；以 transfer-equivalence probe 验证。  |
| θ 模块失效只关闭模块                        | 该模块过去可能已改变 G，并催生下游 traces，关闭后仍有污染后代。                               | 每次 G 更新记录 mechanism-context；上游长期模块失效时标记受影响后代复核，不自动删除。                                           |
| 只测行为连续性                              | 随机 LLM 输出噪声会掩盖内部调制突变，或相反。                                                 | 同时检查 modulation-space 距离与行为分布距离；两层都版本化。                                                                    |

审查后的核心判断：五步方案可以继续进入工程实现，但必须以“有范围的可证伪机制合同”而不是“我们已经找到了唯一正确心理动力学”的姿态交付。本文所有“通过/验证”均表示在声明条件、数据和容差下通过，不表示普遍真理。

## 0.1 不能被设计消除的基本限制

有三类限制必须诚实写进规格，否则第三方很容易指出过度承诺。第一，R 是有限表示，任何有限系统都不可能保证保留所有未来才显现的重要历史区别；本规格只能通过候选预算、保守回退和重新唤醒降低漏检风险。第二，纯观察数据无法一般性识别所有因果 K；部分机制可能永久不可辨识。第三，有限 probe 只能证明已测 scope 内没有发现超阈值问题，不能证明全状态空间连续。

## 0.2 与 v0.6.4 的兼容边界

v0.6.4 已规定：R 是来源锚定的剩余可塑因果状态；χ 代表最小必要历史区别；K 是非冗余条件化因果耦合；K 不构成第五个核心状态；G 可只读 θ 但不得写 θ；R 的正式作用不得绕过连续性保护；经 C 凝固的作用不得在 R 与 θ 中重复计算。本规格只把这些原则展开为可实现的数据结构、状态机、验证合同和测试合同。

# 1 第一部分：R / distinction / coupling 的可施工表示

## 1.1 表示目标

R 的工程表示必须同时满足五个要求：能追溯到 H；能容纳未决而不让未决直接影响行为；能同时维护多个互斥或竞争的 coupling hypothesis；能支持 split/merge/revision 而不复制证据与作用预算；能被确定性重放。

## 1.2 R 的逻辑分层：审计内容与因果内容必须隔离

此前“J 读取 R”如果按字面实现，会产生一个隐蔽旁路：shadow 候选、evidence count、模型解释或 confidence 元数据只要被 J 看见，就可能在尚未取得作用权前影响行为。为封闭该旁路，本实现规定 R 有两个不同的读取视图。

R_full = 完整可塑状态：provenance + distinction + coupling hypotheses + evidence + trials + budgets + lifecycle

R_effective = EffectiveCausalProjection(R_full, theta)

F / J 只允许读取 R_effective

G / C / audit 可以读取 R_full（仍受各自权限约束）

EffectiveCausalProjection 必须是版本化、确定性的函数，只输出：处于 active 状态、当前 scope 命中、预算允许、未 suspended、且未被 θ responsibility handoff 抑制的实际因果作用。任何 shadow、provisional、evidence summary、模型文字解释、trial 预测文本均不得直接进入 F/J。

## 1.4 distinction 的表示

distinction 不是心理标签。第一阶段可采用 exemplar-bound 表示，只声明若干来源锚定经历目前不能安全地与既有等价类合并；只有后续证据支持一般化时，才升级成受限 pattern。pattern 只能引用 IRL 已验证的 ConceptRef、关系、事件类型、来源类型、qualifier、时间和 parent/action 关系。自由文本和 embedding 仅可用于候选召回，不得作为身份判据。

distinction.status=qualified 也不意味着“宇宙真值”；它只表示在记录的 scope、probe 集、版本、数据和容差下，当前等价合并已经不足。

v1 的 carrier 推荐 bounded sparse gated residual：只有在版本化 predicate 命中时，对声明的目标通道施加有界局部 residual。这样能做到可归因、可消融、可预算和可回滚。更复杂 carrier 可以以后增加，但必须实现同样的 scope、effect bound、ablation、handoff 和 replay 接口。

## 1.6 允许的目标通道与 metaplasticity 防自增强

K 不允许携带任意代码。目标必须来自版本化白名单，例如 fast_transition、behavior_modulation、plasticity_modulation。任何 coupling 都不得直接写 θ。

对 plasticity_modulation 施加额外规则：它不能改变自身 coupling 或同 budget lineage 的证据打分、candidate qualification、effect budget、activation gate；不能把由自身作用诱发的派生内容当作新的独立支持；其对 G 的影响至少从下一次已提交有效事件开始，禁止同一事件内“产生 K → K 修改 G → G 立即强化 K”的递归。

## 1.7 容量与归档合同

“R 是有限多重集”并不足以保证长期运行可控，因此实现必须配置 active trace、provisional trace、shadow hypothesis、trial 记录的资源上限或字节预算。超预算时使用冻结的淘汰策略，例如优先归档长期零作用、无新支持且低鉴别价值的 provisional 项。归档只移出 active R，不删除原始 H、revision、provenance 和审计记录；未来事件可通过显式 rehydrate proposal 重新提出，但不能直接恢复作用权。

本规格不声称这种有限资源策略不会漏掉未来才显现的重要区别；这是有限代理的不可避免近似，必须通过实验报告漏检率或回忆率。

## 1.8 持久化建议

第一版建议使用 SQLite，而非大量独立 JSON 文件。SQLite 适合 revision、证据链接、shadow trial、预算、原子提交和重放索引，同时不引入外部服务器。该选择是工程建议，不是架构不变量。

# 2 第二部分：G 的单事件塑形算法

## 2.1 正式接口与最小职责

R_next = G(theta_readonly, R_full, x_tilde, event_r, semantic_z; config_G)

G 的职责不是“让每次经历都留下痕迹”，而是：在新经历进入后，判断现有 R 是否仍足以保留已被证据要求的历史依赖；若不足，只提出最小、可审计、零默认作用的修订。G 不读取无界 H 前缀，不重新解释自然语言，不执行自然时间衰减，不写 θ。

## 2.2 八阶段处理链

1.  **构造 evidence_view：**从 r/z 中提取合法 source、root、ConceptRef、事件类型、parents/action_id、纠错关系和认识论类型。非法或 unresolved 部分不驱动结构更新。

2.  **优先解析强引用：**correction、action outcome、trial result、明确 parent/root 先定位已有对象；纠错不得被当作一个新的独立支持。

3.  **召回相关 trace：**顺序：显式引用 → 版本化结构 predicate → Concept/关系检索 → embedding/LLM 候选召回。后两者只有召回权，没有身份裁决权。

4.  **更新认识状态：**将事件标为 support / counterevidence / resolves_trial / unknown。此步可提交 evidence revision，但不得因此直接改变 active K 参数。

5.  **消费 representation-inadequacy witness：**只有已经由验证子系统建立的 scoped witness 才能证明当前等价类表示不足；单个 residual、一次模型惊讶或语义新颖性不能自己变成新自由度。

6.  **生成最小 repair proposals：**依次考虑 scope specialization、已有 K revision、χ split、功能等价 merge、最后才 create trace。复杂度只在冻结编码方案下比较。

7.  **实例化为 shadow：**任何扩大作用范围、改变 K、split/merge/create 的候选默认零正式作用；旧 active revision 继续承担正式责任。

8.  **不变量检查并原子提交：**检查 provenance、root 去重、lineage budget、shadow 隔离、θ 只读、版本和 replay 信息。

## 2.3 representation-inadequacy witness 的来源

G 不自行用“预测错了”判定 R 不够。witness 是验证子系统产生的版本化对象，含：被比较的当前 equivalence class、控制变量、probe/观察 scope、实际出现的差异、替代解释检查结果、统计证据以及哪些自由度仍不可辨识。G 只消费已满足门槛的 witness。这样把“发现异常”和“创造新结构”解耦，避免 residual→dimension 的旧错误重新出现。

## 2.4 修复候选的选择顺序

候选选择采用硬约束的词典序，而不是任意加权总分：首先必须覆盖所有当前已确认 witness；其次不能违反 provenance、budget、scope、self-proof 和接口不变量；再次在固定编码规则下选择总描述更小者；若仍等价，再选 modulation/behavior perturbation 更小者。MDL/description length 只是一种架构相对的 tie-break，不宣称客观本体最简。

## 2.5 修订不可原地覆盖

active coupling revision 在正式使用期间不可原地训练。新证据可以改变 evidence_state，但如果 causal parameters、scope 或 carrier 需要改变，必须生成新的 shadow revision。通过后进行原子 head switch。这样每个实际行为都能追溯到一个确定 revision，并支持 rollback 与 replay。

## 2.6 G 的伪代码

def plastic_update(theta, R, x, event, semantic, cfg):

evidence = build_evidence_view(event, semantic)

if not evidence.valid:

return R

linked = resolve_explicit_links(R, evidence)

traces = retrieve_relevant_traces(R, evidence, linked, cfg)

revisions = apply_corrections_and_outcomes(traces, evidence)

relations = assess_evidence_relations(traces, evidence, theta, x)

revisions += update_epistemic_state(traces, relations)

witnesses = validation_store.valid_inadequacy_witnesses(traces, evidence)

if not witnesses:

revisions += maybe_open_bounded_zero_effect_watch(traces, evidence, cfg)

return invariant_checked_commit(R, revisions)

proposals = generate_allowed_repairs(theta, R, x, evidence, witnesses, cfg)

proposals = enforce_schema_provenance_scope_budget(proposals)

selected = choose_lexicographically_minimal(proposals, cfg)

revisions += instantiate_as_shadow(selected)

return invariant_checked_commit(R, revisions)

# 3 第三部分：shadow 验证与因果辨识

## 3.1 验证对象不是“正确人格”

系统没有一个外部提供的“正确内部状态”可供 K 拟合。验证只能回答一个更窄但可操作的问题：在声明 scope 内，这个历史区别是否对未来轨迹提供不可替代的信息；某个 K 是否是保留该差异所需的最小可辨识机制。

## 3.2 χ 与 K 分开资格化

χ 先接受 conditional future non-equivalence 检查：在固定当前可比状态、事实访问信息、行动条件和其他声明混杂后，原来被同一 R 表示合并的历史是否仍在预先声明的未来 probe/结果上出现可重复差异。K 再接受 conditional sufficiency 检查：候选耦合能否在不增加事实访问的情况下恢复该差异。

这里的“future non-equivalence”是操作性定义。可观察下游只提供有限 scope 下的证据；没有可测差异不证明任何内在差异不存在，只说明当前实现没有资格为其分配新的有效自由度。

## 3.3 三种验证模式及其证据权重

| **模式**                 | **能回答什么**                                                                                                                | **不能回答什么**                                                                                        |
|--------------------------|-------------------------------------------------------------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------|
| A. 观察性前瞻验证        | 在实际行动轨迹给定/可条件化时，候选是否改进对后续独立事件的预先预测。                                                         | 若 K 本应通过改变行动产生后果，而 shadow 没有实施该行动，则不能据此外推 action-mediated causal effect。 |
| B. 固定输入内部路径探针  | 在固定输入、事实、模型和采样方案下，candidate 与 baseline 是否在声明的 F/J/动作分布上产生预期差异；用于验证作用通路与连续性。 | 不是现实世界的独立真值；不能用模型自己的输出证明 K 正确。                                               |
| C. 受控真实干预 / canary | 在权限允许、风险低、记录完整的情况下，验证 action-mediated effect 和真实外部后果。                                            | 不能为减少不确定性而任意操纵用户或环境；结果需保留 action 因果链。                                      |

内部 counterfactual simulation 只能用于选择最有鉴别力的候选或干预条件，不计入独立现实支持。

## 3.4 “先下注，再开奖”与数据隔离

每个正式 trial 必须在结果出现前冻结：candidate revision、baseline、scope、允许读取的信息、禁止读取的信息、目标变量、时间窗、评分器、支持/反驳准则和 validator version。生成候选用过的数据属于 development evidence，不得再充当正式 validation evidence。holdout 以 causal root、episode 或时间块划分，不按关联消息行随机切分。

## 3.5 统计在线性与多候选问题

持续运行系统会反复检查候选，固定样本阈值会被 optional stopping 破坏；同时不断生成大量候选会产生多重比较假阳性。因此 v1 验证器必须使用预先冻结的样本窗口，或 sequentially valid 的证据累计方法（例如 e-process/e-value 家族的实现），并对同一候选家族设置全局 discovery/evidence budget。具体阈值属于配置，但不得通过反复查看结果、换 scorer、换 probe 或无限生候选提高过线概率。

## 3.6 置乱与消融检验的适用条件

K ablation 是普遍可用的必要检查：保持事实、x、θ、输入和模型条件不变，只撤去 candidate causal effect，观察声明差异是否重新出现。历史标签 permutation 不是普遍有效；只有在 block 级可交换性假设预先成立时，才能执行受限 permutation/null test。时间依赖或来源依赖不满足交换性时，必须明确跳过，而不是硬做随机置乱。

## 3.7 资格化结果

validation outcome ∈ {qualified(scope), rejected, non_identifiable, continue_shadow}

qualified(scope) 只表示在指定数据版本、probe、时间窗、条件域、统计规则和容差下取得资格。超出 scope 时 K 默认没有作用权；scope generalization 必须产生新的 candidate revision 并重新验证。

# 4 第四部分：作用释放、连续性与 anti-drift

## 4.1 设计目标：允许成长，而不是锁死人格

anti-drift 不定义为“尽量少变化”，而定义为阻止无来源、无证据、超 scope、不可归因或通过大量小步绕过审查的变化。长期累计可以很大，但每段实际变化必须可追溯、可测、可回滚。

## 4.2 从 qualified_shadow 到 active 的门

一个候选必须同时具备：qualified χ、qualified K scope、明确 effect bound、无 unresolved hard contradiction、root/lineage/channel/window 预算、当前 θ handoff 状态已解析、modulation probe 与 behavior probe 通过、rollback target 可用。缺一项则继续保持 qualified_shadow。

## 4.3 不采用“0→1 线性放大”的默认模型

不能假设所有 K 都可按 10%、20%、…、100% 线性缩放。v1 的渐进性主要来自两点：作用 scope 从已验证小范围逐步扩展；在同一已验证集合中选择满足 witness 的最小可行 effect。若 carrier 不支持语义保持的缩放，则不得为了“平滑”而任意乘系数。

## 4.4 四层预算 + 通道总量准入

| **预算**                    | **约束对象**                                            | **目的**                               |
|-----------------------------|---------------------------------------------------------|----------------------------------------|
| root budget                 | 同一 causal root 对所有相关 K 的累计支持/作用资格       | 防止复述、摘要、回忆和工具重试无限强化 |
| lineage budget              | split/merge 后共享祖先的总作用资格                      | 防止结构拆分复制作用                   |
| step trust region           | 一次 active head switch 引起的 modulation/behavior 变化 | 防止单步突变                           |
| rolling-window budget       | 真实时间窗口内累计 path length                          | 防止很多合法小步绕过大变化审查         |
| channel aggregate admission | 同一输出通道所有 active K 的总调制                      | 防止一百个小 K 合成巨大调制            |

channel aggregate 超预算时不得自动按比例缩小所有既有 K，因为那会让一个新候选改变旧机制。默认保持已有 active effect，新 candidate 等待；如需重分配，必须作为新的显式 revision 重新通过 probe。

## 4.5 双层连续性指标

行为连续性不能只看自然语言样本。系统同时记录：D_mod，比较 J/F 实际调制或声明内部作用通道的变化；D_beh，在固定输入/事实/模型和重复采样方案下比较行动内容、时机或输出分布。D_mod 能捕捉被语言噪声掩盖的内部跳变，D_beh 能捕捉小参数变化造成的大行为非线性。两个阈值都必须版本化。

## 4.6 冲突、canary 与 hard invalidation

多个 K 在相同 scope、相同 target 上冲突时，不允许仅因数值相消而视为无问题。新候选保持 shadow/qualified_shadow，直到存在一个经验证的 composite 或旧 K 被正式 suspended。active 后进入 activation canary；发现超 envelope、破坏硬不变量或 regression probe 时，原子回滚。

hard invalidation 的优先级高于连续性：当来源被正式纠错、验证数据污染、规则违规或自证循环被确认时，可立即 suspend 对应作用。但 fallback 优先选择“证据未受影响的最近安全 active revision”，只有没有安全前任时才退回 zero effect；任何已发生的外部后果不会被历史回滚假装抹去。

## 4.7 时间不创造新的作用权

没有新合法证据时，时间只能通过 Φ 产生已定义的自然保持/衰减；不能因为一个 K 存在得够久就自动增强。新增 causal authority 必须来自新的、可审查的 evidence + qualification revision。

## 4.8 metaplastic coupling 的额外隔离

一个影响 plasticity 的 active K 只能通过受限的 plasticity modulation 接口改变未来 G 的特定输入/门控，不得修改 validator、candidate family evidence budget、root independence、effect budgets、自己的 qualification 或同 lineage 的强化规则。所有受其影响的 G 更新都记录 active metaplastic coupling IDs 和 θ module IDs，形成 mechanism ancestry，供后续纠错传播。

# 5 第五部分：C / θ 凝固、责任转移与重放

## 5.1 核心修订：不再假定通用“R - θ”减法

非线性 K 与 θ 一般不存在唯一的可加分解，因此“θ 吸收 63%，R 留 37%”不能作为通用本体。v1 改为 responsibility handoff：C 只凝固一个明确、可测试、可寻址的 consolidation slice；θ 生成一个 source-addressable module 接管该 slice，在同一原子事务中为源 R slice 建立 suppression binding。凝固前后检查整体功能近似等价，而不是要求参数可相减。

## 5.2 consolidation slice 与 θ module

ConsolidationSlice

├── source_trace@revision

├── source_coupling@revision

├── scope_predicate

├── target_channel

├── functional_contract / probe_set

├── supporting_roots

└── budget_claim

ThetaModule

├── module_id / revision

├── source_slice_id

├── carrier / parameters

├── composition_order

├── enabled

├── scope

└── mechanism_effect_contract

L 保存为什么接管、证据和审查过程；θ 的 module registry 保存运行时需要的最小 source binding 与 composition order。J/F 不需要直接读取 L。若 carrier 不能提供可寻址、可门控、可重放的 module，或不能证明 handoff 前后的 transfer equivalence，则该 K 不得凝固。

## 5.3 原子 handoff

before: effective effect = active R slice + existing theta modules

proposal: create theta module M for slice S

check: behavior continuity + modulation continuity + plasticity continuity + transfer equivalence

commit atomically:

enable M

bind S -\> M

suppress S in R_effective for the same scope

append L entry

after: effective effect ≈ before effect within declared tolerance

这里的 R trace/revision 不被删除，只有其 effective causal projection 在已接管 scope 内被抑制。由此保留历史与修订链，同时避免重复计数。

## 5.4 θ 现在影响 G，因此 C 必须增加 plasticity continuity review

v0.6.4 允许 G 只读 θ。于是一次 θ 更新可能不只改变当前行为，还改变“未来怎样学习”。因此 C 的候选审查必须同时固定一组标准经历，比较 theta_old 与 theta_candidate 下 G 产生的候选/更新差异。与 consolidation slice 无关的大范围 plasticity change 必须拒绝或缩小 module。

## 5.5 module interaction 与组合顺序

多个 θ module 可能非线性交互，模块化并不自动保证可交换。v1 必须冻结 deterministic composition order，并在新增/禁用 module 时重新运行相关 interaction probes。若 module A 与 B 的组合无法在当前 carrier 下稳定解释和重放，则不得通过简单并列安装；应生成新的组合候选或保持在 R。

## 5.6 长期模块失效与后代复核

若某个 θ module 后来 hard-invalidated，仅关闭 module 仍不够，因为它过去可能通过 G 改变过后续 R。每次 G revision 必须记录 mechanism_context（当时有效的 θ modules 与 metaplastic K）。module 被关闭后，所有明确依赖其 mechanism_context 的后代 trace 标记 needs_review。它们不自动删除，也不自动维持原资格；新的独立证据仍可使其继续成立。

同理，已经发生的外部行动和环境后果保持在 H 中，不因内部纠错而被“撤销历史”。系统只能修正未来状态和对过去的有效证据视图。

## 5.7 版本绑定、split/merge 与额度守恒

consolidation binding 必须绑定具体 trace@revision / coupling@revision / slice_id。后续 revision 不自动继承已凝固资格。split/merge 只能重新分配 provenance、budget 与 binding；不得让一个祖先 slice 在多个 child 上各自获得完整长期 credit。

## 5.8 replay / crash consistency

一次成功或拒绝的 consolidation 至少保存：输入 R revision、θ before、candidate selection、eligibility branch、source/root accounting、C_propose 实际输出、slice、所有 probe 结果、随机上下文、预算判断、接受/拒绝理由、theta module ID、suppression binding、θ after、L entry、算法和配置版本。结构重放读取已提交结果，不重新请求模型生成另一份建议。

# 6 跨五部分的不变量

- 事实权威始终在 H；R 的 provenance 只能引用/派生已验证 z 与 H 来源，不能把模型解释升级为事实。

- F/J 不得读取 shadow、provisional、evidence summary、trial 文本等非正式 R 元数据，只读取 EffectiveCausalProjection。

- 任何新 χ/K、scope 扩张、参数变化或 split/merge 都先成为无正式作用候选；除 hard invalidation 外，不能跳过 qualification。

- 一个 causal root、一个 lineage、一次 split/merge/replay 都不能制造新的独立证据或新增预算。

- 内部 simulation、模型 narrative、自述和重复检索不构成独立验证证据。

- G 可只读 θ；K 可在受限条件下调制未来 plasticity，但不得修改自己的验证/预算/激活规则形成自增强。

- 任何“通过”都带 scope、版本、数据、probe、容差；不把有限测试表述成全局真理。

- C 只允许 responsibility handoff，不允许 R 与 θ 在同 scope 对同一已接管作用重复计数。

- 上游机制纠错必须能定位下游受影响对象并触发 review；不自动擦除历史，也不假装外部后果未发生。

- 所有核心状态改变、head switch、module enable/disable、binding 与账本必须处于可恢复的原子提交边界。

# 10 仍未由本规格唯一决定的问题

以下问题故意保留为实现/实验选择，而不是假装已经解决：

- χ 的最佳 pattern 表示语言；v1 可以从有限 predicate DSL 起步。

- K carrier 是否长期停留在 sparse gated residual，何时需要 low-rank 或小型网络。

- 各类预算、时间窗和 probe 阈值的数值；必须通过模拟与长期运行标定。

- 不同场景下最合适的 sequential evidence 方法和 candidate-family discovery control。

- θ 的最终长期 carrier；本规格只要求 source-addressable、可门控、可版本化并支持 responsibility handoff。

- 对无法安全进行真实干预的因果问题，可能永久保持 non_identifiable；系统不得强行给出确定 K。

- 更高层“修改 G 本身的算法”不属于本规格。当前 G 是被实现者冻结和版本化的塑形规则；Ada 对 G 的自我改写需要独立的 meta-governance 设计，不能从 plasticity_modulation 偷渡实现。

# 11 交付级结论

经过本轮最终审查，五步机制形成了一个内部闭合但明确有限的实现合同：R 用来源锚定的 distinction 与多个 coupling hypotheses 保存必要历史依赖；G 只在已有表示经 scoped test 证明不足时提出最小修订；候选通过前瞻、未见数据和必要的受控干预获得 scope-qualified 资格；正式作用受多层预算、双层连续性和可回滚 canary 约束；稳定作用通过 source-addressable θ module 与原子 responsibility handoff 接管，而不是依靠不成立的通用线性相减。

本设计刻意不把“预测好”“LLM 解释得像”“存在得久”或“参数维数增加”当作成长的充分条件，也不把有限 probe 结果夸大成完整人格或意识证明。若后续第三方审查仍提出问题，最可能集中在具体 carrier、统计阈值、probe 覆盖率和长期资源标定，而不应再是 R/K/G 的基本职责、验证闭环和 R→θ 责任边界彼此矛盾。

当前建议的工程顺序：先实现 schema + SQLite + EffectiveCausalProjection + revision state machine；再实现 G 的保守更新器；随后做 shadow trial harness 与 continuity probes；最后才接 C/θ responsibility handoff。不要先训练复杂 K carrier。
