## 1. 优先级

发生冲突时，依次以下列为准：

1. 用户已冻结的本体与不变量：v0.6.4 架构规格，以及施工合同第一篇第 12.1 节列出的冻结合同；
2. 《核心算子与整体动力学规格》v1.0 明确闭合的合同（含 I01–I22）；
3. v0.6.4 施工合同与 R/G 实现规格中未冻结的工程选择；
4. 《全系统施工总方案》v1.0 的工程选择；
5. 本仓库 `docs/adr/` 中经用户批准的 Nemu 集成决定；
6. `docs/ARCHITECTURE.md`、`docs/CONTRACTS.md`。

代理不得为了让 Nemu 的功能跑通而静默改变算子写权限、证据标准、状态归属或验收判据。确有冲突时，写进 W00 差异登记（任务卡 P0-06），并按 AGENTS.md 第 7 节提 ADR。

## 3. v1.0 的实现范围（到施工总方案的 M2 阶段门）

| 范围内 | 工作包 |
| --- | --- |
| 基线、IDL、规范编码 | W00、W01 |
| 单写事务、对象存储、入口、事实视图、语义治理、权限 | W02、W18、W19、W20、W22 |
| 编排与时钟、授权作用解析、快状态 F | W03、W04、W05 |
| J 编译、真实模型载体 | W11、W12 |
| 任务层、行动生命周期、自主调度 | W21、W13 |
| 结构重放与本机备份、基础指标 | W14、W15（基础部分） |
| 验收（M2 范围）与 genesis 校准 | W16（子集）、W17（子集） |

| 范围外（v1.x 以后） | 原因 |
| --- | --- |
| W06–W10：χ/K 发现、试验资格、G 激活、C 凝固 | 需要真实经历、因果独立证据和驻留时间；规格明确不能用压缩时间代替 |
| W23：多端单权威接入、加密异地备份、切换演练 | v1.0 只有一个桌面终端；本机备份由 W14 覆盖 |

v1.0 中 G 和 C 两个阶段保留在事件顺序里，但只返回「不变」并写入审计（运行状态 `NO-GROWTH`，原因码 `GROWTH_NOT_ENABLED_V1`）。R 为空；θ 只含 genesis 清单。

IDL 至少包含施工合同第一篇第 6.2 节和总方案第 19 节列出的全部消息；R/G 用到的对象（施工合同第 0.4 节）先定义类型和编码，暂不接入运行路径。

M2 范围的验收项（P5-18 执行）：

- 算子项：F01、F02、F03（结构部分）、F05、F06（结构部分）、F07、J01、J05、J06（结构夹具）、X01–X05。
- 系统项：SYS01、SYS02、SYS05、SYS06、SYS08、SYS09、SYS11、SYS12、SYS13、SYS14、SYS15、SYS21、SYS22、SYS23（时钟部分）、SYS25。
- v0.6.4 结构验收：16.1、16.4、16.5、16.6、16.7、16.8、16.11、16.13、16.14、16.15、16.16、16.17；施工合同第一篇第 10 节全部 9 项；第 11 节第一集成里程碑。
- 不变量：I01–I05、I11、I14、I15、I16、I18、I21 进入 CI 或离线核验；其余不变量的结构检查照常运行。
- 行为项（F04、J02–J04、J07、v0.6.4 第 17 节功能验收）属于 M7，v1.0 只做信息性的校准观察，不签发结论。

## 4. Nemu 集成扩展登记

以下是 Nemu 在规格之上的集成决定。P0-06 把它们逐条写进 W00 差异登记，并标明是否改变冻结边界。

| 编号 | 内容 | 是否改变冻结边界 | 依据 |
| --- | --- | --- | --- |
| E1 | 进程间传输：Unix domain socket 改为 Windows 命名管道（`\\.\pipe\nemu-core-<用户SID>`，ACL 只允许当前用户） | 否，只换传输；CanonicalV1 与消息语义不变 | ADR 0002 |
| E2 | worker 隔离：worker 以低完整性级别（Low IL）运行，权威存储位于中完整性目录，由操作系统拒绝写入；协议层能力检查照常 | 否，是 W22 的实现选择 | ADR 0002 |
| E3 | 权威存储位置：`%LOCALAPPDATA%\Nemu\core\`，必须是本机 NTFS；禁止 OneDrive、网络盘等同步目录 | 否 | ADR 0002 |
| E4 | Nemu 桌面应用是 Echo Core 的终端：上报观察和执行结果，接收输出块与行动请求（v0.6.4 第 19.2 节「终端只是入口」） | 否，使用 W18、W21、W13 的既有合同 | ADR 0002、CONTRACTS.md 第 4 节 |
| E5 | 身体读出：从 m 到身体动画参数的固定、版本化读出函数，与自主调度的读出同类（v0.6.4 第 2.1 节允许派生 readout） | 否，但新增了 m 的一个消费者。用户已于 2026-10-13 确认，明确包括姿态和表情 | ADR 0002、CONTRACTS.md 第 7 节 |
| E6 | 机会规则：自主调度的候选行动来自固定、版本化的机会规则表 | 否，即总方案第 20 节的「已授权机会规则」 | CONTRACTS.md 第 8 节 |
| E7 | 说话模式 C：远程模型起草（作为生成过程中被完整记录的中间结果），本地载体在严格 J 下改写成最终输出 | 否；严格结论只覆盖最终改写一步 | ADR 0003 |
| E8 | 说话模式 B：远程纯文本模型生成，状态经「文字投影」J_text 传入，标为「代理实验」，运行状态 `TEXT_PROJECTED`，永不报告严格调制成功 | 与 v0.6.4 第 10 节一致（文字化实现须标为代理实验）；该模式下允许自主行动是对《核心算子》第 14 节默认规则的显式例外，用户已于 2026-10-13 批准 | ADR 0003 |
| E9 | 助手执行器：Codex app-server 作为行动闸门下的连接器；Codex 自身的审批请求转交 Echo Core 权限判定 | 否 | ADR 0004 |
| E10 | 「忘掉」：v1.0 只提供撤回（纠错事件使内容不再进入 c_task）；真正抹除需要另立数据生命周期合同 | 否；抹除留待用户决定 | ADR 0002 |
| E11 | 多语言：IRL 与 Concept Registry 支持中、英、日标签；载体校准覆盖三种语言 | 否 | ADR 0002 |
| E12 | 「Review_and_Remediation」增补缺失时的处理（见第 2 节） | 否 | 本文件 |
| E13 | 分阶段启用：事件顺序从第一天起完整存在；尚未接通的阶段按规格已有的降级路径运行（IRL 走 ⊥sem；F 只在排练谱系中可以停用，此时 m = 0，原因码 `MODULATION_NOT_ENABLED`；G、C 恒等）。m = 0 时暂停依赖核心的自主行动。正式谱系要求全部阶段接通 | 否，使用总方案第 21、24 节和 SYS14 已有的降级路径。用户已于 2026-10-13 批准 | ADR 0005 |
| E14 | 谱系类型：排练谱系（`REHEARSAL`）与正式谱系（`LIFE`）。正式谱系只能由签字的 genesis 清单创建（「诞生」），她的 H 从此开始；排练记录永远不进入正式谱系。诞生时可以选择把排练对话作为导入文档交给她：认识论类型为导入文档，不算她的经历或用户自报，不作为独立证据根 | 否；genesis 就是初始状态，导入走既有的文档来源路径。用户已于 2026-10-13 批准；是否导入由用户在诞生时决定 | ADR 0005 |

Nemu 自己的里程碑记作 N0–N4（ADR 0005），与本规格施工总方案的 M0–M7 阶段门区分。任务卡里出现的「M2 阶段门」一律指 Echo Core 的阶段门。
