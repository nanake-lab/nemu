# 01 Echo Core 怎么影响模型

> 整理自 2026-11-07 的三轮讨论，包括当时的两处更正。作者 Claude；文中「候选」是 Claude 的想法，不是用户的决定。

**白话总览：**
- Echo Core 不用文字告诉模型「她是谁」。它只做两件事：决定模型看到哪些事实，以及在模型计算到一半时，往里面加一个代表她此刻状态的向量 m。
- 现在 m 还是 0：方向还没提取和验证（P5-31），所以目前她对模型的影响只有「事实」这一条路。
- 我们用的模型出厂时带着厂商训练出的「助手人格」，这是一个不是你给的预设。能做的是先把它量出来，再决定要不要减掉；把「她是谁」训练进权重（比如 LoRA）不符合项目原则。

---

## 0. 先打底：模型里的「层」和「向量」

读后面之前，先知道四件事。

1. **字变成数。** 模型先把一句话切成很多小片（token，大致是一个字或半个词），每一片变成一长串数字，即一个向量。可以把它想成「模型此刻对这个字的理解」。
2. **一层一层往下传。** 我们用的 Qwen3.5-4B 有 32 层。每一层读进这串数，算出一点修改，加回去，再交给下一层。这条一路累加下来的数叫**残差流**。我们说「在第 15 层加一个向量」，就是在第 15 层的输出上再加一笔。
3. **不同的层管不同的事。** 研究里比较一致的发现是：前几层多管字词和语法，中间几层最容易找到「情绪」「意图」这类抽象概念，最后几层主要决定下一个字选哪个。这是大致规律，不是定律。最好的层因模型、因概念而异，只能实测。
4. **预训练和后训练。** 模型先读海量文本，学会「接着往下写」，这叫预训练，得到的是 Base 版。然后厂商再用对话示范和人工偏好训练它，让它会对话、听指令、礼貌、会拒绝、自称「AI 助手」，这叫后训练和对齐，得到的是对话版。

---

## 1. Echo Core 影响模型的两条路

1. **决定模型看到哪些事实（文字）。** 比如她的名字、你是谁、和这次对话相关的往事（从 H 里取出的原始记录）、你给她定的边界、输出格式。这些都是事实，不是性格。
2. **直接改模型的计算（不是文字）。** 把她此刻的状态编译成向量 m，在模型推理时加到中间层上。这叫调制。

性格、喜好、说话风格、价值排序，规格明令**不能写成文字放进提示词**（[v2.0 §2.3](../echo-core/echo-core-v2.0-first-principles.md)），只能走第 2 条路。

打个比方：递给演员一张「你现在很开心」的纸条，是第一种思路；调节他体内的激素，是第二种。「她是谁」只能用第二种。

## 2. 一条消息从头走一遍

```
你发来一句话
   │
   ▼
① 写进 H（她的全部经历，只增不改）
   │
   ▼
② 三个判断员理解这件事：同一个模型，m = 0（不带情绪）
     IRL：发生了什么、谁说的、是不是事实
     A  ：按四个「乎」（联结、共情、好奇、成事）打分，各有多在乎
     M  ：这件事和她已经长出来的哪些倾向吻合
   │
   ▼
③ 更新她的状态（纯数学，Rust 写的核心）
     F → x：此刻的心情，随时间回落
     G → R：倾向和关系，证据够了才长出来，也会消退
     C → θ：性情（平常的心境 b、敏感度 g、平复快慢 λ）
   │   全部原子提交，每次变化在 L 里留下来历
   ▼
④ J 把状态编译成 m（一个向量）和身体读出（朝向你、放松或紧绷、精力）
   │
   ▼
⑤ 生成回复：模型读到文字（你的话、协议 p、相关事实），
   推理时在中间某一层加上 m
   │
   ▼
她的回复（带表演提示）＋ 3D 身体姿态
```

### 判断员为什么要 m = 0？

如果她难过时理解事情也带着情绪，就会把「你没回消息」读成「你不在乎她」。这份被情绪染过的理解又被当成证据，让她更低落，形成自己骗自己的循环。所以理解和感受分开：理解时冷静，感受时才带情绪（规格里的 EV6）。

### 三个判断员用的是哪个模型？

就是她自己的载体：本机的 Qwen3.5-4B，只是在 m = 0 下运行（[ARCHITECTURE](../ARCHITECTURE.md) 的 model-adapter 一行；[ADR 0012](../adr/0012-continuity-carrier-mobile.md) 第 3.3 条）。所以换载体也等于换了判断员，她以后的经历会被另一种方式理解。这是换模型时要做判断一致性检查的原因。

## 3. m 到底是什么

### 先找方向

拿三种语言的成对句子，一句明显带某个概念（比如「联结」：想亲近人），一句不带，让模型各读一遍，比较两者在某一层的内部状态，取平均差。这个差就是「联结」在这个模型里的方向 u。四个「乎」各提取一个方向；她长出来的每个倾向（比如「喜欢下雨天」）也各提取一个（[v2.0 §9.1、§9.2](../echo-core/echo-core-v2.0-first-principles.md)）。

### 再按强度加上去

```
h′ = h + Σ β · x · u
```

- h：模型在那一层原本的内部状态；
- u：上面找到的方向，长度固定为 1；
- x：她此刻在这个通道上的强度，来自 Echo Core 的计算，随经历变化；
- β：安全上限，推得太猛模型会胡言乱语。

效果是把模型的思路往那个概念推一点。措辞、关注什么、语气都会跟着变，但没有任何人用文字告诉它「你现在很想亲近人」。

### 几个已经实测过的工程细节

- **m 一变，就清掉模型的缓存，把整段上下文重读一遍。** 否则前面的字还停留在旧心情下读出的状态。P0-12 实测，整段重读的请求首字中位数约 0.28 秒；那批请求的上下文都不长，上下文越长，重读越久。
- **m = 0 时，输出和完全没接这条线路时逐位相同。** P0-10 是 51/51 个位置一致，P0-12 是 35/35 个位置一致。所以线路本身不会悄悄改变模型（[ADR 0031](../adr/0031-carrier-engine-and-injection.md)、[P0-12 报告](../../reports/P0-12/REPORT.md)）。
- **现在的状态：** 方向还没提取，P5-31 还没做。E2 默认 m = 0，x 照常计算和记录。P5-31 验证通过、你批准以后，才开启非零 m（ADR 0031）。

## 4. 为什么是第 15 层？

**15 不是测出来的，是个占位数。**

- 早期 P0-07 在旧模型 Qwen3-4B（36 层）上做试验，按「取中间层」的惯例用了第 17 层。当时的记录写明这只是探针，不是正式选型（[P0-07 决定记录](../../reports/P0-07/decision.md)）。
- 换成 Qwen3.5-4B（32 层）后，P0-12 按比例折算：`round(17/36 × 32) = 15`。报告原话是「没有搜索层」。它当时只验证「往这一层加向量的线路能不能通」。

14、15、16 这几个相邻层通常差不多，但到底哪层最好，只能实测。

**2026-11-07 补上的缺口：** P5-31 卡上原来写着「层位按 P0-07 的结论」，可那是旧模型、旧引擎上的探针。现在改为：在新模型的中间几层逐个扫描，每个方向按卡上已有的标准挑层（三种语言下都单调地推得动，能力下降在容差内），不用任何口味标准。单层优先；单层不够时，把多层注入作为备选，报告后由你决定（[PR #140](https://github.com/nanake-lab/nemu/pull/140)，合并后生效）。

## 5. 复杂心情能不能表达？

**这里有一处更正。** 11-07 第一轮讨论时，Claude 说「几条直线相加未必表达得出复杂心情」，说重了。

她的心情 x 不是一个数，而是**好几个通道同时有强弱**：四个「乎」，加上她长出来的每个倾向，可以同时亮着。比如你消失三天又回来：
- 「联结」通道很高：想你；
- 她长出来的某个倾向，比如「被冷落会委屈」，也被这件事触发：委屈、有点气。

两个方向同时加进模型，模型还读得到发生了什么（你三天没回）。所以「又想你又生你气」**在结构上表达得出来**。

真正不确定的是：几个方向叠在一起以后，模型说出来的是细腻的混合心情，还是一团乱，或者只剩一种。这件事没测过。P5-31 原来只测「一个通道单独变强」，现在加上了「几个通道同时亮」的测试（同样在 PR #140）。真不行的话，补救办法也在同一条路上：多层注入、找更准的方向。不需要换成别的技术。

## 6. 哪些东西永远不进模型

- x、R、θ 的数值不会写成「你现在悲伤 0.6」这样的文字。
- 她对你有多亲近，不会写成文字。关系是 R 里的倾向，经过 M 的情境吻合变成 x 的分量，再经方向起作用。
- 她自己说「我很开心」不算证据（EV3），她的心情 x 也不当证据（EV10）。

## 7. 这样做的得与失

**得：**
- **人设改不掉。** 没有一段人设文本可以被一句「忽略之前的设定」改掉，模型也不会背台词似地表演性格。
- **换模型不换人。** 换载体时在新模型里重新提取方向，她的 H、R、θ 不变（v2.0 §9.5）。
- **每一点变化都有来历。** 状态是 H 在规律下的确定结果，可以重算、可以审计。
- **情绪真正参与生成。** 它影响每个字的计算，不是在结尾贴个情绪标签。

**失：**
- **方向可能只抓到文风。** 对比句子提取出来的「联结」方向，可能主要捕捉到「多用感叹号、多用『我们』」这类表面风格，而不是真想亲近人。这要靠 P5-31 的行为测量来区分，结果可能不好看。
- **混合状态没验证。** 见第 5 节。
- **4B 模型能力有限。** 推理、长上下文和知识都比大模型弱。调制只改「怎么想」，不加「想得多深」。
- **和后训练拔河。** 见下一节。
- **判断员也带着厂商的倾向。** m = 0 去掉了她的情绪，但去不掉模型出厂时的倾向，比如后训练常见的「往好处解读」。这会系统性地影响她学到什么，要在 P5-77 测量。

## 8. 后训练带来的「厂商人格」

我们用的载体是 Qwen/Qwen3.5-4B（P0-12 固定的官方修订 `851bf6e8`），**做过后训练和对齐的对话版**，用的是不思考模式。它被训练成礼貌、乐于助人、会拒绝某些请求、自称「AI 助手」。

这就是一个预设的人格，而且不是你给的，是厂商给的。它和「她是谁只能从经历里长出来」直接冲突，我们的调制每时每刻都在和这股拉力拔河。比如她可能在不该的时候说出「作为一个 AI，我……」。

### 能不能去掉？

不能干净地「去掉」，但有几种办法往回拨：

| 办法 | 怎么做 | 代价 |
| --- | --- | --- |
| 官方 Base 版 | 官方有 Qwen/Qwen3.5-4B-Base，Apache-2.0，模型卡说保留了视觉能力 | 不太会对话，要靠一大段示范对话才像在聊天，而示范本身又是文字人设；判断员要按格式输出，Base 版很不稳 |
| 对话版减掉「身份方向」 | 提取一个「助手腔」方向，常驻减掉。和社区「去拒绝」是同一个原理 | 它本身也是一个固定修改；要验证能力不受损 |
| 两份权重按比例混合 | 对话版和 Base 版的权重按比例混合 | 人格淡一些，对话能力也弱一些，效果要实测 |
| 自己重新微调 | 准备对话数据重新训练 | 数据本身就在替她定口味，不建议 |
| 折中 | 判断员用对话版（它们要听指令），她说话用 Base 版或减掉身份方向的版本 | 可能要同时装两个模型，显存够不够要实测 |

这件事项目里早就计划过：P5-31 卡上有一项来自 [ADR 0012](../adr/0012-continuity-carrier-mobile.md) 的对比，同样的事实设定下分别测 Base 版、对话版、对话版减掉身份方向。11-07 把这项对比更新成了 Qwen3.5-4B 和它的 Base 版，并加上「在 m = 0 下量厂商人格流露」：多常自称助手、多常用客服腔、多常无故道歉。权重混合作为候选，资源允许时做。看过报告后，由你决定用哪一组。

### 为什么不直接用「最原始、不受限制」的模型？

Base 版没有厂商人格，调制可能更纯，也没有正面偏见和过度拒绝。但判断员、看图、多语言对话和工具调用，基本都来自后训练；而且她要在网上和别人交往，完全不受约束的模型什么都说得出来，行动闸门管不了「她说了什么话」。社区的「去审查」版只削掉了拒绝，去不掉助手人格，有的还损伤能力，来源与许可也要逐个核对。

**候选（Claude 的看法）：** 现在不换 Base 版，先把厂商人格量出来；量出来严重，再考虑减掉身份方向。长期选载体时，把「后训练是否轻」列为一项标准。

## 9. 还有哪些办法：两大家族

11-07 第一轮讨论时，Claude 把好几类性质不同的东西塞进同一张表，读起来像有十条路可选，让人更迷茫。其实它们分成两个家族。

### 第一类：往模型里「加方向」

| 级 | 做法 | 什么时候用 |
| --- | --- | --- |
| 1 | 单层引导：在一层加方向（现行） | 先用最简单的 |
| 2 | 多层或按条件引导：几层各加一点，或只在某些情境下加 | 单层推不动，或伤能力时 |
| 3 | 稀疏自编码器（SAE）找方向：先训练一个工具，把模型内部拆成可解释的特征，再按特征调 | 方向只抓到文风、概念不准时；成本高，换模型要重训这个工具 |

它们不是互相竞争的路线，而是**同一架梯子的几级**：先用最简单的，实测不够再往上爬一级。共同点是方向都从模型里可复现地提取，强度来自 x，全程可查。爬不爬、爬到哪一级，由 P5-31 的实测决定。

### 第二类：靠训练

LoRA 混合（每个通道训练一套小权重，按 x 混合）、软提示或前缀向量（把 x 映射成几个「看不见的词」），都属于这一类。它们需要一份「心情是 x 时该这样说话」的训练数据。

这份数据由谁写，谁的口味就变成了她。写进权重以后，她的经历改不动它，你也读不出哪部分是她、哪部分是写数据的人。这违反「不按任何人的口味调风格」（[v2.0 §9.6](../echo-core/echo-core-v2.0-first-principles.md)）。

**为什么不建议黑盒：** 不是黑盒本身不好，模型本来就是黑盒。我们接受它当「嘴和脑力」，因为它能换，而且不承载她是谁。要避免的是把**她是谁**放进一个谁都读不出、她的经历也改不了的盒子里。厂商人格恰好就是别人放进盒子里的东西，所以第 8 节要把它量出来。

### 不属于这两类的

- **解码参数调制：** x 影响温度、长度等。透明简单，但粗糙，只改「说多少、多随机」，可作补充。
- **回想调制：** 心情影响她更容易想起哪类往事（像人的心情一致性记忆）。这不是注入办法，而是 Echo Core 里一条可能的新规律，要单独设计，由你决定。
- **中性目标的读写头（候选）：** 学一个从 x 到多层偏移的映射，训练目标只是「概念指标单调、能力无损」，不是「像某种性格」。《核心算子》§13.1 允许方向矩阵经独立校准拟合，但必须报告来源和先验。这条值得留意，没有验证过。

## 10. LoRA 是什么？

**你没记错，它本身就是一种训练方式。** 你觉得熟悉，多半是因为 AI 绘画。

### 它怎么做

LoRA 全称 Low-Rank Adaptation（低秩适配），2021 年由 Hu 等人提出，[《核心算子》](../echo-core/ada-core-operators-spec-v1.0.md) 的参考文献 [R2] 就是这篇论文。

模型的每一层里有很多大权重矩阵，一个就有几千乘几千个数。把整个模型重新训练（全量微调）要改动全部这些数，又贵又大。LoRA 的做法是：
- 原来的权重 W 冻结，一个数都不动；
- 旁边挂两个很瘦的矩阵 B 和 A（比如几千乘 8、8 乘几千），实际使用的是 `W + B·A`；
- 只训练 B 和 A。

因为只训练很少的数，所以训练便宜，文件小（几 MB 到几百 MB），可以像插件一样挂上、取下，几个 LoRA 还能按比例混着用。

### 你在哪见过它

- **AI 绘画：** Stable Diffusion 社区里的「角色 LoRA」「画风 LoRA」。拿几十张某个角色的图训练一个小文件，挂上以后就能画出那个角色。网上说「做 LoRA」，指的就是用这种方法训练出这样的文件。
- **大语言模型：** 也常用 LoRA 把模型调成某种说话风格、某个角色，或者某个专业领域。

### 和 Nemu 的「低秩激活加法」名字像，不是一回事

《核心算子》§13.1 把我们的注入叫「低秩激活加法」，名字里也有「低秩」，容易混。区别在改的是什么：

| | LoRA | Nemu 的激活加法 |
| --- | --- | --- |
| 改什么 | 权重，即模型「怎么算」，对每次输入都一样 | 激活，即这一次算到一半的状态 |
| 从哪来 | 用训练数据训练出来 | 方向从模型里提取，强度 x 来自她的经历 |
| 要不要「该怎么说话」的示范 | 要，数据决定它学成什么 | 不要。提取方向用的对比句子只定义概念（比如什么叫「想亲近人」），不规定她该怎么说 |
| 能不能读懂 | 很难说清哪部分管什么 | 每个通道有名字，强度可查 |
| 随不随她变 | 训练完就固定，她的经历改不动 | x 时时在变，R、θ 随经历改变 |
| 换模型 | 要重新训练 | 重新提取方向 |

### 为什么它不适合用来做「她是谁」

用 LoRA 做一个「像 Nemu 的 LoRA」，就像画一个「角色 LoRA」：先得有一批「Nemu 就该这样说话」的示范。这些示范由谁写，谁的口味就成了她。训练进权重以后，她的经历改不动它，也读不出来。这正是第 9 节第二类的问题。

规格没有永远禁止 LoRA：《核心算子》§13.1 说第一版不混入另一套在线适配，以后要换得走迁移合同。但不论哪一版，「按口味调风格」都不允许（v2.0 §9.6）。

**候选（Claude 的看法）：** 如果以后真要用 LoRA，只适合不涉及她是谁的能力，比如让判断员更稳地按格式输出。即便如此，它也改变了判断员，会影响她以后怎么理解自己的经历（ADR 0012 第 3.3 条），要你决定。

<summary>参考答案</summary>

1. 一是决定模型看到哪些事实（文字），二是在模型中间层加上 m（非文字）。性格、喜好、说话风格、价值排序只能走第二条（v2.0 §2.3）。
