# ADR 0053　她的卡片

她想邀你玩一局时，可以递来一张写着「现在／晚点／算了」的小卡，你也可以自己回一句。她想给你看东西时，可以把图、链接或文件连同出处放在卡上。卡片在面板里，也可以出现在她身边，或安静地浮在你正在用的窗口上方。你可以关掉跨窗口提示，稍后自己打开面板。你点了什么、说了什么，她就记下什么；卡片到期时，她只知道时间到了。她需要助手时，由她选定用途和助手，QO 接活并把结果连同署名交回来，需要你批准的操作仍由 Nemu 拿给你看。

交付线 · DESIGN-SURFACE-01 · **提议，待交叉审查与用户批准**。用户已定跨窗口默认开启且可总关、真实人类回应进 H、程序固定外框、审批沿用闸门原件、Echo 保有身份与决定权。以下推荐和由此产生的体验选择登记为 V2-195。[原卡](../../tasks/requests/DESIGN-SURFACE-01.md) · [差异登记](../traceability/diff-register.md) · [报告与后继卡](../../reports/DESIGN-SURFACE-01/REPORT.md)

## 1　什么时候值得用一张卡

普通问候、解释和开放问题用已有的聊天。卡片值得占一个位置，限于用户确实需要**选一个、看一样、批准一件**的场合。比如「你今天怎么样」没有合适的预制选项；「现在来一局吗」有；「给你看我说的那张图」需要原件。

| 候选 | 能不能省 | 一个人会怎样 | 留下什么改不掉 | 决定 / 理由 |
| --- | --- | --- | --- | --- |
| 选择 | 文字能问问题，但同一词可能对应不同邀请，转述也会变义 | 当面给出几个真选项，也听对方另提意见 | 当时给出的选项、顺序和用户实际点的那一项 | 推荐首批。仅在有 2–4 个具体选项时使用；普通对话仍自然成立 |
| 展示 | 链接可以直接说；单靠描述找不回给看的那件东西 | 递过来，在旁边说出处 | 展示的是哪一版材料、来自谁、当时附的原话 | 推荐首批单件展示；相册、网页嵌入、可执行附件无须成为卡型 |
| 审批 | 已有 `ApprovalRequestV2`，另造一种「同意」会让用户分不清在批什么 | 看清具体动作后决定 | 原样操作与给这次操作的答复 | 沿用现有审批卡。普通选择中就算写了「同意」，也只是一句回答 |
| 聊天气泡附 Markdown、让模型画界面 | 前者适合聊天；后者的按钮、来源和记录之间没有稳定对应 | 说清楚就行，很少需要自制一块控制面板 | 已展示的文字、控件与动作的对应以后必须能查回 | 保留纯文字退路；模板只接类型化数据、纯文本和受权材料引用 |

### 字段、语言、边界与时效

**决定 / 理由。** 一次投递只有一份定稿。她决定普通卡片的种类、原话、选项的顺序、是否可自由回答或展示哪件获准材料。程序固定控件、选项 ID 和卡与投递的绑定，填入可信的来源、语言标记、有效期与目标位置。选项身份随定稿固定，翻译和界面排序均不能改变它；更换内容须作为一张新卡提出。审批走独立的既有生产者。

| 种类 | 她填写 | 程序填写、显示与限制 | 哪一刻过期 |
| --- | --- | --- | --- |
| 选择 | 问句，2–4 个有序标签，是否附一个自由回复入口 | 问句、可选自由回答各 ≤ C 字节；每个标签 ≤ ⌊C/4⌋ 字节，非空且同卡可区分。选项 ID 随已核定的位置分配。按钮有同级键盘入口，回复框在面板打开 | `expires_at_ns = ActionPlan.deadline_ns`。例：邀约约定到 20:00，20:00 起面板显示已过期，仍可以另发聊天 |
| 展示 | 一件材料的候选引用和一句说明（≤ C） | 一件图、HTTPS 链接或获准文件；程序解析来源记录、提供者、出处标签（≤ C）、不可变对象版本/摘要、类型、长度及原始地址（链接 ≤ C）。图片用经验证的静态预览，文件显示名称和类型，链接显示目标域与完整地址；来源无从核对就退回提议。卡不带可执行内容 | 同一计划的 `deadline_ns` 到时停止互动与跨窗提示；历史保留准确引用，之后查看仍复核访问权 |
| 审批 | 无 | 完整 `ApprovalRequestV2` 的 schema、approval_id、action_id、tier、title、detail、expires_at_ns、action_payload、payload_digest。标题和详情由闸门根据档位与原样字节产生；可以展开原样载荷，核对 SHA-256（32 字节）。现有 IDL 对标题、详情无独立字数上限；带齐全部字段的整帧受 F 限制，同时受闸门编码预算。超限报告「无法完整显示」且不能批准 | 采用闸门的绝对期限，等于请求时刻加配置的审批窗口与计划期限中的较早者。现有窗口默认 60 秒。到点或撤权即失去执行资格；明确拒绝与超时分记 |

这里的上限按 UTF-8 字节计算，含控件字段后整帧 ≤ F。**C** 取会话的 `max_chunk_bytes`，**F** 取 `max_frame_bytes`，**O** 取 `max_object_bytes`。选项数来自原卡；本提案用一个现有分块容纳短文字，四个标签合计占用至多一个分块，目的是限定单次解码及完整展示成本。当前排练部署 C = 2,048、F = 16,384、O = 8,192 字节，因此单标签最多 512 字节。每次按实际协商预算验完整编码；超限给出可缩短或换为引用的具体原因，不静默截断。展示对象引用不复制原件；随卡供应的缩略图编码 ≤ O，解码后 RGBA ≤ 本地验证过的单对象内存预算（当前排练存储对象上限 4 MiB，首版拟沿用，须实测）。大文件只展示已授权、经核实的名称、长度和来源，读取其内容另经原权限。正文不自动抓取网页、读任意路径或启动关联程序。[部署预算](../../core/crates/nemu-core/src/deployment.rs) · [审批生成与字节核验](../../core/crates/action-gate/src/permissions/approval.rs) · [审批窗口](../../core/crates/action-gate/src/lifecycle/mod.rs)

中、英、日共用一份 ID 和来源。她按当前对话语言给原文，可以保留材料的原语；系统控件随界面语言，如「另回一句 / Reply in my own words / 自分の言葉で返す」。不为每张卡强制生成三套文案。长英文分行、中文和日文按可断位置排版，完整标签可读；键盘与读屏按原序读出。审批标题和详情原样保留（现行闸门生成中文）；面板的字段名、按钮、展开说明译成三语，要使闸门正文有多语言版本须由闸门按版本生成，不能让模型翻译替换。两个普通卡的到期规则借用具体事情自己的期限，避免给所有邀约写入一段统一等候时间；过期不抹去历史。[项目语言](../ARCHITECTURE.md) · [现有终端消息](../../core/contracts/terminal.proto)

## 2　在哪里出现，怎样不截断用户正在做的事

| 候选位置 | 适合的体验 | 代价与推荐 |
| --- | --- | --- |
| 面板 | 键盘、读屏、长文本、原样审批；关闭小窗后还可找到 | 首选完整视图。面板在前台就直接显示；隐藏面板只建立可恢复条目，不自行调用现有会聚焦的 `panel.show()` |
| 舞台上她身边 | 已在和她互动时，短句和选择紧贴这次交流 | 仅在明确使用 Nemu 或允许跨窗时显示。舞台本身是不可聚焦的置顶窗口，卡片命中区单独处理，空白仍穿透；键入、自主查看原件和审批均交面板 |
| 独立不激活的置顶小窗 | 在别的普通窗口前仍能选「晚点」或明确关闭 | 总开关默认开。每次最多选择一个即时出现的位置；完整面板记录可随时查。普通选择可直接点，展示用说明和来源，审批只提示「有操作待确认」，点击才打开完整面板。推荐默认静音 |
| Windows 系统通知 | 系统能管理横幅、通知中心和勿扰，适合简单提醒 | 可作后继替代；激活、冷启动、关闭和实际显示各有不同语义。首批不与小窗并发投递，不在通知横幅批准操作 |

**决定 / 理由。** 先看 Nemu 的跨窗总开关（默认开）、自身安静模式、安静时段、锁屏和已授权的跨窗作用域。总开关关闭时收起已浮出的卡；面板和用户主动进入的舞台仍可查看，盖在其他应用上的舞台气泡也受总开关约束。Nemu 自己的安静模式优先于下列两项设置。

面板在前台时优先用面板，其次用正在与她互动的舞台。在其他应用中，若上述边界允许，她可以尝试弹一次不取焦点的小窗，包括用户打全屏游戏或 Windows 勿扰已开启的时候。**「全屏时不跨窗」和「遵守 Windows 勿扰」是两个独立设置，默认均关闭。** 用户开启哪项，才按对应状态抑制跨窗；两项都开时，任一条件成立就收进面板。何时用卡片招呼由她从真实回应中学习。被门控拒绝的主动行动不排队补弹，审批请求可在面板等待到自身期限。[舞台窗口](../../apps/desktop/src/main/stage-window.ts) · [面板窗口](../../apps/desktop/src/main/panel-window.ts) · [V2-79、V2-117](../traceability/diff-register.md)

| --- | --- | --- |

## 3　从她提议到桌面回报

**决定 / 理由。** 候选有「文字块夹一段卡片语法」「桌面收到模型输出就弹」「一张有身份的行动」。前两者无法把这次显示、授权、用户后来点的那个选项绑在同一份内容上。普通卡采用第三条；审批沿用待审批动作创建的闸门请求，不能为显示审批而递归审批。

1. 获准的本地行动选择从已提交 Q 提出 `ActionPlan`，绑定此轮快照、前沿、权限、用途、材料和期限。程序登记不可变的卡片内容及有序选项，进入 `PLANNED → REQUESTED`。她提议的种类、文字及已核实材料可以随提议返回；模型没有展示或写 H/Q 的通道。云端可以依现有用途贡献文字，本地选择暂停时照常暂停。[ADR 0042](0042-cause-projection.md) · [ADR 0045 D1/D2](0045-speak-think-wiring.md)
2. 闸门按 `LOCAL_DESKTOP` 解析实际动作和对象。仅呈现已授权材料是可挽回的本地表达，建议按通用 **T0** 处理；ADR 0047 的不可挽回三档在此无须逐张询问。跨窗另设可单独撤销的操作作用域（同一连接器的「卡片在应用内显示」与「卡片可跨窗显示」），由同一版本化权限资源表达总开关。界面设置经认证入口改变资源版本，桌面呈现前复核，立即收回跨窗资格。卡片不会连带获得读文件、打开网址、发送或执行操作的权限；涉及这些动作时各按本身作用域、原始字节与档位再判。对不可挽回桌面动作，一律不做／先问（默认）／直接做按用户档位，T3 的同意不能记忆。[权限契约](../../core/contracts/permission.proto) · [ADR 0047](0047-permission-contracts.md) · [ADR 0043 §4.1](0043-two-lines.md#41-用户电脑上的行动边界)
3. 主动发来的普通卡与其他主动对外表达共享 **V2-79 / V2-117 的最高频率与最小间隔保险丝**。计数单位是受该保险丝约束的实际主动行动开始；普通卡与说话共用这个计数，切位置、换 ID、重投不能取得新额度。对话中回答用户的追问、审批事务自身及内部活动不额外生成主动机会。勿扰和用户权限是边界；她从真实回应学合适的时机。本卡不采用旧配置值（180 秒、每小时 2 次等）作正常频率，不定新阈值。ADR 0033 对近似助手请求、调用链深度的保险丝用于派助手，不能代替卡片的主动保险丝。[差异登记](../traceability/diff-register.md) · [助手保险丝](0033-helper-fuses-cursor-evidence.md)
4. 外层事务把许可及登记绑定到 action_id、原样载荷 SHA-256、安装/执行会话、权限与撤销版本、预算和期限。P5-14 在单写者边界复核后先消费一次性凭证、预留预算并持久提交 `DISPATCHING`；随后才允许副作用。普通卡复用 `PermissionResult.dispatch_record_id` 标识这次投递；审批尚未授权执行，用**已登记的审批请求记录**及 approval_id 标识这次展示，不能引用未来的执行凭证。下文的「投递引用」是这两种可验证引用之一，绑定同一谱系、安装、动作和内容摘要。[运行时 outbox 落盘](../../core/crates/core-runtime/src/action/dispatch.rs) · [现行投递分支](../../core/crates/action-gate/src/outbox/delivery.rs)
5. #273 将 `OutputChunk`、`OutputEnd`、具有 `INGRESS_APPROVAL` 的会话可收的 `ApprovalRequestV2` 发到指定认证会话；`RunStateV2` 按连接去重。当前分支使用有界长度的生成消息，找不到会话可以直接返回，发送排队成功也不能证明展示。后继协商新的卡片能力，使用有明确种类的新下行帧；只向绑定的目标桌面发送（不广播，不在旧协议里猜消息类型）。带齐展示上下文，同一审批在同一会话只选一个协议路径。[#273 固定提交的 downlink.rs](https://github.com/nanake-lab/nemu/blob/633ee2e4baad97d96f971a499390611b6ac8ad1e/core/crates/gateway/src/downlink.rs)
6. 受信桌面主进程先验内容、摘要、会话及当前边界，按投递引用串行登记本地投递状态，再送固定模板。终端确认窗口可见且本次模板完成绘制才报「已在某处呈现」（只描述窗口和绘制，不证明未被遮挡或人正注视）；面板隐藏、只排队、仅存通知中心分别保持其可证状态。普通卡的显示回执关联原投递，作为 `EXECUTION_RESULT` 由外层事务结算。审批卡的呈现回执只结算提示，不能结算它所询问的操作。一个面板条目可被用户再次手动展开，原卡不会重新自动浮出。[现有桌面桥](../../apps/desktop/src/terminal/bridge.ts) · [运行时结算](../../core/crates/core-runtime/src/action/mod.rs)

**重投与断点。** 只用网络重试会重复打扰，单靠核心写「已显示」则会把丢帧写成成功。终端只存投递/回应传输日志，同卡键是「谱系、目标安装、投递引用」；摘要是不可变校验值，同键不同字节拒绝。核心持有行动真相，终端日志不驱动她的行为。具体断点如下。

| 最后能证明什么 | 恢复时做什么 |
| --- | --- |
| 尚未消费、未许可副作用 | 仅在原计划仍有效、边界未变、执行前检查通过时继续。已失效按原因结案 |
| 已消费，写管道前后失联，或桌面已持久登记「准备呈现」但未持久确认绘制 | 结果不明记 **UNKNOWN**。先核对同一投递的本地日志与认证回执；不能证明没发生时禁止重弹。即使推测崩溃发生在绘制之前也如此 |
| 已确认绘制，回执丢失；两帧并发或重连后收到同帧 | 写回原回执，面板恢复同一条目，不再弹。终端记录缺失或回执矛盾时保持 UNKNOWN。后获有效证据可追加结算，保留原未知记录 |
| 已显示后回应或审批结果的 ACK 丢失 | 回放同一输入 ID 和原样字节，返回原接收/提交结果。重连先认证同一安装和当前主体、新会话重新获取能力；过期凭证、旧会话 token 不能复用 |

## 4　你点了以后，H 究竟记什么

| 现场发生的事 | 可提交的事实、观察者及后果 |
| --- | --- |
| 点普通选项；或在自由框提交 | 桌面控件观察到一次明确的选项 ID 或一段提交的原文；H 记真实回应。取消输入、输入法候选、未提交草稿都没有这层含义。「算了」记录为该选项，如需知道缘由由她在交流中了解 |
| 点展示卡的「查看」 | H 记用户对哪一件材料请求查看。实际打开成功、读取失败由执行端另报；点击不能证明看懂了、看完了或同意了材料内容 |
| 点审批卡的允许一次、允许记忆（仅允许的档位）、拒绝 | 桌面提交原有 `ApprovalDecisionV2`。闸门按同一输入作权限判断并留一份关联的人类回应事实；用户按过按钮与权限最终是否有效分开。普通 `CardResponse` 无法签出同意凭证 |
| 点卡上明确的关闭按钮或有同义说明的键盘命令 | 桌面能观察到用户关闭**这张**卡，所以作为回应进 H，只写「收起了该卡」。审批继续受闸门期限约束；关闭整扇面板、失焦、OS 清理、断线、自动收起，均没有这项手势证据 |
| 有效期到，期间无已提交回应 | 可信核心时钟观察到截止且当时无已收回应，终端可另报自己当时可证的呈现状态。记录到期的系统事实：有明确未投递记录就写「到期前未投递」，有绘制回执就写「曾呈现」，两者均无则显示结果未知。不能推出用户在场、看见、没看见、刻意忽略或拒绝。迟到的真实手势仍可追加，截止时的记录不改 |

**决定 / 理由。** 复用 `UserText` 会丢失按钮与原投递的关系；把关闭或超时伪装成聊天里的「不」会改写事实。新增版本化负载 **`CardResponse`**（候选名）。字段为 schema、稳定回应 ID、投递引用、action_id、卡片定稿摘要、交互位置、反应种类，以及按种类唯一的分支：选项 ID、自由原文及语言、查看对象引用、明确关闭，或闸门已核对的审批决定引用。卡和投递可由同一引用定位，无需另造独立的卡片身份系统。记录事件观察时间与核心接收时间，分别沿用终端消息和 `ReceiptV2`。父关系指向已登记投递；有可核显示回执就另关联。人可以在显示回执确认前点击，按已登记投递及真实手势核验；不能因消息到达次序颠倒而编一条显示回执。

- **入口。** 受信卡片控件经窄 preload 上报一次真实操作；主进程核验窗口、主帧、当前卡实例、该位置可用的选项与手势来源，持久化稳定输入键，再经本机命名管道、已配对并有对应能力的桌面会话交网关。只准用户输入路径调用；worker、助手、模型文本、一般应用总线发布者不能提交此类人类观察。核心从连接及本机可信绑定解析响应者，核对同谱系/安装/卡及响应分支，不能把「配对的设备」直接等同 u*。审批另需 u* 与既有审批能力。证实来源且动作已超期时，把真实点击和执行失效分记；伪签名、错卡、外来选项、改字节则拒收并留入口审计。
- **提交。** 专用入口规范化为 `TerminalEvent` 所用的 stable_source_key、kind、parents、action_id、payload_ref、provenance、payload_digest，核心供给接收位置与治理属性。相同手势键和字节幂等；同键异载荷走冲突。两个真实手势各记一次；互斥业务结果只结算一次，另一手势若确实发生，记其实际处置。输入日志以 `RECEIVED_DURABLE` 和 `CORE_COMMITTED` 区分收妥与入 H；认证故障、时钟不可核或无法绑定来源不冒记人类事实。审批把同一次 `ApprovalDecisionV2` 及其授权/拒绝结果关联落账，不能另发一条客户端事件使同一次点击变两条人类经历。[终端入口](../../core/contracts/terminal_ingress.proto) · [审批核验](../../core/crates/gateway/src/terminal.rs)
- **属性规则。** G05 的版本化资源新增一行 `(CardResponse::NAME, OBSERVATION, ATTR_SOURCE_HUMAN_RESPONSE) → (exogenous=true, self_narrative=false, EVIDENCE_ACCESS_TARGET_DEPENDENT)`。规则由受信来源、事件种类和负载标签共同选择，输出绑定当时的规则表与治理记录。显示回执按自致 `EXECUTION_RESULT / ATTR_SOURCE_SELF_RESULT` 处理，到期按系统维护事实处理。两者均无 HUMAN_RESPONSE 资格，不能进入 θ 的外源样本。同一片段共享证据单位；外源也不自动证明某个因果关系或说法为真。[属性表](../../core/crates/semantic-core/src/attributes.rs) · [ADR 0048 G05](0048-formal-semantic-boundaries.md)
- **理解。** 新增受治理的结构化适配项，把已核的 ID 指到那次投递中对应的原标签/材料和用户动作；改界面语言、交换显示次序都不能改选项含义。自由文字按普通文本理解，在 `m=0` 下绑定到该次 `CardResponse` 原始 UTF-8 字段与跨度，照常走 IRL、A、M、采纳与降级。不能先改写成另一条 `UserText` 再计一次。G05 的「这件事发生」「内容属实」「本人主观体验」逐项按用途核验，推断行为效果仍需 EV4 的可比变化。比如「晚点」只证明用户选了它，不能直接写成「以后晚一点就不会打扰」。

选择卡可同时提供按钮和一个自由答复框；展示卡默认只有查看、关闭，需要答话时从该卡到聊天，沿同一投递提交一次文字回应。审批卡只把既有审批按钮送闸门；用户也可在关联聊天说「这是什么」，这句照常记为文字回应，审批仍待决定。面板可打开原件和反复阅读，不把每次程序重绘都算作用户回应。

## 5　她需要 QO 提供什么

**决定 / 理由。** 她遇到独力做不了的事时，在 Echo 的本地选择路径决定要问谁、交给对方哪些材料，以及怎样看待答复。QO 对 Nemu 是本机接活的服务。只规定双方能观察和核验的接口；QO 的内部组成、界面与其他客户的工作方式由独立项目决定。[ADR 0004](0004-codex-helpers.md) · [#263 §2 S8 固定稿](https://github.com/nanake-lab/nemu/blob/a265b1683c1f600897ceaac3d55ce6fb71457ad2/reports/DESIGN-BRAIN-01/REPORT.md) · [ADR 0045 D1、D2](0045-speak-think-wiring.md)

| Nemu 需要的接口 | 交接时可核对什么 |
| --- | --- |
| **创建与定位** | Nemu 带稳定的客户端任务键、关联的行动/投递、她给任务起的名字、用途（如有限提问或工作任务）、由 Echo 指定的目标助手及其档位（使用档位映射时固定 Nemu 的映射版本及解析结果）、目标与最少必要输入、独立工作目录、可读写/联网/工具的具体作用域、预算资源或档位与期限。服务返回稳定的任务身份、实际接活的提供者/模型以供 Nemu 与所选目标核对；不能满足原选择时返回不可用，任何扩大授权或替换由 Nemu 重新决定。名字可重复，不能作幂等键 |
| **状态与流** | 任务已接收、运行、等审批、完成/失败/取消和可核的未知状态；流式输出有任务、事件身份、序号/游标、原始生产者及通道。遗漏可查缺，重复可识别。最后结果含完成状态、产物或错误、来源、原件引用/摘要和用量（含计量单位、模型/档位，未知写未知）。进度文字不能结算行动 |
| **待批操作** | 每个请求有稳定审批身份，绑定任务、创建客户端、操作种类、实际作用域/目标、**将实际执行的完整原样载荷及其 SHA-256**、可供核对的说明和到期时间。原字节可重取，相同请求不能偷换内容。Nemu 校验后由闸门据原件生成 `ApprovalRequestV2.title/detail`。助手文字或 QO 提供的概要只供对照 |
| **审批归创建者** | QO 把请求交给创建这件活的已认证 Nemu 客户端。Nemu 按 ADR 0047 当前权限处理，可直接拒绝、在相应档位放行或经本机 u* 审批卡。返回决议绑定任务、请求、原样摘要、目标与时效；申请方只能消费匹配决定一次。Nemu 离线、响应未知或待审批时，这项操作不能先做。QO 界面对本任务最多只读，其他客户端不能代批。拒绝、超时、撤权及一次性消费均有可对账结果 |
| **恢复** | Nemu 可凭原任务键查回同一件活，按上次已持久接收的游标重放，并查询待审批和最终状态。同键同内容返回原任务，同键不同内容冲突；事件重复按事件 ID/摘要核对，游标只在本地提交后推进。若历史有缺口、创建 ACK 丢失或操作结果不明，按原身份核对，不能确认则记 UNKNOWN，不换键重做；重启也不能把审批默认为同意 |
| **本机与最小披露** | Nemu 只连接本机、验证服务与令牌，任务与创建客户端绑定；令牌不入日志、H、模型提示。每项任务使用独立获准工作区，核验解析后的真实路径与访问范围（含目录联接、上级、子目录），助手的工作目录和可达授权树必须排除核心目录及谱系存储。只给本次获准的材料，协议 p、c_task 也按用途裁剪；身份、记忆库、原始 H/Q、凭证与其他任务权限留在 Nemu。展示用量，沿 ADR 0033 的助手调用保险丝，不发明费用上限 |
| **进入 H 的事实** | 受信 Nemu 执行器按验过的任务、原行动、提供者/模型版本、返回事件/游标、产物及摘要上报 `EXECUTION_RESULT`，外层事务入 H。可证的是「某助手返回了这段答复」；答复内的命题保留 `model_inference` 等认识论来源，工具实际证据另有原始来源。转引保留作者与引语链，同一结果重放或被她复述不会增加独立证据。S8 的「别人告诉我」、D2 的可溯外根与她实际看到/做过各有来路；流式残片不能冒充完成结果 |

**现有桥的去留。** 选「把 Nemu 的助手执行入口改为 QO 客户端」。保留现有包名、调用方可用的接口及测试夹具，逐项迁移 `helper.ask/task` 的所有者回调；验明没有调用者后才退役被替代的直连助手路径。今天的 `src/base` 是 talk-only 库，使用独立 home、临时目录、只读且无工具/MCP，遇提供者审批回调即拒绝；其合成帧重放测试不是运行中事件游标。直接把这套拒绝改成自动同意或直接整体退役都会破坏说话、起草及可能的 IRL 调用边界。保留这些独立用途的现行隔离与实际生产者记录；同一件助手活只走一种执行路径，切换和回退均先核对在途任务。备选「继续为每个提供者在 Nemu 写一个工作台」会复制产品职责，「同时问两个后端，谁先回用谁」会重复外部行动。[桥的现状与用途](../../executors/codex-bridge/src/base/README.md) · [现有调用边界](../../executors/codex-bridge/src/base/bridge.ts)

### 代价与可改动处

| 跨窗作用域与单一设置 | 复用本地桌面可挽回档；仅新增能独立撤销跨窗的一项，否则关开关仍可能被舞台绕过 | 可以说「在这儿聊，别盖住我正在做的事」 | 窗口一旦弹过，当时造成的打扰不能撤回 |
| 具名投递、回执及手势 | 复用行动／审批记录和 stable_source_key；再少会在重启后混淆两张相似卡，或把超时当人答 | 记得当时问的是哪件事，承认自己不知道对方是否见过 | 已提交的动作、被问的字句、作答者及未知边界留在 H，后续只追加核对 |
| QO 的创建者、任务键与游标 | 作用域和批准复用现有闸门；缺少绑定与游标就无法恢复而不重做 | 请助手做同一件事，会回来问进度，也会分清是谁给的答复 | 实际向外披露的材料、发生的副作用及助手原话无法撤回 |
| 实现拆卡 | 沿用首次聊天的共用链路与一个 ADR；把编码、核心和窗口混在一个 PR，将无法单独验证谁制造了事实 | 先说上话，再学会递东西、接答复 | 已发布的 wire 字节、已发生的投递和对外操作必须可按原义回读 |
