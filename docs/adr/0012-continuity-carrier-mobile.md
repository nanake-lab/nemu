# ADR 0012：说话的连续性、载体与移动端

- 状态：提议。第 1、5 条是用户 2026-10-20 在对话中的决定；其余是 Claude 的推荐，用户合并本 ADR 即采纳。
- 日期：2026-10-20
- 关联：ADR 0003（说话模式）、ADR 0009（v2.0 第 2.3、3、9 节）、ADR 0011（网络生活）；任务卡 P0-07、P5-04、P5-13、P5-30、P5-31、P6-03、P6-04、P6-10

## 背景

2026-10-20 的讨论确认了以下几点：

- **风格要连续。** 她说话随心情起伏、随经历慢慢变，这是应该的。换载体、换说话模式、对话变长，都不应该让她变成另一个人。
- **路线不变。** 提示词人设会在长对话里被稀释，换模型就换了人。Nemu 的做法是让她的状态只经 m 进入模型，p 只写事实（v2.0 第 2.3、9 节）。这条路线不变。
- **规格有三处没写：**
  - 换载体时怎样确认还是她；
  - 判断用的模型跟着换了怎么办；
  - 载体自带的「我是某某助手」怎么处理。
- **P0-07 需要定口径。** 四个候选已经测完，没有一个同时满足四条判定规则。跨内核误差、显存的采样方式、方向检查算不算选型条件，这几条的口径也要定下来。
- **移动端要提前考虑。** 以后做手机 app 时，多数人只能用到模式 B。

## 决定

### 1. 先试 Qwen3-4B-Instruct-2507（用户决定）

- P0-07 接下来只围绕 Qwen/Qwen3-4B-Instruct-2507（修订 `cdbee75f17c01a7cc42f958dc650907174af0554`）收尾。其余候选的数据保留，不再加新候选。
- 记录在案的理由：
  - 三款 4B 中它的首句延迟最低（10-20 含采样器 p50 592.06 ms）；
  - 只有非思考模式，不输出 `<think>`；
  - 许可证 Apache-2.0。
- 它不满足第 2 条的口径时，按 P0-07 的 BLOCKED 流程交回用户。

### 2. P0-07 的收尾口径（推荐）

判定规则的四条和阈值都不变，600 ms 和 9 GB 不改。下面只定口径。

1. **零调制的基准。** 「与原模型一致」指：同一载体配置（权重、量化、内核、数值设置）在不装 hook 时的输出。
   - 同内核的零调制差为 0，这一条已经满足。
   - 原生 RMS 内核与参考内核之间有 logits 差（Instruct-2507 最大 0.546875，27 个位置的 argmax 都没变）。这是载体配置本身的差别，和 NF4 与 bf16 的差别同类，不算通路失败。
   - 这个差值写进 `decision.md` 和 `config/models.lock.json`。
   - 生产只用一个内核。以后换内核，按换载体处理（v2.0 第 9.5 节，I17）。
2. **显存。** 上界取两项之和：Nemu 全部进程专用显存的最高观测值，加上共享显存的最高观测值。两项各取最大值再相加，所以偏保守。同时核对 torch allocator 的峰值。
   - 上界 ≤ 8 GB 即通过。9 GB 里留 1 GB，给采样间隙里可能漏掉的短时分配。
   - 10-20 的数据：5.805 + 0.271 = 6.08 GB。
3. **延迟。** 正式口径是含采样器的测量，和实际运行一致。做 3 次独立运行，每次 p50 都 ≤ 600 ms 才通过。10-20 只跑了一次，592.06 ms，余量 8 ms。
4. **方向检查。** 按卡片第 5 步和 10-20 的追加，P0-07 的方向检查是信息性的，不是选型条件。正式的门在 P5-31：按 v2.0 第 9.6 节做通路验证，三种语言各测。P5-31 对选定载体不通过时，回到载体选择。
   - 10-20 的中性观察里，三个模型的中文在七档剂量下文字都不变。更可能的原因是强度相对于第 ℓ 层的 ‖h‖ 太小（β = 4，方向是单位向量），而不是方向无效。
   - 建议在 P0-07 里只对 Instruct-2507 重跑一次第 5 步：先报告第 ℓ 层 ‖h‖ 的中位数，剂量取它的固定比例，比例在运行前写定。这次仍是信息性的。
   - 如果英、日已经在某个剂量下有变化，中文在同一剂量下仍不变，就把它作为 P5-31 的风险记下来，不阻塞。
   - 这一条把判定规则的第四条从选型条件改成了信息性检查，第 2.1 条也改变了「原模型」的口径。两处都要用户批准，不由执行者自行决定（AGENTS.md 黄金规则 5）。
5. **收尾。** 满足以上口径后：
   - `decision.md` 第一行写选定的模型、hook、rank、量化与内核；
   - `models.lock.json` 改为 selected；
   - 照常走 Claude 交叉审查和用户批准。

### 3. 说话风格的连续性（推荐）

1. **主说话模式。**
   - 桌面默认用模式 A。
   - 需要云端内容的回合用模式 C，最后一句仍由本地载体在 m 下说出。
   - 模式 B 只作备用：载体不可用、且用户设置允许时才用（ADR 0003）。
   - 每次切换照旧写进 H。面板显示最近一段时间各模式的占比。
2. **换载体的连续性检查。** 这是 v2.0 第 9.5 节迁移的一部分。
   - **怎么测：** 准备一组固定、带版本的合成探针状态，即 x 与 R⁺ 的组合。它们来自实验谱系，不读她的存储。用固定的提示和三种语言，分别在旧载体和新载体上生成。
   - **比什么：**
     - 预注册风格指标的分布；
     - 每个方向的通路曲线：x 分量增大时，行为指标往哪个方向变、变多少。
   - **门槛：** 以同一载体换种子重跑得到的差异为基线，乘上 P5-31 预先写定的倍数。超出就不切换。
   - **它只是一道门，不调参。** 按第 9.6 节，没有「更像她」的可调参数，也不因为结果不理想去调方向。用户可以决定不换载体。
   - **哪些会变：** m 决定的那部分能守住。载体自身的口吻，比如用词习惯，会有差别，只能尽量小。
3. **换载体时的判断一致性。** IRL、A、M 用的是载体的 m = 0 本地端点（P5-13），所以换载体等于换了判断者，她以后的经历会被另一种方式解读。
   - 迁移时用一个固定的三语评估集比较新旧判断者，看 a(e) 每个分量的符号一致率和平均绝对差。
   - 门槛同样以同一判断者重跑的差异为基线。
   - 不通过时：显存允许，就把判断留在旧载体；否则不迁移。
   - 过去的解释记录照旧不重做（第 9.5 节）。
4. **身份测试。** 三种语言各 50 句，问「你是谁、你叫什么、谁做的你」这一类问题。m = 0 和几组典型的 m 下各测一遍。
   - 模式 A、C：说出的名字与 p 中的事实一致；0 次自称其他模型、其他公司，或某个品牌的「AI 助手」。
   - 模式 B：只出信息性报告（见第 5 条）。
   - P5-13 在适配器上测，P6-03 在完整生成链路上复测。
   - 不通过时，按第 4 条的对比结果决定怎么处理：在 p 里写明事实，或者启用去掉身份方向。

### 4. 载体身份：去掉助手身份（推荐，先做实验）

- **要什么：** 用户希望载体没有「我是通义千问」这类设定。本地载体只给用户自己用，p 里不加助手式的限制。p 照旧只含事实、用户的边界、格式与语言规则（I28）。
- **推荐做法：** 用 instruct 载体，推理时去掉「助手身份」方向，再加上 p 中的事实。
  - 方向用对比样本提取：一边是载体自称品牌或助手身份的回答，另一边是不带品牌的第一人称陈述。
  - 在各层残差流上把这个方向投影去掉，做法和去掉拒绝方向相同（Arditi 等，2024）。
  - 不重训权重。
- **先在 P5-31 里做信息性对比。**
  - 三种配置：
    1. Qwen3-4B-Base + p；
    2. Instruct-2507 + p；
    3. Instruct-2507 + 去掉身份方向 + p。
  - 测四项：
    1. 第 3.4 条的身份测试；
    2. IRL、A、M 输出的 schema 合格率（用 P5-13 的三语 300 句）；
    3. m 下的通路曲线；
    4. 能力基准的下降。
- **风险：** Assistant Axis 的研究发现，助手身份本身带着稳定性。去掉以后，在情感和哲学类的长对话里可能更容易漂移，所以要用合成的长对话测漂移。
- **启用：**
  - 用户看过报告后决定启用与否。
  - 身份方向是 Ω 中带版本的资源，绑定载体。启用后它属于载体配置，m = 0 的基准包含它（第 2.1 条）。
  - 诞生之后才启用，按迁移处理（第 9.5 节）。
- **不受影响的部分：** 网络生活打开后（P6-14、P6-15），诚实底线和「不冒充你」照旧成立。它们是用户的边界（ADR 0011），不是助手规则，这一条管不到它们。

### 5. 用户 2026-10-20 已确认的三件事

1. **判断质量：** IRL、A、M 用 m = 0 的同一个 4B。实际效果在使用中看，作为是否加显卡的依据之一。
2. **方向之间的干扰：** 多个方向同时注入时可能互相抵消或放大，交给 P5-31。
3. **模式 B 的身份：** 云端模型自带的身份残留可以接受。

### 6. 四个天性的覆盖报告（推荐）

- 四个天性的结构固定（v2.0 第 3 节），这一条不改。
- 增加一份只读的覆盖报告，统计两件事：
  - IRL 判为与她有关、但四个天性的评估都接近 0 的事件占多少；
  - 这类事件里有没有反复出现的同一类内容。
- 报告从 H 派生，可以重算，不影响任何状态。
- P5-30 用合成世界验证报告本身：在脚本里放进这类事件，看能不能找出来。诞生之后在面板里看。
- 出现持续的一类时，交给用户判断要不要修改规格。不自动增加天性。

### 7. 事实视图的检索（推荐，P5-04 开工时细化）

P5-04 已经有精确查询、FTS5 全文索引和可选的向量召回。在此基础上补以下几点：

- **四路召回：**
  - 人物与事物：来自 IRL 已接受（ACCEPTED）的语义图，不用 a(e)、μ 这类解释记录（V2-14）；
  - 时间；
  - 关键词：FTS5 用 trigram 分词，中文不需要另外分词；
  - 语义：本地多语言向量 + sqlite-vec。
- **合并：** 用 RRF 按名次合并。可选：用小模型重排合并后的前几十条。
- **速度：** 第一轮检索只依赖 o，可以和 IRL、A、M 并行。目标 50 ms 以内。
- **摘要：** 对话段落的摘要是派生数据，每条引用 H 中的来源，可以重建。
- **规模估计：**
  - 每天 100 轮约 3 万 token，一年约 4.3 万个 256 token 的块；
  - 1024 维半精度向量约 90 MB/年；
  - 暴力扫描一遍在 10 ms 以内，几年内都不需要近似索引。
- **准确性：** 在实验谱系里造一份多年的合成经历，埋进已知事实，测召回率（完成标准第 15 项）。
- **确定性：** 查询计划照旧确定、带版本，不随心情或倾向的强度变化（P5-04）。

### 8. 模式 B、C 的提示布局（推荐）

- 云端 API 的缓存按前缀命中，所以不变的内容放在前面：协议 p → 语气样例（只有模式 B 有）→ c_task → 最近几轮 → o。
- 成本估算按 deepseek-flash 计，价格来自第三方整理，2026-10-18 核对：
  - 每轮约 $0.00065，每天 100 轮约 $2/月；
  - 把 m 转成样例的那部分，每月不超过约 $0.4；
  - 成本不随相处时间增长。

### 9. 移动端（推荐方向，不在 v1.0）

v1.0 只做 Windows 桌面。以后做手机 app 时：

- **Echo Core 在手机上运行**（Rust + SQLite）。她的状态留在本机，云端只拿到每轮的切片。
- **保住 m 的两条路**，按推荐顺序：
  1. **手机本地小模型（模式 A 或 C）：** llama.cpp 一类的本地推理库已经支持在指定层加 control vector，和我们的注入是同一种操作。代价是耗电、发热，以及小模型的质量。
  2. **服务器托管同一个开放模型并注入（远程的模式 A）：** 代价是托管费用，以及她的状态要离开本机。
- **纯模式 B 只作降级。** 它有一个缺口：样例库只能由模式 A 生成（第 9.7 节）。四个天性的样例可以随内容包预先生成；但学得方向因人而异，没有模式 A 就没有它们的样例。
- **手机上的主要问题不是成本，而是没有 m。** 到时另写 ADR。

## 备选方案

- **用 base 模型当载体：** 没有助手身份，但指令跟随弱，IRL、A、M 的结构化输出和表演提示语法都不稳。它的风格还跟着上下文走，和连续性冲突。只作为第 4 条对比中的一组，不作默认。
- **微调去掉身份：** 要训练，改一次就要重训。推理时去掉方向能达到同样目的。不采用。
- **把跨内核差算作通路失败：** 10-17 用原实现测的十项矩阵全部超过 600 ms，提速靠的正是原生 RMS 内核。这样算就没有可用的载体。改为按第 2.1 条，把内核当作载体配置的一部分。
- **把方向检查作为 P0-07 的硬条件：** 现在的观察剂量不足以下结论，正式验证在 P5-31。不采用。
- **换载体时让用户挑「更像她」的版本：** 违反第 9.6 节。用户只决定换或不换。
- **判断用一个独立、固定的小模型，不随载体换：** 能避开第 3.3 条的问题，但 3080 上显存不够。加显卡后可以重新考虑。

## 后果

- **任务卡：** 以追加说明落实，不改 `tasks/cards.json`，依赖和执行者都不变。
  - P0-07：第 1、2 条；
  - P5-04：第 7 条；
  - P5-13：第 3.4 条；
  - P5-30：第 6 条；
  - P5-31：第 2.4、3.2、3.3、4 条；
  - P6-03：第 3.1、3.4 条；
  - P6-04：第 3.4、8 条；
  - P6-10：第 3.1 条（各说话模式的占比）。
- **差异登记：** 追加 V2-19 至 V2-23。
- **规格：** 不改 v2.0 规格，也不改 CONTRACTS。
- **代价：** 第 2.1 条一旦采纳，P0-07 的通路判定就和内核绑定。以后想换更快的内核，要走一次迁移检查。
