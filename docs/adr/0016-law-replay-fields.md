# ADR 0016：R 的典型幅度递推与分配重放字段

- 状态：提议。用户 2026-10-22 在对话中同意方案（a）；用户合并 P5-32 即采纳。
- 日期：2026-10-22
- 任务卡：P5-32（契约变更），依赖 P5-21；为 P5-23 解除阻塞
- 关联：ADR 0007（只增不改、字段号不复用、冻结点）、ADR 0009（v2.0）；差异登记 V2-34、V2-35、V2-38 至 V2-48；`docs/traceability/P5-23.md` 第 1 节 D4、D5；`reports/P5-23/BLOCKED.md`
- 变更类别：契约变更，只增。已发布的消息、字段号、类型标签与黄金向量都不变。

## 背景

P5-21 按最小字段集存 R（V2-34）。P5-23 实现规律引擎 G 时发现，下面两类状态在 IDL 里没有，G 无法按 v2.0 第 5.2 节的规范定义计算。

1. **典型幅度 r_k 的递推状态。** r_k 是 k 的全部吻合组中 p_c 的加权平均，权重 ω·μ，截断到 [0, r_max]。ω 每来一组关于 k 的证据就乘一次 ρ_k，所以逐组更新要存分子与分母：

   ```
   M_k ← ρ_k·M_k + μ_{c,k}·p_c,   U_k ← ρ_k·U_k + μ_{c,k},   r_k = clip(M_k/U_k, 0, r_max)（U_k = 0 时 r_k = 0）
   ```

   `Tendency` 只存截断后的 `typical_magnitude`：截断丢掉了符号，也没有分母。r̃_k = max(r_k, r_min) 进入每一组的支持 S 与强度，所以最普通的一组证据也需要更新它。
2. **改写旧分配时的重放数据。** 三种情况要改已经记入的分配 (c, j)（P5-23 D5）：
   - 新候选按 EV5 回溯收集到的旧组：v2.0 第 5.2 节「其他倾向已记入的份额相应调整」；
   - 后来加入组的成员：组的均值变了，S、强度、p_c 随之改变（V2-39）；
   - 容量移出一个倾向后，同一边的其他倾向收回份额，否则 I25「每一边之和为 1」不成立（V2-43）。

   要改 (c, j) 的贡献，需要它此刻的新近权重 ω_{c,j}，也就是 c 之后 j 的每一组的 ρ_j 之积；或者按次序重放 j 的递推。`EvidenceAllocation` 只有 support、intensity、share，证据组也没有次序，两样都做不到。

### 为什么从已有字段推不出来

P5-23 试过的办法（`reports/P5-23/BLOCKED.md`）：

- **反推：** A_k 与 B_k 混合了 W 与 \|S\|，S 又是 μ 与 clip(2p/r̃ − 1, −1, 1) 的乘积。推不出 μ、p_c，也推不出 Σω·μ。截断后的 r_k 丢了符号和分母。
- **只调整其他倾向「今后」的份额：** 旧组已经按满份额记入。再分给新候选，一边之和就超过 1，违反 LP2、I25。
- **把调整量按新证据记入（ω = 1）：** 旧贡献已经衰减，新的负调整不衰减，净贡献会改变符号（违反 LP1），B 也可能低于 n₀ + κ。
- **在 G 的单次调用里按全部历史重算：** G 的输入是 R 和本事件带来的证据组，没有历史的 b、σ̂，也没有每组的 μ、p_c。

## 决定

### 1. 新增五个字段

| 消息 | 新增字段 | 类型与约束 | 含义 |
| --- | --- | --- | --- |
| 倾向 | `magnitude_sum` | double，必填，有限 | M_k = Σ ω·μ·p_c |
| | `magnitude_weight` | double，必填，≥ 0 | U_k = Σ ω·μ |
| 分配 | `ordinal` | uint64，必填 | 这一组是该倾向的第几组，从 0 起；建立后不变 |
| | `mu` | double，必填，[0, 1] | μ_{c,k} |
| | `projection` | double，可缺省，有限 | p_c = ⟨Δ_c, d_k⟩；教导组缺省，不进入 r_k |

`typical_magnitude` 保留，作为由 M、U 得出的值，就像 π 由 A、B 得出一样。F 的情境作用 f_k 读它（v2.0 第 6 节），读的一方不必知道递推。

### 2. 以后继消息实现（ADR 0007 第 2 条，V2-35 的做法）

已发布的消息不改：改动的消息一律以带新类型标签的后继消息实现，旧消息原样保留并标为取代。

| 后继 | 冻结标签 | 字段 |
| --- | --- | --- |
| `TendencyV2`（取代 `Tendency`） | `echo.tendency-v2` | 1–15 与前任相同；16 `magnitude_sum`，17 `magnitude_weight` |
| `EvidenceAllocationV2`（取代 `EvidenceAllocation`） | `echo.evidence-allocation-v2` | 1–5 与前任相同；6 `ordinal`，7 `mu`，8 `projection` |
| `EvidenceGroupV2`（取代 `EvidenceGroup`） | `echo.evidence-group-v2` | 1–6 与前任相同；7 `reserved`；8 `allocations`（EvidenceAllocationV2，按 tendency_id 成集合） |
| `RSnapshotV2`（取代 `RSnapshot`） | `echo.r-snapshot-v2` | 1–3 与前任相同；4 `reserved`；5 `tendencies`（TendencyV2，按 tendency_id 成集合） |

- 证据组与 R 的快照只是因为装着换代的消息才换代：活的消息不能嵌入被取代的类型（`check_compat.py` 规则 6）。字段 7、4 换了类型，所以保留旧号；新字段号大于前任的最大号（规则 5），字段名不变。
- 没有其他活的消息嵌入这四个类型。`CoreTransactionV2.staged_r` 是对象引用：从此它指向 `RSnapshotV2` 对象（`object_type` 为 `echo.r-snapshot-v2`），消息本身不变。

### 3. 两条语义检查（`core-types/src/semantic.rs`）

- **倾向：** 旧的 `check_tendency` 的全部检查，再加上 `magnitude_weight = 0` 时 `magnitude_sum = 0`。
- **序号：** 对一个倾向，R 中各证据组对它的分配，序号正好是 0, 1, …, N_k − 1，各出现一次（N_k = `group_count`）。

### 4. 重放的依据

改旧分配时，G 先在本步把要改的值算好、存进分配，再从初值出发、按序号升序对这个倾向的全部分配逐个执行 D4。

**重算这些值时只用当前的量：**

- 份额调整（回溯分摊、容量移出）：只改份额，取本步处理这一组之前各倾向的 π（V2-40）；S、强度、p_c、μ 不变；
- 后来的成员：用本步的 b、σ̂、r̃ 重算这一组的 S、强度、p_c（V2-39）。

**重放本身只读存下的值：**

- 每个分配的 S、强度、份额，所在组的可信、可核实。W = 强度 × 可信 × 可核实 × 份额，按这个次序相乘，与第一次记入时的算法相同；
- 序号决定次序。μ、p_c 用来重算 M、U：M ← ρM + μ·p_c，U ← ρU + μ；
- ρ、N、F、上一组的符号、A、B 都在重放中由 S 的符号与 W 重新得出。

**初值不存：** 由规律版本与 genesis 给出：n₀ + κ_k（κ_k 来自谓词的条件数），u* 的依恋先验与信任的初始证据 A_att（P5-23 D4.0、D6）。

**为什么与按 H 次序的整段重算逐位一致（I23）：**

- 整段重算从 H 的开头逐个事件执行同一个 G。重放是 G 的定义的一部分，在增量计算里发生的那一步，整段重算也在同一步、对同样的已存值执行同样的运算。
- 只用有限 binary64，次序固定，所以两边逐位相同。
- 存下的值本身就是计算用的值：G 存值前先把 −0 归一为 +0，W 由存下的因子按固定次序重算，所以重放与第一次计算看到的是同一组位。
- 值没变时，从初值按序号折叠同一组分配，运算与当初逐组记入完全相同，结果与已存的倾向逐位一致。这条恒等性在 P5-23 里有测试。

### 5. 字段最小且够用：按三种情况走一遍

逐种情况列出重放读什么、写什么，确认不需要历史的 b、σ̂，也不需要其他倾向的 π 历史。

| 情况 | 本步重算的值 | 重放读的 | 需要的新字段 | 不需要 |
| --- | --- | --- | --- | --- |
| 回溯分摊：新候选 n 加入旧组 c 的一边 | n 的新分配：S、强度、p_c、μ 用本步的 b、σ̂、r̃_n；同一边的份额用本步各倾向的 π | 其他倾向 j 的全部分配：S、强度、份额（c 的已更新）、可信、可核实；序号；μ、p_c | `ordinal`（次序）；μ、p_c 只用于 M、U | j 的历史 b、σ̂（S、强度不重算）；任何倾向的 π 历史（份额用本步的 π） |
| 后来的成员加入组 c | c 的 Δ_c 与峰值；每个已有分配的 S、强度、p_c（本步的 b、σ̂、r̃）；符号变了的一边重新分摊（本步的 π） | 同上 | `ordinal`；S 的符号可能变，F 与之后的 ρ 随之变，所以全部分配的 μ、p_c 都要用来重算 M、U | 历史的 b、σ̂、π |
| 容量移出倾向 e | 同一边其他倾向的份额（本步的 π） | 同上 | `ordinal`；μ、p_c 用于 M、U | 同上 |

**每个字段都用到：**

- `ordinal` 三种情况都用；
- `mu`、`projection` 用于重放时重算 M、U。只改份额时 ρ 序列不变，M、U 也不变；但成员变了会改变 S 的符号，进而改变此后的 ρ，所以必须能重算；
- `magnitude_sum`、`magnitude_weight` 在每一组都用。理论上它们也能由全部分配重放得出，但那样每来一组都要读出这个倾向的全部旧组。A_k、B_k 存在倾向里是同一个理由：普通的一组证据只读写倾向本身。

**不需要的：**

- 每个分配的当前 ω（方案 b）：重放会算出 ω，不必存；
- 组在 H 中的位置：次序由每个分配的序号给出，回溯记入的分配序号排在后面（V2-41）；
- ρ 的历史：由 S 的符号与 N、F 重算；
- 历史的 b、σ̂、π：见上表。

## 备选方案

- **（b）每个分配存当前的 ω，每来一组就更新：** 字段少一些，但每来一组都要重写这个倾向的全部旧组对象。不采纳。
- **（c）换一种不需要这些状态的参考写法：** 等于发布新的规律版本（v2.0 第 0 节第 4 条），而且必须放弃回溯分摊或移出后的重新分摊，违反 LP2、I25。不采纳。
- **直接给 `Tendency`、`EvidenceAllocation` 加字段：** 改变已发布消息的字段表，违反 ADR 0007 第 2 条与 `check_compat.py` 规则 1。不采纳。

## 后果

- **契约：** 新增 4 种后继消息，4 种旧消息标为取代。生成的 Rust、Python、TypeScript 类型随之更新。黄金向量只追加：每种新消息至少 3 个合法、3 个非法，另有针对新字段的定向向量。冻结 P5-21 发布的 IDL 为基线 `baselines/p5-21/`。
- **迁移（ADR 0007 第 11 条）：** 没有任何已发布的字节被重新解释。R 还没有接入存储（P5-02、P5-29 未开工），排练存储与正式存储里都没有 R 的对象，所以不需要迁移或备份。以后的生产者只产生后继类型；旧类型保留，用于读旧数据和测试。
- **P5-23：** 本卡合并之前，P5-23 在 `law/` 内部用与这五个字段一一对应的临时结构实现，只在 crate 内部用，不持久化、不跨进程（用户 2026-10-22 决定），并保持草稿。合并之后把最新 main 合并进 P5-23，换成生成的类型，删去临时结构，重跑全部测试。
- **存储（P5-02、P5-29）：** 重放要读出一个倾向的全部分配，存储上需要按倾向索引证据组。
- **差异登记：** 追加 V2-50，指向本 ADR，解决 V2-48。
