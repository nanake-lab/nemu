# ADR 0022 — BodyReadout v2 的舞台接线与动画映射

状态：PROPOSED。2026-10-24 用户授权 P3-06 扩大目录并实现候选；最终契约变更待交叉审查和用户合并批准。PR 保持 `needs-user`。

## 背景

P5-22 已发布 `BodyReadoutV2` 与 IDL `ReadoutV2` 后继消息，舞台仍只有旧 `stage.readout`。P3-06 要求三项读出驱动身体、去除面部基线、固定版本映射参数进入 profile，并供评审台预览。卡片原目录不足以完成接线，用户已明确授权本 ADR、`packages/contracts/`、舞台两个入口及评审台 HTML；P2-06 等用户选定期间允许在重叠目录工作，尽量新增独立文件，后合并者解决冲突。

## 决策（候选，待批准）

1. 按 ADR 0007 只增不改：新增 `stage.readout.v2`，载荷 `{ readout: BodyReadoutV2 }`，外壳仍为舞台协议 `v: 2`。旧 `stage.readout`、旧 `BodyReadout`、旧字段及全部 IDL、CanonicalV1/Protobuf 字节保留；不把 v2 冒充旧消息。旧消息仍可校验解码，但迁移后的舞台不读取旧读出字段，收到旧入口时回中性，不恢复已删除的表情基线。新生产者应发送后继入口。
2. profile 只新增可选 `bodyReadoutMapping`，其类型由 contracts 导出，旧 profile 仍可加载。映射版本 `body-animation-v2-candidate-1`，`calibration: pending` 明示待校准；不修改正式内容包或 genesis。没有配置时使用同版本候选初值，未知映射版本拒绝。评审台调整只在内存生效并提供候选 JSON，不自动持久化或定稿。
3. 候选初值沿用既有动画幅度和节奏边界：energy 线性映射节奏 0.5–1.5 倍、幅度 0.5–1.5 倍，中性均 1；tension 映射姿态/耳朵偏移负 0.5 倍、尾巴系数 0.75–0.25，中性为零偏移和尾巴 0.5；facing 直接作视线朝向用户的权重，身体最大朝向偏移 10 度。依据是 P3-01/P3-03 的节奏边界、已有姿态/rig 限位，以及较小的偏移初值；这些数值没有通过审美或 genesis 校准，不是定稿，最终由用户或 P5-17 决定。
4. 读出应用器只接收三项读出，约 2 秒固定 Hermite 动画平滑；未连接、m 未应用、缺失或非法输入均回 `(0.5, 0, 0.5)`。不保存、不累计、不影响行动选择和权限；映射不计算天性通道到三项的系数（那属于 P5-12/genesis）。
5. L3 删除基线输入，保留 `emo`、口型、眨眼；句末提示按原固定曲线归零，并清理自定义表情残留。
6. `main.ts`、`stage-app.ts` 只接后继命令、核心可用性和逐帧应用；新逻辑放独立模块。验收脚本仅启动无界面 Chromium。两段真实 180 秒待机视频交用户观看，人工意见不阻塞。无用户级或系统级设置变更。

## 备选方案

- 修改旧舞台载荷或把 v2 转旧字段：违反只增不改，且可能恢复旧表情基线，拒绝。
- 只迁移应用器、不接舞台：无法交付端到端行为。
- 直接把候选参数写正式内容：跳过用户/P5-17 校准，拒绝。

## 后果与验证

新旧发送方需显式协商入口；旧客户端继续使用旧字节，新客户端旧读出回中性。回退时恢复旧应用和旧 profile 即可，不重写任何权威存储或历史字节。测试覆盖旧载荷/字段仍解码、后继载荷拒绝旧字段、profile 向后兼容、边界/中性/幂等/失联回中性、L3 自定义表情清理及无隐藏持久状态。旧 IDL 与冻结向量应保持字节不变。交叉审查由用户另开 Codex 会话安排，执行者写「请审查」后停下。

若后续需要差异登记，编号使用「待定」，本 ADR 不占用其他任务的编号。
