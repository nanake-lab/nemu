# ADR 0010：v1.0 范围、谱系与诞生（v2.0 核心）

- 状态：已采纳（2026-10-19，用户在对话中同意；以本 ADR 合并进 main 为准）
- 日期：2026-10-19
- 关联：ADR 0009（v2.0 核心）、ADR 0011（网络生活）
- 取代：ADR 0002 决定 4，以及其备选方案中否决「v1.0 直接做到完整 Echo Core v1」的理由
- 修订：ADR 0005（排练、谱系、N3）；`docs/echo-core/README.md` 第 3 节；登记项 E13、E14

## 背景

- ADR 0002 把 v1.0 限定在 M2 阶段门，不成长（NO-GROWTH）。理由是旧规格的成长需要真实的驻留时间和因果独立的证据，日期无法预定。
- v2.0 的成长不依赖驻留时间：证据一来就按规律计算，没有计时器，也没有次数门槛（v2.0 LP5）。旧理由不再成立。
- 用户希望她从出生起就在成长。

## 决定

1. **范围：** v1.0 包含 v2.0 的全部机制，成长从诞生起开启。不再分成「v1.0 不成长、v1.x 再开」两期。
2. **三种谱系（扩展 ADR 0005 第 3 节）：**
   - **REHEARSAL（排练）：** 情绪接通，F、J 运行，m ≠ 0；成长关闭，G、C 恒等。诞生时转为只读存档。
   - **LIFE（她的一生）：** 诞生时由 u* 签署的 genesis 创建，成长开启。
   - **EXPERIMENT（新增）：** 在合成世界里验证与校准规律。不含用户的数据、排练存储或正式存储；不能导入 LIFE 或 REHEARSAL；开发与测试可以随时用临时存储创建。
   - 三种谱系互不可读，类型写在存储头部。
3. **E13 修订：**
   - G、C 恒等只用于排练谱系，以及用户暂停成长时（原因码 `GROWTH_PAUSED`）。
   - 正式谱系要求全部阶段接通，包括成长；核心拒绝在不完整的配置下创建或运行正式谱系。
   - 开发期间 F 尚未实现时，排练谱系仍可按原降级路径运行（m = 0，`MODULATION_NOT_ENABLED`）；F 就绪后，排练谱系接通情绪。
4. **排练中的主动：** m ≠ 0 之后，ADR 0005 中「排练期间她只回应、不主动开口」的理由不再成立。排练中的主动按与正式谱系相同的边界运行；用户可以用安静模式或权限关掉。
5. **成长暂停：** 这是 u* 的一项权限。暂停期间 G、C 返回不变，恢复时按 H 补算（v2.0 第 5.4 节）。
6. **诞生：** u* 签署 genesis 清单并执行 `echoctl birth`。她的名字是 H 的第一条事实。签署诞生的人就是她依恋的对象 u*。
7. **N3 重新定义：**
   - v2.0 的验收通过（v2.0 第 17 节，按 P5-18 重排后的清单）；
   - 实验谱系的验证与校准完成；
   - genesis 签署；三种说话模式与全部功能就绪；
   - u* 执行诞生。
8. **日期：** 设计定稿（本 PR 合并）后重新排期。ADR 0002 的 v1.0 日期与 ADR 0005 的 N3 时间点不再作为承诺；新的日期由重新排期确定。N2（2027-01-17）是否受「排练接通情绪」影响，一并评估。
9. **备份：** 本机备份写到另一块本地磁盘或移动硬盘，不上云。W23（多端接入、加密异地备份、切换演练）仍不在范围内。
10. **网络生活：** 诞生之后才打开，边界见 ADR 0011。

## 备选方案

- **维持 NO-GROWTH 的 v1.0：** 她出生后要过很久才开始成长，与「一切成长出来」相反。否决。
- **诞生后分期打开成长（先 R 后 θ）：** 分期没有依据。否决。
- **排练也开启成长：** 排练是开发期，开发中的错误会变成她的经历。否决；排练只接通情绪。
- **用用户的真实数据做实验：** 违反 AGENTS.md 第 3 节第 14 条和 ADR 0005。否决。

## 后果

- 工作量增加：规律引擎、重算、实验谱系、方向提取与验证、网络生活。排期需要重做；`tasks/cards.json` 的修改需要用户批准。
- 排练接通情绪，需要 F、天性评估（原 A_x）、J 在 N2 之前就绪。
- ARCHITECTURE §2 第 26、27 项需要改写为 v2.0 的验收；§6.5 的范围、运行状态、谱系描述随之修订。这些修订需要用户批准。
- `docs/traceability/scope-v1.md` 中 W06–W10 的「v1.x」路由作历史保留，按 v2.0 重新路由。
