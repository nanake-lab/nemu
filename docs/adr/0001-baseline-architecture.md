# ADR 0001：v1.0 基线架构

- 状态：已采纳；其中「Agent」「离线」两行、「动画」一行里的行为状态机（改为物理状态机），以及人设文件、记忆库、主动性引擎、情绪模型的设计，已被 [ADR 0002](0002-echo-core-as-nemu-core.md) 取代；里程碑命名与顺序见 [ADR 0005](0005-rehearsal-and-birth.md)
- 日期：2026-10-13

## 背景

Nemu 从 Live2D 2D 原型转向 3D。目标是原创、高完成度、可长期扩展，并且最大限度由 Codex 与 Antigravity 自动化开发。开工前需要一次性定下总体路线，避免中途推翻。

用户明确了项目的根本目标：Nemu 是只属于自己的东西，想分享时可以分享，也可以一直自己留着。同类开源项目很多（AIRI、Mate-Engine 等），但它们是通用平台；基于它们改造，得到的是「别人的平台套上 Nemu 的皮」，并且要长期跟随上游路线。因此选择自建一套小而清楚的代码，从 MIT 项目中自由借用零件。

## 决策

| 领域 | 决策 |
| --- | --- |
| 运行时 | Electron + three.js（WebGL2）+ @pixiv/three-vrm v3，TypeScript |
| 角色 | VRoid Studio 打底 → Blender 无头脚本精修 → VRM 1.0；运行时只认资产契约 |
| 动画 | VRMA 片段 + 五层程序化叠加 + XState 行为状态机 |
| 语音 | sherpa-onnx（Silero VAD + SenseVoice）；Qwen3-TTS：用 VoiceDesign 设计原创音色，运行时用 Base 模型克隆，每种语气一段参考音频（Base 不接受文字指令）；wLipSync |
| Agent | AI SDK 6 ToolLoopAgent + @ai-sdk/mcp，本地 SQLite 记忆，T0–T3 权限分级 |
| 办公协作 | 自研 .NET Office COM MCP 服务；Windows-MCP 可选 |
| 开发分工 | 按目录划分所有权；契约包解耦 |
| 授权 | 默认私有；代码仓与 Nemu 内容包分开管理，许可清单完整，任何时候都可以单独公开代码或整体公开 |
| 离线 | 断网时自动切到本地模型（Ollama + 0.6B TTS），保证 Nemu 不依赖任何云服务也能存在 |

## 备选方案与否决理由

- **Unity 6 + UniVRM：** 渲染与动画工具最强，但依赖编辑器图形界面，AI 代理难以端到端自动化；官方 MCP 在 2026 年仍处于公测并变动；开源贡献门槛高；不能复用现有 Electron 原型。
- **Godot 4：** 开源、场景为文本，但 VRM 插件成熟度、AI 代理熟悉度、浏览器内视觉验证都不如 Web 栈；有 Windows 透明窗口长时运行闪烁的报告。
- **WebGPU 渲染：** three-vrm 的节点材质仍在开发，可能频繁破坏兼容；v1.0 用 WebGL2，WebGPU 留作舞台层内部可选后端。
- **AI 图生 3D 作为主角：** 拓扑、表情 blendshape、卡通着色达不到要求；仅用于道具。
- **Live2D 与 3D 双线：** Live2D 无法满足坐窗沿、走动、转身等场景交互，双线会分散资源。

## 后果

- 渲染表现力的上限低于 Unity；以舞台协议为边界，必要时可以单独替换渲染进程。
- 角色观感依赖 VRoid 塑形质量；N1 设立去留决策点。用户已决定不委托外部建模（2026-10-13）：不达标时由用户自己再迭代一轮，整个项目由用户自己完成。
- 所有决策只允许在接口内替换实现；推翻任何一项都需要新的 ADR 并经用户批准。
