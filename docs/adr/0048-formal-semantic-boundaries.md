# ADR 0048　从原载荷到已采纳解释

交付线，P5-43，提议。U1–U4、U9 已选定，本 ADR 的标签、字段号和编码待交叉审查与用户批准。[设计决定](../../reports/DESIGN-EVIDENCE-CONTRACT-01/DECISIONS.md) · [原始缺口](https://github.com/nanake-lab/nemu/blob/650e9f138e6bf534450f5a5163571e88b3ce1303/tasks/requests/P5-06-formal-semantic-boundaries.md)

## 背景

现有语义图可以引用对象，却不足以从图节点找回事件的具体字段。候选记录保存了生产者的提议；重放还需要知道核心接受了哪些结果。D13-A 要求对「确实有人这样说」「话的内容属实」「这是那个人的主观体验」分别给出依据。[ADR 0033 §4、§6](0033-helper-fuses-cursor-evidence.md) · [完整设计对照](../../reports/DESIGN-EVIDENCE-CONTRACT-01/P5-43.md)

## 决策

1. **来源及原文（G01、U1）。** 每个定位以 ADR 0046 的 `RecordVersion` 为端点，路径由原始消息的字段号和必要的重复元素索引组成。空路径且无区间表示整件；区间是被选 UTF-8 字符串上的 `Utf8Range`。按原载荷的规范字节、类型域摘要、对象长度和资源版本核验，拒绝半个字符及跨对象套用。一个节点可同时引用多个定位。由转写、转义等派生的内容保留各自端点、转换资源与根。逐层归属沿用 `SpeakerAttribution` 及其有序 `QuoteLayer`，每层在自己的原件上核验。配对、ASR 置信度、模型文字均不足以证明发言主体。提交前只读材料的可见范围由事务借出，提交后以同分支前缀为准。身份及用途授权依赖 P5-40，逐层证据、派生链和前沿清单由 P5-06/P5-53 核验。
2. **概念（G02、U2）。** 注册表按版本读。概念按核心分配的永久 ID 保存，修订绑定前任、采纳依据、grounding、三语定义和签名；暂存与采纳同事务发布。provisional 可缺失尚未知的定义。stable 需要有依据的定义。deprecated 仍供历史解释。每个别名至多指向本版一个存在的代表，允许逐级归并，拒绝环、冲突与悬空。一般概念关系另存其治理类别及证据。改名不产生新经历，不重置证据顺序。
3. **图和适配（G03、U3）。** 首批条目只读 `UserText.text` 与 `UserUtterance.text`（两者均为字段 2）。条目绑定载荷标签、schema、注册表、已注册谓词和角色。首批只提出「该载荷给出了这段原话」；Claim 携带定位过的原文，模态为报告，时间可明确不适用、未知或引用正式事实。自然语言陈述的内容、其真值、音频说话人和发生时刻须另有依据。按钮、触摸、执行回执、桌面、会话、维护及其余未登记来源均显式返回未支持。保留 Ref、Claim、Act 三类节点；角色、谓词签名、边和交互种类只从所绑定版本的注册表解析。记录间用途遵循 ADR 0045 的映射 v1。
4. **阶段采纳（G04、U4）。** 独立记录 IRL、A、M 的输入、候选、实际输出、允许读集、生产资源、隔离核验、治理、覆盖范围及结果。未覆盖的目标未评；M 的已知零、已评未知和阶段失败分别编码。A 只能给出完整 `NatureVector` 或失败。重解释沿用 `RecordRelation`，新解释指向同事件、同阶段旧解释；覆盖精确到被替换目标。用 `RelationQueryReceipt` 及其 `RelationSet` 核对同端点、用途、前沿的独立清单。结果只在外层事务中生效；检查对象形状不能证明真实的调度、权限、原子提交或查全。
5. **属性与目标前提（G05、D13-A）。** 规则资源以受治理的来源、事件种类及载荷类型选择输出；产物绑定实际输入、规则及治理依据。真实回复、触摸、缺席的外源单位按既有边界归类；同一片段多次报告共享单位。桌面观察、自致工具结果、内部念头与维护各有独立规则。三个核实项分别携带作用范围、三值和各自依据；未知须写明原因。主观为真需指明体验者。逐目标事先固定所需核实与 EV4 比较依据，证据组装再使用。分句反应或多个真值在事件级不能安全区分时，相应目标保持未解决。缺席的时间与单位事实取自所属后继卡；桌面空闲不能产生缺席。规则不引入可信度、权重或反应阈值。

## 编码、兼容与回退

候选字段表见 [IDL](../../core/contracts/semantic_evidence.proto)。新标签均取 schema_version 1，使用 CanonicalV1。表示无序身份的字段使用规范集合，保留字段路径、引语层和转换链的次序。字段更换类型时在后继中保留旧号为 reserved，追加字段号高于旧布局最大号。有活跃生产者或活类型嵌入时用 `@retains`；旧标签继续按原义读写。三个终端上传入口对本文件中所有标签拒收。P5-06 接线后核对全部生产者和嵌入者，再另案登记退役。[ADR 0007](0007-initial-idl-canonical-encoding.md) · [ADR 0046 §4](0046-speak-think-contract-gaps.md#4-迁移与回退)

U9 保留旧字节和旧解释。新语义确有需要时由获准流程追加有来路的解释；旧布尔值、旧父关系和旧语音进度保持原义。恢复使用旧应用与备份，SYS17 的存储执行归后继卡。[版本决定](../../reports/DESIGN-EVIDENCE-CONTRACT-01/DECISIONS.md#u9旧材料怎样用于新规律)

## 备选与后果

| 新增结构 | 沿用旧字段会缺什么 | 她会怎样使用 | 固定下来的事实 |
| --- | --- | --- | --- |
| 多处定位 | 原件上的具体位置、派生版本 | 找到引语在原话中的字节 | 当时收到的原件与转换来路 |
| 概念修订及有向映射 | 签名、旧称的去向 | 后来理解旧称 | 本版历史身份及治理 |
| 文字、语音适配和图后继 | 能验证的原文 operand 与签名 | 区分听到的话和已证实的事 | 本版映射及原文字段 |
| 阶段记录 | 实际获准的判断与未覆盖部分 | 可以后来补全 | 当时的读写、采纳和失败 |
| 分类规则及分项核实 | 单一布尔值丢失核实范围 | 内容待查也记得对方确实求助 | 当时的规则及各项出处 |

原提案里的等价集合、跨来源通用值域、整批迁移均未选用。以上结构落实 ADR 0039 的 P1、P3、P4、P7、P9、P10。只有经受信核心核验和外层事务提交的结果可用于后续治理。[原则](0039-echo-core-principles.md#23-十条原则)
