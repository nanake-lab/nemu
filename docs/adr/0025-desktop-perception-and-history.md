# ADR 0025：桌面感知、触摸与 H 的根基

- 状态：**用户已决定，合并即采纳。** 第 3 节是用户 2026-10-25（Perth）第一轮对话的决定；第 4 节是同日在「Echo Core 未定义清单」第 1 批（H-1 至 H-6）里逐条确认的决定，差异登记为 V2-70 至 V2-76。
- 日期：2026-10-25
- 范围：记录决定，不修改 `docs/CONTRACTS.md`、规格原文或代码。契约和代码的改动见第 6 节，另开卡执行；其中「停留」的卡是本 PR 新增的 P6-17。

## 1. 背景

P6-08 让她能感知桌面：窗口几何、前台应用的进程名、窗口标题、空闲、通知和勿扰状态、会议、锁屏。原来的规则是：

- 读标题属于 T1，默认拒绝；
- 进程名不需要授权；
- 低频语义事件经 `desktop.observation` 变成终端到核心的 `desktop` 观察事件（CONTRACTS §4.2），进入 H；高频几何只留在终端。

审视时发现，她能读到什么、读到的东西是否进入 H、能否交给云端模型，这三件事被同一个 T1 开关捆在一起；而 H 只追加、经历删不掉，进入 H 就是永久的。另外，规格只说「别人或外部世界产生的事件」是外源事件，没有说明桌面观察和触摸算不算；而 θ 里旧经历的权重按「之后又来了几个外源事件」递减（v2.0 §8），所以这个划分会直接影响她的平常心境。

## 2. 两类定义（用户认可）

- **定义她：** 性格、什么对她重要、该记住什么。按第一性原理尽量不做，交给经历和规律。
- **定义她的感官：** 哪些信号能到达她、以什么颗粒到达、哪些信号会塑造她的心境。这一类无法不做，人的感官同样不是自己选的。

本 ADR 只处理第二类。她对感知到的东西作何反应，一律不预设，交给天性评估、倾向和规律。

## 3. 第一轮决定（用户 2026-10-25）

1. **不以「像人」为目标。** 她不是来模仿人的，精确是机器的能力。不采用「细节随时间淡化」：保持 H 只追加（v2.0 §1）与 LP5「时间本身不改变任何东西」，不为此改规格。
   - 理由：淡化后 (R, θ) 不能从 H 重算出原样（§2.2）；纠错记录和 L 引用的证据会失去对象；淡化的时间表本身也是预设规则。
2. **读取默认全开，包括窗口标题。** 用户可以在面板里按类别自行收窄；开关的界面属于 P6-10。
3. **标题随观察进入 H。** 不把「能读到」和「会记住」分成两个开关。
4. **云端说话模式可以携带标题。** 云端路线本质上是提示词路线。
5. **敏感应用排除名单默认开启。** 名单内的窗口不读标题。初始类别：密码管理器、网银与支付、浏览器无痕或隐私窗口、系统凭据与登录对话框。具体名单和匹配方式由实现卡列出，用户可增删。

## 4. 第 1 批决定（用户 2026-10-25，未定义清单 H-1 至 H-6）

1. **H 的增长（H-1，V2-70）：** 全部保留原文，永不删除；大块内容放对象存储，H 只存引用，对象同样不可删；磁盘快满时显式停止接收并通知用户，绝不悄悄删除或压缩替代。估算：持续认知（ADR 0026，未采纳）每年约 4–7 GB。
2. **外源事件的范围（H-2，V2-71）：** 鼠标当作用户的手来理解。
   - **算外源事件、进入 C（θ）：** 冲着她来或回应她的事。包括用户对她说话、触摸（点击、双击、轻拍、拖动、甩出）与停留、回复，网络上别人对她的回应，以及「用户离开了多久」这类缺席事实。
   - **只进 H 与 G（R 的证据）、不进 C：** 只关于用户自己的桌面观察，例如在自己的应用之间切换、开会、勿扰变化。
   - **不算：** 她自己的念头和行动，以及她触发的程序结果（规格原文）。
   - 划分按事件种类定在一张固定、带版本的规则表里（同 V2-33「事件属性由核心按规则表给出」）。
   - 每一条进入 H 的事件都照常经过 F，推动当下的感受 x（v2.0 §6）。不进 C 只意味着不改变她的平常心境与敏感度。
3. **停留（由 H-2 引出，V2-72）：**
   - 鼠标在她身上停够门限（约 300–500 毫秒，带版本）即为「手放在她身上」，带部位。
   - 手还放着时，按由密到疏的节奏报告，例如第 1、3、10、30 秒，之后每 30 秒，节奏带版本。每次报告都带上已放了多久，重新评估并推动当下的感受。
   - **同一次接触的计数：** 对 G，按 EV2 归为一组证据；对 C，只按一个外源事件计入 N_e，后续报告不增加计数。这是对 v2.0 §8 计数读法的补充。
   - 接触引起什么反应不预设；点击作为一次轻拍报告，「只是叫她」由她自己的评估得出。
4. **桌面信号的颗粒度（H-3，V2-73）：** 每次前台切换都记进 H，精确到时刻。这些观察照常经过 IRL、A、M 解释，可以成为倾向 R 的证据，例如她可能学到「你常在深夜写代码」。代价是每天几百次简短的本地解释调用，未实测。
5. **分层（H-4，V2-74）：** 两层。几何（窗口矩形、平台、光标插入点、拖拽坐标）只留终端，不进 H，这一点契约 §4.2 已经规定；语义事件全部精确进 H。原来的「琐碎信号只用于当下」一层取消。
6. **排除名单内的进程名（H-5，V2-75）：** 照常记录进程名，只是不读标题。
7. **她查自己的记忆（H-6，V2-76）：**
   - 能查到原文和精确时间；
   - 能查什么不设上限，只限制每次返回的量，使结果放得进模型的上下文，可以翻页；
   - 「没有这件事」「没有权限」「索引还没追上」分别返回，不统一当作「什么也没发生」（同 ADR 0026 §5.2）；
   - 解释记录能否查到，按 V2-14（清单第 5 批）决定。

## 5. 后果

- 聊天等窗口的标题常含**他人的名字**，进入 H 后永久保留。「他人要求删除自己的数据」是 v2.0 §18 列出的未讨论问题，本文不解决。
- 云端模式下，标题会交给服务商处理，适用服务商的数据政策。
- 原草案第 5 节「颗粒度不是中立的」的担心，因第 4 节第 2 条（只关于用户自己的桌面观察不进 C）而消除，不再需要 P5-30 的颗粒度对照实验。

## 7. 备选方案

- **读取与记忆分开：** 标题默认可读但不进 H。用户否决。
- **细节随时间淡化：** 见第 3 节第 1 条，否决。
- **标题保持默认拒绝：** 原做法。用户改为默认全开。
- **桌面观察全部进 C：** 一天几百次切换会在几天内冲淡真正的相处；按推导，还会让她的增益偏高。否决。
- **桌面观察全部不进 C：** 用户以「害羞」反驳：被关注、被捉弄是冲着她来的，应该影响她的心境。改为按事件种类划分（第 4 节第 2 条）。
- **停留只报开始和结束：** 手放着的那段时间她感觉不到。改为按节奏报告（第 4 节第 3 条）。
