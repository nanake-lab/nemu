# ADR 0031：载体推理引擎与注入通路

- 状态：草案，记录用户 2026-10-29 已作出的决定，提交审查；由用户合并采纳。
- 日期：2026-10-29
- 依据：[P0-10 报告](../../reports/P0-10/REPORT.md)、[速度与 IRL 实测](../../reports/P0-10/BENCHMARK-REPORT.md)、[注入配对实测](../../reports/P0-10/INJECTION-REPORT.md)、[P0-09 选项草稿](../../reports/P0-10/P0-09-OPTIONS.md)。
- 关联：ADR 0012；v2.0 §9.5–9.6；《核心算子》§13.2；P5-13、P5-31；E2 文字排练与 E3 声音里程碑。
- 范围：只记录选型、接入约束和启用条件，不新增截止阈值、校准参数或异步编排细节。本次不修改生产代码、模型锁或历史测量记录。

## 背景

P0-10 已测量同一模型修订下 llama.cpp 的 Q4_K_M、Q8_0 速度与 IRL 输出，以及 Q4_K_M 的注入通路。Q4 的 decode 更快、载体显存观测更低，但原生 prefill 与客户端 TTFT 之间存在额外等待；既有报告没有把这段等待分解归因。原生 control vector 的注入位置与 token 掩码也不同于旧 Transformers 通路，旧方向和验证结论不能直接迁用。

P0-10 只提供测量与选项；本 ADR 记录用户据此作出的决定，不将测量完成等同于 P5-31 迁移验证通过。

## 决定

### 1. 引擎与模型

- 运行时采用 **llama.cpp b11669**（提交 `620d2225cc436ab0b001e3200e590e3b286ef9ab`），量化采用 **Q4_K_M**；Q8_0 不采用。
- 模型仍为 **Qwen3-4B-Instruct-2507**，修订保持 `cdbee75f17c01a7cc42f958dc650907174af0554`（`cdbee75f`）。
- Transformers 通路保留为研究台，不作为运行时通路。

### 2. 注入与迁移

- 先采用原生 **control vector 的整层残差位置**。
- P5-31 按 v2.0 §9.5–9.6 做迁移验证；若不通过，退回 **attention 残差后位置，加自有接入**。
- **旧向量不得复用。** 新通路需要重新提取并验证方向；退回位置也不免除新引擎上的提取与验证。

P0-10 已证明位置与掩码的差异：旧位置在 attention 残差后、FFN norm 前，原生位置在整层残差后；原生广播覆盖全部 prefill 位置，旧掩码只覆盖末位置。三语三对样本证明了提取技术可行性，不能替代全部方向、三语通路单调性与能力无损验证。

### 3. 每次更新 m 的顺序与缓存

每次更新 m 前，按以下顺序执行：**显式清 KV → 安装本次向量 → 重新 prefill**。不得复用旧 m 下的 KV；设置向量成功不表示 KV 自动失效。

- 优先进程内直接调用 llama.cpp 库。
- 若使用 llama-server，必须同时设置 **`--cache-ram 0`** 和 **`cache_prompt=false`**，并遵守上述显式清 KV、安装向量与重新 prefill 的顺序。

依据为 `benchmark-run-03` 的 Q4 原始 `Q4_K_M/server/server.stderr.log`：日志显示默认内存提示缓存启用，大小上限 8192 MiB，并注明每个新任务开始时会把空闲槽位保存到提示缓存。474 个任务中，提示缓存更新路径触发 **274 次**，日志计时中位数 **3550.005 ms，约 3.55 秒**。其中 273 次有保存提示的日志，另一次是初始空缓存更新；274 是更新路径触发次数。

这可解释已测客户端 TTFT 与原生 prefill 的差距，但禁用后的实际改善仍需补测。该缓存还可能恢复旧 m 下的 KV；原速度运行是 m = 0、无注入，不能据此声称已观察到 server 恢复旧 m。独立的注入实验已确认：保留旧 KV 再换向量的诊断与 fresh-B 不一致。

原日志可由[文件映射](../../reports/P0-10/benchmark-run-03/raw-filemap.json)中的上述路径恢复；[压缩对象](../../reports/P0-10/benchmark-run-03/objects/0e577355f9d10a6f09f6598382ae364474399395abe461d33e8b02e2e2e1c888.gz)解压后 SHA-256 为 `0e577355f9d10a6f09f6598382ae364474399395abe461d33e8b02e2e2e1c888`。本条是对既有日志的离线核对，不是新的 GPU 测量。

### 4. IRL

采用**原 wire schema、本地、异步**通路，IRL 不挡回复；紧凑 schema 不采用；**不新设截止阈值**。原 wire schema 的来源合格率与紧凑版的差异见 P0-10 实测，不把 schema 合格率当作语义正确率，也不把 P0-08 的 P90 用作部署截止时间。

### 5. E2 文字排练

- m 通路接好，默认 **m = 0**；**x 照常计算与记录**。
- P5-31 验证通过后，**经用户批准再开启非零 m**。
- 实验谱系可以带 m 运行；其余谱系隔离要求不变。

零注入依据来自 P0-10 的同配置对照：中、英、日分别 24、11、16 个输出位置，合计 **51/51 个位置的完整 logits 字节一致，最大差为 0**。这是已测输入和配置的证据，不是任意输入或跨量化的一致性保证，也不代表非零调制行为已验证。

本条调整 E2 的启用时点：ADR 0010 §2–3、ARCHITECTURE §6.5、P5-19 与任务总览中“排练接通情绪 / m ≠ 0”的要求，在 E2 按本条分阶段执行。默认零注入不等于停算 x，也不免除 P5-31 的验证或改变正式谱系的完整接通要求。

## 备选方案

| 方案 | 用户决定 |
| --- | --- |
| Q8_0 | 不采用 |
| Transformers 作为运行时 | 不采用，保留研究台 |
| 原生整层残差注入 | 先采用，接受 P5-31 迁移验证 |
| attention 残差后位置与自有接入 | 原生通路迁移验证不通过时回退 |
| 紧凑 IRL schema | 不采用，保留原 wire schema |
| E2 立即开启非零 m | 默认 m = 0，P5-31 通过且用户批准后再开启 |

## 后果

- P5-13 按上述引擎、量化、注入与 KV 约束实现；本地 IRL 端点使用原 wire schema。原 J01、J05、AT13、身份测试及资源/回执校验要求保留。
- P5-31 负责新通路方向提取、通路与能力验证及迁移；不能复用旧向量或把 P0-10 的零注入结果当作迁移批准。
- 新增 **P0-11「--cache-ram 0 TTFT 补测」**，只测量，归入 E3 前置；不阻挡 E2 的默认零注入文字排练。
- 本 ADR 不宣告旧固定句、完整延迟预算或同驻显存验收通过，也不放宽既有验收阈值。

## 未决事项

- **`--cache-ram 0` 下的客户端 TTFT：** 下一个用户安排的 GPU 窗口由 P0-11 补测确认；当前没有禁用缓存后的实测结果。
- **GPT-SoVITS V5 与渲染同驻显存：** 未测。P0-10 的载体单独显存不能代替实际同驻测量，本次 TTFT 小卡也不承接同驻验收。
