# ADR 0027：声音模型——目标 Breeze TTS 2，过渡 GPT-SoVITS V5

- 状态：提议。第 1、2、4、6 条是用户 2026-10-25（Perth）在对话中的决定；第 3、5 条是 Claude 的建议。用户合并即采纳。第 4 条对 ARCHITECTURE 的影响待用户确认，见该条。
- 日期：2026-10-25
- 取代：`docs/ARCHITECTURE.md` 中 `voice-sidecar` 与「合成」两处的 Qwen3-TTS；P4-02 卡中「Qwen3-TTS Base」的模型选择（卡在声音工作恢复时修订）。
- 关联：ADR 0017（端点与抢话目标）；P4-02（PR #45，已暂停）、P4-03；Echo Core 未定义清单第 7 批 V-1 至 V-3。

## 背景

- **目标（用户 2026-10-25）：** 她的内在状态影响语气、语速、停顿和笑声，而不只是把文字读出来。情感表达优先；不要求覆盖中英日三种语言。
- **现用的 Qwen3-TTS 不满足：**
  - 官方模型表：只有 1.7B 的 CustomVoice、VoiceDesign 支持指令控制，0.6B 不支持；
  - 1.7B 在用户的 RTX 3080 10 GB 上实测合计 9.21 GB（P4-02 报告），和大脑放不下；
  - Artificial Analysis 语音竞技场（盲听 Elo）：930。
- **Breeze TTS 2：**
  - 竞技场开源模型第 2（1230），第 1 是 35B 的 Fish Audio Drama 3（1248），本机跑不了；
  - 用户试听认为情感表达到位；
  - 控制方式：一条自然语言指令（Voice Direction）控制语气、节奏和情绪，加内嵌事件标签，例如 `(laugh)`、`(sigh)`、`[笑]`、`[叹气]`；
  - 3B，中英两种语言；社区 8 GB 版在 Windows 上峰值约 7.2 GiB；
  - 许可：权重、衍生模型与本机生成的音频仅限研究和非商用；商用需向 Resonia 申请书面授权。
- **显存（估算，未实测）：** Breeze 峰值约 7.2 GiB，加上常驻大脑（即使用 4-bit 也约 3 GB）、Windows 桌面和渲染，超出 10 GB。大脑需要常驻，不能在说话时才加载 Breeze。
- **GPT-SoVITS V5（2026-10-05 发布）：**
  - 330M + 77M 参数，推理速度约为 v2 的 4 倍；
  - 用户转述的第三方评测说显存约 3.5 GB，官方没有给数字，待实测；
  - 支持中、英、日、韩、粤；
  - 作者自测中文零样本音色相似度 0.78–0.81，高于真人原声的 0.755；1 分钟素材即可微调；
  - 代码与预训练模型都是 MIT 许可；有 Windows 一键包；
  - 有语速参数，没有音高参数；
  - 情绪只能靠参考音频表达，没有指令和标签，也不能生成笑声；
  - v3 以后不支持流式，整句生成完才返回。

## 决定

1. **目标声音：Breeze TTS 2。** 用户接受它的非商用许可。在升级显卡或给她配专用电脑后启用。
2. **过渡声音：GPT-SoVITS V5**（v5turbo，零样本）。当前重点在 Echo Core，声音排第二，过渡期使用它。用户 2026-10-25 先选了 Ming-3.0-tts 0.5B，同日改为 GPT-SoVITS V5。
3. **接口按目标模型的控制方式设计（建议）：** 语音的风格输入是「一条自然语言指令 + 内嵌事件标签」。情绪进入声音的两条路线都落在这两种控制上，测试后再定：
   - 路线 A：模型在 m 下写标记；
   - 路线 B：由快状态 x 映射成指令。

   每个模型各写一个适配层，换模型只换适配层。过渡期的 GPT-SoVITS 适配层把指令落实为「选一段参考音频 + 语速」，标签不生效。现有的 `TtsProvider.style` 和表演提示词表要修改，另开契约卡，不在本 ADR 里改契约。
4. **语言：** TTS 选型不再要求覆盖中英日三种（用户决定）。Breeze 只有中文和英文。

   这条与 ARCHITECTURE 的两处冲突：原则 4「三种语言……同一个声音，同一个人」，以及完成标准第 10、11 条里的日语语音。建议改为：**识别和文字仍是三种语言；说话的语言随目标声音（Breeze：中、英）**。待用户确认后，在本 PR 一并修改 ARCHITECTURE。
5. **她的音色（建议）：** 最终音色在 Breeze 上克隆和挑选。P4-03「选声音」等目标模型可用后再做；过渡期的音色不定稿。
6. **依赖登记：** Breeze 是非宽松许可的运行时依赖，按 AGENTS.md 第 6 节，由本 ADR 记录用户批准：
   - 权重不进仓库，也不随 Nemu 分发，由使用者自行下载并接受其许可；
   - 公开发布或商用 Nemu 时，需要另选宽松许可的默认声音（GPT-SoVITS 是 MIT，可作候选），或取得 Resonia 的书面授权。

## 备选方案

| 方案 | 不选的原因 |
| --- | --- |
| Qwen3-TTS 0.6B（现用） | 不支持指令控制；竞技场 930 |
| Qwen3-TTS 1.7B | 实测 9.21 GB，和大脑放不下 |
| Ming-3.0-tts 0.5B 作过渡 | 竞技场 1191，有情绪标签和笑声等标签，MIT；但官方只在数据中心卡上测过，没说明流式和显存；据评测，情绪控制和克隆音色不能在同一次调用中组合；在 Windows 上部署较粗糙。用户改选 GPT-SoVITS V5 |
| CosyVoice 3 0.5B 作过渡 | 能在同一次调用里克隆音色并用指令控制情绪，但没上竞技场 |
| Fish Audio Drama 3 / S2 Pro | 35B MoE / 5B 且为研究许可，本机跑不了或不合适 |
| 现在就用 Breeze | 和常驻大脑放不下 |

## 后果

- **P4-02（PR #45）恢复时：**
  - 改为 GPT-SoVITS V5 适配；旁路服务的取消、健康检查代码保留；
  - 显存和首个声音的延迟在 3080 上重测。
- **显存：** 用现在的 transformers NF4 载体时，大脑实测约 6.1 GB，加上 GPT-SoVITS 约 3.5 GB，已接近 10 GB。换用 llama.cpp 载体（P0-10）后会宽裕。
- **首个声音的延迟：** GPT-SoVITS 不支持流式，延迟等于第一句的合成时间，大概率达不到 P4-02 原定的 250 ms 首包，需要重测后另定目标，ARCHITECTURE 第 5 节延迟预算里 TTS 一项也随之重估；ADR 0017 的说完判定和打断目标不受影响。按句切分要尽量让第一句短。
- **情绪：** 过渡期的情绪靠一组参考音频，需要准备「她」在各种情绪下的参考录音，没有笑声。这对 Echo Core 的开发没有影响。
- **ARCHITECTURE：** 本 PR 已把 `voice-sidecar` 和「合成」两处改为指向本 ADR；原则 4 与完成标准第 10、11 条等第 4 条确认后再改。
