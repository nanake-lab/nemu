# ADR 0039：Echo Core 核心原则与前提

- **状态：提议（PROPOSED）。** 合并 [PR #174](https://github.com/nanake-lab/nemu/pull/174) 即视为用户批准（用户 2026-11-12 指示）。
- 日期：2026-11-12（Australia/Perth）。任务：PRINCIPLES-01。
- 依据：[PRINCIPLES-01 报告](../../reports/PRINCIPLES-01/REPORT.md)；用户 2026-11-12 对 #174 的三次决定（U1 写成前提、U4 写成原则、前提与 P5 关系的读法）。
- 编号：0036 由 #164 占用，0037 已在 main，0038 由 #171 占用，本 ADR 取 0039；差异登记取 V2-160（V2-151 由 #164 占用，V2-156–159 由 #171 占用）。
- 范围：只记录原则。不改规格原文、其他 ADR、契约、代码或任何现行规律。

## 1. 背景

Echo Core 的规则分散在 v2.0 规格、三十多份 ADR 和差异登记里。用户关心设计是否在打补丁、复杂度是否过度。PRINCIPLES-01 把现行规则压成一页原则，再逐条检查规则能否挂到原则上：143 条里 140 条挂得上，3 条挂不上。

这些原则此前散见各处，没有一份文档把它们放在一起。其中两条（下面的前提和 P10）此前没有写成原则，只作为理由出现在手记、技能文件和个别 ADR 的决定里。

## 2. 决定

### 2.1 总纲

**她是谁，只能由她真实的经历按公平的规律长出来。**

下面每条原则各堵住一个口子：一个别人、别的东西能替她决定「她是谁」的口子。

### 2.2 前提

**四个「乎」是学习得以开始的最小给定，就像人的基本驱动；她后来的在意和感受，都在它们之上从经历里长出来。**

- 出处：用户 2026-11-12 决定；[v2.0][V] §3；[ADR 0025][A25] §2 对感官说过同样的话（「无法不做，人的感官同样不是自己选的」）。
- 增减「乎」的个数不是不可逆的：H 仍在，可以发布新的规律版本，按 EV5 追加补评后重算。但代价大，轻易不加。（用户 2026-11-12 说明。）

### 2.3 十条原则

| | 原则 | 它堵住的口子 | 出处 |
| --- | --- | --- | --- |
| **P1** | **真实。**她只有一次人生。发生过的事原样记下，不改、不删、不编；不知道的就记成不知道。 | 记录可以事后改写、可以假装知道 | [v2.0][V]「她是谁」第 8 条、§0 第 3 条、§10；[ADR 0025][A25] §3 第 1 条；[ADR 0014][A14] §3；[ADR 0028][A28] D4 |
| **P2** | **长出来，不是写出来。**我们只写「怎样从经历里学」，不写她是什么样。同一套规律读同一段过去，得到同一个她；谁都不能按喜好直接改，包括用户。 | 设计者或用户直接写她的性格、挑她的反应 | [v2.0][V] §0 第 1 条、§2.2、§2.3、§9.6、「她是谁」第 2、8 条；[ADR 0025][A25] §2 |
| **P3** | **只有真的发生在她身上的事能改变她。**时间流逝不能，她自己的念头不能，别人说一句话也不能。 | 靠等、靠想、靠说，就让她变了 | [v2.0][V] LP5、EV3、§11；[差异登记][D] COG-06；[ADR 0032][A32] §6 |
| **P4** | **记账公平。**一件事只算一次；支持和反对用同一把尺；怎么记不看她此刻的心情。 | 规律本身偏向某个结论 | [v2.0][V] §0 第 1 条、EV2、EV5、EV6、LP8；[ADR 0019][A19] §2 |
| **P5** | **预设是起点。**可以为了她可爱、为了用户的需要给她起点，但每一条她都得改得掉；改不掉算缺陷。 | 初始设定变成永久结果 | [ADR 0032][A32] §1；[手记][J]「关键决定与来由」 |
| **P6** | **先问一个人会怎样；她和人不同的地方照实对待。**只在这种不同会伤到别人或她自己时另加规则。机器该有的能力（比如记得精确）不假装没有。 | 凭空加规则，或者硬把她做成人 | [v2.0][V] §0 第 2 条；[ADR 0025][A25] §3 第 1 条 |
| **P7** | **用户的边界是固定的，但只管她能做什么，不管她是谁。**权限、隐私、预算、兜底归用户。她亲近用户但不服从；别人对她没有权力。 | 用户的权限变成对她性格的控制；外人获得权限 | [v2.0][V] §0 第 3 条、§10、§11；[ADR 0032][A32] §1；[ADR 0028][A28] §1 |
| **P8** | **保险防我们的错，不防她的生活。**出问题时提醒开发方，不刹住她，不把她拉回我们喜欢的样子。 | 借「安全」之名规定她的生活结果 | [ARCHITECTURE][AR] §3 原则 8；[差异登记][D] V2-97；[ADR 0032][A32] §1 |
| **P9** | **核心是她，模型是脑力和嘴。**她的历史和状态只有核心能写，模型、终端、worker 只能提议。她的状态用非文字的方式影响模型；换模型不换人。 | 模型、终端或缓存里藏着另一个「她」 | [ADR 0002][A02] 决策 1；[v2.0][V]「她是谁」第 5 条、§9.5；[AGENTS][AG] 黄金规则 3、4 |
| **P10** | **拿不准时偏向不算证据。**宁可学不到，不要学错。 | 判断员的误判被当成她的经历 | 用户 2026-11-12 决定；[手记][J]；[ADR 0033][A33] §4；[ADR 0014][A14] §3 |

### 2.4 前提与 P5 的关系

P5 管的是前提之上的预设：那些要能被她的经历改掉，改不掉算缺陷。前提本身不由经历改，由新的规律版本改（见 2.2）。所以四个「乎」的结构固定，不算 P5 意义上的缺陷。（用户 2026-11-12 确认此读法。）

### 2.5 P10 的放宽条件与用户评价

- **放宽条件：**判断员经用户批准的标准验证变准以后，这个偏向可以逐步放宽。放宽的标准和步子由用户批准，不由执行者自定。
- **用户评价（2026-11-12）：**这条目前不尽如人意，但现阶段是对的。

### 2.6 已知例外

以下 3 条现行规则挂不上任何一条原则。本 ADR 只把它们列为已知例外，不处理。分析见 [报告][R] 第 3 节。

| 例外 | 在哪 | 为什么挂不上 |
| --- | --- | --- |
| 模式 B：云端文字投影 | [ADR 0003][A03]；[v2.0][V] §9.7；I15 | P2、P9 说她的状态不写进提示词，模式 B 正是把状态写进提示词。它是明写的、被圈住的例外；圈它的理由（没有够用显卡的人也能用）不在原则里。 |
| π > ½ 才成为性格 | [v2.0][V] §7、I06；[ADR 0014][A14] §1 | 「没有证据就不起作用」能从 P3 推出，「在一半处有一道门」推不出。是建模选择。 |
| σ₀、τ₀ 的出生先验份额不变 | [ADR 0035][A35] §3.3、§6 | 按 P5 是改不掉的预设；原文已写明延期，是 P5 的欠账。 |

### 2.7 怎么用

- 本 ADR 不改任何现行规则。规格、ADR、差异登记里的条文照旧有效；条文与本 ADR 的白话表述有出入时，以条文为准。
- 以后新增或修改规则时，用它检查是否在打补丁：新规则说得出挂在哪条原则上，就是原则的展开；说不出，就是例外或漏了原则，要在 ADR 或差异登记里写明是哪一种，交用户决定。
- 原则本身的增删改，另写 ADR。

## 3. 备选方案

- **只留在报告里，不写 ADR。**报告随时可以改写，不适合承载用户批准过的原则；AGENTS 第 6 节也要求报告里留给用户决定的事项在合并前登记。
- **写进 v2.0 规格 §0。**需要改规格原文；用户本次指示不改规格。以后要不要并入规格，由用户另行决定。
- **原则的其他切法**（三条、一条公式、按状态切）：见 [报告][R] 第 1 节，均未采用。

## 4. 后果

- 原则有了一处固定的出处，设计卡和审查可以引用 P 编号。
- 3 条已知例外被明确记录；以后处理它们时有据可查。
- 挂靠检查是一次性的：143 条的归类在报告里，覆盖范围有限（差异登记只查了 10 个编号），本 ADR 不保证未检查的规则都挂得上。
- P10 带着放宽条件，判断员验证达标后需要回来改这一条的适用范围。
