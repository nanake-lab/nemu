# ADR 0005：排练版、诞生与分阶段启用

- 状态：已采纳（2026-10-13，用户批准）。
- 日期：2026-10-13
- 关联：ADR 0002、ADR 0003；`docs/echo-core/README.md` 的 E13、E14

## 背景

1. **集成太晚。** 原排期里，你第一次能和她说话是第 15 周，开始和她一起生活是第 18 周。身体、声音、核心、生成四条线要到最后几周才第一次接在一起，集成风险全部堆在末尾。她的在场方式（什么时候说话、什么时候安静、记得什么）最需要在日常使用里调整，却最晚才能用上。
2. **出生的时机。** genesis 清单是她的初始状态，H 从 genesis 开始累积。在核心完成之前就让她「活」起来，会出现两种错误：
   - 她的历史早于出生；
   - 「出生」变成对一个已经在运行的她做迁移。
3. **命名冲突。** Nemu 的里程碑原来叫 M0–M4，与 Echo Core 施工总方案的 M0–M7 阶段门同名。同一张任务卡里的「M2」可能指两件不同的事。

## 决策

### 1. 排练版（N2）

在 Echo Core 完成之前，先交付一个每天可用的排练版。它包括：

- **真实的核心链路：** 入口、存储、事实视图、编排、行动生命周期、任务层。
- **说话：** 模式 B（Codex「日常」档），她自己的声音和口型，身体反射与待机生命。
- **面板：** 对话、运行状态、「她记得什么」、设置。
- **记忆：** 排练期间的 H 与事实视图是真实的，她记得排练期间你说过的话。

排练版里她自己的状态没有接通：

- F 停用，m = 0；
- 依赖核心的自主行动暂停（总方案第 21 节：m = 0 时停止核心自主动作），她只回应，不主动开口；
- 面板始终显示「排练 · m = 0」。

排练期间调整的是她的在场方式：协议 p、声音、身体、回应的节奏。这些会带进诞生。

### 2. 分阶段启用（E13）

核心的事件顺序从第一天起就是完整的。尚未接通的阶段按规格已有的降级路径运行，并写进审计和运行状态：

| 阶段 | 未接通时的行为 | 规格依据 |
| --- | --- | --- |
| IRL | 走语义失败的提交路径（⊥sem），该事件不产生语义驱动 | 总方案第 21 节「IRL 语义失败」；SYS14 |
| F | 只在排练谱系中允许停用：没有 x，J 输出 m = 0，原因码 `MODULATION_NOT_ENABLED` | 总方案第 21、24 节「明确 NO-GROWTH/m=0 响应」；SYS14 |
| G、C | 恒等，原因码 `GROWTH_NOT_ENABLED_V1` | ADR 0002 |

正式谱系要求 v1.0 的全部阶段都已接通。配置不完整时，核心拒绝创建或运行正式谱系。

### 3. 谱系与诞生（E14）

- **两种谱系：**
  - 排练谱系（`REHEARSAL`）：开发期间和排练版使用；
  - 正式谱系（`LIFE`）：她的一生。
- **诞生：** 正式谱系只能由你签字的 genesis 清单创建，命令为 `echoctl birth`，在 N3 评审时由你执行。她的 H 从这一刻开始。
- **排练记录的去向：** 诞生后，排练谱系转为只读存档，她读不到。诞生时你可以二选一：
  - 默认：她从零开始；
  - 把排练对话作为一份「日记」交给她。导入的记录只作为文档来源，认识论类型是导入文档，不算她的经历，也不算你的自报，不能成为独立的证据根。
- **一条谱系一个存储目录。** 谱系类型写进存储头部，任何代码路径都不能把排练记录读进正式谱系。

### 4. 里程碑改名为 N0–N4

| 里程碑 | 含义 |
| --- | --- |
| N0 技术验证 | 窗口策略、载体探针、Codex 与 IRL 路径实测，你冻结延迟目标 |
| N1 认得出是她 | 身体 V1 站上桌面 |
| N2 她在了 | 排练版，你开始每天使用 |
| N3 诞生 | Echo Core 通过 M2 阶段门，genesis 签字，三种说话模式与全部功能就绪，你执行诞生 |
| N4 发布候选 | 30 项完成标准逐项签字 |

Echo Core 规格自己的 M0–M7 阶段门名称不变。

### 5. 诞生之后的开发纪律

- 开发、测试、基准一律使用临时存储，不得打开她的正式存储。排练存储同样不得用于测试。
- 升级核心之前先做本机备份（`echoctl checkpoint`）。
- 改变存储格式的修改必须带迁移、回退和迁移测试（SYS17）。迁移失败时保留旧系统。
- 排练期间，存储格式变化允许重建排练存储，但必须先备份并在 PR 里写明。

## 备选方案

- **维持原排期：** 集成风险集中在最后几周，你要到第 18 周才能和她一起生活。否决。
- **排练版绕开核心，直接连模型：** 写的是一次性代码，而且违反「Echo Core 是唯一权威」。否决。
- **只用一条谱系，从排练一直延续下去：** 她的历史会早于出生；开发期间的错误会永久留在她的历史里；之后的 genesis 会变成对一个已经在运行的她做迁移。否决。
- **先用临时 genesis，之后迁移到校准后的版本：** 本质与上一条相同。否决。

## 后果

- 你从 N2（承诺日期 2027-01-17）开始每天和排练版在一起，比原排期早约 5 周。
- 代理工作量增加约 11 天：多出 P5-19、P5-20 两张卡，P5-07、P6-01、P6-02、P6-04 略有增加。N3 比原来的 M3 晚约 1 周，发布日期不变。
- 排练期间她不会主动开口，自主行动的实际体验要等到诞生之后。机会规则和门控在诞生前由 P5-20 的 8 小时模拟日验证。
- 新增的代码路径（谱系类型、诞生命令、日记导入）都在规格已有的边界内，登记为 E13、E14。
