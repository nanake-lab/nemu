# ADR 0029：θ 估计器递推状态的后继存储契约

- 日期：2026-10-27
- 状态：2026-10-28 用户批准三路径最小扩围和完整状态内嵌方案，已实施；存储消费者冲突 B3 阻塞完整验收，待交叉审查及用户最终合并
- 任务：P5-36；草稿 PR #108
- 核对基线：`3f8f98e5ac3cba2f2b4718ca242a5a0c226d0fbf`
- 依据：ADR 0007、ADR 0019 §8、V2-94 至 V2-98、V2-100、V2-103，以及 `reports/P5-25/METHODS.md`

## 背景

`ThetaSnapshot.estimator_state` 是未定格式的 `ObjectRef`。P5-25 已合入纯函数实现，但其 `DynamicsState` 和 `RunningTime` 仍为内存结构。只保存 θ、σ̂、τ̂、总权重和 ĥθ，不能恢复下一次递推所需的全部信息。状态也不能藏在手写 JSON、Debug 文本或额外进程缓存中。

2026-10-28 更新：main `32a5888e` 已包含 PR #95、#65，二者不再构成目录阻塞；#110（`4c8dd453`）仍开放并占用契约目录，本轮继续只做恢复准备。P5-36 尚未修改 IDL、生成器、语义检查、向量或基线。本提案记录字段需求与实现约束。消息名称、类型标签及字段号待目录释放后依 ADR 0007 分配；不把此提案当成可读取旧资源的格式定义。

## 决策提案

### 1. 保存实际递推状态

来源为 `core/crates/core-kernel/src/dynamics/types.rs:109` 的全部字段，以及 `time.rs:14`。四通道采用既有 Nature 顺序；慢漂顺序采用现有 `components` 的 b₄、g₄、λ₄。序列长度与顺序必须由契约固定。

| 内存字段 | 必须保存的内容和原因 |
| --- | --- |
| `law` | 完整 θ 规律参数和其版本绑定；更换先验、检测参数或运算资源会改变下一次结果 |
| `values` | 当前 b、g、λ 各四个有限 binary64；下一次计算与比较实际使用这些值 |
| `weight` | 外源事件的共同加权质量；当前实现四通道共用一个质量，不能另造四条独立递推 |
| `reaction_sum[4]` | 反应加权和；只保存 b 无法逆推出原始舍入后的和 |
| `square_sum[4]` | 以当次更新前 b 为参考的残差平方加权和；不能替换为对更新后 b 重算 |
| `sigma[4]`、`variance[4]` | σ̂ 与实际保存的方差；不能以 σ̂² 恢复方差并假定逐位相同 |
| `duration_log_sum[4]`、`duration_mass[4]` | 已结束的正时长段之 log 秒数加权和与质量；log 和可以为负，不能套非负质量检查 |
| `duration_log_mean[4]`、`tau[4]` | 已保存的含先验对数平均与 exp 结果；不能在读取时用代数等价式重算 |
| `zero_duration_count[4]` | 零时长段独立计数；不能加 ε 后混入对数平均 |
| `runs[4].sign/start_ns` | 未结束段的符号及运行时间域起点；零符号表示无开放段，右删失段不计入已结束统计 |
| `detector.segment_count/changes` | 当前段事件数和联合变点数；四通道同时越界只算一次联合变点 |
| `detector.mean/positive/negative[4]` | 检测均值与正、负累积量；仅保存变点数无法继续 CUSUM |
| `event_count`、`h` | 外源学习事件数与当前 ĥθ；不能用全部 H 事件数代替外源计数 |
| `last_event` | 显式有无，以及 ordinal、event time、ID；用于后继事件顺序和身份检查，ordinal 不等于学习事件数 |
| `last_running_time` | 显式有无，以及 origin、event、累计 stopped、累计 running 四个整数纳秒值；支持跨事件停机和时间一致性检查 |
| `drift_sign[12]`、`drift_count[12]` | 每个 θ 分量的连续变化方向与次数；恢复后不能重新从零开始计算慢漂 |

初始状态也必须完整编码。特别是 genesis 的 τ 使用现有 `exp((nτ × log(τ₀))/nτ)` 次序，不能直接写 τ₀ 的位值。相同原因适用于方差、σ̂、g、λ 与各个已保存的中间量。

### 2. 规律与参数绑定

新增明确版本化的 θ 参数消息，覆盖 `DynamicsLaw` 的全部字段：版本、b₀/g₀/σ₀/τ₀ 四通道先验，baseline/variance/duration 三种先验质量，change prior、prior weight、minimum，g 与 λ 的上下限，以及 detector shift sigma、threshold。旧 `LawParameters` 没有完整表达 duration weight 和 CUSUM 参数，不能只对旧消息求摘要就声称绑定了完整参数。

快照绑定规律资源引用及 θ 参数消息的规范摘要。摘要使用既有规范编码和 SHA-256 规则，不使用 Protobuf 传输字节、Rust Debug 或 JSON 文本。解码检查参数内容与声明摘要；实际恢复还需调用方提供已解析、验证的规律资源，核对版本与引用。一个自洽的摘要不能证明来源可信，也不能证明事件属于合法 H 前缀。

`DynamicsFuses` 的 jump notice、drift run、drift margin 是 V2-100 所述随规律绑定的校准资源视图；它不在 `DynamicsState` 内，但恢复后继续调用 C 必须使用同一已绑定资源。不得将旧的用户可调 fuse 含义移入后继契约。校准数值仍由实验谱系提供，本卡不填写或重新校准。

### 3. 只增不改及语义检查

新增携带上述完整状态的 θ 后继快照与所需子消息。旧消息定义、字段号、枚举值、类型标签和已冻结字节保留；新消息实现后再将旧消息标为被取代。是否嵌入或以有明确目标类型的引用保存状态，须在最终 IDL 中唯一确定并由规范编码向量固定，不能继续保留任意私有载荷。

`core-types/src/semantic.rs` 及 Python、TypeScript 的对应检查必须一致覆盖：

1. 所有浮点值有限，沿用既有零规范化；质量及计数非负，σ̂、方差、τ 和适用的先验严格为正。对数加权和、对数平均、均值等有符号量不错误地限制为非负。
2. 固定四通道与十二分量布局；符号仅为 −1、0、1；联合变点数、段计数、零时长计数和慢漂计数不大于外源事件数。计数仍服从当前数值实现的精确整数边界。
3. 初始状态和有事件状态的标记一致；事件 ID/ordinal/time 的合法性、末次事件与运行时间的 event time 一致。使用检查整数运算验证 `event − origin = stopped + running`，开放段起点不超过末次运行时间。后继连续性还须结合旧状态检查，单条消息不能证明整段 H 合法。
4. 规律版本、完整参数和摘要一致；资源解析失败、未知格式或不一致不得恢复成可运行状态。不能给缺失统计量补零、用旧快照猜测状态，或在解码时裁剪数值。

具体可达性约束应由 P5-25 真实状态轨迹核对后写入校验，不能为简化 schema 排除合法状态。浮点运算产生的存量位值作为状态保存；恢复检查不得以重新计算后替换的方式“修正”。

### 4. 与持续时间、数值界和报警的关系

- V2-95：沿用运行时间、排除停机、正时长的对数平均、零时长单计和未结束段右删失；固定现有 libm 0.2.16 和运算次序。本提案不扩张当前精确纳秒转换时间域。
- V2-96：计算故障界由同一规律与状态推导，严格大于界才拒绝。`StepBounds` 是本次计算的派生结果，不作为新的可调阈值或隐藏递推状态。
- V2-97：Jump/SlowDrift 照常应用并报警；计算故障拒绝整个候选并保留旧状态。慢漂累积量进入快照；报警、通知和复核记录仍由后继外层事务按规律与 H 前缀绑定后进入 H/L，本卡不接管运行时发布。
- 无新外源学习事件时状态不更新。自身行动、程序回执、自我叙事和诱骗反馈等被排除来源不能因序列化/恢复而进入学习计数。

### 5. 恢复与验收

需要 P5-25 所属模块提供受验证的完整导出/恢复接口，见 `tasks/requests/P5-36-dynamics-roundtrip.md`。不开放任意可变字段，也不让 core-types 生产依赖 core-kernel。

2026-10-28 接口核对：现有 `pub(super)` 已允许 dynamics 同级模块访问全部字段。最小扩围仅为新增 `dynamics/storage.rs`、`dynamics/storage/tests.rs` 和修改 `dynamics/mod.rs` 注册/重导出；无需修改 types/time 的可见性或 C 的递推接口。请求文件的新增章节列出独立逐字段位比较与真实恢复续算方案，待主会话裁定，本轮不实施。

至少以 genesis、含正/零时长与停机的轨迹、含变点与慢漂的轨迹验证真实内存状态 → 规范消息 → 三语言字节/语义检查 → 真实内存状态，逐一比较全部浮点 `to_bits`、整数、标记和字符串。在多个中间前缀恢复后继续同一后缀，必须与不中断执行一致。错误资源、计数、时间、质量及未知标签分别构成负例；每种新消息至少三合法、三非法，不以总案例数替代逐消息覆盖。

旧资源没有完整状态格式，不能声明自动无损迁移。仅在已识别旧格式、具备完整源数据和明确映射时单独验证迁移；否则保持旧读取能力，并按既定规律从 H 重算的后继流程处理。不得默认初始化缺失字段后继续正式状态。

## 备选方案

1. 只存 θ、σ̂、τ̂ 与一个不透明引用：不能证明完整恢复，拒绝。
2. 读取时根据少量统计量重算中间量：可能改变舍入与下一次结果，不能满足本卡逐位往返，拒绝。
3. 完整显式状态及版本资源绑定：采用本提案；代价是消息、语义校验和跨语言向量更多，需与 P5-25 接口协作。

## 后果和未完成项

本提案不改变任何运行行为。ADR 批准、V2-107 至 V2-109 的正式条目、精确 IDL 分配、语义实现、逐消息向量、正式基线冻结和真实往返均未完成。编号截至本次主线与开放 PR 核对仍为本卡预留；实施和合并前再次核对。实现目录释放和恢复接口是独立阻塞，不能由本提案或旧基线测试替代。

## 2026-10-28 实施定案（取代前文准备阶段状态）

用户已批准三个 core-kernel 路径的最小扩围，指定采用后继 θ 快照内嵌完整估计器状态，要求验证真实逐位恢复和续算，并明确排除迁移及运行时接线。本分支合入 #110 / main `f24f1256259c998bc213a9dc93103fcfb9cfe89a`；#95/#65/#110 的旧占用和桥接范围阻塞均已解除。

- 新 `theta.proto` 唯一定义五个消息：`ThetaEstimatorParameters`、`ThetaRunningTime`、`ThetaLastEvent`、`ThetaEstimatorState`、`ThetaSnapshotV2`；类型标签分别为 `echo.theta-estimator-parameters`、`echo.theta-running-time`、`echo.theta-last-event`、`echo.theta-estimator-state`、`echo.theta-snapshot-v2`。字段号以该 IDL 为准。V2 保留旧 1–4 字段，保留不用 5–9，新参数/摘要/状态使用 10–12；旧定义和旧黄金字节未改变。
- 选择**内嵌**完整参数及估计器，不再保留“可选任意引用”方案。参数涵盖全部 DynamicsLaw 和 DynamicsFuses 字段，`numerics_id` 固定为现行 `P5-25-v2-93-98-libm-0.2.16`。参数摘要是既有 CanonicalV1 类型域分离 SHA-256；不以传输字节或 JSON 求摘要。
- `export_snapshot(state, revision, law_version, fuses)` 只复制已保存位值；`restore_snapshot(snapshot, expected_law_ref, law, fuses)` 校验后构造全新 DynamicsState。恢复核对完整 ObjectRef 和独立传入 law/fuses 的规范参数字节，不从原状态/H 回填，不重算 variance、sigma、log mean、tau 等中间量。不增加运行时依赖。
- Rust `semantic::check_theta_message` / `check_theta_snapshot_v2`、Python `echo.theta.check_theta_message`、TypeScript `echo/theta.checkThetaMessage` 是**显式语义边界**。通用 WireMessage/runtime 解码只保证结构与基础字段规则；消费估计器前必须调用语义边界。kernel 导出/恢复与三个测试探针均调用它。资源认证、H 前缀完整性和实际停机来源仍由调用方负责，消息自洽或摘要匹配不等于可信。
- 合法真实状态含零规范化后的有限 binary64；符号整型经语义检查限定 −1/0/1。质量非负，方差/σ/τ 正，计数小于 2^53 且不超过学习事件数；ordinal/time 保留完整 u64，不能当 binary64。解码不修补、裁剪或初始化缺失状态。
- `baselines/p5-35` 冻结合入 #110 后、实施本卡前的八个 proto 和黄金摘要；当前所有既有基线 0 违例。新增黄金 15 合法、69 非法，五种消息各有 3 合法、至少 3 非法。部分合法源夹具直接取真实 C 的前缀 0/17/64；声明合成来源，不代表个体校准。
- 真实 C 的 65 个前缀分别经两种编码回到 Rust，并经 Python/TypeScript 解码复编码形成 260 份返回字节；恢复后比较所有内存字段的 `to_bits`/整数/标记/字符串，逐事件比较同一后缀、ThetaChange、signals、StepBounds。额外验证报警边界、超过 2^53 的 ordinal 和合法次正规基线值。该交换验收接入 `pnpm test:core-contracts`，普通 kernel 测试始终执行独立真实状态对照，不依赖外部文件才做断言。

**新发现 B3：** `ThetaSnapshot::SUPERSEDED` 使 core-store 的既有新写门禁拒绝旧类型，但 `transaction.rs` 仍只消费旧 θ。完整工作区测试因此失败，fact-view 的存储夹具也受影响。不得通过取消标记、例外放行旧写入或修改断言来消除失败。修复需要明确的后继存储接线，超过本轮边界；见 `reports/P5-36/BLOCKED.md`。本 ADR 不授权迁移、权威存储格式变更或运行时发布，也不声明 P5-36 已全部验收。

## 2026-10-28 B3 存储消费者扩围（用户批准）

用户明确批准 core-store 的 θ 对象写入、暂存/当前头、版本识别及直接受影响的 core-store/fact-view 夹具；核对其他开放 PR 的实际路径后没有目录冲突。原 B3 的“未授权存储适配”判断失效，本轮直接实施。它不改变 C、不扩大到历史重放、自动迁移或完整运行时编排。

- 新对象写入和对象读取调用既有完整 θ 语义校验；事务暂存/当前头绑定使用 V2。保留 `SUPERSEDED` 门禁，不设置旧类型例外。以生成 schema 的类型标签分派旧/新快照，未知 θ 类型拒绝。
- 旧 θ 仅按旧解码器读取原字节。缺失估计器状态不补零、不猜造、不自动转换。持有 writer lock 时先以只读 SQLite 连接检查头；旧 θ 明确返回“explicit complete-estimator migration is required”，在打开可写连接之前拒绝，避免关闭连接隐式 checkpoint 改动旧 WAL。既有 R V2 拒写仍有效。
- 对象 prepare、暂存能力、最终提交和 SQL 事务边界不变；语义失败不发布状态指针/账本/索引。存储重开仍验证既有引用闭包和提交清单；新增 θ 类型检查不是执行历史重放。SQLite 物理格式号与迁移实现没有改动。
- 验证复用既有真实 C 轨迹、私有字段位比较和故障注入点：把 65 个导出前缀送进临时存储提交，关闭重开后读取，交回原 kernel 断言验证全部位值与同一剩余事件。合成 law 对象只提供持久引用闭包；独立传入的测试 law/fuses 由原 kernel 轨迹核对，不声称已实现生产资源解析器或 H 来源认证。
- 后继仍需单独设计缺少完整状态的旧历史迁移/恢复来源、P5-26 全 H 重算、P5-29 运行时资源认证及事务编排。旧头目前明确不可写；本卡不签发 SYS17 或整系统接续验收。当前实测与完成状态以 `reports/P5-36/REPORT.md` 和保留的原始证据为准。

## 2026-10-28 首次审查修复：贯通调用方资源上限

审查在共同 4 MiB 配置下发现 Rust 语义入口仍额外使用固定 1 MiB 上限，拒绝了其他两语言接受的合法 θ。修复移除该内部常量；Rust `check_theta_message`、`check_theta_snapshot_v2`、`theta_parameters_digest` 与 kernel `export_snapshot`/`restore_snapshot` 均显式接收调用方 `Limits`，存储传入 `StoreConfig.encoding`。结构校验、参数摘要和可信上下文规范字节比较使用同一配置，没有新增字段上限、改变 IDL/数值/成长语义或绕过语义验证。宽配置的接受与窄配置的拒绝都进入回归，见 `reports/P5-36/review-fix/`。
