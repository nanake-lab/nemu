# ADR 0051　IRL 命名管道上的调用、来源与采纳

交付线 P5-49，提议，待交叉审查与用户批准。过渡期由用户指定的 DeepSeek 可以为 IRL 产生候选。核心需要分别回答三个问题：这次允许读取什么，谁实际上给出了哪些字节，以及这次事务采纳了哪一份解释。

## 背景

P5-07 已能在进程内保存输出及解析结果。其模型侧原始 wire schema 使用一次调用内的来源别名。P5-43 已有正式原文定位、概念版本及阶段采纳类型。还缺少跨进程传送材料、关联实际生产者和返回结果的合同。[P5-07 基础层](../../workers/irl/README.md) · [ADR 0048](0048-formal-semantic-boundaries.md)

## 本机三段管道

| 谁调用谁 | 发送者获准提出的操作 | 接收方用什么核对 |
| --- | --- | --- |
| 核心 → IRL worker | 派发一次解释，提供只读材料，取消该次调用。worker 可请求清单内对象并交回候选或失败 | 双方将协议版本、请求标识、连接会话及对端角色与受信宿主的本次启动记录核对。核心私有地关联完整的 `ProposalBindingV2` |
| worker → bridge | 为同一解释请求取得获准的外部候选，转送已获披露许可的内容 | bridge 核对本次委派的生产者、允许披露的材料、用途与授权版本。对端没有获准或发送前授权已失效，记录未发送 |
| worker → 本地 model-adapter | 在指定的模型、解码资源和 m = 0 条件下请求实际输出 | adapter 核对调用、资源版本，记录本次实际执行的模型和隔离事实。结果经 worker 回到核心 |

三个连接均使用仅本机可达的 Windows 命名管道。宿主按启动实例设置 ACL，将对端的操作系统身份与本次授予的角色绑定；同账户下的其他进程同样需要本次启动凭据。两端认证完成后才传材料。消息体里的角色、用户 ID、供应商字符串及管道名都不能证明身份。ADR 0047 的本机用户绑定和执行凭证各有专用作用域，继续由其签发方验证；IRL 调用没有行动、管理或终端上传权限。[ADR 0047](0047-permission-contracts.md)

每次调用以本次会话和请求标识关联，返回和取消均须匹配原调用与方向。版本化 IDL 限定每一方向可用的消息。接收方在分配载荷前检查帧长度，按本次设置检查累计对象和输出字节。人定的容量和消息大小上限均取可调整设置，记录生效版本。尺寸超限与结果截断分别记录；只有实际收到的前缀可以留作不完整的输出。等待理解没有截止时长。

## 哪些字节可以读取

核心按事务借出目标事件的原始载荷、获准的 `FactProjection` 和所需的注册表视图。每个可取对象都有本次调用的读取许可和 `ObjectRef`。对象应能按该许可取回实际字节，接收端按声明类型、资源版本、规范摘要及长度核验。服务端在取件时复核调用、用途、读集和可见前沿。事务内暂存材料只在被借出的范围可读；提交后按同分支前缀解析。模型输入只投影本次获准字段；核心内部用于检查陈旧结果的状态绑定不随投影交给云端。源于本地读集的材料还须逐项满足外发授权。[对象引用](../../core/contracts/base.proto) · [状态与事实视图](../../core/contracts/state.proto)

worker 在单次调用内把原 wire 别名还原到固定原件。模型照抄的片段由程序在绑定字段的原始 UTF-8 字节中定位。唯一匹配才可直接取位；重句需要能唯一定位的已有来源依据，缺失或歧义保留为未解。采用 P5-43 的 `SourceLocation`、`SourceField`、`RecordVersion`、`Utf8Range`。核心复核原文、字段路径及字符边界。谓词、角色、值、模态、时间按绑定注册表和 `ClaimV2` 等正式 operand 解析，未登记的概念只可提出治理申请。转写与嵌套引语沿用 `SourceMetadataV2`、`SourceTransform`、`SpeakerAttribution`。模型报出的作者与探针编号均留在原始输出中。[来源与语义对象](../../core/contracts/semantic_evidence.proto) · [引语端点](../../core/contracts/speak_think.proto)

## 谁给出了候选

本机认证的对端证明谁交回了结果。生成文字的实际生产者另随本次调用记录。两条路径各自保留如下材料：

- **本地**记录经核对的模型、版本化解码设置、隔离与 m = 0 执行依据、实际输出对象。
- **远端**由受信本机调用方绑定授权、服务提供者、实请模型标识、实返模型标识（若有）、服务公布的修订（若有）、生效的格式与参数、获准材料清单、实际请求内容和响应对象。认证密钥排除在材料和记录之外。不可得的权重或 tokenizer 摘要保持缺失。DeepSeek 的成品文本没有本地载体激活测量。用已记录的中性输入、读集与实际隔离依据核对 EV6；依据不足时保留候选，核心拒绝采纳。

沿用 ADR 0046 的 `RemoteAttemptStatus` 和实发、实返的记法。未发送时不得生成实发回执，服务端未回包时不得补写模型名、成功原因或使用量。已有 `RemoteCognitiveReceipt` 绑定独处认知步、文字采纳及内部产物，IRL 调用另以本事件的绑定和正式语义候选为端点。请求对象保存可核验的应用载荷，原始输出和从中解析的候选分别保存，重放用留存字节。[ADR 0046 §2.1](0046-speak-think-contract-gaps.md)

## 从候选到本轮回复

1. 核心以实际连接、请求、目标事件、读集和 `ProposalBindingV2` 对照返回。已发送但断线时记录结果未知，保留已知发送事实。取消、取消确认、失败、陈旧和成功按实记录。迟到成功不能撤销已经生效的取消；未知结果先核对，不能自动再发。
2. `SemanticCandidateV2` 关联解析图、生产者与实际输出。核心将原始调用的材料、生产者回执、候选及原始输出逐项对应。对 IRL，`StageAdoption.producer_resource` 仍等于 `binding.environment.irl`，该字段标识绑定的解释资源。单次实际供应商与模型由调用事实证明。沿用 `check_stage_execution` 将阶段记录与受信执行事实比对；只有核心能形成暂存 z 与概念修订，并在同一外层事务中连同相关记录发布。[核心阶段核验](../../core/crates/core-types/src/semantic/evidence/stages.rs)
3. 本轮模式 B 回复须读到已含本次有效解释、有序依赖及应有状态更新的前缀。合法无作用也可完成。积压时继续等待；失败结束本轮回复、界面报告故障；后补成功不补发。无关任务可继续运行。传输回执、输出完成、暂存成功均不足以启动本轮角色回复。[ADR 0042 §3.1](0042-cause-projection.md)

## 备选、后果与兼容

| 能否省去 | 一个人会怎样 | 哪些事实必须保留 |
| --- | --- | --- |
| 仅靠请求内角色和对象名，无法限定谁可取哪一份材料。故按连接认证、按次借阅 | 把这件事所需的材料交给受托者 | 本次已披露的内容和当时的授权 |
| 仅用本地模型资源标识无法追溯远端调用。保留实发与实返，沿用既有候选、来源与采纳类型 | 听别人提出解释，再核对原话并作判断 | 实际提供者、实际文字、原话版本和当时的采纳结论 |

P1/P4/P7/P9/P10 分别由真实回执、中性输入、逐用途授权、外层事务和证据不足时拒收落实。[ADR 0039](0039-echo-core-principles.md)

实现时新增的内部标签一律在 Rust、Python、TypeScript 三端终端上传入口拒收。对仍有生产者的前驱使用 `@retains`，旧记录按冻结版本读写，回退仍按旧标签解释。冻结前 merge 最新 main，其他契约先合并时重新执行生成器、生成基线与向量，同时跑兼容检查。完整契约和实际双端验收的分工见[规格对照](../traceability/P5-49.md)。
