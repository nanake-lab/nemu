# ADR 0008：Echo Core 规格澄清——快状态只存短期信息、授权作用只投影一次、J 显式以时间为输入

- 状态：已采纳（2026-10-19，用户在对话中批准；以本 ADR 合并进 main 为准）
- 日期：2026-10-19
- 来源：[Echo Core 规格数学结构核验](../traceability/echo-core-math-audit.md)（PR #32）中的 P-1、X-2、X-3
- 变更类别：规格澄清。不改 `docs/echo-core/` 原文、IDL、阈值和验收编号。
- 影响的卡：P5-10、P5-11、P5-12；调用授权作用编译的后续卡（P5-08、P5-19）

## 背景

数学核验发现三处原文有歧义或前后冲突，都在 v1.0（M2）范围内，必须在 P5-10、P5-11、P5-12 开工前定下来。按 `docs/echo-core/README.md` 第 1 节，经用户批准的 ADR 是规格优先级的第 5 层。本 ADR 不推翻任何一处原文，只在有歧义或冲突的地方，选出与原文其他条款一致的读法。

## 决定

### 1 快状态只承载短期信息（P-1，登记 W00-C03）

**问题：**
- O §5.1 声称：「同一 R/θ 和未来条件下，两个初始 x 的差满足 ‖δx(t)‖∞ ≤ e^{−λ_min t}‖δx(0)‖∞」。这个界只对纯时间投影成立。
- O §5.2 的 A_x 写法 `u = tanh(W_z f(z) + W_x x̄ + a)` 和事件门 `g(z, x̄)` 都读 x̄，事件映射因此可能放大初始差异。核验的反例（PHI-7）里，事件流完全相同，两个起点略有不同的 x 却长期停在相反两侧。
- 这与 O §5.1 第 2 段相抵触：「若某历史区别在 x 已固定后仍对未来核心端点产生稳定、不可替代的条件差异，则该区别不应……长期塞进 x，而应进入 R 的 witness/χ/K 路径」。

**决定：**

1. **不变量：** 每次事件映射 x̄ ↦ x̃ 对 x̄ 在 ∞-范数下非扩张，即 Lipschitz 常数 ≤ 1。这里的事件映射包括 F_event 作用、Project_X 和 F_out。由此，同一 R/θ、同一事件序列下，O §5.1 的收缩界在含事件的区间上也成立。
2. **v1.0 的实现方式：**
   - A_x 的输入视图不含 x̄，只含已验证的 z 和固定版本的编码器，即 `u = tanh(W_z f(z) + a)`。O §5.2 只是允许 A_x 读 x̄，并未要求，因此这是收窄输入权限，没有扩大。
   - 事件门只依赖 z，写作 `g = g(z)`。
   - F_event 的 R/θ 作用保持为常数有界稀疏向量。P5-09 已经只接受常数向量。
   - F_out 保持恒等（O §5.3 的正常情形）。需要非恒等时，必须先证明它非扩张。
3. **以后放开的条件：** 如果要让事件作用依赖 x̄，例如「已经很高兴时，同一句话让她更高兴的幅度变小」这种饱和效果，必须证明组合后的事件映射仍非扩张（核验报告 D-1 给出了条件），并另写 ADR。只允许抑制型依赖，不允许自我放大。
4. **情绪延续的归属：** 持续时间超过 T_x 的情绪延续，例如「她一整天都记着早上那句话」，只能经 R 的记忆痕迹（O §5.1 第 2 段的 witness/χ/K 路径）实现。这样的延续能说明来源，也受预算约束。

**验收（P5-10）：**
- I05 的执行检查扩展到含事件的区间：固定 R/θ 和同一事件序列，随机取两个初始 x，断言二者之差满足收缩界。
- 核验 PHI-7 的正反馈构造必须无法通过 A_x 输入视图表达。

**后果：** v1.0 是 NO-GROWTH，R 为空，所以 v1.0 的 Nemu 没有超过 T_x 的情绪延续。事实层面的记忆（她记得你说过什么）走事实视图，不受影响。T_x 的取值在 genesis 校准（P5-17）中确定。

### 2 授权作用编译只做一次时间投影（X-2，登记 W00-C04）

**问题：** `CompileAuthorizedEffects` 在 O §3.2、§10.1、§12、§15 和 S §12 中共有五种写法。O §15 先算 `R_bar = Phi_R(Delta; R)`，再算 `CompileAuthorizedEffects(R_bar, theta, validity(t), t, config)`。如果 R̄ 保留旧锚点，q 包络会被施加两次：核验 PHI-9 中，正确值是 e^{−0.5}，这样算却得到 e^{−1}。这违反 I04、I21，也违反 O §15 自己写的「重复读取不累计衰减」。

**决定：** 统一采用 S §12 的形式：

```
CompileAuthorizedEffects(stored_R, stored_θ, process_time, validity) -> E_eff
```

- 输入是存储快照，带最后一次提交的锚点。时间投影只在函数内部做一次。
- 任何时间投影视图（例如 O §15 的 R̄）都必须把投影时刻记为新锚点。对投影视图编译的结果，必须与对存储快照编译的结果相同：`Compile(Phi_R(Δ; R), t) = Compile(R, t)`。
- O §10.1 的两参数写法读作同一个函数，并补全 validity 和 process_time 两个参数。

**验收：**
- P5-09 已按此实现，见 `docs/traceability/P5-09.md` 中 O 15 一行和 `i21` 测试。
- P5-10、P5-12、P5-08、P5-19 调用编译时一律传入存储快照。
- 补充组合律的性质测试（核验报告 D-3）。

### 3 J 显式以时间为输入（X-3，登记 W00-C05）

**问题：** O §12 的签名是 `J(theta, x, R; carrier_config)`，函数体却用到了 t 和 validity_snapshot。R 证书到期、θ module 的 ValidityContract 到期，都会让 m 随 t 改变。这与 O §12.1 的「相同合法输入和载体版本必得相同 m」冲突。

**决定：**
- J 的签名为 `J(θ, x, R, t, validity; carrier_config)`。
- S §12 的 `JStateView` 必须包含 process_time 和 validity 快照。「相同合法输入」包括这两项。
- F §10 的 `m(s) = J(θ, x(s), R(s))` 读作 `J(θ, x(s), R(s), s, validity(s))`。

**验收（P5-12）：**
- 同一 (θ, x, R) 在到期前、后给出不同的 m。
- 相同的 (θ, x, R, t, validity) 重复计算，m 逐位相同。
- 重放时用记录下的 t 能复现 m。

## 不在本 ADR 内

- **P-2 与 X-1（登记 W00-C06、W00-C07）：** 只影响成长（W06–W10），与 v1.0 无关，写 θ 成长规格时再由用户确认。
  - P-2：机制祖先取沿修订与交接继承后的传递闭包。
  - X-1：全局测试机会编号 j 只在一处记录，另一处只保存引用。建议记在 Q 的治理记录。
- 核验报告第 4 节的设计建议（D-1 至 D-10）不在本 ADR 内决定。其中 D-7（统计资格所需的独立经历块数量）是 θ 成长设计要先回答的问题。

## 备选方案

- **P-1 只改措辞，把收缩界限定在无事件区间：** x 仍可能自我放大并长期保留历史差异，与 O §5.1 第 2 段冲突，I05 的检查也抓不到。未采用。
- **X-2 统一为 O §15 的「先投影再编译」：** 需要每个调用方都正确地重新记锚点，容易出错，而 P5-09 已按 S §12 实现。未采用。
- **X-3 让调用方保证 t 不变，签名不变：** 把到期语义推给了调用方，重放时仍缺少输入。未采用。
