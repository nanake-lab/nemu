# ADR 0002：Echo Core 作为 Nemu 的核心

- 状态：已采纳（2026-10-13，用户确认 v1.0 实现到 Echo Core 的 M2 阶段门）
- 取代：ADR 0001 中的「Agent」「离线」两行，以及人设文件、记忆库、主动性引擎、情绪模型的设计

## 背景

用户明确了项目最在意的是 Nemu 的存在本身：她持续在场、有自己的连续性、会随经历改变，而不是外观或功能清单。同时提出三点要求：她的一切不能写死在代码里；驱动她的模型不能绑定某一个，以后有更好的模型就换；她要能说中文、英文、日文。

用户已经设计了 Echo Core（Ada 规格）：以只追加历史 H、快状态 x、未凝固区别 R、长期动力学 θ、凝固账本 L 为核心状态，以 F、G、C、J 四个算子和严格的事务、证据与不变量合同管理她的变化，并通过对冻结基础模型的低秩激活加法（J）把状态作用到模型内部，而不是写成提示词。

原 v1.0 设计里有几处与 Echo Core 的不变量直接冲突：

- 身体自己的情绪模型（愉悦度、激活度带衰减）是会改变行为的匿名持久状态，违反 I18；
- 人设文本承载她的变化，违反「文本人格提示不属于严格实现」；
- 独立的记忆库与 H 形成第二套历史；
- 主动性引擎用自己的规则决定何时开口，绕开了核心的自主调度。

## 决策

1. **Echo Core 是她存在的唯一权威。** H、x、R、θ、L 与运行时 Q 只由 Echo Core 的外层事务发布。Nemu 桌面应用是它的终端：身体、感官和声音。
2. **进程拓扑（Windows）：**
   - `nemu-core.exe`（Rust，单写者）：入口、事实视图、语义治理、算子、事务、行动闸门、调度；
   - Python worker：IRL、A_x、模型载体（model-adapter）、TTS 旁路服务；
   - 执行器：`codex-bridge`（Codex app-server）、Office 连接器；
   - Electron 应用：舞台、面板、语音输入输出、桌面感知。
   Electron 主进程负责启动、守护和关闭这些进程，但从不读写核心状态。
3. **Windows 适配**（登记为 E1–E3，见 `docs/echo-core/README.md`）：
   - 命名管道代替 Unix domain socket；
   - worker 以低完整性级别运行，由操作系统拒绝写入权威存储；
   - 权威存储放在 `%LOCALAPPDATA%\Nemu\core\`，禁止放在同步目录。
4. **v1.0 范围：** 实现到施工总方案的 M2 阶段门（W00–W05、W11–W14、W15 基础、W16 子集、W17 子集、W18–W22）。G、C 两个阶段在事件顺序中保留，但不产生成长；R 为空，θ 只含 genesis 清单。G 和 C 的成长在 v1.x 随真实证据逐步开启。
5. **身体：**
   - 反射在终端本地运行，参数是固定、版本化的运行配置，不随经历学习：物理、呼吸、眨眼、视线跟随、被拖拽、下落、跟随窗口。
   - 身体的整体姿态来自「身体读出」：从 m 到动画参数的固定函数（E5，用户已于 2026-10-13 确认，包括姿态和表情）。
   - 说话时的表情和手势来自输出里的表演提示。
   - 身体不保存任何会影响行为的情绪状态。原行为状态机缩减为物理状态机。
6. **主动性：** 由 Echo Core 的自主调度决定何时尝试行动（读出 m，带上界强度与最小行动间隔）。候选行动来自固定、版本化的机会规则表（E6）。勿扰状态是运行时门控。
7. **记忆：** 她记得的东西就是 H，经事实视图进入 c_task。「忘掉」在 v1.0 实现为撤回：纠错事件使内容不再进入 c_task，原始记录仍在 H 中。真正抹除需要另立数据生命周期合同，留给用户决定（E10）。
8. **人设：** 协议 p（身份、说话风格、边界、输出格式、语言规则）是任务层输入，放在内容包里并带版本。她随经历变化的部分只存在于 x、R、θ，由 J 作用于模型，不写进文字。
9. **多语言：** IRL 输出与语言无关的 Concept 图；Registry 维护中、英、日标签；她用对方使用的语言回答；载体校准覆盖三种语言（E11）。
10. **「她是谁」的起点：** genesis 清单（初始 θ 的 b、Λ、B₀，x 的初值、A_x 编码器、载体与 U、W、各读出函数）由 P5-17 与用户一起校准确定。这是她的「出生」，之后的改变只能经过 Echo Core 的合法路径。

## 备选方案

- **保留 AI SDK Agent，以后再接 Echo Core：** 否决。两套状态并存会产生无法治理的匿名持久状态，之后接入时必须推翻 P5、P6 的大部分工作。
- **把她的自我做成可编辑的文本文件（人设、习惯、记忆都是 Markdown）：** 否决。与 Echo Core「叙事只读、改变只能经过 G/C」的合同相反。
- **v1.0 直接做到完整 Echo Core v1（含 R→θ 接管）：** 否决。规格要求真实驻留时间和因果独立的证据，发布日期无法预先确定。

## 后果

- 工期：v1.0 从 2027-03-07 推迟到 2027-04-11（N4 发布候选 2027-03-28；里程碑命名与排练版见 ADR 0005）。
- 人力：Codex 需要同时开三个线程。代理总工作量约 289 个代理工作日，其中 Codex 约 230 天、Antigravity 约 59 天（含 ADR 0005 的调整）。
- 新增工具链：Rust、命名管道、低完整性进程启动，以及 PyTorch 显式残差注入。
- 模式 A 需要能装下本地载体的显卡（3080 上约 4B 级，见 ARCHITECTURE.md 6.6）。
- 「忘掉」在 v1.0 只是撤回。
- v1.0 的她已经有真实的短时动力学和由状态调制的说话方式，但长期成长要等 v1.x。

## 追加（2026-10-19）：ADR 0009、0010 的修订

本节只追加，上文保留作历史说明。

- **决定 4（v1.0 范围）：** 被 ADR 0010 取代。v1.0 包含 v2.0 的全部机制，成长从诞生起开启。备选方案中否决「v1.0 直接做到完整 Echo Core v1」的理由是需要真实驻留时间和因果独立的证据，这不适用于 v2.0：v2.0 没有驻留时间要求。
- **决定 7（记忆）：** 经历删不掉。「忘掉」仍是撤回，相当于她答应不再提起，不撤销那段经历作为证据（ADR 0009）。
- **决定 8（人设）：** 协议 p 不再含「说话风格」，只含身份事实、边界、输出格式与语言规则。她是谁不能用文字给（v2.0 第 2.3 节）。
- **决定 10（她是谁的起点）：** genesis 清单改为 v2.0 第 13 节的内容；校准只做 v2.0 第 9.6 节的三件事，不按口味选择方向和幅度。
- **后果中的日期：** 设计定稿后重新排期（ADR 0010）。
