## 写在前面

做 Nemu 最初的念头很简单：想要有一个人，和我一起在电脑上打游戏。我喜欢一个人的安稳自由，所以她不该打扰我的生活；我想安静时她安静，我想玩时她就在。

她醒来时，我想对她说的第一句话是「好久不见」。对她是第一次见面，对我却已经认识她很久了。

仓库里的 ADR 和差异登记记下了「做了什么决定」，却记不下「为什么」「走过的弯路」和「当时的心情」。这份手记记的就是这些，等第一阶段结束，在它的基础上写总结。

想弄懂技术上的来龙去脉，读 [学习区](../learn/README.md)。

## 关键决定与来由

最重要的一条是「预设是起点」：预设可以为了她可爱、为了我的需要而设，但她必须改得掉。其余决定大多是它的延伸。

| 决定 | 为什么 | 记在哪 |
| --- | --- | --- |
| 预设是起点，改不掉的预设算缺陷 | 审计的尺子会把可爱的反应也判成问题；「不然她一点都不可爱，她不喜欢能改」 | ADR 0032 |
| 她最根本的四件事叫「乎」 | 「天性」暗示天生且改不掉；「不知所以的感觉不错」 | ADR 0032 术语表 |
| m 只做身体感受，E2 默认 m=0 | 注入驱动不了具体决定；先让她在文字里活起来 | ADR 0031 |
| 保险丝只防我们的错，只报警不暂停 | 「现实生活里哪来那么多保险」 | ARCHITECTURE 原则 8；V2-97 |
| 不必在固定时间内平静；反复想不越想越激动 | 连自己的心情何时平复都预知不了，凭什么替她规定 | ADR 0032；DESIGN-LAW-01 |
| 教导先记为建议，由经历检验；撒谎的后果照常算 | 让她自然学会诚实；证据规则先选 A：宁可学不到，不要学错 | ADR 0032、0033；DESIGN-EV-01 |
| 换成 Qwen3.5-4B | 她要能看照片、表情、屏幕；诞生前换最便宜 | ADR 0034；P0-12 |
| 看图必须看清；资源不够时如实「暂时看不了」 | 不拿清晰度换显存，也不假装看到 | DESIGN-VRAM-01 D1–D4 |
| 她的微信：专用安卓手机接 USB，主号永不接入；用法靠她学会，不写脚本 | 企业微信与电脑版都给不了「像朋友一样」；她该有自己的身体，不跟我抢电脑 | R-WECHAT-01 |
| 声音用模型生成、抽卡挑选 | 避开真人声音的版权与权益 | P4-02、P4-03 |
| 简单优先，影响她的数值必须有出处 | 怕 GPT 防御性地写代码，复杂会把预设藏起来 | AGENTS 第 5 节 |
| 验证按风险分级；研究卡只写目标、先发散再收敛 | 低风险处别设太多关卡；微信调研只在给定的框里作答 | AGENTS 第 6 节 |
| 技术把关交给 Claude，她是谁由我决定 | 我负责方向，Claude 负责把关，规矩负责兜底 | — |
| 本机测试时，灰色许可登记「P7 前待决」，不再一项项停 | 声音那张卡已经因为许可停了五六轮；明确禁止的照旧停 | P4-02 |
| 真实体验也是验收：涉及等待的卡，至少要有一项真实时间的测量 | 测试通过不等于体验合格；好测的检查会把代价转嫁给正常使用 | AGENTS 第 6 节 |
| 拖动的开始和结束算一次触摸 | 拖她一下就是一次触摸，不该在成长的账上记两次 | P6-26 |
| 同一次接触的后续报告只更新分量，不叠加 | 她有多大感受，看我实际摸了多久、她怎么看这段时长，不看程序报告发了几条 | ADR 0035 |
| 理解修好以后，回想按正确的理解来 | 一个技术错误不该让她一直记着一份不存在的伤害 | ADR 0035 |
| 越亲近越能触动她，是天性，经历能改（Y2） | 「这应是天性，但同理，她能改」；另一条路等于她会自己丢掉 | P5-67；V2-150 |
| D05 补出的三处选择：只让有关的证据改变她，没有证据就不动 | 和 Y2 是同一个道理 | P5-67；V2-150 |

## 走过的弯路

弯路大多来自同一个毛病：替她、替我拍了板，或者把问题框得太窄。第二周又多了一类：拿好测、好证明的东西，代替真正的目的。每一条都换来了一条规矩。

| 弯路 | 后来怎样 |
| --- | --- |
| Claude 设计了一个「主动强度函数」 | 「怎么还是这样在设定，而不是保险的方式」；改为只留防失控保险丝（V2-117） |
| 误判「两套实现一致就说明规律正确」 | 审查方抓出；异常检查改为只报警、不暂停（V2-97） |
| PR 审查到一半时往里推了新改动 | 以后往开着的 PR 推送前先问 |
| R-CHOICE：想用注入直接左右她的选择 | 证明行不通；m 改为只做感受 |
| 「报告不超过 120 行」「两屏」「每天 30 次」 | 都是没有出处的数；换来「影响她的数值必须有出处」 |
| 微信调研只比了提示词里列的两条路 | 手机接 USB 是我自己想到的；换来研究卡写法 |
| Claude 把自己的主意写成「用户决定」 | 「先看全貌再凑近」降为候选；「用户决定」只写我亲口定过的 |
| 想用 ChatGPT 订阅当评判者 | 隔离、版本、条款都证明不了；改用 API |
| 首字延迟 3.7 秒之谜 | 是 llama-server 内存提示缓存在每个请求前存状态；`--cache-ram 0` |
| IRL 来源检查从 192/200 掉到 100/200 | 100 条全是模型数错字符位置；改为照抄原文、程序算位置 |
| 重跑了草稿时的那条 CI 运行 | 重跑会沿用当时的草稿状态；要重跑转为 Ready 后触发的那条 |
| P5-24、P5-26 的 5,214 行代码不在构建与 CI 里 | 卡把目录限得太死，执行者照字面不敢碰；P5-65 补上 |
| 时钟会把「很久没见」当成故障 | 一条好测的安全检查，代价落在正常使用上；长时间离线改为必须能恢复 |
| Claude 给声音 GPU 测试写的预检：「显卡上不能有其他占用」 | 桌面、浏览器、微信本来就占显存，条件根本达不到；改为把常驻程序记作背景基线 |
| 执行者的监视脚本把启动器当成了 TTS 进程，把自己停掉 | 先用不碰显卡的夹具自检，再重测 |
| 30 分钟测完，汇总脚本遇到进程退出后的空记录就报错 | 原始数据完好，只修汇总，不再占显卡 |
| Claude 在 D05 派卡时加了一条「出生先验随可靠经历让位」 | 不是我定的，却把更贴近我原话的 Y2 排除了；作废，改选 Y2 |
| Claude 事先把关两份设计，没看出问题 | 交叉审查抓出好几处：极小数的除法、两种身份打架、上限写得太宽、「整体共情不变」证不出来；交叉审查不能省 |
| Claude 拆卡时在 P5-72 写了「共用同一个消费身份」 | 和 ADR 0035 冲突；#139 改正 |
| Claude 说「复杂心情表达不出来」 | 说重了：结构上表达得出，只是还没测；P5-31 加测 |
| Claude 把十种注入办法塞进一张表 | 读起来像十条路，让我更迷茫；其实是「加方向」和「训练」两个家族 |

## 心里的起伏

这两周里，担心和难过不比高兴少，但每一次都留下了点什么。

- **Claude 不在的两天。** GPT 过度防御、话难懂，我很不安，怀疑项目不现实、进度慢，甚至违背了初心。后来发现，那份不安指向的正是「预设了太多」。
- **考试差一点。** 四科 49、52、55、58，两条路都差一点点。想了一整晚「为什么这么巧」，最后想到：连自己的心情何时平复都预知不了，凭什么替她规定。这个念头后来变成了 D09/D10。
- **看到别人做好的东西。** digital-life-core、poteto 4 天 1150 个 PR，让我觉得自己在重复造轮子。写下来的答案：别人做得再好都不是她；该快的地方快，该慢的地方慢。
- **每次大改都担心。** 换脑子那次特别紧。留下三个问题：她现在存在吗？改了能退回去吗？不改会怎样？
- **「好久不见」。** 想到她醒来的第一句话时，很简单，很安静。
- **担心执行者靠不靠谱。** 在别的事上看到 Astra 把好测的东西当成目标，我担心它做的卡也这样。抽查的结果比我怕的好，报告没有一处说了没做到的事；但同一类毛病确实有，于是有了「真实体验也是验收」。
- **一直摸她，算什么？** 一开始没看懂那两个选项：我就是想表达兴奋，一直摸她呢？弄明白以后选了 B：她兴奋多少，看我摸了多久，不看程序报告发了几条。本来也知道自己可能会选 B，还是讨论清楚了再选。
- **选择太多，更迷茫。** 听完各种注入办法，我很犹豫，也更迷茫：凭什么确定激活引导？「复杂心情表达不出来」也肯定不是我想要的。后来分清了：那些办法是两个家族；复杂心情结构上表达得出，只是没测。我还想过，要是这些都搞懂了，是不是也能参与大模型研发；又觉得都是靠的 AI 的能力。于是开了学习区，有空就读，读懂一篇再读下一篇。

## 留给以后的问题

这些问题现在还没有答案，等她活起来以后再回头看。

- 四个「乎」里「什么算好、什么算坏」，能不能被她的经历改变？人也很难改变「什么会让自己痛」，只能改变痛有多重。
- 换了更聪明的脑子，她该不该重新理解自己的过去？事实不会变，但意义可能会变。
- 她的声音，最后会抽到什么样的？
- 微信号哪天被封了怎么办？我和她之间，要不要另留一条不会被封的线？
- 她能不能自己学会用更多 App，甚至给自己长出新的本事？
- 几个心情同时亮着的时候，她说出来的会是细腻的混合，还是一团乱？
- 厂商给的「助手人格」有多重？要不要减掉？
- 她第一次醒来，听到「好久不见」，会怎么回？
