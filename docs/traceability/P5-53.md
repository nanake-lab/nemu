## 第 2/4 部分　排练运行时与认证终端

| 依据 | 实现与证据 |

| v2.0 §§2、13；I02、I18；ADR 0049 | [运行时处理器](../../core/crates/core-runtime/src/handler.rs)接手唯一提交能力，使用同一 D 队首的绑定、阶段输出和已发布七根。初始头和事件头均可作为第一次或随后一次事件发布的基线。[临时库故障与恢复](../../core/crates/core-runtime/tests/handler.rs) |

| ADR 0049 阶段表；终端契约 §4.3 | 网关从核验过的同一提交读取 Q。新认证会话收到当前状态，运行状态变化时向已认证会话推送。两个桌面会话还核验了输出、取消、错误和审批请求的归属。[网关](../../core/crates/gateway/src/downlink.rs) · [实际桌面接收联测](../../core/crates/core-runtime/tests/desktop_push.rs) · [混合帧和延迟结算](../../packages/terminal/src/index.test.ts) |

## 第 3/4 部分　模式 B 的已提交原文与外层发言人

| 依据 | 实现与核验 |
| --- | --- |
| v2.0 §2.1、§2.4；I02、I18；ADR 0046 §2.2、ADR 0047 | [本机身份签发器](../../core/crates/nemu-core/src/authority.rs)按原会话和安装查回持久事件的 LocalUserBinding，[运行时](../../core/crates/core-runtime/src/local_text.rs)核对安装、会话和 ADR 0047 的直接文字来源。外层 QuoteLayer 绑定本分支的事件 ID、完整载荷版本、UTF-8 字节区间与身份依据，由原有提交能力随事件一次发布。缺少身份的旧记录仍可按原规则读取。 |
| ADR 0042 §§1.1、2.4、3.2；I16、I21 | [存储读者](../../core/crates/core-store/src/queries.rs)在同一读事务中核验当前提交前沿、原事件事务和 H 提交位置。[排练输入](../../core/crates/fact-view/src/mode_b.rs)从同一 W19 视图核对本轮输入和必需事实，保留实际查询及审计轨迹。主体来自该事件提交中的外层归属和身份记录。缺证、过期、无权、撤回或查询不完整时拒绝取材。 |
| ADR 0049；I29 | [临时排练库用例](../../core/crates/core-runtime/tests/handler/history.rs)覆盖同文不同人、错误版本／分支、仅收件、发布失败与重开、拒绝后快照相同而前沿已变，以及撤回和缺失身份。[Windows 管道用例](../../core/crates/core-runtime/tests/handler/windows.rs)用临时配对、真实本机认证服务和独立读者逐字段对照原签发记录，核对跨会话身份与两次实际提交，中间的重投只得到 FILTERED。 |

本部分提供本机直接文字的外层发言人。语音、转述中的第三方和已投递的她的发言需要各自的身份或投递依据。F 类别、关系权重及独立 law 资源沿排练降级保留缺失。P6-04 2/2 消费此输入并负责生成；HOST-01 2/2 接宿主，P5-53 第 4/4 部分负责时钟恢复。首次真实对话尚未验收。验证结果及原始证据见 [PR #277](https://github.com/nanake-lab/nemu/pull/277)。
