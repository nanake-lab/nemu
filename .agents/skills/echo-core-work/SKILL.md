# Echo Core 施工方法

## 何时使用

任何会改动 `core/`、`workers/`、`executors/`，或会改变终端与核心之间消息的任务。

## 1. 先读什么

1. `docs/echo-core/README.md`：优先级、v1.0 范围、Nemu 集成扩展登记（E1–E14）。
2. `docs/adr/0005-rehearsal-and-birth.md`：分阶段启用、排练谱系与正式谱系、诞生。
3. 任务卡「必读」列出的规格章节，读原文转换版，不要只读摘要。
4. `docs/traceability/`：已经实现的条款和对应测试，避免重复或冲突。

规格有歧义时，不要选一个「看起来合理」的解释直接实现。在 `docs/traceability/diff-register.md` 追加一条，然后实现最保守的解释，并在报告的「待用户确认（阻塞）」里列出。最保守的解释是：拒绝、隔离或不产生成长。

## 2. 规格对照表

每张卡在 `docs/traceability/<任务号>.md` 写一张表，并在报告里引用：

| 规格条款 | 原文要点（一句话） | 实现位置 | 测试（含验收编号） |
| --- | --- | --- | --- |
| 《核心算子》4 | 单事件顺序 Γ→Φ→H⊕r→IRL→F_in→G→C→F_out→提交→J | `core/crates/core-runtime/src/process.rs` | `X06`、`tests/order.rs` |

## 3. 验收编号的组织

- 规格里的验收编号（F01…F07、J01…、X01…、SYS01…、v0.6.4 的 16.x、施工合同的 10.x）一律原样作为测试 ID。
- 测试放在 `core/tests/acceptance/<编号>/`，每个目录包含：
  - `README.md`：构造、预期、所用 profile；
  - 测试代码；
  - 运行后生成的 `result.json`（结论只能是 passed、failed、not_run、non_identifiable 之一）。
- 每个编号既要有拒绝用例，也要有能成功的正向用例。恒等 G、C，常量 J，忽略 m 的模型，都必须被相应正向用例杀死；但这类正向用例属于 M7 时，在 v1.0 标为 not_run，不要伪造。
- 结构夹具 profile（`profiles/structural_fixture/`）只用于逻辑测试，不得用来声称行为有效；它签发的任何证书或资格都不能进入正式数据库（AT12）。

## 4. 最容易违反规格的地方

| 错误做法 | 正确做法 | 依据 |
| --- | --- | --- |
| 把所有输入塞进一个 `context` 字典传给算子 | 每个算子一个只含获准字段的 DTO | 总方案第 3 节 |
| Proposal 版本对不上时「顺手 rebase」 | 拒绝，重新计算 | I14、施工合同 3.4 |
| J 或调度读取原文、z、H 或审计文本 | 只读授权作用视图和 x | 《核心算子》3.2、12 |
| 读取时把衰减写回存储 | Φ 和 CompileAuthorizedEffects 是纯投影 | I21 |
| 同一事件推进两次时间，或 F_out 再做一次驱动 | 一次 Φ、一次脉冲 | I04、5.3 |
| m 改变后复用旧的 KV 缓存 | 缓存键包含 m 摘要，m 变了就重算 | J05、《核心算子》13.2 |
| worker 打开 SQLite 写数据 | worker 低完整性运行，只返回 Proposal | I02、E2 |
| 用模型文字说明「她变了」当作证据 | 只认验收编号要求的测量 | 《核心算子》14 |
| 终端保存「心情」变量来驱动表情 | 表情基线来自核心推送的身体读出 | I18、CONTRACTS.md 第 7 节 |
| 模式 B 的回执写成严格调制 | 标为 `TEXT_PROJECTED`、非严格 | ADR 0003、I15 |
| 尚未接通的阶段直接跳过，不留记录 | 走规格的降级路径（IRL 走 ⊥sem，F 停用时 m = 0），写审计和运行状态 | E13、总方案第 21 节 |
| 「F 停用」的分支在正式谱系里也能走到 | 停用只在排练谱系的类型能力下可以构造；正式谱系启动时检查全部阶段已接通 | E13、E14 |
| m = 0（排练或载体失效）时照常自主行动 | 暂停依赖核心的自主行动；只有模式 B 的 `TEXT_PROJECTED` 例外 | 总方案第 21 节、ADR 0003 |
| 测试或基准打开用户的排练存储或正式存储 | 一律在临时目录里新建测试谱系 | AGENTS.md 黄金规则 14 |
| 外部行动结果未知时自动重发 | 进入 UNKNOWN，核对后处理 | X04 |
| 为了让测试通过，换一个 profile | 每次语义相关修改都升版本并重验 | 《核心算子》19 |

## 5. 报告里必须写的东西

- 规格对照表的链接。
- 涉及的不变量（I01–I22）分别怎样检查：类型能力、运行时断言、离线核验器，还是测试。
- 新增或修改的 IDL 消息，以及黄金向量的变化。
- 差异登记新增的条目。只要有新增，就是阻塞项。
