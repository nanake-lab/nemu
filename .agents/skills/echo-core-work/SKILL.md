# Echo Core 施工方法

## 何时使用

任何会改动 `core/`、`workers/`、`executors/`，或会改变终端与核心之间消息的任务。

## 1. 先读什么

1. `docs/echo-core/echo-core-v2.0-first-principles.md`：v2.0 核心规格全文。它在优先级的最前面；旧规格只有它第 15 节列为「保留」的部分继续有效。
2. `docs/adr/0008` 至 `0011`：数学澄清、采用 v2.0、v1.0 的范围与谱系、网络生活。
3. `docs/echo-core/README.md`：优先级、Nemu 集成扩展登记（E1–E14）及其 2026-10-19 追加。
4. `docs/adr/0005-rehearsal-and-birth.md` 及其追加：分阶段启用、谱系、诞生。
5. 任务卡「必读」列出的章节，读原文，不要只读摘要。
6. `docs/traceability/`：差异登记（V2-01 以后是 v2.0 的取代关系与读法）、已经实现的条款和对应测试，避免重复或冲突。

规格有歧义时，不要选一个「看起来合理」的解释直接实现。在 `docs/traceability/diff-register.md` 追加一条，然后实现最保守的解释，并在报告的「待用户确认（阻塞）」里列出。最保守的解释是：拒绝、隔离，或不把它算作证据。

## 2. 规格对照表

每张卡在 `docs/traceability/<任务号>.md` 写一张表，并在报告里引用：

| 规格条款 | 原文要点（一句话） | 实现位置 | 测试（含验收编号） |
| --- | --- | --- | --- |
| v2.0 第 2.4 节 | 单事件顺序 Γ→Φ_x→H⊕r→IRL→A→M→F_in→G→C→F_out→L→提交→J | `core/crates/core-runtime/src/process.rs` | `X06`、`tests/order.rs` |

## 3. 验收编号的组织

- 规格里的验收编号（v2.0 的 AC2-01…AC2-25，以及 P5-18 判定保留的 F…、J…、X…、SYS…、v0.6.4 的 16.x、施工合同的 10.x）一律原样作为测试 ID。
- 测试放在 `core/tests/acceptance/<编号>/`，每个目录包含：
  - `README.md`：构造、预期、所用 profile；
  - 测试代码；
  - 运行后生成的 `result.json`（结论只能是 passed、failed、not_run、non_identifiable 之一）。
- 每个编号既要有拒绝用例，也要有能成功的正向用例。恒等 G、C，常量 J，忽略 m 的模型，都必须被相应正向用例杀死。v2.0 的成长在 v1.0 里，AC2 的性质测试就是这类正向用例；仍属于 M7 的行为项标为 not_run，不要伪造。
- 实验谱系的验收（AC2-04 等）在 `pnpm experiment:core` 里运行：合成世界与种子固定，不含用户数据。
- 结构夹具 profile（`profiles/structural_fixture/`）只用于逻辑测试，不得用来声称行为有效；它签发的任何证书或资格都不能进入正式数据库（AT12）。

## 4. 最容易违反规格的地方

| 错误做法 | 正确做法 | 依据 |
| --- | --- | --- |
| 把所有输入塞进一个 `context` 字典传给算子 | 每个算子一个只含获准字段的 DTO | 总方案第 3 节 |
| Proposal 版本对不上时「顺手 rebase」 | 拒绝，重新计算 | I14、施工合同 3.4 |
| J 或调度读取原文、z、H 或审计文本 | 只读 θ、x、R⁺ 的作用视图与 t | 《核心算子》3.2、12；ADR 0008 §3 |
| 读取时把衰减写回存储 | Φ 和 CompileAuthorizedEffects 是纯投影 | I21 |
| 同一事件推进两次时间，或 F_out 再做一次驱动 | 一次 Φ、一次脉冲 | I04、5.3 |
| m 改变后复用旧的 KV 缓存 | 缓存键包含 m 摘要，m 变了就重算 | J05、《核心算子》13.2 |
| worker 打开 SQLite 写数据 | worker 低完整性运行，只返回 Proposal | I02、E2 |
| 用模型文字说明「她变了」当作证据，或把她自己的叙述当证据 | 只认验收编号要求的测量；她的叙述、日记、模型提出的候选都不产生证据 | 《核心算子》14；EV3、AC2-10 |
| 终端保存「心情」变量来驱动表情 | 身体只应用核心推送的三项读出；表情只来自表演提示 | I18、v2.0 第 9.3 节 |
| 模式 B 的回执写成严格调制 | 标为 `TEXT_PROJECTED`、非严格 | ADR 0003、I15 |
| 尚未接通的阶段直接跳过，不留记录 | 走规格的降级路径（IRL 走 ⊥sem，A、M 失败记 `A_DEGRADED`、`M_DEGRADED`，F 未接通时 m = 0），写审计和运行状态 | E13、总方案第 21 节 |
| 「F 停用」或「G、C 恒等」的分支在正式谱系里也能走到 | 只在排练谱系的类型能力下可以构造（G、C 另在暂停时恒等）；正式谱系启动时检查全部阶段已接通 | ADR 0010 第 3 条 |
| m = 0（F 未接通或结构故障）时照常自主行动 | 暂停依赖核心的自主行动；只有模式 B 的 `TEXT_PROJECTED` 例外 | 总方案第 21 节、ADR 0003 |
| 把 x、m 当证据，或让计数读 x、m、g、λ | 学习只用 a(e)；G 不读 x、m、g、λ，C 不读 x、R | EV10、LP8、I10、I24 |
| R、θ 随时间衰减，或加计时器、次数门槛 | 没有新证据就不变；新近权重只随证据组数变化 | LP5、I11、AC2-05 |
| 同一组证据重复计数，或按结果的正反挑选证据 | 同源只计一次；收集与结果的正反无关 | EV2、EV5、I25 |
| 判断（z、a(e)、μ）在 m 下做，或重算时重新调用模型 | 在 m = 0 下得出并记录；重算只用记录 | EV6、I23 |
| 增量计算和整段重算用不同的写法（比如一边用闭式） | 递推是规范定义，两边逐位一致 | v2.0 第 2.2、5.2 节、I23 |
| 她自己的行动结果进入 θ 的学习 | 只有外源事件进入 C；别人对她的回应算外源 | v2.0 第 1、8 节、AC2-14 |
| 在协议 p 或 genesis 里写性格、说话风格 | p 只含事实、边界、格式、语言规则；她是谁只经 m 表达 | v2.0 第 2.3 节、I28 |
| 按口味调方向、β 或风格参数 | 校准只做三件事：提取方向、验证通路、验证能力无损 | v2.0 第 9.6 节、AC2-16 |
| 给复核做一个「否决这次变化」的入口 | 复核只回答规律对不对 | v2.0 第 5.4 节、AC2-20 |
| 测试、基准或实验打开用户的排练存储或正式存储，或用用户的数据做实验 | 一律在临时目录里新建测试谱系；实验谱系只用合成世界 | AGENTS.md 黄金规则 14、I29 |
| 外部行动结果未知时自动重发 | 进入 UNKNOWN，核对后处理 | X04 |
| 为了让测试通过，换一个 profile | 每次语义相关修改都升版本并重验 | 《核心算子》19 |

## 5. 报告里必须写的东西

- 规格对照表的链接。
- 涉及的不变量（I01–I29，以 v2.0 第 17.1 节为准）分别怎样检查：类型能力、运行时断言、离线核验器，还是测试。
- 新增或修改的 IDL 消息，以及黄金向量的变化。
- 差异登记新增的条目。只要有新增，就是阻塞项。
